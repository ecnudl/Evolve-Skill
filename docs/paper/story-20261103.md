## 1 三种定位

### 1a 持续累积、互不干扰

**Title**: *Accumulate Without Interference: Routed Executable Skills for Continual Skill Learning Across Heterogeneous Benchmarks*

**Abstract**: LLM agents that learn skills from experience usually store them as text injected into every prompt, so a skill learned on one task silently changes behavior on all others. We represent skills as small executable procedures with an applicability predicate that run around a frozen solver, so a procedure alters only the requests on which it fires and leaves every other request byte-identical. In a sequential five-benchmark protocol (SearchQA, OfficeQA, ZebraLogic, SpreadsheetBench, ALFWorld) read on all five held-out test sets after every step, the learner acquired a constraint-solving procedure that raised ZebraLogic accuracy by 10.0 points (21 items fixed, 1 broken), and an exploration-memory package learned in the same framework in a separate single-benchmark run raised ALFWorld accuracy by 11.9 points on its first held-out read (18 episodes fixed, 2 broken; a later in-chain re-read of the same 134-episode panel gave +17.9, room-clustered 95% CI [−6.1, +41.9]) [deepseek-v4-flash; GLM-5.3 chain pending]. No accepted procedure fired outside its benchmark, so forgetting and negative transfer on the other benchmarks were exactly zero, whereas merely swapping the per-benchmark instruction cards cost up to 22.1 points. Accumulation helped where the model lacked a capability (state tracking, exhaustive search) and found nothing to add where the remaining headroom was answer format.

需要的主张：A1 多步累积（链上多个学到的程序共存且各自有效）；A2 不遗忘、无负迁移；A3 前向/后向迁移；A4 顺序无关。
证据：A2【已支持，按构造】；A1【部分】每条链只学出 1 个程序（ZebraLogic），ALFWorld 包是导入的；A3【需实验】没有任何相似 bench 增益；A4【需实验】。风险：审稿人会说“任务身份已知、程序按 bench 隔离，零遗忘是平凡的”（参数隔离类持续学习的老问题），故事会落到“零遗忘但零迁移”。

### 1b 不需要验证集的验收

**Title**: *No Validation Set Required: Fresh-Slice, Byte-Exact Acceptance of Learned Executable Skills*

**Abstract**: Methods that improve LLMs from experience keep an update only if it helps on a held-out validation set, which must be large to resolve small effects and loses validity when reused adaptively. We show that for skills written as executable procedures that fire on a subset of inputs, the fixed validation set can be dropped: training rounds are checked on pre-drawn training-side confirmation slices, and each accept/reject decision reads a separate training-side acceptance batch, determines byte-exactly which requests the candidate changes, scores unchanged requests as exact ties, and requires a practical gain over a pooled no-procedure baseline. Packages accepted this way improved held-out test accuracy by 11.9 points on ALFWorld (18 episodes fixed, 2 broken; acceptance +24.0) and 10.0 points on ZebraLogic (acceptance +12.0), and changed no request on the other benchmarks of a five-benchmark chain; in both accepted cases the decision slices had been used before (ALFWorld's acceptance slice on its third use; ZebraLogic's acceptance and confirmation slices in earlier runs), which we disclose. Measured same-text noise—6.7 points between two byte-identical arms on 150 ALFWorld episodes—explains why an earlier single-baseline rule accepted a package with zero test effect and motivates the pooled baseline and exact ties. With only a zero-shot instruction card and no validation data, the system reaches the level of validation-selected text-skill optimizers on QA benchmarks and is numerically above them on ALFWorld, where a learned procedure fires (about 6–8 of 134 episodes; within the same chain the procedure's gain over the card alone is not significant); ZebraLogic has no text-skill baseline yet [cross-run comparison, GLM-5.3 only; same-time baselines pending].

需要的主张：B1 收下的包在留出测试集上有效；B2 验收能分开有用与无用（误收率、功效已知）；B3 不触发处零伤害；B4 与带验证集的方法相当或更好。
证据：B1【已支持】三例（alfworld-v11、main-v6 D Zebra、main-v6 G Zebra；验收或确认片都复用过，见行 1、2、5；G 链 11/04 09:48 打开：+21.0 [+15.3, +26.7]，42 好 0 坏）；B2【部分】只有 3 个“收下且读过测试”的例子、已知 1 次旧规则误收；另有 ≥2 个事后读数有效的程序在验收之前（自写测试检查、整包确认）就丢了，不算验收误拒（行 14），没有标定；B3【已支持，结构性】；B4【部分】只有跨运行对照（§2.1），ZebraLogic 没有基线。

### 1c 可执行 vs 文字技能

**Title**: *Code, Not Prose: Executable Skills Gain Where They Fire, While Textual Skills Carry Benchmark Conventions—and Their Harm*

**Abstract**: What do skills that LLMs learn from experience actually contain, and what happens when they are reused on other tasks? Across two validation-selected text-skill optimizers (SkillOpt, GEPA), our own text-rule learner and a zero-shot instruction card on five benchmarks, nearly all measurable gain was benchmark-specific answer convention: the zero-shot card scored highest (five-benchmark macro average 66.7 vs 66.0 for SkillOpt and 63.5 for GEPA), and text learned on one benchmark hurt others (at one stage GEPA's QA-specific hints cut ALFWorld from 120 to 93 of 134 episodes). Executable procedures behave differently: they supply state the model cannot keep (visited and empty containers in ALFWorld) or search it cannot do (constraint solving in ZebraLogic), adding 10.0 (ZebraLogic; 21 items fixed, 1 broken) and 11.9 points (ALFWorld, first held-out read; 18 episodes fixed, 2 broken) on held-out tests, while the same ALFWorld content given as text scored 20.1 points below its executable form. In a full 5×5 swap of instruction cards with the procedure package fixed, foreign cards cost up to 22.1 points (only one swap helped significantly, +7.6; other gains, up to +4.9, were not significant), whereas routed procedures changed no request outside their own benchmark. This suggests a division of labor—text for conventions, routed and gated per benchmark; code for capability gaps—and explains why procedure learning found nothing to add on format-bound QA benchmarks.

需要的主张：C1 文字技能 = 作答约定；C2 文字跨 bench 有害；C3 程序在能力缺口处有效；C4 同一内容代码胜过文字；C5 程序不伤害别处。
证据：C1、C2、C5【已支持】；C3【已支持】（一个学到的、一个导入的）；C4【已支持，仅 ALFWorld】。弱点：这是分析型论文，回答不了负责人“不需要验证集也能达到基线”的主张；交叉读数与植入读数是事后上界、同面板重复读。

### 1d 推荐：1b 为主线，1c 作机制，1a 作评测框架

**Title**: *Learning Skills Without a Validation Set: Routed Executable Procedures Help Where They Fire and Stay Silent Elsewhere*

**Abstract**: Prompt optimizers keep a skill update only if it helps on a held-out validation set, and experiential memories mostly keep what they collect without a paired acceptance test, because a textual skill touches every request and its harm can only be seen on the whole distribution. We make skills local: each is an executable procedure with an applicability predicate, run around a frozen solver behind a fixed zero-shot instruction card, so the set of requests a candidate changes is known byte-exactly before any model call. Locality lets us replace the fixed validation set with pre-drawn training-side confirmation and acceptance slices, on which unchanged requests are exact ties, only touched items carry signal, and a pooled no-procedure baseline absorbs measured same-text rerun noise; in our development history these slices were reused, including in both accepted cases below (ALFWorld's acceptance slice on its third use; ZebraLogic's acceptance and confirmation slices in earlier runs), which we disclose. In a sequential five-benchmark chain read on all five held-out test sets after every step, the learner acquired a ZebraLogic constraint solver (+10.0 points; 21 fixed, 1 broken) and carried an ALFWorld exploration-memory package learned the same way in a single-benchmark run (+11.9 on that run's first held-out read, 18 fixed, 2 broken; the in-chain re-read of the same 134-episode panel gave +17.9, room-clustered 95% CI [−6.1, +41.9]), while the other three benchmarks received byte-identical requests; swapping only the textual instruction cards between benchmarks cost up to 22.1 points. Without validation data the system is comparable to validation-selected text-skill optimizers where the remaining gains are answer conventions and, on ALFWorld where a learned procedure fires, numerically above them (about 6–8 of 134 episodes, cross-run; within the chain the gain over the card alone is not significant); ZebraLogic has no text-skill baseline yet [second solver chain, same-time SkillOpt/GEPA/memory baselines and acceptance calibration pending].

理由：(1) 直接对应负责人的故事；(2) 它的核心机制“局部性”正好用上我们最硬的数据：请求逐字节相同（行 7）、换卡伤害对程序沉默（行 9）、同一内容代码比文字高 20.1 分（行 6）；(3) 1a 单独讲只剩“零遗忘、零迁移”，1c 单独讲是分析文，都比合起来弱。达到投稿水平前必须补的三件事里 E1（G 链读数）已于 11/04 完成（第二种模型复现：+21.0，42 好 0 坏）；还必须补 **E5（同时段基线）、E6（验收标定）**；E2、E9、E10、E13 是便宜的加固。

## 4 “不需要验证集”的论证

### 4.1 我们说的“没有验证集”是什么意思（论文里要原话写清）

- 方法里**没有一个固定、反复使用的选择分区**；每个接受/拒绝决定用训练池里新抽、事先划好的一片题，只用一次；测试集只在链末读一次，不回流到学习。它**不是**“没有任何留出数据”：验收片本身就是一次性的留出片。10/21 方向建议里提给负责人的第 6 项决定“每批新题只用一次的整版验收算不算验证集”（状态 §5）至今没有定论，论文里要正面回答：算一次性留出片，不算验证集；区别是不复用、不在多个候选之间挑最优、决定后作废。
- 要披露的例外：v2.18 的“拆开重判”在同一批确认题上检验多个子候选（负责人批准的放宽，最终以另一片新题上的验收为准；流程 v2.18 段）。

### 4.2 用什么替代

1. **新鲜练习片**：每步运行批 → 最多 6 轮训练（练习题 = 运行批 + 采纳的生成题）→ 每轮一片事先划好、轮间不重叠的确认题（main-v4：SearchQA 尾部 6×40，其他 6×4）→ 验收批只读一次（ZebraLogic 运行 60 / 确认 40 / 验收 100；SearchQA 验收 1,000 题）。来源：流程 v2、v2.11、v2.14 段；账本 10/31 06:10。
2. **被碰到的题记账**：训练轮只跑两包启用程序不同的题（修好多于弄坏、净增 ≥ max(1, 2%)）；验收里请求逐字节相同的题只发一次、差值记精确的 0（v2.3 起；零调用回放：验收格子省 69% / 20%，训练格子约 45% 可不发）；v2.21 把门统一成“只看请求不同的题：净修好 ≥ max(3, 10%)、弄坏 ≤ 修好的 2/3”，并在新抽的被碰到的题上验收（≥ 60 道，按路由零调用抽样）。来源：流程 v2、v2.3、v2.21 段。
3. **整批不退步**：验收差值除以整批题数；父包在本 bench 没有程序时用合并基线 S′ − (S+C)/2，因为 S 与 C 请求相同也会差 +6.67（账本 10/29）；main-v6 用整批 +5 分实用线；v2.21 改为“整批不低于 −1 分”作伤害护栏。来源：流程 v2.2、v2.9.7、v2.11、v2.21 段。
4. **相同请求记账**：链末读数里与 C 请求相同的格子直接复用（v2.18），并列第二分析（请求相同记 0，10/31 起的固定报告形式）。这把“别的 bench 不受伤害”变成可数的量：非目标 bench 上被改动的请求数（main-v4/v5/v6、implant-v5 都是 0）。来源：流程 10/31 段、v2.18 段。
5. **不放松的部分**：泄漏检查、沙箱、静态禁令、元选项反事实、两位判官核对程序笔记是否属实；验收、冒烟、封存题的答案不进任何角色的提示。来源：流程 v2.1、v2.9、zebra-pc-v1 段。

**为什么局部性能代替验证集**：文字技能对本 bench 的每个请求都生效，每道题都可能被改坏，只能在足够大、代表整个分布的留出集上看净效应。可执行程序只改触发处的请求，改了哪些题在调用模型前就能逐字节算出，没改的题差值恒为 0、不含噪声；于是 (i) 证据全集中在被碰到的题上，(ii) 伤害只可能发生在被碰到的题上，(iii) 整批不退步可以由被碰到的题直接推出。代价：低覆盖的程序在整批门槛下按构造过不去（SearchQA 候选只碰 30 多题/1,000，状态 §0 11/02 13:5x），这正是 v2.21 改成“被碰到的题上净增 + 整批不退步”的原因。

### 4.3 它不保证什么

- **测试集上一定有增益**：验收是有限片上的选择；alfworld-v10 在旧规则下验收 +6.0 通过，测试 F 92 = C 92。
- **迁移**：只保证“不触发就不变”，不保证别处变好。
- **触发处不出错**：触发判断和笔记是模型写的，触发的题可以变坏（main-v6 Zebra 1 坏；cross-v5 D 链 Zebra 3 坏）。
- **任务身份未知时无害**：现在每个 bench 有自己的外壳和卡，程序还有来源范围规则（流程 v2.14 段）。Zebra/ALFWorld 程序在别处 0 触发，是 applies() 自己不触发还是范围规则挡住【待核】。
- **研究者自由度**：门槛和机制是看过结果后一版版改的：v2.2 门槛在看过 main-v2-1 验收后定；v2.9.7 在看过 v10 的验收和测试后定（已在预注册披露）；ZebraLogic 循环改进（v2.15/v2.16）的依据引用了 v3r4 的测试读数（账本 10/31 01:35）。
- **统计**：每题每组只读一次；区间只含题目抽样；ALFWorld 只有 4 个房间簇（+17.9 的区间 [−6.1, +41.9]）。
- **跨时段漂移**：复用相同请求的格子消除了重跑噪声，但不同时段的跨运行比较不受保护（同一请求不同时段约差 6 分，账本 10/21 06:02）。
- **训练池会用完**：每步要新题，例如 LiveMath 283 道正好用完（流程 10/22 段）。

### 4.4 让它可信的对照

已有：同文本重跑地板（行 15）；安慰剂与“程序当文字”对照（alfworld-v11 验收 S′−P_y +21.3，测试 F−P_F +14.9、F−T_F +20.1）；路线 A 的 cal-1 里安慰剂文字让分数动 −9.8 到 +3.6 分（账本 10/20 23:43）；逐程序消融（alfworld-v11 去掉 p-alfworld-1-14 验收掉 18.7 分）；规则回放（alfworld-v10 在合并基线下 +2.67 → 拒；main-v2-1 D 第 3 步在实用规则下 +9.0 → 收，流程 v2.2 段）；已知有效程序当正对照（v3r4 在 100 题验收探针 96 对 83，会过 +5 线，账本 10/30 18:27）。
