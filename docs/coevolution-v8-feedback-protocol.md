# V8：公开错误反馈配对实验（运行前冻结）

日期：2026-09-13。

目标：测试具体、可追溯的公开错误反馈，是否比笼统反馈更能修复同一初始回答，并且不损害原本正确的回答。这是验证反馈接口的工程消融，不是 Skill 自进化、DeepResearch 效果或原始 SkillOpt 的 benchmark 比较。

## 面板与干预

- 新开发面板：Coding 4 个、Spreadsheet 2 个、RuleReasoning 2 个结构家族，各 2 个实例，共 16 题；实例不作为独立家族。
- 每题 4 次独立初始请求，共 64 个配对位置。repeat 只是请求身份，不代表供应商提供了可复现随机种子。
- 每个位置生成一次，再从同一原始回答分出 generic 与 structured 两次修订。两臂原始回答、解析产物、公开任务、公开示例、模型及 token 上限相同。仅 structured 增加具体失败阶段、错误类型、公开约束和回执引用。
- 所有初始回答均入组，不按失败/成功筛选或补抽。生成与两臂修订顺序分别使用固定种子打乱，统一 4 workers、HTTP 至少间隔 3 秒。
- 总计 192 个逻辑请求，每次上限 8,500 tokens；沿用最多 3 次固定 HTTP attempts，语义重试为 0。来源未接入任何 Skill，不能将本结果解释为 Skill 收益。
- Coding 保留旧 OS 沙箱，Native 保留旧公式/规则解析器；不自动修答案、不放宽白名单。

任务中的待修 starter 是明确的宿主任务夹具；实验比较的是模型自然生成的初始回答，不是强行损坏模型回答。任务更复杂是设计意图，是否存在学习空间必须由成绩确认。不是实际公开 benchmark 或未经改造的真实项目。

Coding starter 的公开例子可通过，错误主要在非公开边界；Native starter 在公开例子即有错误。领域间公开反馈信号强度并不相同，领域增益差异不能直接解释成某领域本质上更适合该反馈方法。

## 隔离和分析

仅公开案例进入修订，私有 oracle 统一在全部修订完成后评分，不反馈给 Skill、Research 或模型。旧 V7 final 的具体答案、轨迹与私有夹具不作为输入。

主指标：全尝试任务成功率的 structured−generic 差值；无法交付/无法评分保留在分母中按 0 计。家族内先平均实例与重复，再计算家族等权差、簇 bootstrap 区间和精确 sign-flip；8 个家族只支持探索性结论。

辅助指标：交付有效率、oracle 可用率、双方可评子集的语义差值、领域宏平均、最差领域、初始正确后的退化。API 成功不能等同于合法产物或求解正确。各子集必须同时列分母；多个辅助检验不作为事后替代主指标的显著性依据。

初始求解恰好共享，不是两次独立轨迹。generic/structured 是独立修订请求；随机输出仍会造成差异，重复和簇统计不会消灭全部不确定性。

源码/面板/协议在首次 API 前冻结并落盘。缓存、预算与调用意图匹配；未决请求停止，不静默重抽。完成后重复 run 必须纯离线。此实验不批准 scope 扩张，不激活任何新验证器。
