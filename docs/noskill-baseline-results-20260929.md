# 五域 No-Skill 开发基线结果（2026-09-29）

五个基准均已完成全部预定位置的生成与评分记录，共 **1,419道任务、每题2次、2,838个位置**。这是空 Skill 的 `S0` 开发基线，不是持续进化结果、独立 final，也不是原论文全量成绩复现。不同领域的声明任务族粒度不同；两次重复不能当作两倍独立任务。

配置统一为 BigModel `glm-5.3`、low reasoning、每次模型调用输出上限4,096 tokens；不使用 Skill、Research、LLM judge 或按成绩重抽样。运行在 PJLAB Linux。SearchQA/KOR/BigCodeBench为一次生成，ALFWorld为最多50步的交互 episode，Spreadsheet为生成代码后隔离执行工作簿修改；因此模型调用数不等于任务位置数。生成并发通常为10，Spreadsheet因容器内存限制为2。

## 2. 数据来源与未知项

- **SearchQA**：仓库既有 `data/searchqa_split/train/items.json` 的400道开发题，存在历史曝光。6个 unknown 为未获成功响应的 HTTP 400；冻结客户端未记录具体服务端原因。主指标是严格 EM，不能用宽松 substring match 的93.63%替代。[原始聚合与重复波动](results/noskill-searchqa-20260928.json)
- **KOR-Bench**：预先按完整规则族冻结的500道开发题、50族；5类别各100题。160个 unknown 全为响应截断，其中 Puzzle 120、Cipher 36、Logic 3、Operation 1、Counterfactual 0。未中途提高预算或重抽失败。[逐类别结果](results/noskill-korbench-20260928.json)
- **ALFWorld B**：仓库既有39条 train 清单均来自上游 **train**，不是 `valid_unseen`；无重复游戏，声明场景族39个。12个 unknown 中，10个为暂停后环境不可续接、经核查关闭的中断位置，2个为响应截断。旧A因初始任务目标丢失被隔离，不与B合并；B持久提供初始公开观察，仍限50步。恢复只继续未开始位置，没有重抽中断记录。[缺陷审计](results/alfworld-goal-loss-audit-20260928.json) · [恢复说明](baseline-resume-20260929.md)
- **BigCodeBench**：官方 `v0.1.4` instruct 数据，冻结修订 `b74c0d0bf70d2c0bc459be537895cca163007f1a`；1,140题预分400/128/128/484，本轮仅400 development。族为词面近重复分组，不保证完整语义独立。2个 unknown 分别为原生超时和一次清理中断；800份模型回答未重生成。评分使用8GiB串行容器，不等同上游30GiB配置。[数据与运行预算](results/noskill-bigcodebench-20260928-preparation.json)
- **SpreadsheetBench B**：Verified400冻结修订 `ab0b742b0fc95b946f212d80ac7771b5531272e4`，沿用既有80道开发题，未删题、未改gold。B显式使用目标引号与空字符串缓存兼容评分版本；此前80/80静态参考可读不等于模型产物都可评分。62个 unknown 为1个截断、61个宿主代码 `native_cell_values_hard_all_cases`。本轮事后只读诊断将61个原生unknown细分为：**52个预测工作簿未建立公式缓存（32题）、8个产物执行异常、1个缺少输出工作簿**；gold在兼容检查下无缺失缓存，159个实际执行均确认清理，没有容器超时或清理失败。`openpyxl`保存不负责计算公式；这些原因不能全归为基础设施或推理失败，**原unknown标签与分数保持不变**。保留上游开发集排除说明对应任务的全分母结果；final中的既有gold配对问题仍未解决，本次不涉及final。[数据资格及限制](results/continual-spreadsheet-preparation-20260928.json)

这些是**已知小计，不是完整账单**：SearchQA有6份回执缺 usage；ALF有8个未闭合调用意图，是否已发送及实际用量不能由意图推定。ALF的10个中断任务位置与8个未闭调用不是同一分母。模型任务位置已闭合为终态，不意味着每条底层调用都取得回执。含重试的全部计费用量未知；合计不包含隔离的ALF A、失败启动或环境准备。

原生评分已知容器执行：KOR 840次、2,001.893303秒；BigCodeBench 799次、4,704.886404秒，另1个中断评分成本缺失。此口径只含评分阶段，不覆盖ALF交互或Spreadsheet生成阶段的隔离执行、下载与准备；“无评分阶段容器”不等于无运行成本。

## 4. 现在可以得出的结论与下一步

1. 已建立真实、可回放的五域空 Skill 参照，且 BigCodeBench/KOR 存在充分可见的难度空间；不能再用小型近满分控制面板概括公开基准能力。
2. 交付和评分覆盖仍是重要混杂因素。Spreadsheet可考虑在**新协议下统一计算所有模型产物的公式**并保留旧分数，而不是只挽救52个未知位置；先验证计算兼容性、资源隔离和gold不变。KOR的截断同样应在未来统一的新预算协议中研究，不能修补当前失败样本后改写基线。
3. 接下来在相同求解与评分条件下开展已准备的 SkillOpt / GEPA 单阶段学习对照，再比较本方法获校准的反馈。五域 No-Skill完成**不代表五阶段学习已完成**，也不证明 Skill、Research 或跨域泛化已有效。
