## 1 跑的是什么

- **方法（路线 B v2.2，配置 `main-v2-2`）**：技能 = 一包可执行的小程序，挂在做题模型周围（调用前给提示或提取数值，调用后检查输出）。
  工程师（GLM-5.3）读错题写程序。每一步：跑题 → 诊断 → 出题 → 最多 6 轮“写程序 + 在练习题上和现任包比” → 自测 → 验收 → 冻结。
  验收在没见过的新题上把新包和空包比：整批高 5 个百分点以上才收下（SearchQA 是 2 个点且显著）。
- **两条链**：G 链 GLM-5.3 做题，D 链 deepseek-v4.1-flash 做题；写程序、出题等方法角色两条链都用 GLM-5.3。
  顺序 SearchQA → OfficeQA → LiveMath → SpreadsheetBench → ALFWorld，每个 bench 一步。
- **时间与花费**：10/24 16:57 – 10/25 11:33，约 18.5 小时，约 2,761 万 token（G 1,565 万、D 1,196 万）。

## 3 为什么一个都没收下

1. **将近一半的程序没机会被评估（工程问题，大多可修）**。51 个提案里，16 个在训练中被采纳，12 个评估后不采纳，23 个死在评估之前：
   - 代码格式检查 C2：6 个（顶层调用 re.compile、set() 等，v2.3 已允许这类纯常量）；
   - OfficeQA 工程师输出被截断：两条链的 OfficeQA 步骤几乎整步作废（v2.3 已把上限提到 32,768，并给摘录限长）；
   - 适用判断从不为真被直接删掉：3 个（新发现，见第 5 节第 6 条）；
   - 篇幅超限 C3：3 个；ALFWorld 状态检查 C7：2 个；
   - 防泄漏/禁词 C4：5 个，筛查 C9：4 个（这两类是有意的安全检查，不建议放松）。
2. **训练轮里的“有效”多半是噪声**。9 个训练轮采纳了候选，证据多是“31 题各跑 2 次，修好 8、弄坏 3”这个量级；而同一题原样重跑本身就会翻转——SearchQA 约 15%（cal-1），今天的探针里 BBEH 时间计算 8 题里有 3–4 题翻转。两次表格题验收都显示：训练里有效的包，换到新题上约等于 0。
3. **写出来的程序大多只“检查 + 提示”，不直接算答案**：字数提示、报错提醒、区域超出预览提醒。能直接把答案算对的程序几乎没有出现。
4. **测量本身有噪声，验收题也偏少**：D 链表格题每组有 19–32% 的格子被严格解析器判为“没交程序”（v2.3 已修解析）；同一文本的对照组 C 与空包相差 ±4 个百分点。表格题验收 60 题 × 2 次，新包 − 空包的 95% 区间宽约 ±9 个百分点，比 5 个点的门槛还宽：真有 +5 的包大约一半会被拒，完全没用的包也有约七分之一的机会凑到 +5。所以 v2.2 的验收只算选择证据，方法效果最终看测试集；想让验收本身可信，题数要多几倍（花费也多几倍）。

## 4 各 bench 适不适合这套方法（我的判断）

| bench | 判断 | 理由 |
|---|---|---|
| SearchQA | 低 | 错在“不知道”，程序补不了知识，只能提示格式和长度。建议降为“不相似考试”（只看会不会变差）。 |
| OfficeQA | 待定 | 这次工程师连材料都没看全（截断），不算真正试过。v2.3 修好截断后值得再试，但文档长、花费高。 |
| LiveMath | 低 | 证明型选择题；程序想到的“捷径”都落在元选项上，被检查拦下；真正的推理写不成程序。 |
| SpreadsheetBench | 中 | 做题本身就是写程序，程序能检查输出；出现了第一个区间不含 0 的程序级线索（D 链 4-10，+15）。但整包没有提升，训练轮的收益不迁移。 |
| ALFWorld | 中到高（这次没测到） | 10/21 的试点里，状态记录程序让成功局从 16/42 升到 26–28/42。这次两条链的工程师都死在机械问题上（键名、C2、C4、C7），修好后值得再试。 |

## 5 bug 清单

**已在 v2.3 修好**（代码已写、审查一轮后全修、零调用回放决定不变、登记测试 1,996 项全过；尚未启动）：
1. OfficeQA 工程师输出截断（E1 上限 32,768，E2 摘录每段不超过 6,000 字符）。
2. C2：允许顶层纯常量（E3，新沙箱策略版本）。
3. 钩子顺序和绑定作用域规范化（E4）。
4. D 链解析器把“粘在句末的开头”“多余的结尾”误判为没交程序（E5）；“两段代码取最后一段”等你定。
5. 相同请求重复花钱（T1、T2）：零调用回放显示验收格子 −69%（main-v2-2）、训练格子约 −45%，决定全部不变。

**这次新发现**：

6. **适用判断从不为真时被直接删掉，没有反馈**。D 链 ALFWorld、表格题、LiveMath 各 1 次。例子：ALFWorld 程序检查 `admissible_commands`、`recent_history`，但路由时看到的视图只有 `initial_observation`、`admissible_commands_at_reset`、`task_text`（工程师提示里写对了，是工程师写错）。
   建议：像 C2 那样给一次修改机会，并告诉它“你的适用判断在 N 道题上全为假，路由视图的字段是……”。
7. **移植新 benchmark 前要修的**（Codex 只读改动地图 `execskill-probes/docs/handoff/ceiling-probes-20261025/port-map-route-b.md`）：
   - 同一 bench 连做两步时语料记录会被覆盖（`step.py:963`）；
   - 包一直为空时链末连基线都不读（正对照要另定“只读基线”）；
   - 新 bench 名字会落进 13 处默认分支。
8. **探针脚本的 ZebraLogic 判分（我审核时漏掉）**：没在提示里给数据集的列名，却按列名判分，模型答对的值也被判错。已改为按值零调用重判；以后移植要按官方格式在提示里给列名。

**方法层面（不是 bug，要你定）**：

9. **训练轮的采纳门槛对噪声太宽**（v2.2 去掉了符号检验）。两次表格题都是训练里“有效”、新题上为零。
   可选：采纳前在另一半练习题上复核一次，或恢复符号检验。代价是少采纳，好处是少跑无效验收。
10. **考官的检测器和出题作用很小**。检测器十步共写了 29 个，一个都没通过资格检查；出题大多没过难度带或捷径检查，只有 OfficeQA 出成了题。可以考虑先关掉检测器省 token。
