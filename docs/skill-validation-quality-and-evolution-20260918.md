# 评分器改进、面板准备与 Skill 泛化进化状态

日期：2026-09-18。性质：代码修复、离线工程测试和历史开发记录回放；没有新增模型调用，没有改写历史成绩。

## 一、本轮做了什么

### 1. 修复真实工作簿评分器

文件：`skillopt/envs/spreadsheetbench/evaluator.py`。

- 空范围、逆序范围、非法坐标、缺失参考工作表不再零检查通过。
- 同时读取公式视图与缓存值视图：没有计算结果的公式不再通过 `None == None` 被认成正确。
- 合法空白仍可通过；有缓存时比较计算值，不要求公式文本一致。
- 输出增加 `passed / failed / invalid_spec / unknown / missing_output` 和版本标识。若已有确定值错误，同时存在缺失缓存，保留已确认失败及部分证据缺失，不用 unknown 抹掉真实失败。
- 原有单元格数值比较规则及 `(ok, reason)` 接口保留。旧调用方只看 `ok` 时仍不能区分环境／规格问题与语义失败。

限制：没有实现公式重算或缓存新鲜度证明；某些返回空字符串的公式与未计算缓存无法区分时保留 unknown。旧 rollout 的另一套文字反馈未重构，不能作为新主线可信证据。V16 使用另一个公式 DSL，因此这项修复不改变其历史分数。

### 2. 给三条件面板加入开发前检查

文件：`skillopt/skill_validation/panel.py`；已接入 Stage-2 首次模型提案之前。

报告任务／任务族／项目、三条件位置、重复产物、同父候选、共同错误、修复／回归／不确定、逐任务族配对结果、全尝试成功率和审计覆盖率。不同检查项数量不改变任务分母，同题重复不变成新任务。

诊断仅使用 development 的 H；测试确认任意改变其他分区的合法审计标签不会改变报告。报告写入 `host_only`，不进入模型视图。样本不足返回 Pending；这些规划阈值不是统计充分性或安全证明，也不是新增的部署 Gate。

### 3. 用真实旧数据验证回放入口

文件：`skillopt/skill_validation/legacy_panel.py`。

复用原严格导入器和公开证据回放，不重新请求模型，不执行历史产物。先按来源和 development 阶段筛选，再按固定 solve ID 顺序枚举，保留损坏／缺依赖的拒绝记录。每个案例仍有独立公开视图与宿主 H。

当前导入范围不够确定旧 Skill 的父子角色，所以非空 Skill 保留 `unassigned`。没有为了凑三条件而伪造 Current/Candidate；没有把已经使用过的旧数据重新声明为独立确认集。

## 四、下一步如何让评测真正推动泛化进化

### 先接 3A：验证结果改善准入判断

固定一批来源明确的真实候选及 No-Skill／Current／Candidate 产物，让三种验证器评价完全相同的候选。独立 H 判断是否减少有害接受、是否保留有益候选；同时报告启用覆盖率，不能以全部拒绝包装成功。

真实面板先按公开任务结构、项目／任务族和来源规则冻结，再采集产物；不按哪个验证器效果好选择候选。开发、校准、审计、Skill 确认及 final 保持分开。当前 64 题只是开发先导预算，重复用于测随机波动，正式样本量取决于独立任务族和配对差异。

### 再接 3B：共同父 Skill 的单轮反馈分叉

同一父 Skill、同一开发任务与初始产物、同一 updater 和预算，只改变反馈来源：固定 Rubric、等预算无 Research、Research 的新增有效证据。

传给 updater 的不是总分，而是：

- 应保留的成功行为及适用条件；
- 执行确认的约束违反与最小反例；
- 不适用条件和用户明确授权替换的例外；
- 哪些信息来自 Research，哪些来自开发 H 摘要，哪些来自实际执行；
- unknown 与未覆盖义务，不把猜测当成错误。

复用历史局部编辑思想，但重新对接新主线的可见反馈白名单；不能直接复用包含历史私有答案的旧 dict。更新对象是 Skill 文本和前提／例外，不是仅修订当前答案。

例如，把“修改时保留所有旧依赖”改为“保持任务明确要求延续的行为与接口；对明确要求替换的旧规则更新依赖并验证新行为，不把旧规则本身当作必须保持的约束”。这是条件化内容更新，随后还必须用新任务验证，不能靠这句话自身声明跨域安全。

冻结候选后分别报告：

1. **强制使用 raw Skill 的效果**：来源能力保持、跨域同机制迁移、Near-Miss／无关任务退化。
2. **经过 Gate 的部署效果**：准入、限制、回退、覆盖率及成本。

只有第一类改善，才支持内容变得更可迁移；只有第二类改善，只能说明系统更会安全地使用 Skill。目标域若参与验证，应称为经目标域验证的迁移，而不是完全未见领域泛化。

再做一个小消融：删除 Research 独有的执行反例证据，尽量保持格式和预算，检查收益是否随之消失。由此定位真正起作用的是新证据，还是额外提示长度／计算量。

本轮没有提前搭建完整多轮框架；下一阶段重点是上述一次闭环，而不是继续在容易题上扩大训练。
