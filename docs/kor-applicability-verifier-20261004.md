# KOR无标签适用性验证器：不看标签检测Skill的跨域损害（10/4，第3步第一部分）

**结论先行：只读公开规则、题面和回答的可执行检查，在E与F两份独立学出的S1上都复现了官方标签测得的KOR损害（黄金资格通过的位置上，同位置净值：E 无标签 −14 vs 官方 −13；F −21 vs −20）。** 0模型调用、0新观测；黄金与官方分数只用于检验仪器。这是已暴露开发数据上的事后测量，不是独立final结论或部署授权。**v5（下文）把检查扩展到9条cipher规则**：cipher上无标签与官方判定0分歧，F S3的cipher损害（20胜/49负）可完全不看标签测出。

## 为什么做

E/F的S1都是在BCB上学出的编程清单，强制注入后KOR的operation/puzzle明显退化，但这只能在最终评测（带标签）时看到。要让协同进化在学习阶段就收到“这条Skill在哪里有害”的反馈，需要一个不依赖标签的跨域检查器。KOR的operation与多数puzzle规则完全由公开文本定义，可以机械检查。

## 设计

[kor.py](../skillopt/applicability/kor.py)（`kor-applicability-verifier-v4`）：

- **输入只有公开规则、公开题面和模型回答**；从不读取黄金或官方分数，不暴露给求解器或学习器。
- **按公开规则文本的sha256精确登记16条规则**：operation 10条（自定义二元运算、复数、矩阵）与puzzle 6条（24点、Hidato、岛屿、数独、区域多米诺、摩天楼）；`RULE_IDS`声明每条对应的公开(category, rule_id)，研究脚本在面板上核对。未登记：词缀谜题（需词典）、逻辑网格（自由文本线索）、格子和（题面未给出“指定数字集合”）、箭头迷宫（公开文本既未规定跳跃距离，也未规定哪些落点算“拐点”）。
- **题面必须被完整消化**：operation题只能是“Compute …/If … find X”加白名单中的答案格式句，puzzle题必须是网格加该谜题的固定说明；任何多余文字或题内改规则一律`unknown`。
- **判定语义**：`pass`=满足全部公开约束；`fail`=无答案区间或可证违反；无法严格解析、未规定的自定义运算优先级（如`-1○2`、`2i⊕3`）、不支持的写法、以及“求X”逆问题（代入只能证伪，不能证明解集完整，从不判pass）一律`unknown`。算术用精确高斯有理数；无理数用80位向外舍入的区间包络表示，只能证明答案错（差的包络不含0），永远不能证明对，因此无理数答案至多判失败或未知。矩阵按完整结构读取，多米诺按完整坐标语法读取。答案区间与官方KOR评分器一致（第一个`[[...]]`）。
- 研究脚本[report_kor_applicability.py](../scripts/report_kor_applicability.py)（`kor-applicability-study-v4`）把KOR面板逐题绑定到冻结No-Skill计划，位置集合由计划的题×重复次数推出；每个评测单元的计划必须声明同一位置集合、且配置除`methods`外与No-Skill参考完全相同（模型、预算、运行时）；每个位置绑定为 封存检查点（`skill_text`必须等于该阶段声明的Skill，No-Skill为空）→分数→预测→题目；中断或不可用的预测不判定。

## 黄金资格：14道题的黄金违反自身公开约束

160道登记题（operation 100、puzzle 60）中：**101道黄金通过**，45道因逆问题/改规则/题面畸形/无理数答案无法判定，**14道（operation 4、puzzle 10）的黄金本身违反公开规则**，逐题人工复核确认，例如：104※13按规则应为10而黄金当作24；Hidato黄金重复28、缺18；岛屿黄金直接照抄未解题面；多米诺黄金相邻接触或区域覆盖数≠2；摩天楼黄金与可见数线索矛盾或少一行。三类分开统计，主结论只用“资格通过”的题。

在这14道题上，官方评分对每个条件都把**14个满足全部公开约束的回答判错**，同时把3–6个违反规则、恰好复现错误黄金的回答判对。

## v5：扩展到cipher（10/4下午，零调用，Codex两轮后ACCEPTABLE）

**为什么**：F的S3在KOR上最大的损害来自cipher，而v4只覆盖operation/puzzle。cipher规则是确定的加解密过程，答案可以完全由公开规则重算。

**设计**（`kor-applicability-verifier-v5`；operation/puzzle代码与判定不变）：
- 面板10条cipher规则中登记9条：仿射、Solitaire密钥流、8网格对角移位、Porta、双圆盘、摩尔斯数对、5行折返栅栏、S盒分组、ASCII×12。**规则21（XOR+置换）不登记**：其“固定密钥”只以“e.g., '10101010'”举例给出，公开文本并未确定唯一答案，宁可不判。题面必须完整匹配“Plaintext/Ciphertext + 可选Key或period/increment + 固定答案格式句”，方向须一致；cipher题由模板完整消化，因此不再用全局“改规则”关键词扫描（否则明文`PARAMETER`会被误判为改规则）。
- **多读法语义**：公开文本留有选择时（散文与其自带示例矛盾，或约定未写明），在每种可接受读法下重算答案；**所有读法都给出该回答才判通过，没有任何读法给出才判失败，其余未知**。实际出现的分歧：规则9旋转方向（散文“向右”与示例`s[n:]+s[:n]`相反）及内盘J重复（每个密文J可解为两个外盘字母，P无法解密）；规则16加密时上行列的“#”位置（示例在第5行、散文在第1行，解密与读法无关）；规则22中16字节密钥对8字节分组的对齐（每块重置或连续使用）与输出只要求A–E大写（含F的答案无论大小写都判未知）；规则7网格编号的两种理解结果恒等。解密时某读法给出的明文不在规则声明的字母表内，则该读法对此题不可接受。
- 答案区间与清洗与官方cipher评分逐字一致（首个`[[...]]`→`$\boxed{}$`→`[...]`；去掉引号、换行、空格、方括号；区分大小写精确比较）；需要依赖被清洗字符才能比较的答案（如含空格的明文）判未知。

**黄金资格**：登记的90道cipher题中82道黄金通过、8道依赖读法（规则9×3、16×4、22×1）、**0道违反公开规则**。

**真实记录（零调用，正式目录`/root/kor-applicability-20261004-v5-{e,f-s3}`）**：cipher黄金资格位置上，无标签与官方在全部双方有判定的位置**0分歧**（E各条件163–164/164；F的S3另有1个回答超过全局2万字符上限判未知）。cipher上的S1/S3相对No-Skill（改善/退化）无标签与官方完全相同：E S1 21/21，F S1 23/38，**F S3 20/49**。登记位置合计500/1,000（黄金资格通过366）：

| Skill | 官方（全部登记资格位置） | 无标签 | 官方（同一批有判定位置） |
|---|---:|---:|---:|
| E S1 | 34/46 | 26/40 | 31/44 |
| F S1 | 34/68 | 28/64 | 31/66 |
| F S3 | 34/68 | 24/69 | 31/67 |
| F S4（KOR上学出） | 38/56 | 26/52 | 33/53 |

F S3在官方口径下与S1持平（各−34），无标签口径更差（−45 vs −36），差额来自operation中官方计为“改善”的格式类规则（见上节）。在KOR上学出的S4把登记位置的净值收窄（官方−18、无标签−26），但cipher仍为18/42（与官方相同），operation的官方改善（12/7）在无标签下只剩3/6，又是格式类规则。[F S1–S4结果](results/kor-applicability-v5-f-s4-20261004.json)

**cipher损害集中在机械计算规则**（F S3逐规则，改善/退化）：ASCII×12 **0/11**、双圆盘0/7、Solitaire 0/7、仿射1/6、S盒0/5；摩尔斯7/4、Porta 7/6、栅栏4/1反而略好。S盒规则在三份Skill下都只有退化（E S1 0/4、F S1 0/7、F S3 0/5）。抽查F S3的ASCII×12错误：`G`答876（应为852）、`O`答960（应为948）、`W`答1032（应为1044），即ASCII码差1–2；一例解密直接写出`HELLOWORLD`这样的“像样”单词。**完成tokens（零调用复核）**：逐题取两次重复的平均完成tokens，S3/No-Skill比值的中位数在cipher为**0.70**，在operation为1.03、puzzle为1.00——S3只在cipher上明显缩短推理，而cipher正是S3在KOR上损害最集中的类别。注意不能按“变好/变差”分组比较tokens：No-Skill自身在两次重复一对一错的cipher题上，答错样本的完成tokens中位数就只有答对样本的0.52倍，按结果分组会把这种选择效应误当成Skill效应。因此结论仅是“QA上学到的Skill缩短了cipher推理，且cipher损害集中在机械计算规则”，与“简洁作答迁移导致粗心错误”的假设一致，但仍是单历史相关证据，不是因果结论。

审查与测试：Codex第一轮NOT ACCEPTABLE（2项P1：规则21把示例密钥当作确定、规则22对小写f的归一化使依赖拼写的答案判通过；3项P2：规则22密钥对齐未列读法、密文小写f被拒、全局关键词扫描误伤cipher数据），全部修复后第二轮5项RESOLVED并核对了规则5的`n`、规则12末尾符号、规则6重复的9、规则8密钥配对、规则24整除均无需额外读法，**VERDICT: ACCEPTABLE**。专项测试153项（Linux冻结源码上同样153项通过）、相关回归215项通过；36,000例随机模糊测试无崩溃、无“可接受答案判失败”、无“非唯一确定答案判通过”。`-v5pre-*`目录为审查前试跑，勿引用。结果：[E](results/kor-applicability-v5-e-20261004.json) · [F S1–S3](results/kor-applicability-v5-f-s3-20261004.json)

## 边界与下一步

- 已暴露开发数据上的事后测量，每个Skill只有一条学习历史；不是官方分数替代，也不构成部署授权。
