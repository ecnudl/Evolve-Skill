# 研究目标：保留来源收益，降低跨领域负迁移

更新：2026-09-09，根据最新研究目标补充。本文中的三领域分数是用户提供的**说明性示例，不是真实实验结果**；不修改正在运行的V3协议或其预设统计。

## 1. 优化目标不是逐项SOTA

| 条件 | 来源领域A | 迁移领域B | 迁移领域C | 等领域平均 |
|---|---:|---:|---:|---:|
| No-Skill | 60 | 70 | 70 | 66.67 |
| 过往进化方法（示例） | 80 | 60 | 60 | 66.67 |
| 我们希望的方法（示例） | 78 | 75 | 75 | 76.00 |

希望保留的是可迁移的收益，而不是来源benchmark的最高单点分数。例中来源净收益保留率为 `(78−60)/(80−60)=90%`，相对Base的平均净收益为+9.33个百分点；其他两域由负迁移变为正迁移。90%只是例子的结果，**不是已经确定的门控阈值**。

研究应同时回答两个问题：学到了多少可保留的有用经验，以及为这些收益付出了多少跨域损失。全部fallback会令损失为零，但没有来源收益，不能算完成目标。

## 2. 固定一组可解释的结果指标

以相同模型、工具、预算下的No-Skill为锚点，逐domain报告，不能只保留一个总体均分：

- **平均净收益：**先求各domain相对Base的分数差，再按预定domain权重平均。题量较多的benchmark不能自动获得更大权重。
- **最差领域净变化与最大退化：**分别报告最小的domain差值及最大负差幅度；避免来源收益掩盖另一领域的明显损失。
- **负迁移领域占比：**多少个domain低于Base。这是有限已测领域的描述，不是统计风险概率。
- **平均负迁移幅度：**仅对低于Base的部分取差额，再按全部domain权重平均；正收益不抵消这项损失。
- **来源收益保留率：**仅对预先指定的source domain计算 `(ours−Base)/(reference−Base)`；reference没有正收益时未定义，不能填0或1。可大于1或小于0，不人为裁剪。
- **辅助项：**逐domain绝对分数、最差绝对分数、覆盖率／fallback率、调用与推理成本，以及来源收益。不同benchmark难度不同，最差绝对分数不能替代最差相对退化。

所有分数必须预先定义同向归一化方式；把数值放到0–1并不自动证明不同benchmark的指标含义可比。一个domain有多个benchmark时，先按预定规则汇总域内结果，再跨domain汇总；不得根据成绩重新分组或改权重。

新纯统计模块 `skillopt/cross_domain/portfolio_metrics.py` 实现domain级描述指标，不调用模型，不产生新的显著性检验或“安全认证”。缺失数据不填成0，也不静默删除领域。用户示例只用于计算正确性的单元测试。

已有命令行入口可运行说明性示例：

```bash
conda run --no-capture-output -n skill python scripts/summarize_domain_portfolio.py \
  --input configs/cross_domain/portfolio_objective_example.json \
  --output outputs/portfolio_objective/user_example_20260909.json
```

本次示例汇总已执行，输出带 `kind=illustrative_example`，模型调用数为0。输出已存在时脚本拒绝覆盖，应查看既有文件或指定新的文件名。入口也支持明确标记为`observed_scores`的实际domain级分数，但不会自动验证其模型／版本／划分来源，更不执行benchmark；真实实验仍需独立保存这些证据。

## 3. 如何影响算法，而不是只换一张结果表

学习阶段保留候选的局部工作版本、批准版本和不具执行资格的待修订对象；允许来源收益略低于单任务极值，但必须有可验证的实际学习收益。扩大适用范围时，检查跨域净收益与损失约束，不让单一来源分数决定全局部署。

可用“跨域收益最大化，受负迁移预算与来源收益保留约束”来描述方法目标；具体风险预算、保留门槛和不确定性处理应在下一份协议中提前固定。遇到不确定结果允许限制scope、补证或fallback，不把单次随机损失直接说成稳定因果伤害，也不靠不断重抽直到通过。

验证器的学习目标也要对应这一点：不仅发现候选没有修好的错误，更要发现相对Base新引入的错误，并把可复现失败包送回Skill修订。DeepResearch负责研究领域契约与检查缺口；Rubric只有经过独立校准，才可作为范围判断的证据，不能自行替代冻结benchmark成绩。

## 4. 后续正式实验的最小比较单位

至少需要同一套冻结系统在三个**真实不同domain**上的完整分数向量：No-Skill、正常训练与选择的SkillOpt、我们的完整方法。需要同模型、同工具、相近预算，保留重复学习历史及配对评测。跨领域但底层机制相同、同领域不同机制、无关任务作为预先定义的诊断分组。

不能拿“强制注入已经被来源门拒绝的Skill”冒充正常SkillOpt，也不能把不同模型、不同Skill、不同实验日期的零散最高分拼成一个跨域向量。开发用于进化与门控，最终公开benchmark在Skill／验证器／router冻结后独立评测。

当前V3只覆盖构造Coding项目，无法直接验证这个三领域目标。它用于完善学习—验证闭环及揭示具体接口缺口；其结果保留在独立报告中。下一步工程优先级仍是稳定编辑／执行接口、补齐失败包与来源反例回流，然后接入真实多领域评测，而不是继续把相似小任务换domain名称。
