# 两轮 Skill／执行式验证器协同进化：运行前协议

日期：2026-09-09。目标是推进一个实际可运行的闭环，而不是继续无限扩展静态审计。所有正式模型请求前冻结任务、代码、模型配置和下述计划；API 健康检查单独记账。

## 固定范围与停止边界

- PJLAB `glm-5.3`，temperature=0，请求 reasoning_effort=low，stream；一个共享客户端，全局并发4，不改凭据或代理。
- 两条独立执行流，每条包含固定验证器、进化验证器两条分支，每条分支固定两轮。执行流标签不是受服务端保证的随机种子。
- 每轮均运行，不以中途成绩、headroom、Commit 次数或显著性改变轮数／样本量。只因沙箱不可用、任务参考自检失败、代码／缓存完整性不符、预算耗尽或一个完整阶段超过20%目标响应不可用而停止。
- 最多一次影响可运行性／数据正确性的工程重启；必须另建目录保留失败，不用同一测试结果反复调参。非关键小问题如实记录，不无限修订。
- 主研究逻辑调用上限1600；每个请求最多沿用传输层2次重试。按计划不超过1400次逻辑请求，缓存复用会减少实际调用。格式不合法和长度截断保留，不重新抽到成功。

## 任务和划分

48个作者构造的Python代码更新任务，3个应用上下文，每上下文8个不同操作族，每族包含局部更新／明确替换旧策略两个相关请求。相关请求属于同一个cluster。

每个上下文的操作族0/1/2/3分别用于learn0/gate0/learn1/gate1；操作族4–7留出。因此每轮6个学习任务、6个新的gate任务，最终24个留出任务、12个cluster。全部仍是跨应用Coding，不是真实Spreadsheet／Research跨领域公开benchmark。

Starter是旧策略实现，新需求涉及多个相关输出；输入契约是明确的有限输入域。原生Python交付，沿用现有AST限制和隔离执行器。完整有限oracle由任务作者制定，不把参考代码或私有答案发送给solver或反例搜索模型。每个任务预先检查参考、旧实现、缺陷实现和合法替代实现。参考自检仅说明该有限域一致，不是对任意程序输入的形式化保证。

局部更新和策略替换是候选Skill适用性near-miss配对，而不是把后者误标为完全不需要Constraint Preservation。公开提示不得包含split标签或私有评价答案。

## 每条分支的实际闭环

1. 当前Skill在本轮学习任务生成两次答案；No-Skill提供同任务／同轮参照。学习阶段可读取硬测试失败诊断。
2. 模型基于完整任务、当前代码与开发失败生成一个新的机制Skill候选；候选再在学习任务上重复执行。每轮只生成一个候选，不反复抽取。
3. 固定选取候选学习回答的第0轮提出反例探针。每个gate任务生成No-Skill、Current、Candidate三条件、各两次答案。
4. 当前版本的验证器只看到可见契约、**当前候选代码（不提供starter）**和已有验证经验，提出最多4个JSON输入及确切的契约／代码引用。宿主检查引用与合法输入域，再实际隔离执行reference与candidate。
5. 合法探针在No-Skill、Current、Candidate上共同执行，不把模型声称的expected当答案。公共检查和真实探针差异共同形成有范围限制的checked-pass／fail／unknown。没有反例不是正确性证明。
6. 先写入不可变Commit／Restrict／Reject决策，再开放gate的完整私有审计。旧决策不因事后发现错误而悄悄回写。
7. 进化分支把已执行的开发反例和未复现的质疑写入有上限的验证经验库，作用于**下一轮**反例搜索及Skill反思；固定分支保持初始搜索记忆。相同提案／执行预算，区别在是否更新经验。

这是实际的Skill文本更新和验证经验更新，不是自动生成新Rubric程序或自主DeepResearch。资料研究接口后续可接入；本轮不声称已完成DeepResearch算法。

## 门控和适用范围

本轮是研究用操作门，不是统计安全认证。候选在学习集相对Current须有正的净收益、相对No-Skill不差；策略替换保护组不得出现观测到的源任务损失。gate对Current及No-Skill不能出现已验证的配对损失。缺失／无法形成可执行探针时Restrict；明确伤害或无效候选Reject；证据符合预定条件才Commit。无源收益时保留局部候选并Restrict，不为了产生Commit放宽阈值。

Commit允许在本研究限定的Coding契约更新场景使用该内容，属于探索性部署，不等于取得跨领域泛化证书。Restrict／Reject保留已提交Current；尚无Current则回退No-Skill。保留候选内容和所有证据，允许零Commit结果，但零覆盖不算安全进化成功。

## 最终冻结评测

四条分支的最终Skill、验证经验、最后候选和完整轨迹全部冻结后，才生成留出回答。每条执行流比较No-Skill、固定验证器选择的Skill、进化验证器选择的Skill，以及两条分支各自最后候选的无条件部署诊断；24任务×5条件×3次重复×2执行流=720个预定新回答。

最后候选部署是选择／拒绝机制的内容诊断，不是额外训练了一条完整“无门控进化”分支。开发阶段相同任务、同流、同轮、同重复、相同Skill内容可以复用同一真实调用，明确记录共享request hash；最终五条件分别重新调用，不用重放代替部署实验。

主要比较为进化验证器分支与固定验证器分支；相对No-Skill为次要比较。按同task／stream／repeat配对，先重复平均、流内任务平均、cluster等权，两个流保留独立结果；共享cluster bootstrap保留全部重复和流结构，仅作探索性区间。不把720个回答当720道独立题，不宣告等效性，不依据一个流领先决定研究方向。

报告每轮提交／限制／拒绝、覆盖率、真实有限oracle收益与退化、未知／API截断、验证经验变化、两个流的最终差异和成本。所有最终任务均按计划执行，未见评测不回流到候选／验证器。
