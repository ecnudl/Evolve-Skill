# coevo5 第一批代码 Codex 审查（第 2 轮，2026-10-17 18:06）

> 模型 gpt-6-astra（推理档位 ultra），只读沙盒。审查对象：按第 1 轮 14 条修改后的第一批代码（提示见下方说明；第 1 轮原文见 [r1](coevo5-code-review-b1-r1-20261017.md)）。原文如下，未改动。

1. **MAJOR — Breach settlement and global halt are not atomic.** [calls.py:125](../../skillopt/coevo5/calls.py#L125), [budget.py:214](../../skillopt/coevo5/budget.py#L214). Settlement releases the ledger lock before `halt()` reacquires it. Another process can reserve and send between them; a crash in that interval leaves a recorded breach without a persistent halt. Reproduced admission after the breaching settlement, before the halt. A bound breach can also have `overrun=0`, so replay cannot infer it. **Fix:** encode settlement and the breach-induced halt in one journal event, and latch the endpoint before persistence can fail. Merely appending separate settlement/halt lines under one lock still permits torn-tail recovery to retain only settlement. Add concurrent-admission and crash-prefix tests.

2. **MAJOR — Journal failures can become ordinary outcomes and strand reservations.** [calls.py:86](../../skillopt/coevo5/calls.py#L86), [budget.py:134](../../skillopt/coevo5/budget.py#L134), [cells.py:179](../../skillopt/coevo5/cells.py#L179). If the reservation event is persisted but state replacement raises, `reserve()` never returns its ID. The frozen backend swallows the exception as `model_call_exception:OSError`; no recorder stop flag is set. An in-memory reproduction through `run_cell()` produced zero client calls, `stop=None`, a row-11 unknown, and an open 3,248-token reservation. Subsequent admissions waited indefinitely on its still-live owner. Settlement failures have the same exception-swallowing problem. **Fix:** retain reservation identity across uncertain commits, latch bookkeeping failures independently of backend reasons, force `Pause`, and reconcile or quarantine the ledger before further admission. Extend fault injection through the frozen solver and cell runner.

3. **MAJOR — Waiting reservations can miss a halt/resume cycle.** [budget.py:190](../../skillopt/coevo5/budget.py#L190), [budget.py:231](../../skillopt/coevo5/budget.py#L231). A waiting request checks only the current `halted` value. If halt and authorized resume both occur during its polling sleep, the original unit’s request proceeds despite §13.4 requiring a fresh unit attempt. Reproduced with cap 1,000, an open reservation of 900, and a waiter requesting 800: halt → settlement → resume allowed the old waiter to reserve. **Fix:** retain a halt generation and reject pending admissions spanning that generation, or enforce a verified drain of old waiters before resume. Add this interleaving test.

4. **MAJOR — Shared qualification waiters automatically retry paused work.** [evaluation.py:59](../../skillopt/coevo5/evaluation.py#L59). When qualification A raises `Pause("cleanup", ...)`, an already-waiting evaluation B acquires the lock, finds no pointer, and starts `attempt-2` using the original consent. This starts new native scoring without fresh recovery authorization or confirmed cleanup. A threaded in-memory reproduction produced exactly that sequence. **Fix:** persist interruption/paused state under the qualification lock; waiting callers must stop. Require a recovery decision tied to that failed attempt before creating another attempt. Test concurrent first use with both cleanup failure and process interruption.

5. **MAJOR — Reuse remains unbound to the current run.** [evaluation.py:110](../../skillopt/coevo5/evaluation.py#L110), [evaluation.py:134](../../skillopt/coevo5/evaluation.py#L134), [evaluation.py:218](../../skillopt/coevo5/evaluation.py#L218). Matching chain names, stage, benchmark, configuration and Skill do not establish run ownership. A predecessor from an older same-chain run skips execution and later fails unsealing. An older `stage0-glm` source also passes the shared-source exception, silently importing historical results. Reproduced reuse into a new run followed by unsealing an `old-run-only-task` result, without calling `test_tasks()`. **Fix:** bind records to the frozen run identity and registered chain/shared-stage-zero roots; validate these before creating an attempt and throughout reuse resolution. Test identical labels/settings across distinct runs and test rosters.

6. **MINOR — Monitoring selects the wrong attempt after attempt 9.** [evaluation.py:199](../../skillopt/coevo5/evaluation.py#L199). Lexicographic sorting selects `attempt-9` over `attempt-10`. Reproduced a tenth attempt containing one completed cell while monitoring reported the abandoned ninth attempt’s nine cells. **Fix:** sort validated numeric suffixes or read explicit active-attempt metadata; add a 9→10 regression test.
