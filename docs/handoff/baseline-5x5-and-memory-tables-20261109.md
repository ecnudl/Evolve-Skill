## 怎么读

- **两个模型**：GLM 指 G 链，做题用 GLM-5.3；DS 指 D 链，做题用 deepseek-v4-flash。SkillOpt 和 GEPA 写技能的反思模型，两条链都是 GLM-5.3。
- **同一条链上 SkillOpt 和 GEPA 共用同一次任务卡 C、Empty B 和链末 C_end 读数**，所以这三行在两种方法的表里相同。
- **Empty 就是 B 组**：什么都不加，不发任务卡，也不发技能。SkillOpt 和 GEPA 都从空技能开始，空技能发出的请求和 B 一样。
- **任务卡 C**：每个 bench 起点的一段历史指导，10/17 由 GLM 只看公开题型说明零样本写成。ZebraLogic 没有这张卡，它的 C 和 B 请求完全相同。
- **第 k 步后**：按 SearchQA、OfficeQA、ZebraLogic、表格题、ALFWorld 的顺序，学完第 k 个 bench 后的技能，在五个测试集上全部新跑一遍。粗体是这一步自己学的 bench。“技能没变”的行，只是同一段文字重读。
- **差值**：同一批题上两组的配对比较，单位是百分点，方括号是 95% 区间。▲ 区间整体高于 0；▼ 整体低于 0；没有符号是区间包含 0；≡ 两边请求一样或技能文字一样，只是重跑噪声；△ 区间高于 0 但差值小于同文本波动，不算证据；？ 只因表格题判不了的格子的计分口径才显著，不算证据。
- **表格题判不了的格子**：没有回复、没有产物或评分出错。主读数对 C、B、C_end 算对，对技能组和记忆组算错，对技能组和记忆组偏保守。
- **每格只读一次**。同一段文字重读时差值的波动幅度见文末，判断差值要和它比。
- 测试集题数：SearchQA 400，OfficeQA 172，ZebraLogic 200，表格题 204，ALFWorld 134。ALFWorld 按局计。

## 二、记忆基线

每个 bench 单独从练习数据建一份记忆，只在这个 bench 的测试集上读，没有五乘五。两次运行用的是同一份冻结的记忆：

- **只发记忆**，`membase-v2`：请求里只有记忆内容，不加任务卡。和同一次运行里新跑的 Empty B 配对比较。
- **任务卡加记忆**，`membase-v1`：请求里是任务卡加记忆内容。和同一次运行里的任务卡 C 配对比较，也给出减 B。
- 两次运行在不同的日子，v1 和 v2 之间的数字差里含服务漂移，只能描述，不能当配对比较。
- ZebraLogic 没有任务卡，所以 v1 的“任务卡加记忆”和 v2 的“只发记忆”在 ZebraLogic 上是同样的请求，相当于同一个比较读了两次；v1 里 C 和 B 是同一个格子。
