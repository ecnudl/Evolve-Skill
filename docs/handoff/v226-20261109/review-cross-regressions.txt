B3: resumed cross-gate inspection and cross-card route scope
Root cause: run_pairs pinned the fired item IDs, but every redo reran sandbox
inspection. An inherited intermittent fault could move the fired item from
zebralogic-00 to zebralogic-01 and then fail the unchanged-pair-binding check.
The full-touch card gain rule also applied to every fired off-home benchmark,
including a non-target slice with a single informational inherited fault.
Fix: main-v10 records each inspection in a record-hashed
v226-cross-inspection-<bench>.json. Its deterministic core binds configuration,
phase, home, bench, unit, parent/candidate/proposed package hashes, slice IDs,
harm registration, routing views, card text, runtime and full workbook hashes.
Resumes verify the core and reuse signatures, fired items, request changes,
potential changes, faults, attribution and observations. Narrowing rechecks use
separate v226-cross-inspection-narrowed-<bench>.json records. Runtime/core drift
still raises. Only the cross card's route target uses the card gain/full-touch
rule; incidental inherited-fault items on other benches use the no-harm rule.

  test_cross_gate_redo_reuses_sealed_narrowing_rechecks
  test_cross_card_non_target_inherited_flake_uses_no_harm_rule

B6: unchanged inherited procedure fault only in S'
Root cause: any S' fault absent from S was attributed to the candidate, even
when the same procedure ID/hash was enabled in both arms. This randomly
rejected a procedure or card because of an inherited timeout.
Fix: main-v10 classifies independent faults of unchanged procedures enabled in
both arms as inherited/informational. Changed requests are measured normally.
Added/changed procedures and shell interactions (duplicate binding names,
assembly/cap faults) retain candidate attribution. Narrowing uses this same
inspection result and attribution rule.
Tests:
  test_candidate_arm_only_unchanged_inherited_timeout_is_measured[False, True]
  test_candidate_arm_only_inherited_fault_is_informational_during_narrowing
  test_inherited_shell_interaction_fault_still_belongs_to_candidate
    [note_duplicate_name-bindings, note_over_declared_cap-notes]
Pre-fix evidence: both procedure/card S'-only timeout cases returned no selected
candidate and failed the acceptance assertion. They were written and run
before changing production code, confirming B6 rather than assuming it.

A3: corrupt cross-gate recovery records
Root cause: JSON decoding happened before verified(), so truncated completed,
pair-pin and cell records could be contained as candidate errors. Unreadable
records also needed the configuration-pause classification.
Fix: all cross-gate recovery reads use v226_candidates.read_record in main-v10;
read, decode and verification occur in system scope. Package recovery loads
also run in system scope. Legacy configurations retain the original reader.
