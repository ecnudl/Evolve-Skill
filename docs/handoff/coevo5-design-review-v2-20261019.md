# Codex 设计审查：第 2 版改动登记（一轮，2026-10-19 09:11）

> 原文照录（gpt-6-astra，推理强度 ultra，只读）；处理见 [第 2 版改动登记](coevo5-registration-v2-delta-20261019.md) §12。

The design is broadly sound. I found one launch blocker and several fixes below. No prohibited run artifacts were opened and no models were called. Appendix incompleteness is not a finding.

1. **Blocking before launch — §11(3), qualification reuse.** “Reuse unchanged” conflicts with v1 §§20.2, 24–25: the SpreadsheetBench engine certificate incorporates the snapshot’s absolute code path. Create the final v2 snapshot **before** rerunning the 23 engine controls and training-reference qualification, all without model calls; then recompute qualified pools, panels and tolerances. Reused instructions/rubrics need an explicit version-aware import preserving original hashes, generation prompts, receipts and provenance: current validators reject mismatched protocol versions. Preserve historical records rather than relabeling them.

2. **Should-fix — §7, single-word exception and information boundaries.** Check **all mechanical matches** before granting the exception. V1’s checker returns its first reason and conflates single-word and multiword `answer_text` hits; exempting that result could accidentally bypass mandatory rejection. Freeze selection of the ≤3 evidence examples and handling of insufficient context. Whole-training-pool evidence, including check-half items, is acceptable for a **veto-only adjudicator after final rewriting**; explicitly prohibit feeding its evidence or rationale back into proposals, research or rewriting. Apply the answer-distribution prohibition to every adjudicated rule, not only collision cases. Descriptive baseline auditing is appropriate.

3. **Should-fix — §4, evidence and transfer validation.** Require **2–8 distinct displayed proposal-half task IDs**, with exact displayed response/code linkage when repeated answers have different diagnoses. Validate against that displayed subset, not the full diagnoses dictionary. The current requirement only establishes cited codes ⊆ targeted codes; require every targeted code to have cited support, preventing unsupported codes from enlarging triggers. Assign stable proposal IDs before filtering: rejection of the nominated transfer rule must not invalidate siblings or trigger another analyst attempt. Keep evidence IDs/codes out of rendered Skill text. Proposal-half contrast successes are sound.

4. **Should-fix — §5.1, simulation claim; clarify §§5.1–5.2 scheduling.** Remove “null C1 passage does not increase.” A zero-call check using the supplied model—SearchQA, τ=1, 35 triggers, 20,000 simulated histories per setting—gave approximately **3.4% → 4.4%** when repetitions doubled. Retain the stronger design if preferred, but report its tradeoff as illustrative component behavior. Unequal repetitions are otherwise valid: C1/C2/C3/C4′ remain sums of per-item means, and per-item format averaging is correct. Freeze scheduled denominators, retain unknown handling, use fresh parent draws each round, and clarify that inherited composite testing still has **no controls**.

5. **Should-fix — §10, cost justification and aggregate accounting.** The arithmetic is correct: **1.44B − 174M − 58M = 1.208B**, rounded down to 1.2B. The cost justification needs replacement: maximum SearchQA focal-plus-control cells increase **10,400 → 17,200**, about **65%**, excluding unchanged forward cells. Produce a zero-call v2 schedule/token table including scaffold length and extra parent regressions. Keeping old caps is legitimate, but completion is not guaranteed. Individual v2 caps total **1.303B**, or **1.245B without v2-ds**. Pin exact prior spending/outstanding obligations, preserve the v1-ds reservation, and charge smoke, NoSkill and optional v2-ds against the shared v2 allowance.

6. **Should-fix — §§1 and 9, readout interpretation.** Not rerunning baselines is sound for the narrowed objective. Explicitly retire **all P1–P4 tests and their inherited “overall success” labels**; v2 cannot establish superiority of its redesign over v1. NoSkill is a useful descriptive reference, but its difference from v1 stage 0 combines possible service drift with sampling randomness and any execution differences—it is not an identified drift correction. Report per-benchmark denominators/eligibility, missingness, timestamps, model settings and prompt/runtime hashes. Freeze the v2 design before opening v1 test results.

7. **Should-fix — §§2 and 9, scaffold wording.** The fixed scaffold correctly removes section activation from C1 and the E learning contrast. Describe \(M_E[5]-M_E[0]\) as **incremental performance change above the fixed scaffold**, rather than “only learned content”: length, wording, interactions and evaluation/service variability remain. The scaffold contrast includes the backend wrapper activated by nonempty Skill. These are conditional contrasts, not a unique causal allocation. Rename “from blank to instruction level” to “from scaffold-only to instruction level.”

8. **Should-fix — §6, partial examiner edits.** The 450-character hard limit with a 300-character prompt target is reasonable. Specify evolving-state validation: edits targeting an item removed earlier are skipped and logged; deterministic handling governs conflicts. Valid siblings survive, but failure of the final whole-rubric validation means **no revision**. “Drop only the offending rule/edit” is correct for local failures, not malformed envelopes or invalid aggregate rubrics.

9. **Optional — §§8 and 11, integration checks.** Archive ranking is sensible; freeze tokenization and a final deterministic tie-break. Preserve old archive bytes/hashes, append version-matched Calc pages, and advertise Calc in analyst/research prompts. Add offline cases covering leakage exceptions, evidence/transfer failures, mixed repetitions, format averaging and provenance imports; the two live smoke steps may not exercise them. Training-derived taxonomy is legitimate protocol development, but the check half remains adaptive selection material, not independent holdout evidence.
