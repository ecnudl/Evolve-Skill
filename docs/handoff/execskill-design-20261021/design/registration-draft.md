## 0 一页摘要（给负责人）

1. **这是什么。** 一个新协议，名字叫 `fivebench-execskill-v1`（"五个 bench、可执行技能、第 1 版"）。学到的 Skill 不再是一段
   文字，而是一个"程序包"：几条小程序（叫"过程"），每条自带一个判断"这道题要不要启用我"的小程序（叫"适用条件"）。
   做题模型外面套一层固定代码（叫"壳"），壳在发请求前后运行被启用的过程。过程只能做三件事：往提示里加一段整理好的
   信息；从题面里抽数字、替模型做精确计算（最多多问模型一次）；把某些动作标成"不建议"（ALFWorld）。**过程改不了模型的
   最终回答**，也改不了答案格式要求。
2. **两边都进化。** 工程师（GLM-5.3 扮演）读失败记录写过程；考官（GLM-5.3 扮演）写"失败检测器"和"出题程序"。
   两边都有改不动的锚：参考答案、模拟器、程序算出的真值。
3. **没有验证集。** 每个版本"收不收"只在一批本路线从没用过的真实训练题上决定一次，四组同时段逐题交错：新包、旧包、
   只有任务卡、安慰剂（占同样位置、做同样调用、但内容是别的题的，所以对这道题没用）。新包必须同时胜过旧包和安慰剂。
   这批题用过就作废。生成题**永远不当验收标准**，在试点里也不当筛子（第 7 节解释原因）。
4. **实话（题量决定的）。** 按您认可的顺序，第一步 SpreadsheetBench（表格编程题，91 道可用）、第二步 OfficeQA（财政
   公报计算题，74 道）只认得出约 10–12 分以上的提高；一条真实 +5 分的改进被收下的机会只有约 13%–41%（估计，第 6.6 节）。
   最可能的结果是"两步都不收"。这不等于"过程没用"，只等于"这个题量认不出"。
5. **建议（负责人决定 #1）。** 试点改成 SpreadsheetBench → ALFWorld（文字家务游戏）：ALFWorld 有 3,514 局没用过的
   训练局、模拟器判成败、任务卡下约一半失败，验收 150 局能认出约 10 分（估计），代价做题约 0.6–1.3 亿 token（估计）。
   默认仍按您认可的 SpreadsheetBench → OfficeQA（约 0.22–0.63 亿 token，估计）。
6. **考官一侧的诚实预期。** 在试点题量下，失败检测器在 SpreadsheetBench/OfficeQA 上"无法判定"；出题程序的"预测效度"
   （生成题上谁好谁坏是否和真题一致）需要至少 8 组对比才能检验，试点凑不够，会写"无法评估"。这两条都事先写明，不会写成
   "考官进化成功"。
7. **迁移的诚实预期。** 文献（Break It Down, arXiv 2608.20274）和本项目证据都指向：代码形式的过程主要在本 bench 有用，
   跨 bench 迁移可能接近零甚至比文字差。测试时专门加一组"把每条过程改写成文字说明"的对照来直接量这一点。
8. **先冒烟，后试点。** 冒烟分四段：零调用检查（含隔离箱逃逸探针）→ 约 60 次新接口探查 → 夹具题和少量真题的小规模真跑
   （每种钩子至少触发一次、故意注入故障）→ 一个完整小步。冒烟任何一项不过，先改登记（出 v1.1）再试点。
9. **需要您拍板的事**在第 14 节（共 22 项，按"冒烟前 / 试点前 / 以后"分组，每项都有默认值）。

## 2 学到的东西长什么样（对象与规则）

### 2.1 过程（被学习的部分）

每条过程是一个 Python 模块（≤ 6,000 字节；模块顶层只许 import、常量（字面量 ≤ 2,000 字符）、函数定义），加一份记录：
编号 `p-<来源bench>-<步>-<n>`、来源 bench、说明（≤ 600 字符，只给人看，不给做题模型看）、声明的钩子、声明的上限、
回放测试、血统（父过程、工程师调用的请求哈希）、`excluded_benches`（缩小适用范围用，默认空），以及内容哈希。
程序包 = 有序的过程列表（≤ 24 条，源码合计 ≤ 64,000 字节）+ 父包哈希，按内容寻址、只写一次。

**钩子（封闭集合）：**

| 钩子 | 什么时候跑 | 能做什么 |
|---|---|---|
| `applies(view)` | 每道题开始一次（ALFWorld：每局开始一次，在登记的"开局视图"上） | 只返回真/假，决定启用 |
| `before_call(view, state)` | 问答/表格：第一次请求前 | 返回**有类型的字段**（事实列表、表格、候选、警示），壳用固定表头渲染成一段说明 |
| `bindings(view)` | 问答：第一次请求前（精确计算类过程） | 从题面抽出带名字的数值，每个数值和它的原文引语必须逐字出现在题面里（固定代码核对），否则丢掉 |
| `sheet_feedback(view, run_report, state)` | 表格：程序在公开输入上试跑一次之后 | 给出有类型的修改建议，并决定是否请求**一次**修改调用 |
| `alf_before_step(view, state)` | ALFWorld：每步请求前 | 有类型的字段 + "不建议的动作"列表（只标注，不删除，模型仍可输入） |
| `alf_after_step(event, state)` | ALFWorld：每步执行后 | 只更新状态 |

结构性保证（壳没有这些接口，所以做不到）：改系统提示、改格式要求句、改/抽取/重写最终回答、替模型选动作或换动作、
看参数以外的任何东西。

### 2.2 任务卡与格式护栏（冻结，不学）

- **任务卡** = v3 I-ds 链起点用的五份 GLM 写的指令（`dl:/data/coevo5-20261019-v3-pre/texts/texts.json`；长度与哈希前缀：
  searchqa 1,846 字符 `48b10afc…`、officeqa 2,926 `2e92500a…`、livemath 2,068 `9cb3d860…`、spreadsheetbench 2,907
  `48a5df7f…`、alfworld 2,301 `5ae6ea9b…`，实测 [CM 2.10b]），是已知最强的文字基线（cal-1：ids-full 154.5 对 seed-only
  153.5 对 parent:A 135.75，200 道 SearchQA × 4 次，实测 [FP F42]）。**只给当前 bench 的那一张**：v3 把五张全给，别的
  bench 的答案格式建议在 OfficeQA 上造成 −9.5 到 −33 分（E4/E9 实测 [FP F51-F52]）。
- **格式护栏** = 每个 bench 固定的一句格式要求，只作指令：SearchQA/OfficeQA "Return the concise final answer inside
  <answer>...</answer>."、`LIVEMATH_CONTRACT`、`SHEET_CONTRACT_V2`、ALFWorld "Act in the text environment. Return a single
  action inside <action>...</action>."（backends.py:35, 53-56, 381-382, 730）。**不做任何输出改写**（改写就是"答案修补"，
  不算学到的 Skill）。每格核对：问答的送分回答与模型回答逐字节相同；表格的送分程序就是冻结抽取函数从模型回答里抽出的程序。
- **ALFWorld 动作规范化（只到第 1 级，所有组都开）**：取 `<action>` 标签内文本（没有就取整段回答），去掉前缀 "action:"、
  首尾引号空白和末尾句号、忽略大小写，**与某个可选动作完全一致**才换成那个动作，否则原样执行。**不在整段回答里搜索
  "最早出现的可选动作"**——那会执行模型自己否定过的命令，是动作修补（D3 里带记录器的组 41.0% 步骤靠它救回，对照组 13.2%，
  25/26 次成功用过它，dl:/data/feasibility/D3/critic-result.json:4 [审查 MA-M11]）。这一点改动了工作假设 A9（见第 16 节）。
  每步记录规范化方式，每组报告第 1 级规范化的比例。
- **有类型的说明 + 词表筛**：过程不能直接给模型写自由文字；它返回字段，壳用固定表头渲染（例如 "Facts extracted by a
  helper program (may be incomplete):"）。字段里出现登记词表中的答案格式指令（如 answer/respond/output/return/json/
  "only the"/"just the"/bare/"single letter"/round/"decimal places"/units/<answer/<action/```，SpreadsheetBench 另免
  "format" 一词）时，该字段被丢弃，并记一次**过程故障**（计入 2% 上限）。

### 2.3 路由器与壳（固定代码）

- 路由器每道题（ALFWorld 每局）开始时在隔离箱里把所有适用条件跑一遍，记启用日志。ALFWorld 的路由视图登记为
  `{initial_observation, admissible_commands_at_reset, task_text}`，由一次零调用的预先重置写进题目文件，做题时逐字节核对哈希
  [审查 EA-E11, MA-M15]；永远不给模型写的代码路径或题号。
- 一条过程的适用条件出错 = 这道题不启用它（记 `predicate_fault`）；过程本身出错 = 这道题从出错点起不带它继续做
  （"失败即放行"，记 `procedure_fault`）。两者都计入 2% 故障上限，**都不算基础设施故障**，不会让运行暂停（第 4.4 节的新表行）。
- 空程序包时，壳发出的每个请求（系统提示 + 用户内容的哈希）和每个预测必须与冻结的 `backends.solve` 完全相同（零调用等价测试）。
- 说明放在用户 JSON 的最后一个键 `procedure_notes`；系统提示（基础 + 格式句 + 任务卡）在 S'、S、P 各组逐字节相同。说明总长上限：
  问答/表格 4,000 字符，ALFWorld 每步 1,500 字符；超出时按包内顺序整条跳过（确定性，所有组同样处理）。

### 2.4 精确计算往返（A10）

1. 精确计算类过程用 `bindings` 抽出带名字的数值；壳渲染成固定说明并附登记原句："If you need arithmetic, you may write
   <calc>EXPRESSION</calc> tags (at most 8) using these names or plain numbers; they will be evaluated exactly and returned
   to you once."
2. 第一次回答里有合法 `<calc>` 标签时，壳用**固定的精确计算器**求值（分数算术；只许数字、名字、+ − × ÷、整数指数
   |e| ≤ 12、括号、abs/round/min/max/sum；嵌套 ≤ 20 层；任何中间结果分子或分母超过 4,096 位就判 `computation_failed:magnitude`；
   每个表达式 ≤ 300 字符），然后**最多多发一次**请求，用户内容 = 第一次的内容 + 第一次回答 + 计算结果 + 登记原句
   "The expressions above were evaluated exactly. Use these values if they are relevant and give your final answer in the
   required format."。
3. 计算失败时结果写 `"not evaluated"`（安慰剂组也一律写这个，见 6.3）；第二次回答送达且未截断就作为最终回答，否则退回第一次
   回答（记 `second_call_fallback`）；第一次回答已截断就不发第二次（按截断判错）。
4. 两次调用的用量都记进这一格；格的"送达状态"取两次里最差的那次（用于基础设施守卫），判分用实际作为最终回答的那次。

### 2.5 表格题的试跑与修改往返

- 壳在第一次回答后，把抽出的程序在公开输入上试跑**一次**：用一个一次性容器，命令行和环境变量**逐字节复制冻结的
  `_native`**（pids 128、nofile 256、tmpfs 256m、OMP/OPENBLAS=1 等，backends.py:169-178），用一个复制的试跑脚本返回最后一行
  报错（≤ 500 字符）；结果存进格记录，重放时读回，不重跑 [审查 FA-F10, FA-F2, EA-E6]。
- 过程看了试跑报告可请求**一次**修改调用；修改调用带上原程序、壳自己的报错信息和过程给的有类型建议。修改回答送达就用它，
  否则退回原程序。表格的"公开输入"以**只读挂载文件**交给隔离箱，绝不内嵌进协议消息（开发机实测 89 个训练工作簿：中位数
  10,238 字节，最大 599,328 字节，8 个超过 48 KiB [审查 EA-E1]）。
- 并发锁只在每次容器执行期间持有 native 锁，绝不跨越一次模型调用（冻结 cells.py:126-132 的 `on_reply` 抢锁在两次调用的格里会
  死锁，[SB G3; 审查 FA-F9, MA-M8]）；单元测试：3 个 native 锁、12 个工作线程，不死锁。

### 2.6 隔离箱（A3）

- 安全边界**只有容器**；语法检查和导入白名单只是卫生和确定性层（D6 的进程内运行器不是边界 [FP F33]）。

  实测 [LO F29-F30]），不新建镜像。
- 容器参数复制冻结 `_native` 的整套加固再收紧：`--network=none --read-only --user=65534:65534 --cap-drop=ALL

## 5 一个 bench 上的一步（父包 S）：八个小步

每个小步是一个"单元"（复制的 `run_unit`：加锁、attempt-N 目录、只写一次的 `unit.json`）；暂停后不会自己恢复。

**5.1 跑题。** S 在跑题段上跑登记的次数，每格写完整轨迹（启用日志、每步视图、原始回答、规范化方式、说明、计算/修改往返、
全部回执、裁判结果）。若 S 里继承来的过程在本 bench 跑题段上启用 ≥ 10% 的题，任务卡组 C 也在跑题段上跑 1 次，作描述性
"入场读数"（S − C），不进任何决定 [审查 ME-F11]。基础设施未知 > 1/10 暂停。

**5.2 考官诊断（考官进化的前一半）。** 跑题段按题目对半分成"写的一半"和"验的一半"。固定的机械类别（零参考答案，单元测试，
不算考官进化）：问答 `no_answer_tag, json_answer_untagged, multiple_answers, truncated_or_suspected, empty_reply`；表格
`no_program, excel_formula_only, fence_glued, program_exception_on_public_input`；ALFWorld `step_budget_exhausted,
revisit_empty_receptacle≥3, repeated_action_loop, nothing_happens_share>0.2, inadmissible_share>0.2, level1_canonical_share`。
考官只针对**没被任何机械类别或已收检测器覆盖**的失败写新检测器（≤ 3 条，≤ 2 次调用），验收规则见 7.1。

**5.3 考官出题（考官进化的后一半）。** SearchQA 不出题（没有程序真值），只进化检测器。其余 bench 规则见 7.2。出题程序的代码
在本步冻结；用于测预测效度的 G_acc 要等工程师写完以后，由登记员把**冻结的出题程序**用在验收段 A\* 的公开题面上生成，工程师
从来看不到 [审查 FE-F1, ME-F5]。

**5.4 工程师改过程（Skill 端进化）。** 一次提案（≤ 3 处改动），每处改动依次过固定检查，第一处失败给一次修改机会，再失败就丢掉：
- C1 解析；C2 语法与禁用名（2.6）；C3 大小与上限；
- C4 泄漏：说明、每个字符串字面量和数字字面量，**只检查不在本题公开题面里出现的内容**（说明里引用本题自己的数字是允许的
  [审查 FA-F12]），对照跑题段参考答案语料（`leakage.findings/mechanical`），命中交一次裁定调用，否决就丢；另加三条静态禁令：
  LiveMath 元选项（源码或输出里出现 `STRONGER_OPTION` 原句 "One of the remaining options is correct, but a stronger result can be
  proven." 的任何片段、或 "stronger result/statement" 字样、或按选项位置/字母规律作答的代码）[审查 EE-F1, FA-F13, ME-F1, MA-M20]；
  OfficeQA 公报期号与页码字面量 [审查 ME-F3]；ALFWorld 带编号的具体容器字面量（如 "drawer 3"）[审查 ME-F2, EE-F12]；
- C5 隔离箱加载；C6 零崩溃：在本路线**已存的全部跑题轨迹**（本 bench 和前面的 bench）上，每个钩子在两个新工作进程里各跑一遍，
  无故障、结果一致；
- C7 回放测试（固定的性质种类，不许模型自己写判断函数；`return True` 式的空测试不可能）：每处改动 ≥ 1 个测试对应它声称修复的失败
  轨迹；**非空性**：同一性质在"拿掉这条过程"或"输入被扰动"时必须为假、带上时为真；**反向测试**：在成功轨迹上不许把赢的那一步
  动作标成不建议、不许对已通过的表格题请求修改；ALFWorld 的状态类过程必须和固定的参考记录器（D3 的手写记录器，固定代码）在
  ≥ 97% 的步上一致；计算类过程的 `bindings` 必须逐字出现在题面里 [审查 FA-F6, MA-M12, EA-E9]。回放只证明"不崩、确定、做了它
  声称的事"，**不证明能修好**，报告里只作卫生项；
- C8 格式护栏没被碰：重渲染后系统提示哈希不变，回答通道不变；C9 说明字段过词表筛，超限即故障。
- 候选 S' = S + 存活的改动。没有存活的改动 → 本步结束，验收段不消耗。

**5.5 自测（不是验收，只查"会不会坏格式、会不会崩"）。** S' 与 S 在本 bench 的 G_self（≤ 60 道生成题 × 1 次）和前面各 bench 留下的
生成题集（每个 ≤ 40 道）上各跑一次，同时段交错。**只允许两种拦截**：(a) S' 的故障率 > 2%；(b) S' 在任一题集上的格式违规率
（不带答案标签、JSON 答案、没有程序、无效动作等不依赖真值的标记）比 S 高 ≥ 5 个百分点且符号检验单侧 p < 0.05。准确率只记录，
**不拦截**（生成题从没预测过真题：E1 生成题 +13、真题 0；E9 饱和在 0.891 且漏掉真实 −9.5 [FP F50, F52]；[审查 FE-F3, EE-F3]）。
被拦下时工程师有一次修改机会，再被拦就本步结束、验收段不消耗。

**5.6 验收。** 第 6 节。验收前把 S'、安慰剂、拿掉对照抽签、A\*、G_acc 全部封存。

**5.7 冻结并传下去。** 收下：S' 成为新父包；新过程的适用范围**默认是"全部 bench"**（靠适用条件自己判断）；不再用生成题上的差值
决定范围 [审查 FE-F4]；只有在后面某个 bench 上、作为候选被正式验收的"缩小范围/撤掉"改动才能改范围（继承来的过程在任何 bench 都
可以被撤掉或缩小 [审查 MA-M10, ME-F11]）。同时用一个钉死的提示词（每条过程一次 GLM 调用）把每条过程改写成给做题模型看的文字说明，
冻结哈希，供测试时的"文字对照组"用（8.1）。"通用 / 仅本 bench"这类标签只在测试读取后按 8.4 的规则给，不影响路由。
没收：S 原样传下去，S' 存档。

**5.8 读测试集。** 试点只在最后读一次（第 8 节）。

## 6 验收：一批新题只做一次决定

### 6.1 各组

| 组 | 内容 | 作用 |
|---|---|---|
| S' | 候选包 | 被判的组 |
| S | 父包 | 决策对比 1 |
| C | 只有任务卡 + 格式句，没有过程 | 描述性；第一步时 S 就是空包，C 与 S 逐字节相同，是同时段"同文本重复"的噪声底检查 |
| P_y（配对安慰剂） | S 加上每条变动过程的"配对替身"：适用条件、钩子、提示位置、调用触发规则都相同，内容换成**这条过程在同一验收段另一道题上的输出**（按种子配对，长度相差超过 20% 时截断或用同一过程别的题补足） | 决策对比 2：排除"随便多一段同类信息、多看一眼就会涨分" |
| P_i（无关文字安慰剂） | 同上，但内容换成登记的无关文字（v3 的 8 段对照文字，protocol.py:102-124），长度相同 | 描述性第二安慰剂（方向建议要求至少两段安慰剂 [DR §4 留]）；只在 SpreadsheetBench、OfficeQA、LiveMath 上跑（便宜）；ALFWorld、SearchQA 上是否跑见负责人决定 #9 |
| 拿掉对照 S'∖p | 见 6.5 | 每条过程的因果效果（不进决定） |

替身的细则（[审查 FE-F5, FA-F11, ME-F9, MA-M22, EE-F6]）：
- **说明类**：说明分成"固定说明句"（过程声明的常量表头）和"内容"两部分；替身保留固定说明句，只换内容。这样"一条带适用条件的
  文字规则"和"一条真正执行计算的过程"能被区分开。
- **计算类**：替身照样给出"抽出的数值"（来自配对的另一道题）和同一句邀请；模型写了 `<calc>` 就同样多发一次请求，但结果一律写
  `"not evaluated"` 并原样回显表达式（真组计算失败时也写这个），所以两组的调用规则相同，只有"算出的值"不同。
- **表格修改类**：替身保留原程序和**壳自己的报错信息**，只把过程给的建议换成配对内容；是否请求修改由 S' 的过程在替身组自己的轨迹上
  "影子运行"决定（影子运行的结果不给模型看）。
- **ALFWorld 不建议类**：替身标注同样数量的"不建议"动作，从当前可选动作里按种子随机选；**状态类**：每步换成配对局在同一步号
  （超出就取最后一步）的状态说明。
- 每轮都报告 P_y − S 与 P_i − S。若 P_y − S 的 95% 上界 < 0（替身本身有害），决策对比 2 记为"不提供信息"，此时收下需要对比 1
  在单侧 2.5% 水平成立（更严），报告写"胜过父版本；配对替身有害，所以'多一段内容就涨分'的解释已被对比 1 单独排除"。
  若 P_y − S 的 95% 下界 > 0（替身本身有用），照实写"多一段同类内容本身就有帮助 x 分"，这是仪器事实，不是学到的效果。

### 6.2 同时段交错

一轮里所有格（各组 × A\* 的题 × 次数，加拿掉对照、加 G_acc）放进一个种子顺序，一个线程池发送，绝不按组排序（cal-1/D1 的做法，
step.py:105-121）。为了让"需要隔离箱的组"和"不需要的组"不在时间上错开，ALFWorld 每局不管哪一组都先拿同一种局锁和隔离箱锁
（任务卡组跑一个空包工作进程）；每轮检查各组"开始发送时间"的中位数相差不超过本轮时长的 5%，超过则本轮"未定"[审查 ME-F28]。
每格记派发与完成时间；按组、按 15 分钟报告简短回答比例、答案格式比例、回答长度（同一文本的简短比例在 cal-1 里按 15 分钟从 5% 到
96% 变化，D11 实测 [FP F45]）。OfficeQA 两段时间、ALFWorld 4 块、SearchQA 4 块，块内交错，统计按块分层。

### 6.3 每道题的分数

每道题每组取各次 v2 完成口径的平均；候选组 S' 把"未知"和 `unknown_fault` 都算错，对照组把"未知"算对（v3 的保守约定，
stats.py:19-28 [CM F38]）；所有组都没送达的题退出所有对比（`shared_unanswered`）。

### 6.4 判据（交并检验，一批只决定一次）

**收下 S' 当且仅当以下全部成立：**
- **D1**：d = S' − S 在 A\* 上的单侧配对 sign-flip 置换检验 p ≤ 0.05（100,000 次随机翻转；OfficeQA/ALFWorld/SearchQA 在块内翻转，
  ALFWorld 按房间整组翻转），且折算到整批的平均差 ≥ 0.02（D1 的最小值 [FP F41]）；
- **D2**：e = S' − P_y 同样的检验 p ≤ 0.05（替身有害时按 6.1 的规则改用更严的 D1）；
- **D3 故障**：变动过程的故障（含路由阶段的故障，分母是整个验收段 A 而不只是 A\*，[审查 FA-F16]）≤ 2%；
- **D4 格式**：S' 的格式违规格数 ≤ S 的 + max(2 格, 2 个百分点)（问答：答案标签；LiveMath：单个字母；表格：交出程序；ALFWorld：一局里
  可选动作占比 < 0.9 算违规）[审查 EA-E8, FA-F18]；
- **D5 仪器**：每组基础设施未知 ≤ 10%（否则暂停）；重发后仍推理不一致 ≤ 1%（否则暂停）；共同未答 ≤ A\* 的 10%；开始时间平衡（6.2）；
- **D6 第一步专用**：S 与 C 逐字节相同时，双侧 p(S vs C) < 0.01 → 暂停（交错或确定性坏了），不出决定；
- **D7 LiveMath 专用**：决策只在**没有元选项的题**上算；另在含元选项的题上跑一次"遮住题干只给选项"的探针（S' 与 C，各 1 次）：若 S'
  的遮题准确率比 C 高 ≥ 10 分且单侧 p < 0.05，判"走捷径"，不收。

两个对比都要成立是交并检验，不需要多重校正，误收概率 ≤ 5%。C 只描述（S' − C、S − C，双侧 95% 区间）。
整条链 5–9 个决定、每个 5%，全局零效应下至少误收一次的概率约 0.2–0.35（估计，决定之间独立）；报告写明决定个数，测试读取是确证性证据。

### 6.5 随机拿掉对照（A11，因果归因）

- 对每条变动过程 p（启用题数 |F_p| ≥ 10）：在它启用的题里按种子随机选一半 W_p，加跑一个"拿掉 p"的孪生格（同样次数、同一顺序里交错）。
  τ_p = W_p 上 [S' − S'∖p] 的平均，自助法 95% 区间。因为是在启用的题里随机拿掉，τ_p 是"p 在它会启用的题上的因果效果"（FlowEvo 的
  配对撤除 [RW §2]）。只有一处改动时，S' − S 在它启用的题上就是这个效果，不另跑。
- **继承来的过程**（来自前面的 bench）在本 bench 验收段启用 ≥ 15 道时，同样拿掉一半，得到"前向迁移"的因果估计，**不碰测试集**
  [审查 ME-F11]。
- τ 永远不进决定、不用来剪枝、不给任何角色看。单条过程在 25/50/100/200 道启用题上只认得出约 19/14/10/7 分（估计 [spec-measurement §7.3]），
  多数会写"无法分辨"。

### 6.6 把握有多大（事先告诉负责人）

单个对比在真实效果为 +3 / +5 / +10 分时被认出的概率（估计；按 3.3 的联合 MDE 反推，正态近似；括号里是审查用各 bench 自己的噪声
算的更低值，critique-fidelity-evidence F9、critic-ee-calc §1）：

| bench（验收大小） | +3 分 | +5 分 | +10 分 |
|---|---|---|---|
| SpreadsheetBench 60 × 2 | 0.17 | 0.32（0.13–0.27） | 0.76 |
| OfficeQA 50 × 4 | 0.21 | 0.41（0.18–0.33） | 0.88 |
| ALFWorld 150 × 1 | 0.22 | 0.42（0.21–0.43） | 0.89 |
| LiveMath 200 × 2（若全用；只用无元选项题会更低） | 0.30 | 0.59 | 0.98 |
| SearchQA 1,000 × 1 | 0.80 | 0.99 | 1.00 |

两个对比都要过时还要再打约 0.85–0.9 折。**按默认试点，如果真实效果是 +5 分，两步都不收的概率约 0.71（估计，[审查 FE-F9]）。**
所以"没收下"的意思只能写成"这个题量下没认出 ≥ MDE 的效果"，绝不写"过程没用"。

## 7 考官一侧：什么算"被收下"

### 7.1 失败检测器（A7）

- 检测器是一个只读轨迹的判断程序，**看不到参考答案，也看不到直接决定对错的字段**：问答与表格看题面和回答，但最终答案标签里的内容、
  程序在公开输入上的运行状态被遮掉；ALFWorld 只看**前 10 步**（"早期预警"），不看总步数和是否赢 [审查 FE-F2, FA-F7, ME-F13, MA-M13,
  EE-F9, EA-E10]。（ALFWorld 失败局全部跑满 50 步，124/124 [FP]；早停只在赢时发生，backends.py:768-770；所以"步数 = 50"一条就能
  "完美"预测失败。）
- 在验的一半上，**只在残差格上算**：残差格 = 没有任何机械类别、也没有已收检测器报警的格。收下当且仅当：报警 ≥ 10 格且来自 ≥ 6 道题；
  按题整组自助的单侧 90% 下界 (查准率 − 残差格基础失败率) ≥ 0.10；残差失败里的查全率 ≥ 0.15；和已有检测器的报警集合重合度
  （Jaccard）< 0.8；无故障、两次运行一致。模型写的标签永远不当证据。
- 题量太小时直接写"无法判定"：SpreadsheetBench、OfficeQA 在试点大小下验的一半只有 12–16 道题，几乎不可能达到下界（[spec-measurement K6]）。
- 收下的检测器按 bench 留存；在同一 bench 后续步的验的一半上连续两次不达标就撤掉。

### 7.2 出题程序（A8）

- **考官写的程序只输出"改题方案"，不碰参考答案**；固定的宿主代码执行方案并计算真值 [审查 MA-M14]：
  - OfficeQA 类：方案给出要改的数字和算式；固定代码先用原数字按算式**精确复现原题参考答案**（复现不了就丢），再按新数字用精确计算器
    重算，写明舍入；新数字必须逐字出现在改后的题面里，答案不许直接出现在题面里（D6 有 2/7 题把答案写进了题面 [FP F30]）；
  - LiveMath 类：方案给出符号变体和真值表达式（受限语法）；固定检查器在隔离箱里用 sympy 50 位精度求值，恰好一个选项等于它，未求出的
    积分/级数丢掉；正确选项的字母按题号轮换（每个字母 20% ± 5%）；**不许出现元选项**；
  - SpreadsheetBench 类：方案给出输入工作簿的单元格改动；固定代码在 recalc 镜像里重算参考工作簿，再做两次 v7 判分的资格检查（零模型调用
    [SF F24]）；只用字面值答案（openpyxl 写的公式没有缓存值，无法判分 [SF R5]）；
  - ALFWorld：没有环境生成器，只能从没用过的现成局里**挑选** [SF R9]。这一类单独报告为"挑选效度"：同样大小的一组按种子随机挑的局作
    零模型对照，要求挑出的局在目标特征（例如目标物位置类型、需要打开的容器数）上确实偏移；**不计入考官一侧的主张** [审查 FA-F8, FE-F2]；
  - SearchQA：不出题。
- 四道关：**真值**（程序或模拟器算出，固定检查代码）；**难度带**（父包在 30 道探针题上 1 次的通过率在 20%–80% 之间；最多改两次参数）；
  **捷径**（LiveMath 遮题干只给选项、OfficeQA 去掉表格只给问题、表格题去掉工作簿，2 次都答对的题丢掉；一个题集里被丢比例 > 25% 就整套不用）；
  **标签规律**（只许用题目自身内容和程序真值，不许利用训练标签的规律）。四关都过叫"准入"，只是工程，不算进化。
- **预测效度**（考官的主打指标，但**不是门**）：
  - G_acc = 冻结的出题程序在验收段 A\* 的公开题面上生成（工程师没见过，[审查 FE-F1]），在验收那一轮里**所有组**都做一遍（1 次），与真题交错；
  - 每轮得到若干组（生成题上的差值，真题上的差值）：S'−S、S'−P_y、S'−C、P_y−S；第一步时 S−C 在两边都应为零，是登记的**阴性对照**，
    P_y−S 是第二个阴性对照；
  - 一个出题程序累计 ≥ 8 组"真题上有信息"的配对（真题差值的 90% 区间不含 0）之后，才做登记的检验：配对差值的斜率 > 0（置换检验单侧
    p < 0.05）且阴性对照通过 → "效度成立"；两组以上配对上生成题与真题差值的差超过 2 个合并标准误 → "效度被否定"并撤掉；否则"无法评估"；
  - 试点每个 bench 只有一轮，最多 4–5 组配对，**事先写明：试点里预测效度"无法评估"**；
  - 用途：只有"效度成立"的出题程序，其题集才可以在**以后的步骤**里当筛子用。试点里不会发生。
- 考官"进化成功"只有两种：按 7.1 收下的检测器；"效度成立"的出题程序。都没有就照实写"考官一侧没有进化成功"。

## 17 术语表（给负责人）

- **过程**：工程师写的一小段程序；壳在做题前后运行它，做三类事之一：加一段整理好的信息、抽数字并替模型精确计算、把动作标成不建议。
- **适用条件**：每条过程自带的判断程序，只读题目公开内容，决定这道题启不启用它。
- **路由器**：固定代码，每道题开始时跑一遍所有适用条件，记"启用日志"。
- **壳**：包在做题模型外面的固定代码；运行过程，但改不了模型的最终回答。
- **程序包 / Skill**：过程的有序集合；S = 父包（上一步传下来的），S' = 候选包，F = 试点结束时的最终包。
- **任务卡**：每个 bench 一段冻结的作答说明（v3 I-ds 起点用的五份 GLM 写的指令），只给当前 bench 那张。C 组 = 只有任务卡。
- **格式护栏**：每个 bench 固定的一句"答案写在哪里"的要求，所有组相同，不学。
- **动作规范化（第 1 级）**：把 "action: go to X" 这类写法对齐到完全相同的合法动作；不做其他猜测。
- **安慰剂 P_y / P_i**：P_y 把过程的内容换成它在另一道题上的输出（同类但对这题没用）；P_i 换成无关文字。用来排除"随便多一段内容就涨分"。
- **拿掉对照（孪生格）**：同一道题、同一时段，再做一遍拿掉某条过程的版本；两者之差是这条过程的因果效果。
- **A\***：验收段里"至少有一条变动过程会启用"的题；只在这些题上决策，其余题不发送、不消耗。
- **结构性零共享**：两组发出的请求逐字节相同的题，只做一格、两组共用。
- **消耗账**：只能追加的记录；每道题第一次发送前写入，写过的不再用。
- **同时段交错**：几组的所有题放在一个随机顺序里一起发，消除时段差异。
- **MDE（最小可检测效应）**：在登记题量下有 80% 把握认出的最小提高（百分点）；比它小的认不出，不等于没有。
- **交并检验（IUT）**：两个比较都要过才收；每个用 5% 门槛，整体误收也不超过 5%。
- **sign-flip 置换检验**：把每道题的组间差随机翻正负号很多次，看实际平均差有多极端；不依赖分布假设。
- **不劣检验**：问"是不是没有比对照差超过 5 分"。
- **Holm 校正**：同时做很多个检验时，按从严到松的顺序调整门槛，控制"至少错一次"的概率。
- **检测器 / 机械类别 / 残差格**：检测器是考官写的、读作答记录判断"属于哪类失败"的程序；机械类别是固定代码的类别（如"没有答案标签"）；残差格是
  没有任何机械类别和已收检测器报警的格，新检测器只在这些格上算查准率和查全率。
- **查准率 / 查全率 / Jaccard**：报警里真失败的比例；真失败里被报警的比例；两个检测器报警集合的重合度。
- **出题程序 / 准入 / 难度带 / 捷径检查**：考官写的程序给出"改题方案"，固定代码算出真值；四关都过叫准入；父包通过率在 20%–80% 之间叫在难度带里；
  遮住题干或表格也能答对的题被剔除。
- **预测效度 / 阴性对照**：生成题上"谁比谁好"是否和真题一致；阴性对照是本来就应该是零的比较（如第一步的 S 对 C），用来检查方法本身不出假信号。
- **评分器 v2 / 完成口径**：也认 JSON 写出的答案，只会把官方判错改判对；截断、空回答、格式无效都算错。
- **推理 token**：模型正式回答前"想"的部分；本协议关掉，每次回执核对为 0。
- **账本、预留、B、M**：每次调用前按上界预扣 token；M 是请求里写的长度上限，B 是账本按来预留的上限；回答超过 B 会让账本全局停止。
- **隔离箱 / 容器 / 子进程**：运行模型写的代码的封闭环境；不联网、只读、无特权；每次请求一个新子进程。
- **elucid**：新做题接口在代码里的名字。**GLM-5.3**：扮演工程师与考官的模型。
- **单元、attempt、暂停、重做**：每个小步是一个单元；暂停后由负责人决定终止或在新 attempt 目录里重做。
- **SB / OQ / LM / SQ / ALF**：SpreadsheetBench / OfficeQA / LiveMath / SearchQA / ALFWorld。**v3**：上一版协议 `fivebench-coevolution-v3`，结果冻结。
- **M / E 标注**：实测 / 估计。**FlowEvo、CoEvoSkills、GRASP、Break It Down**：最接近的四篇 2026 年工作（第 12 节）。
