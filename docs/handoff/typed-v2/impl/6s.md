## Choices

- Pins moved on purpose (no test deleted or weakened): (1) `tests/test_typed2_shared.py`, the 5w golden file list:
  the six receipts `s0..s5/frozen.json` are now asserted exactly and removed before the unchanged 5w digest is

  in `tests/test_typed_reads.py`, the hand-sealed manifests of `tests/test_typed2_identity.py` (positive case) and
  `tests/test_typed2_base.py` (prepared smoke root), and the `real_services` fixture of
  `tests/test_typed2_services.py`: they gain the now required `schedule` / `memory_lock` (code defaults), as step 5b
  added `base_card`; (3) `tests/test_typed_cli.py`: `state_summary` gains `schedule`, `phase`; the printed prepare
  summary gains `schedule`, `memory_lock`.
- The default-field ACCEPT is shown by the unchanged goldens: `test_format_base_sends_every_request_and_cell_of_the
  _5x_tree` and the 5w golden of `test_typed2_shared` (requests, cells, done-unit order) pass untouched.
- `phase` values follow DESIGN 3.6 (`learn` / `read`), not schedule-lock S10's `learning` / `reading` (DESIGN
  ranks higher; read-plan 5.1 says the same).
- R79 is applied only under `learn_first` (under `interleaved` learning follows reading by design); for both
  orders a receipt is never re-made for a state a read already mounted (closes the case R79 leaves to interleaved).
- `learn` under R79 runs `load_frozen(k)` (a check, no learning), so a missing or changed s<k> file or receipt
  pauses at once, as R79 asks.
- The pause unit of a frozen-state pause is `s<k>`; its detail is a fixed code (`receipt_missing`,
  `receipt_invalid`, `library_changed`, `typemap_changed`, `state_unreadable`); `read_mount_changed` names
  `read-<event>`. `chain.SCHEDULE_PAUSES` are members of `readplan.PAUSE_REASONS` (tested).
- Q2's start check was built (read-plan 5.1 keeps it) and runs only for `learn_first` in mode `run`.
- `heavy_for` refuses a manifest without `memory_lock`, and the shared `heavy` refuses a call without a unit for
  every bench (v218_lock itself would refuse only on sheet and ALFWorld).
- The reset wrap applies to the reset the services build (`preparation_reset`); an `alfworld_views` handed in
  explicitly (a test seam) is used as given.
- `open_panel` returns a dict and reads only the keys it needs from `setup`, so the pass can hand it the whole
  `_from_services` dictionary.
