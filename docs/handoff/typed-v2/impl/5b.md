## Choices

1. The base reaches the mount explicitly: the chain's `builder` and the reads pass `base_card=` to `mount_fn`, the
   chain passes it to both writers; the `Services` wrappers (`real_services`, `smoke.fake_services`) forward
   `**kw` unchanged. `mount`, `mount_identity`, `system_card`, `base_text` and the writer functions default to
   'format' (direct calls and the golden tests keep their bytes); the private `_routed_mount` and
   `reads._cell_builder` take it as a required keyword.
2. `prepare.base_card_of` refuses a missing value as well as an unknown one (fail closed: a root prepared before
   5b, or a hand-made manifest, never runs on a silent default). It guards `load_manifest`, `chain.run` (before
   anything is written) and `_Run`; the reads use it whenever a manifest exists. Only the explicit smoke form of
   `read_panel` without a manifest (tests) mounts on the code default. `real_services` adds no check of its own
   (`chain.run` refuses before the ledger opens).
3. `B` joins `MOUNT_ARMS` (second place), so the manifest's informational `mount_arms` list changes (it is not a
   sealed constant compared at load).
4. Minimal labels before Step 5: noise `Ba`/`Bb` (the mirror of `C0a`/`C0b`), no-harm baseline `B`. Step 5w
   replaces them by `B#1..3` and `B@noise`.
5. The chain state records `base_card` and `_open_state` refuses a resume with another one, like `machinery_code`
   and `container_scope`. Needed for the fake smoke, whose synthetic manifest is rebuilt at every start.
6. Writers: one key `base_card = {'meaning', 'text'}` in the user payload; the frozen v2.25 card system texts and
   the ten pinned engineer system texts are unchanged. The block is left out where the base text equals the
   format block, so 'format' requests and every ZebraLogic request are byte-identical to cdf85b6 (golden). Under
   'historical' the first-attempt card request gains the block: IMPLEMENTATION-ORDER "Do not touch" lists that
   request, the addendum's D17 (higher precedence) mandates the block; under 'format' it is untouched. The fix and
   format-retry requests carry no block (they are about the screen and the reply format). The base text is
   `mount.base_text` itself, so the writer sees exactly what the solver receives.
7. Card screen under 'historical': the public block given to `cards.card_screen` is `format_block + '\n' + C`
   (`_screen_public`): text the solver already receives is never a reference leak or a copy of an example. This
   relaxes the four content screens for C's text only (a larger public text can only remove findings); under
   'format' the call is unchanged. Without it, a card that reuses a C phrase also echoed in an example reply would
   be refused as `copied_examples` (tested both ways).
8. `prepare` seals only the field `base_card`; the base texts are frozen machinery texts (`v222_cards`, pinned by
   the machinery list), so the manifest's `cards` (format blocks) are unchanged and no C text is copied in.
9. The CLI passes `--base-card` to the adapters only when given (the existing adapter call pins hold) and prints the
   sealed value after `prepare`, so the operator sees 'historical' before the run.
10. The engineer label lives in `T/engineer_prompt.py` (typed prompt module, no new frozen read; `MACHINERY_SYMBOLS`
    unchanged), the card writer label in `W`.
