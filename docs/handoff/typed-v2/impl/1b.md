## Choices

- **Which starts are checked.** DESIGN 3.5 says `run` calls `start_checks`; spec identity 1.8 says unbound starts
  (local tests, `smoke --fake`) are not checked, and the real smoke builds its services before it calls `run`. The
  switch is `Services.machinery_code`: `real_services` always sets it to the manifest's sealed record (and refuses a
  manifest without one), so every real start (CLI run, resume, real smoke) passes `start_checks` inside `run`; fakes
  leave it None and get `own_root` only. No new `run` parameter and no Services field beyond the task's list.
- **`start_checks` signature.** `check` and `provenance` are keyword-only zero-argument callables without defaults
  (`run` passes `machinery.check(real=True)` and `prepare.typed_code()`); it returns the verified record, which `run`
  keeps in `Services.machinery_code` and the state. A manifest with `bound` not true is refused before `check()`
  runs (spec identity 1.10); the comparison covers every key of both records.
- **Order.** `start_checks` and the cap check run before the chain directory is created, so a refusal writes nothing
  (stricter than "before the ledger opens").
- **Ledger cap.** `services.cap`, else `manifest['caps'][chain]`; the code constant is no longer a fallback. Fakes keep
  `cap=None` and the synthetic manifest seals `caps`, so test helpers that set `services.cap = None` need no change.
- **Container scope of fakes.** None (no containers); the state stores None for fakes. `run` requires a non-None
  scope to equal `container_scope_of(root)` (services built for another root are refused).
- **Learning width source.** `cells` uses the constant `LEARN_WIDTHS`, as `reads` uses `WIDTHS`; 1a's
  `load_manifest` already refuses a manifest whose sealed `learn_widths` differs from it.
- **`typed_code`** filters `prelaunch.sha256_list(tree)` (same line format and file rule as `typed_tree`); a tree
  without typed files gives `files: 0` (the fixture trees), which a real start can never match.
- **`load_manifest`** checks the code identity's form and this code's list pins, never the process-dependent values
  (readout and status need no bound process); `start_checks` compares those.
- **`prepare`** calls `machinery.check(real=False)` (spec identity change list) without a test seam; a bound prepare
  on dl records the snapshot, an unbound one `bound: false`, which every real start refuses.
- **`SMOKE_LIMITS`** carries the five keys (`max_program_proposals` 3, `gate_repeats` 3 as DESIGN 3.2 says), so the
  smoke's `Services.limits` has every key; 4c may reword it.
- **`heavy`**: signature only; the real one ignores `unit` (per_cell_plain), `lock_setting` None; call sites unchanged.
- **`services_for`** builds a real `chain.Services` (not a SimpleNamespace), so the read tests get every current and
  future field with its default.
