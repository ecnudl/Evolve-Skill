## Choices

- `is_typed_v1` -> `is_typed_v2` (same body). The task says it "follows the version"; spec/identity.md proposed
  deleting it (it has no caller). Renaming keeps one predicate on the new version and leaves no typed_v1 name.
- Default names `SCHEDULE_DEFAULT` and `MEMORY_LOCK_DEFAULT`: DESIGN 3.6 gives the values but no names; the names
  are those of spec/schedule-lock.md change list row 1 (same pattern as `READ_PLAN_DEFAULT` in spec/read-plan.md).
- `LIBRARY_VERSION` and `TYPEMAP_VERSION` are the literals DESIGN 3.5 writes; both loads also require
  `module == VERSION` (spec/identity.md 1.4).
- `own_root` judges keys that are present: a manifest or state without `version` / `configuration` is not "another
  typed version" and passes (the existing CLI fixtures have such files); `load_manifest` and `chain._open_state`
  still require the keys. An existing file that cannot be read as a JSON object is refused (fail closed). The path
  check runs on the path as given and resolved, so a neutral symlink into a typed-v1 root is refused.
  `typed-v<n>` matching is on the hyphen form only (spec's `typed-v(\d+)`).
- `own_root` is called by `check_root` (after the name checks), by `load_manifest` (first), by `read_panel` (first)
  and by the five CLI commands; for `smoke` on both `--root` and its `<root>-smoke`. `chain.run` and `smoke.run`
  were not changed (start_checks is 1b's).
- `draw_keys` records the seed actually used by `prepare` (the `seed=` test seam), so a manifest prepared with
  another seed states it truthfully and is refused at load. `writers.EXAMPLE_TAG` is imported lazily inside
  `draw_keys`, so `prepare` (imported by `reads`) does not import the engineer machinery at module load and no third
  copy of the typed-v1 literal exists.
- `sealed_constants()` is the one list of manifest keys compared with the code at load; later steps can extend it
  (`machinery_code`, `schedule`, `memory_lock`, `tau_rule` are not in it yet, per the task).
- `bind_machinery` refuses any entry of `<snapshot>/skillopt/execskill` named `typed` or `typed.<ext>` (a module
  `typed.py` would shadow as well as a package), and does so before the "already imported" check, so the refusal
  is testable in-process.
- Message texts use the literal `typed-v2` where DESIGN words them so; the readout title and `own_root` messages use
  `VERSION`.
