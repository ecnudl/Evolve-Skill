## Done

`T/gatestats.py` (new, 422 lines, imports only `math`, `fractions`, `collections.abc`):

- Labels: `REPEAT_SEP = '#'`; `repeat_labels(arm, repeats) -> ('<arm>#1', ..., '<arm>#R')`;
  `arm_of_label(label) = label.split('#', 1)[0]`; `repeat_of_label(label) -> int >= 1`, `None` for a bare label.
- `arm_runs(cells, items, arm, repeats) -> {'sums': {item: S}, 'squares': {item: S}, 'unknown': u}`. `cells` is the
  chain's `{(item_id, label): row}`; only the R labels of the listed items are read. `correct` True -> 1, False -> 0,
  None without `infrastructure_unknown` / `configuration_error` -> 0 and counted in `unknown` (O1; the complement of
  the re-run predicate of `T/units.py`); any other `correct` value raises (O11). A missing cell or an
  infrastructure / configuration unknown raises `UndecidableRuns` (a `ValueError` with `arm`, `missing`,
  `infrastructure`, `expected` counts and no item content).
- `repeat_statistics(baseline, candidate, *, items, repeats, minimum_points, multiplier, subset=None)`: D, Q, n,
  better / worse / tied, `reaches` = reaches(D, n), `no_regress` = no_regress(D), reported `gain_points`,
  `se_points`, `tau_points`, `per_item = [[item, S_B, S_K], ...]`, `unknown_final = {baseline, candidate}`,
  `excluded_unknown = 0`, `scores = 'binary'`. With `subset`: `subset_*` fields (D, m, counts, gain, `reaches` over
  the subset against the WHOLE-slice Q and n, informational se of the subset and the scaled se).
- `calibration(baseline, *, items, repeats, minimum_points, multiplier)`: the noise record body (`kind 'noise'`,
  `rule 'baseline_repeats'`, Q, se, tau, `mixed_items`, `runs_correct`, `unknown_final`, `per_item = [[item, S]]`).
  A comparison whose baseline is the same arm gets the identical Q, se and tau (tested).
- `card_decision(stats)`: `accepted` / `gain_below_tau` / `not_more_better_than_worse`.
  `no_harm_decision(stats)`: `merge` with `merged` / `harm_beyond_tau`.
  `program_decision(stats, fired_stats, fired_cells)`: `accepted` / `never_fired` / `gain_below_tau` /
  `not_more_better_than_worse` / `harm`; adds `fired_items` (n_f), `fired_cells = [[item, count], ...]` (count > 0,
  slice order), `difference_sum_fired`, `gain_points_fired`, `better_fired`, `worse_fired`, `tied_fired`,
  `reaches_fired`, and the informational `se_points_fired = (100 / (R n_f)) sqrt(2 Q_f / (R - 1))`,
  `se_points_scaled = se_points * sqrt(n / n_f)` (None when n_f = 0).
  Every decision function re-derives the statistics from their own `per_item` list and refuses a dict whose derived
  fields differ: a decision is never taken from a stored flag.
- `recompute(record)`: rebuilds a stored card, program, no-harm or noise record from `per_item`, `repeats`,
  `minimum_points`, `multiplier`, `unknown_final` (and `fired_cells`) and returns `{**record, **rebuilt}`, so
  `recompute(record) == record` iff the stored decision is reproduced; chain fields pass through unchanged.
- Integer forms (a = a_num / a_den, c = c_num / c_den exactly, from `Fraction(value)`):
  `reaches(D, m) := 100 D a_den >= a_num R m and D >= 0 and D^2 n^2 (R-1) c_den^2 >= 2 c_num^2 Q m^2`;
  `no_regress(D) := 100 D a_den >= -a_num R n or D >= 0 or D^2 (R-1) c_den^2 <= 2 c_num^2 Q`
  (= DESIGN 3.4 with a = 3, c = 2).

## Choices

1. Reason names follow DESIGN 3.4 (precedence over spec/gate.md 1.4, which said "as typed-v1"): card
   `not_more_better_than_worse` (typed-v1 `better_not_above_worse`); program `gain_below_tau`,
   `not_more_better_than_worse`, `harm` (typed-v1 `fired_gain_below_tau`, `fired_better_not_above_worse`,
   `whole_slice_regression`). No-harm reasons are not named in DESIGN: typed-v1's `merged` / `harm_beyond_tau` kept.
   Constants `CARD_REASONS`, `PROGRAM_REASONS`, `NO_HARM_REASONS`.
2. `mean_points` is kept in every decision record as an alias equal to `gain_points` (spec 3.2 keeps it; `W`
   `revision_result`, the typing evidence and the skill origin read it today), so `W` works unchanged. For a program
   it is the whole-slice gain; the deciding gain is `gain_points_fired`.
3. `fired_items` is the count n_f; the fired item list is in `fired_cells` (O12). Added beside DESIGN's
   `difference_sum_fired`: `gain_points_fired`, `better_fired`, `worse_fired`, `tied_fired`, `reaches_fired`.
   Typed-v1's `fired_n`, `fired` and `whole` sub-dicts are not produced (DESIGN 4.1 replaces them).
4. `unknown_final` is `{'baseline': u_B, 'candidate': u_K}` in a comparison and an int in a noise record.
5. Records also carry `reaches`, `no_regress` (booleans of the two integer forms), `baseline_runs_correct`,
   `candidate_runs_correct` (spec 3.2); noise records carry `kind 'noise'` (lets `recompute` dispatch),
   `rule 'baseline_repeats'`, `mixed_items`, `runs_correct` (spec 3.2). `minimum_points` / `multiplier` are stored as
   the caller passed them.
6. `minimum_points` and `multiplier` are taken exactly with `Fraction(value)` (the exact value of the float; 3.0 and
   2.0 are exact); refused when negative, non-finite, a bool or not a number.
7. R >= 2 is enforced at every entry point, `repeat_labels` included; a bool or float R is refused.
8. Item ids are non-empty unique strings (as `T/prepare.py` requires of task ids); `items` is an ordered list.
9. `repeat_of_label` refuses a non-canonical suffix (`F#`, `F#0`, `F#01`, `F#x`, `#1`, non-ASCII digits) instead of
   returning None, so a malformed label can never pass as a single-run cell.
10. `arm_runs` reads exactly the R labels of the listed items and ignores everything else in `cells` (other arms,
    bare labels such as learn-side `F`); it raises one `UndecidableRuns` with the counts of the whole arm (new
    exception class, part of the refusal contract; the wiring maps `missing` to `incomplete_unit:missing_cells` and
    otherwise pauses `gate_cells_unknown`).
11. `repeat_statistics` uses generic `subset_*` field names; `program_decision` maps them to `*_fired`.
    `program_decision` refuses fired statistics of another comparison and `fired_cells` that do not match the subset;
    `fired_cells` may be a mapping (zeros allowed) or the stored list form.
12. Decision functions re-derive their statistics from `per_item` with type-strict equality (1 vs 1.0 vs True,
    list vs tuple) and refuse a mismatch; `recompute` instead returns the rebuilt record for comparison and raises
    only for records without statistical inputs (`writer_screens_failed`, `screen:...`, `smoke_fault`) or of an
    unknown kind.
