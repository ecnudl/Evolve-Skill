## Done

Code, `T/mount.py` only (`mount()` itself, `solve` and every other function are unchanged; the two docstring lines
of step 1a stay):
- `_route(record, *, typemap, library, vector, candidate, arm)` (new): the former lines of `_routed_mount` up to the
  selection call, moved unchanged: map/library check, `_check_candidate`, vector check, `typemap.assign`, the routing
  fields, the unknown-item candidate record, active card and programs, `_consistent`, `card_skill`, the other-type
  remap to F, the card candidate, `programs_offered`. Returns None for an item of no type, else
  `{'type', 'card_text', 'programs', 'arm', 'candidate'}` with the arm and candidate in effect. No call of any kind.
- `_routed_mount(...)`: same signature and same single caller; now `_route` + the selection part (the `selector`
  requirement, `_select` or `not_needed`, `programs_enabled`, `enabled`, the forced program with its id check and
  candidate record). Same record values, same requests, same refusals in the same order.
- `_forced_record(candidate)` (new, extracted): a `Procedure` becomes its sealed record, a dict is deep-copied; used
  by `_routed_mount` and `mount_identity`, so both read the same forced record.
- `mount_identity(bench, item, *, arm, typemap, library, vector, candidate=None, view=None, runtime=None)` (new,
  signature of spec/gate.md's change list): `mount`'s preamble (arm check, item check, view derivation, strict
  signature for routed arms), then C0 = format block, C = historical card, routed arms through `_route`. Returns
  `{'system_card_sha256': sha256 of the composed system card, 'programs_offered': [[skill_id, skill['sha256']], ...]
  in library order, 'forced': the applied program candidate's record_sha256 or None}`. No selector, no embedder,
  no solve: zero calls.

## Choices

1. Golden values are pinned digests, not a `git show` at test time: a HEAD-based load would compare the split with
   itself once the build is committed and needs `.git` on the Linux machine. Which values: computed on 2026-11-12
   before the edit, with the committed `T/mount.py` of 8375ecb (`git show` output loaded as module
   `skillopt.execskill.typed.mount_committed_8375ecb` from `/tmp/typed2-neutral/golden-5m`, since removed) and
   with the working-tree file before the edit (same code, 1a changed two docstring lines): equal on all 50 cases,
   and equal again under Python 3.10. `mount.py` of 8375ecb is byte-identical to the typed-v1 code commit 9ca2754,
   so the pins are also the "stored typed-v1 expectation" of spec/gate.md test 4.1.5.
2. Exact axis-vector embeddings in the new fixtures (all routing numbers exact: threshold 0.0, distances 0.0 or
   sqrt 2). Measured: the jittered fake embedder of `test_typed_mount.py` gives a centroid component
   0.9999772496845104 on 3.13 and 0.9999772496845105 on 3.10 (Python 3.12 changed `sum` over floats), so digests
   over it would fail on the Linux 3.11 suite.
3. The digest is over `json.dumps(payload, ensure_ascii=False)` without `sort_keys`: key order is part of the bytes.
4. `_route` takes the record and fills the same fields in the same order; it has no `bench` / `view` parameter
   because routing uses neither (the view enters only the selection request). `_routed_mount` keeps its signature.
5. `mount_identity` repeats `mount`'s five-line preamble instead of refactoring `mount()` (the task allows nothing
   else in `T/mount.py` to change); the identity-equals-mount test guards the mirror, refusal messages included.
6. `mount_identity` refuses an applied program candidate whose record has no `record_sha256` string (`ValueError`
   "A program candidate is a sealed record with its hash"). `forced = None` means "no program forced", so such a
   candidate would otherwise carry F's identity and be shared silently; `mount()` is unchanged (it records
   `sha256: None`, and the solve's package build refuses the record).
7. `forced` is the candidate record's own `record_sha256` (what `mount` records as `candidate['sha256']`), not
   re-verified with `Procedure.from_json`, consistent with `mount`.
8. `programs_offered` pairs are `[skill['skill_id'], skill['sha256']]` (`sha256` = canonical hash of the body,
   written by `make_skill`, covered by the library's record hash), in library order (the order of the selection
   index). Names and descriptions are not added: a skill id is never reused in one library (`next_id` checks every
   id, retired ones included) and a program joins the library only with its frozen description (`C`:913).
9. The two refusals of `mount`'s selection part (programs without a selector; forced id equal to a chosen
   program's id) are not refusals of `mount_identity`: it makes no selection, and the clash depends on the reply.
10. "Router call" is read as the solver model's program selection call (`_select` and the selection request
    functions); "solver" as `mount.solve` and the frozen `solver.solve` (judge and scorer counted too); "embedding"
    as `TypeMap.assign_view` and the fixture embedder (the vector is always the caller's).
11. The test file has its own fixtures and imports no helper from `tests/test_typed_mount.py`, which Step 5 may edit.
