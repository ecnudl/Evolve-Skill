## Choices

1. Units and order of a shared step: noise, typing, outcomes, `member-<b'>-outcomes`, card rounds (each: writer,
   `card-r<j>` arm, then, if the home rule passed, `member-<b'>-base` the first time and `card-r<j>-member-<b'>`),
   `card-r<j>-learn`, `outcomes-card`, `member-<b'>-outcomes-card`, programs (smoke, gate, member arms).
2. The member base runs lazily, when the first candidate of the step passed the home rule: same arm and same rule as
   an eager run, no cells when nothing passes at home (about 0.6 M tokens per chain saved then, D16 e).
3. `member-<b'>-outcomes-card` is also a gate arm (as the home `outcomes-card`): its identity equals the accepted
   round's member arm, so "that card's member runs" are the program member baseline through the same identity proof
   as DESIGN 3.4 case (e), with `shared_arm_mismatch` as its check and `baseline_selected: true` in the record.
4. "At most as many": the member block keeps the first `len(current examples)` rows of the member's list (the same
   rule: failures first, seeded order). A per-outcome cap was built first and dropped: when the current bench shows
   only failures and the member only successes (the real-writer test scenario) it shows no member example at all.
5. Member block head mirrors 5b: `format_block` always, `base_card` only where the base adds to it (never under
   'format'); the sentences say "base card" in words, so under 'format' no non-solver request contains `base_card`
   (5b's assertion holds unchanged). No member task card is shown (D16 names examples, base card, sources, rule).
6. The checks stop at the first member harm (the verdict is known; later members run no cell; the revision summary
   shows them `not_run`). With this bench order M has at most one member.
7. `reason: 'member_harm'` (a fixed token, also the writer's `failing_clause`) plus `member_harm: <bench>` in the
   record; the readout prints `member_harm (bench)`. The writer never sees a bench name in the summary (source label).
8. Every card / program record of a shared step carries `shared_with`, `members` (possibly empty) and `member_harm`,
   including zero-call and smoke-fault rows; records of one-bench types carry none of them (byte-identical).
9. The card screen also reads the member examples, corpora and learn ids, and its public block the member format
   blocks and base cards: the frozen card prompt promises a check against every shown example and reference; D2's
   length rules are unchanged.
10. Fitting: member examples / trajectories go first, so the current bench's part only shrinks when the members
   alone cannot make room (`dropped` reports both).
11. `decisions.json` key `shared_type` (not `members`, which the typing record already uses for a source's size).
12. `T/gates.py` (not in this step's file list) gains three re-exported names, so the chain keeps one import path
   (`gates.*`) as decided for 5w; `gatestats` stays the only place of the arithmetic.
