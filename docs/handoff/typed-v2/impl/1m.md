## Choices

- **`check(*, real, snapshot=None)`**: one optional keyword more than the task's `check(*, real)`. Spec identity.md
  (behaviour 9, change list) requires a real start to be bound to `MACHINERY_SNAPSHOT`, and DESIGN 5 / Step 7 runs
  `machinery.check(real=True)` in a fresh interpreter bound to a stand-in copy. The default (`None` means
  `MACHINERY_SNAPSHOT`) keeps every production call `check(real=True)` strict; the bound-interpreter test of
  Step 7 passes `snapshot=<stand-in>`. Paths are compared after `resolve()`. Ignored when `real=False`.
- **Strict file sets (checks 2 and 3)**: every file under `<root>/skillopt` outside `skillopt/execskill/typed` and
  outside `__pycache__` directories must be in one of the two lists. DESIGN 3.5 (3) says "no unlisted `.py`"; an
  unlisted non-`.py` file is refused too, because some are importable (a sourceless `.pyc`, an extension module) or
  read by globbing (`policy-v2-*.json`), and the data list covers every other file (F11). `__pycache__` contents
  are skipped: there a cache is only used next to its listed source.
- **Symbolic links** inside the compared area are their own problem `symlink` and are never followed (a linked
  directory would otherwise hide importable modules from the walk). F11: the snapshot has none; this tree has none.
- **Check 2 also refuses** an unlisted file in the snapshot and a `skillopt/execskill/typed` path there (spec
  behaviour 8: no unlisted `.py`, and a typed package in the snapshot would shadow this tree's).
- **Order of execution** 1, 2, 3, 5, 4, 6: check 4 runs after check 5 so that it also covers the modules that
  `require_symbols` imports.
- **`REQUIRED`, names known so far**: (a) an AST scan of the committed starting point of `T/` (HEAD `8375ecb`):
  every name imported from a frozen module and every attribute read on a frozen-module alias; each name was then
  confirmed by import. `client.call` and `client.get` were dropped: they are reads on a local variable named
  `client`, not module attributes. (b) The names DESIGN 3.1 to 3.3 give for the new modules: `v225_cards`
  (`_reference_values`, `PATH_LIKE`, `CARD_RETRY`, `RETRY_REASONS`, `CARD_WRITER_INPUT_CHARS`), `coevo5.leakage`
  (`normalize`, `_numbers`, `_numeric`, `_significant`, `_value`, `_grams`, `LEAK_MIN_SINGLE_WORD`,
  `LEAK_MIN_SIGNIFICANT_DIGITS`), `engineer` (`absent_findings`, `EDIT_KINDS`), `policy` (`check`, `source_limit`,
  `MAX_CONSTANT_CHARS`, `IMPORTABLE`, `FROM_ONLY`, `FORBIDDEN_NAMES`, `FORBIDDEN_ATTRIBUTES`, `FORBIDDEN_MODULES`,
  `ORDINARY_ATTRIBUTES`, `RECEPTACLES`), `protocol` (`MAX_DESCRIPTION_CHARS`, `MAX_HEADER_CHARS`,
  `MAX_NOTE_CHARS`), `engineer_reader` (`FENCE`, `MAX_REPLY_BYTES`, `Unusable`, `tolerant_json`, `schema`,
  `normalize`, `defined_hooks`), `profiles` (`HOOKS`, `MAX_CHANGES`), `package` (`MAX_STATE_BYTES`). All exist in
  this tree. A name that typed-v2 no longer uses does no harm: the machinery is frozen, so it keeps existing.
- **Errors** are plain `ValueError` (the code base's `require` convention); messages name paths and names only,
