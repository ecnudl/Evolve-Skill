## 0 一句话

Skill 在五个 bench 上依次进化。与此同时，检验它的"考官"也一起进化：考官包括评分细则（rubric，文字项＋代码项）和测试题。

- 每条新规则都要通过考官出的**泛化测试**，证明它在哪里适用。
- 通用的规则放进共享部分；只对本 bench 有用的规则限定适用范围。
- 考官的每次修改都要有资料查证（DeepResearch）支持。
- 全程不用验证集。

## 1 已定的实验框架（负责人 10/16 15:03）

### 1.1 bench 顺序的理由（10/16 18:30，数据来自账本与只读核对）

逐个 bench 的情况（GLM-5.3，除注明外都不是测试集；"能学"指以往任何方法有没有可信提升）：

| bench | 训练题 | 指令（bzero）相对空 | 以往能学吗 | 对别的 bench | 成本与接入 |
|---|---|---|---|---|---|
| SearchQA | 400（另有 4,000 道新题，2 块未读） | +13.4 点（975 道新题，140 好 10 差） | 唯一有可信测试提升的（+47 题/400）；从空 Skill 出发门会收 | 用到 OfficeQA 上相对空 +17.6～+21.6；GEPA 的 SearchQA 格式提示强行注入时 KOR 187→152、ALF 120→93 | 最便宜（每题约 1–3.5k tokens）；学习、生成题都已接入 |
| OfficeQA | 50 训练 + 24 验证 | +18.9 点 [+7.8, +30.6]，几乎全是格式 | 6 个带门阶段都没收；bzero 重做一遍有 12–18/74 题翻转，噪声大 | 用到 SearchQA 上相对 SearchQA 的指令 −2.8、−7.2 | 每次调用约 6k tokens；学习已接入，没有测试格 |
| LiveMath | 155 | +1.0 点（200 题，文字几乎无用） | 3 个带门阶段都没收 | 带"只答选项字母"的那份让 SearchQA 掉 63.6 点 | **最贵最慢**：单次调用可达 6.5 万 tokens，一个带门阶段 2–7 小时；学习已接入，没有测试格 |
| SpreadsheetBench | 80 | 没有 bzero | 没有；约 1/3 的题无法判分 | 未见可信影响 | 测试一遍 36–61 分钟；阶段工具拒绝它，要新接 |
| ALFWorld | 39 | 没有 bzero | 没有；No-Skill 已 89.6%，接近天花板 | 被 SearchQA 格式提示伤害过（93/134） | Skill 每一步都重发，带 Skill 时每局 29–50k tokens；阶段工具拒绝它，要新接 |

定为 **SearchQA → OfficeQA → LiveMath → SpreadsheetBench → ALFWorld**，理由：

1. **能学到的先学，增益在表里出现得早、保持得久。** 只有 SearchQA、OfficeQA 有大的可学增益（+13、+19 点，主要是作答格式）。
   放在前两步，它们的提升会出现在后面每一行；后面三步再检验这些提升会不会被遗忘。
2. **SearchQA 第一。**
   - 训练题最多、噪声最小、最便宜，适合作为整条链的起点。
   - 它学到的"按要求简短作答"之类习惯最通用：以往别的 bench 的 Skill 用到 OfficeQA 上，相对空 Skill +17.6～+21.6 点。
     所以第一行里 OfficeQA 有望不经训练就涨，这是"共享部分能迁移"的直接证据。
   - 反过来，OfficeQA 学到的 Skill 用到 SearchQA 上，比 SearchQA 自己的指令低 2.8、7.2 点（相对空 Skill 仍高 12.8～17.2 点）；
     OfficeQA 先学，这些规则会在 SearchQA 还没有回归题保护时进入 Skill。SearchQA 的 Skill 用到 OfficeQA 上只低 1.4～5.4 点，区间都含 0。
3. **OfficeQA 第二。** 它的格式要求更具体（答案标签里只写纯数字、百分号、单位）。放在 SearchQA 之后，SearchQA 的回归题可以把这些
   规则挡在 OfficeQA 分区里。它的训练题少、噪声大，放在第一步不稳。
4. **LiveMath 第三。**
   - 三个问答类 bench 的答案格式互相冲突：短文本、纯数字、单个字母。这正是分区要解决的问题，放在一起连续检验最清楚。
   - "只答字母"是最危险的外溢。LiveMath 放在 SearchQA、OfficeQA 之后，两者的回归题都已经就位。
   - 它本身几乎学不到东西，阶段又慢，不适合放在前面。
5. **SpreadsheetBench、ALFWorld 最后。**
   - 以往没有任何方法在它们上面学到东西，它们在这条链里主要用来检验"不伤害、不遗忘"。
   - 两者都还没接进阶段工具，排在后面，工程可以和前三步并行。
   - ALFWorld 训练题最少（39 道）、接近天花板，放最后；这也和旧五域链 ALFWorld 在最后一步一致。

排除过的顺序：
- OfficeQA 打头：第一步噪声大；它的规则用到 SearchQA 上比 SearchQA 自己的指令低 3–7 点。
- LiveMath 打头：学不到东西，还可能把"只答字母"带给 SearchQA。
- SpreadsheetBench 或 ALFWorld 打头：以往学不到东西，第一步很可能空转（旧链以 BigCodeBench 打头，第一步之后 KOR 训练分 746→691）。
- 问答与操作类交替：伤害会提前出现在还没有回归题保护的 bench 上，也要求 SpreadsheetBench、ALFWorld 先接好。

顺序对两个模型相同。

**同时发现的工程缺口（写进 §8）**：
- deepseek 现在只能跑 SearchQA、OfficeQA，而且不能跑测试题；复现需要给 LiveMath、SpreadsheetBench、ALFWorld 和测试评测接上 deepseek。
- 阶段工具不支持 SpreadsheetBench、ALFWorld 的学习；它们没有默认细则，也没有 bzero。
- OfficeQA、LiveMath 还没有测试格。
- 新快照上要重新验证 SpreadsheetBench 的判分器。
  - 测试集规模：SearchQA 400、OfficeQA 172、LiveMath 125、SpreadsheetBench 279（可判分的）、ALFWorld 134。
  - 测试集只在方法与代码冻结后，由评测步骤读取。
- **模型**：GLM-5.3 出主表，deepseek-v4-flash 复现。
- **测试时**：只有 Skill 文本。各 bench 的官方判分**不变**——考试本身不进化，否则成绩没法比。进化的是方法内部的考官。

## 2 每一步的流程（在第 k 个 bench 上）

符合负责人定的大流程"训练执行 → 反馈 → analyst → 候选 → 决定"，改动只落在各环的实现上。

1. **训练执行**：用当前 Skill 做 bench k 的训练题，每题 2 次。
2. **反馈**：考官的评分细则逐题诊断。
   - 代码项先判格式：百分号、单位、选项字母、列表格式、动作语法等。
   - 文字项判内容与方法。
   - 诊断连同训练题的对错与参考答案，一起交给 analyst。
3. **analyst**：提出若干条规则（每条是对 Skill 的一处插入或改写），并写明它针对哪类题。
4. **出泛化测试题**：
   - 出题器为每条规则出两类题：迁移题（把规则背后的道理搬到别的 bench 的题型里）、边界题（规则不该起作用的情形）。
   - **DeepResearch 逐题审核**：核对参考答案、检查有无歧义，然后修改或丢弃。
5. **逐条检验（X v2）**：每条规则单独加到当前 Skill 上，逐项检查：
   - (a) bench k 中它针对的训练题：按"内容"判断是否多做对；格式翻转由代码项单独计。门槛用同一次运行里的"无关文字"对照来定。
   - (b) bench k 的其他训练题：不能变差。
   - (c) 回归题：不能变差。回归题包括前面各步收下的测试题，以及其他 bench 的少量真训练题。
   - (d) 迁移题：帮得上就算通用；帮不上就限定在 bench k。
   - (e) 边界题：如果被乱用，必须限定范围或改写，否则不收。
   - 分初筛、复核两轮，复核用新的运行。
6. **合入**：
   - 通用规则进共享部分；限定规则进 bench k 的分区，并写明适用条件。
   - 收下的测试题进回归题库。
7. **考官进化**：用本步训练题的真实对错检查评分细则。
   - 细则判断与真实对错不一致的地方，交给 DeepResearch 查原因：查 bench 的说明、判分规则和题目材料。
   - 据此提出新增或修改的细则。文字项都要写；能机械检查的，同时写成代码。每条带引用。
   - 只有在另一半训练题上一致率更高，才收下。
8. **评测**：新 Skill 在五个 bench 的测试集上各测一遍。协议固定，不做任何挑选。

## 3 各部件

### 3.1 Skill 的结构

- 由两部分组成：共享部分（通用原则），加上每个 bench 一个分区。
  - 分区开头写一句适用条件，如"当任务给出美国财政部公报页面并要求数值答案时"。
  - 总长 ≤32 KB。
- 目的：把"作答习惯"关在它自己的 bench 里。之前跨数据集最大的伤害，就来自作答习惯外溢到别的 bench。

### 3.2 评分细则（rubric）：文字项＋代码项

- **每条细则包含**：
  - 文字描述；
  - 能机械检查的，附代码检查（正则、数值容差、结构或语法检查）；
  - 适用范围（通用，或某个 bench）；
  - 证据（引用，或训练题编号）。
- **用在三处**：
  - 反馈诊断（§2 第 2 步）；
  - 逐条检验中，区分格式翻转与内容对错（§2 第 5 步）；
  - 审核生成题，检查参考答案的格式。
- **起点**：每个 bench 根据任务说明写一份初始细则（零样本，与 bzero 同源），另有一份通用细则。
- **衡量考官本身**：用"细则判断与真实对错的一致率"。
  - 只在还没用来改细则的训练题上算：每步一半训练题用来改细则，另一半用来查。

### 3.3 DeepResearch（查证）

- **作用于三处**：
  1. 审核与修正生成的测试题。
  2. 为新增或修改的细则找依据。
  3. 判断一条规则是 bench 习惯还是通用道理时找依据，例如该 bench 的判分说明是否规定了这种格式。
- **资料来源**：要求可复现、留记录。
  - 包括：题目自带的材料；各 bench 的任务说明与判分规则；参考资料（维基百科、表格函数文档、ALFWorld 动作说明等）。
  - **负责人 10/16 18:10 同意联网搜索**。经开发机网关访问；每个结论都带引用。
- **谁做什么**（回答负责人 18:10 的问题"谁在查询和 search"）：
  - **查证模型**：GLM-5.3，与 analyst 同一个模型、单独调用、单独提示词。它决定搜什么、读哪些页面，最后下结论。
    不引入更强的模型，避免把"更强的模型"混进方法效果。
  - **程序**：真正调用搜索引擎和下载页面；按黑名单过滤；保存页面副本；核对引用；限制次数；全程留记录。
  - **搜索引擎**：候选是智谱 BigModel 的联网搜索接口（用现有账号），或维基百科等免费接口。工程第一步在开发机上测通再定，
    测试只发与 benchmark 无关的查询。
    - **10/16 19:25 开发机连通测试**（经 PJLAB 网关，一个与 benchmark 无关的查询，脚本 `/root/.config/weak-solver/search_check.py`）：
      - BigModel 联网搜索：HTTP 429，错误码 1113"余额不足或无可用资源包"，现有账号没有这项服务的额度；
      - 维基百科搜索接口：可用；
      - DuckDuckGo 网页搜索：返回人机验证页，不可用；
      - 直接下载网页（docs.python.org）：可用。
    - 因此先用"维基百科搜索 ＋ 一份固定的官方文档清单（各 bench 的任务说明与判分规则、Python / openpyxl / Excel 函数文档、
      ALFWorld 说明）"，查证模型在这两处检索；搜索接口做成可替换的。负责人若给 BigModel 联网搜索充值，可以换成通用网页搜索。
  - **做题模型不联网**：测试时只看到 Skill 文本。
  - 已有代码的情况：冻结的 v10 里，Research 只能从 16 个 Python 3.11 官方文档页里挑（`skillopt/continual_learning/verifier.py`
    的 `APPROVED_PATHS`），没有搜索引擎；9 月的 DeepResearch 冒烟也只读官方文档。所以联网搜索是新组件，要新写、新审查。
- **一次查证的流程**：
  1. 程序提出要查的问题。来源有三种：审题（生成题的参考答案对不对、有无歧义）、改细则（判分规则是否要求某种格式）、
     归类（某个作答习惯是本 bench 的规定还是普遍做法）。
  2. 查证模型写 1–3 个搜索词。
  3. 程序去搜，按黑名单过滤，返回标题和摘要。
  4. 查证模型挑最多 3 个页面，程序下载并存档；不够就再搜一轮，最多 3 轮。
  5. 查证模型下结论，每条附原文引用；程序核对引用逐字出现在存档页面里，对不上的结论作废。
  6. 结论只是证据：改不改细则、留不留题，按事先登记的规则决定（例如改过的细则要在另一半训练题上一致率更高）。
- **防泄漏**：
  - 只处理训练题、生成题和细则，永远看不到测试题。
  - 黑名单：托管 benchmark 题目或答案的网站（数据集托管页、各 bench 的代码仓库与论文附件、SearchQA 题目的出处 j-archive 等），
    具体名单在登记时列出。
  - 写进 Skill 的只能是做法，不能是具体事实或答案；规则写入前过泄漏检查，不得含训练题答案。
  - 每次搜索和每个页面都存档，可复查。

### 3.4 出题器 v4：泛化测试题

- 不再模仿训练集。
- **迁移题**：每条规则出 3–5 道，用问答类 bench 的题型（SearchQA 式问答、OfficeQA 式表格计算、LiveMath 式选择题），并带可核对的参考答案。
  - LiveMath 式只出能核对的题。
- **边界题**：每条规则出 3–5 道，多数只需检查作答格式，不需要参考答案。
- **SpreadsheetBench、ALFWorld**：很难出带标准答案的新题。
  - 只做边界题（格式、动作语法）。
  - 这两个 bench 的"不伤害"检查，用它们自己的真训练题。
- 研究审核后的合格率要报告，作为考官质量的一部分。

### 3.5 逐条检验 X v2（相对今天的版本的改进）

- **格式翻转与内容对错分开计**：今天 OfficeQA 上 Skill 之间的差异，几乎全是格式翻转（账本 10/16 15:01 条）。
- **"无关文字"对照**：每轮放 2–3 段无关的文字，当作规则一起测，量出"改了文字"本身带来的波动，再据此定门槛。
  - 原因：今天用"同一 Skill 重复做"量出来的噪声偏小。
- **新增**：跨 bench 回归，以及通用 / 限定分类。

  测试题完全相同，登记时核对。

**"从任务说明指令出发"这条链（负责人 10/16 19:10 决定加上）**：
- 是什么：起点从空白换成五份任务说明指令（各放在自己的分区），其余流程完全相同。
- 为什么：以往在 SearchQA 上，从空白学一步约等于一份指令（−0.5 点 [−2.3, +1.2]），在指令之上再学一步 +0.1 点 [−1.6, +1.8]。
  只报"从空白出发"，审稿人会问"这不就是一份指令能给的吗"。
- 代价：多一条五步链，GLM-5.3 约多 2–3 天；也可以先在 deepseek 上跑。

**消融**（讲故事用，挑 2–3 个）：
- 不出题：只在真训练题上逐条检验；
- 用模仿训练集出的题（v3）代替泛化测试题；
- 不用 DeepResearch；
- 只用文字细则；
- 不分区：所有规则都放共享部分。

## 5 为什么这样设计：之前的结果 → 设计上的回应

| 之前的结果 | 设计上的回应 |
|---|---|
| 学到的东西大多是本数据集的作答习惯（OfficeQA 指令带来的 +18.9 点主要是格式）。跨数据集时会伤害别的 bench：GLM-5.3 上 LiveMath 的"只答字母"让 SearchQA 掉 64 点；旧五域实验在代码题上进化后，推理规则题从 746 掉到 691 | Skill 分区；每条规则用迁移题和边界题分类，作答习惯限定在本 bench；加跨 bench 回归题 |
| 模仿训练集出题：生成题上的收益到真题上不兑现（10/15–16，三个模型）；v3 保真度不过线 | 出题器不再当"假验证集"，改为给规则出泛化测试题；规则对本 bench 是否真有效，仍由真训练题判 |
| 逐条检验挑出的规则，在 24 道 val 上效果未建立；差异几乎全是格式翻转；"无关题"浮动 −0.83…+1.83 题 | X v2：格式与内容分开计；用"无关文字"对照定门槛 |
| 同输入噪声大（124 题上中位 6、最大 14）；真效应只有 +1～+3 题 | 两轮检验加对照；只在大效应上下结论；主张写成"不用验证集也不差于用验证集的方法"加"伤害更少"，不追求小增益 |
| L3：演化后的细则给出的验证反馈好于只给对错（+5.0/250，p=0.047），但细则演化本身未证实；同一清单由程序执行还是由模型判定，候选无差别；可执行细则在求解时 +2.7 点 | 细则用文字项加代码项；考官质量用一致率单独衡量，不把"细则进化"直接说成 Skill 提升 |
| Research 在冻结代码里只对 BigCodeBench 开放，几乎没用上 | DeepResearch 作用于出题审核、细则依据、作答习惯与通用道理的判断，覆盖全部 bench，每条带引用 |
| 从空 Skill 出发、效应大时，门会收；任务说明指令带来的提升在 6 个"模型 × bench"组合上都稳定 | 从空白出发：作答习惯这类大效应能被学到、被收下，这是主要的可观效果来源 |
| deepseek 上跨数据集互换 Skill 不害，GLM-5.3 上有害 | 主表用 GLM-5.3（伤害看得见），deepseek 复现 |

## 6 怎么讲（事先登记的主张）

- **主张 1（不用验证集）**：本方法全程不用验证集。五步结束时，各 bench 的测试分数不低于用验证集选择的 SkillOpt、GEPA。
- **主张 2（泛化，伤害少）**：每步之后，对"已学过的 bench"（遗忘）和"还没学的 bench"（负迁移）的平均伤害，小于基线。
- **主张 3（考官在进化）**：
  - 细则与真实对错的一致率随步数提高（在新的训练题上算）；
  - 研究审核后，测试题的合格率高于审核前。
- **分析**：每个 bench 学到的规则里，通用与限定各占多少，并举例。
- **读法纪律**：所有主张、读法、对比都事先登记；区间含 0 写"未建立"；负面结果照实写。

## 7 效果预期（照实说）

## 10 相关工作（10/16 检索；部分只读了摘要，投稿前要重查）

**结论**：每个部件单独看都有人做过。没有找到把它们组合起来的工作，也没有"不用验证集、五个 bench 依次进化、看迁移与遗忘"的实验协议。

| 工作 | 做了什么 | 和本方案的区别 |
|---|---|---|
| SkillOpt（arXiv 2605.23904，2026-05） | 对一份 skill 文档做小修改，在留出的选择集上严格变好才收。六个 bench 含 SearchQA、SpreadsheetBench、OfficeQA、LiveMath、ALFWorld | 要验证集；每个 bench 单独做；起点非空；不看依次学习与遗忘 |
| GRASP（EMNLP 2026，arXiv 2605.29668） | 一次改一条 skill。"修好的 − 改坏的 > 0，且改坏的不多于现有库"才收；用训练（开发）集上按题型平衡抽取的探针 | 探针随机抽，不按规则的来源错误；一次一个 bench；没有生成题、分区和考官进化 |
| SkillRubric（arXiv 2609.34557，2026-09） | 每个 skill 由适用说明、行动指导、评分细则组成。指导"有改善且不过度回退"才收；细则"与标签更一致、且没有放松标准"才收 | 多模态智能体加强化学习；细则只由模型判，没有代码检查；不查资料；不看遗忘 |
| EvalGen（UIST 2024） | 评判标准写成 Python 函数或模型判分提示，按与人工打分的一致率挑选 | 不在 skill 学习里，也不随查证进化 |
| PromptPex（arXiv 2503.05070） | 从提示里抽出规则，为每条规则及其"反规则"出测试，作回归题 | 测试只查是否遵守规则，没有标准答案；不用来决定规则的适用范围 |
| DR Tulu / RLER（ICML 2026） | 用检索到的文档生成评分细则，并随训练增补 | 改的是模型权重；不对照标签检查细则质量 |
| EFRE（arXiv 2610.11373，2026-10-08） | 证明依次优化提示词会遗忘：FinQA 在学完 Bio 后掉 25.1 点；改用函数库 | 是"遗忘更少"这一主张的主要对手，也说明这个问题真实存在 |
| SkillsBench（arXiv 2602.12670） | 自己生成的 skill 平均没有收益 | 与我们"学到的不比任务说明指令好"一致；主张必须过这一关 |
| 模型编辑的评价标准（Yao et al.，EMNLP 2023） | 可靠性、泛化、局部性、可移植性 | 迁移题 / 边界题，就是把"可移植性 / 局部性"用到自然语言规则上；作为思想来源引用 |

另有几项相关工作：
- **规则带适用情境**：AutoGuide（规则带适用情境）、MetaSPO（共享提示加任务提示）。
- **从经验积累 skill**：ACE（条目式 playbook，记录有帮助 / 有害的次数，没有逐条的因果检验）、EvoSkill（从失败中提出 skill，用验证集挑选，报告了 OfficeQA）。
- **用研究智能体核对题目答案**：AutoBencher、FutureHouse 的 Crow。

**新意落在组合与协议上（检索未见）**：
1. 每条规则按它自己的来源错误检验，再加不伤害检查，以此代替验证集；
2. 为每条规则合成跨 bench 的迁移题 / 边界题，决定它放共享部分，还是限定在某个 bench；
3. 收下的测试题累积成跨 bench 回归题，防止互相干扰；
4. 考官（文字项＋代码项）只在有引用的查证支持下修改，并用没见过的标签衡量准确率；
5. 五个 bench 从空白依次进化，给出完整的迁移 / 遗忘表。

**对设计的修改（建议，待负责人定范围）**：
- **基线增加以下几项**：
  - SkillOpt / GEPA，标注数据量与本方法相同：它们的选择集从同一训练池里切；
  - 一个不设门、逐条积累的方法（ACE 或 EvoSkill），依次运行；
  - 把本方法的门换成 GRASP 式的"修好 − 改坏"门，用来隔离"按来源错误检验＋生成题"的贡献；
  - 每个 bench 各自独立的 Skill；
  - 任务说明指令（通用的一次性指令）。
- **关键风险**：主张要成立，本方法必须比"任务说明指令"更好。这是 SkillsBench 的发现，也是我们以往的结果。建议主表同时报告"从任务说明指令出发"的版本。
- **遗忘对比**：主张 2（遗忘更少）要直接与 EFRE 式的依次优化，以及上面的基线比。
- **划分比例**：SkillOpt 论文给出两种划分比例（4:1:5 与 2:1:7），对比前要确认用的是哪一种。
