## 0 一页摘要（给负责人）

**负责人 22:3x 的定调（有约束力，逐条改在哪里见第 21 节）**

- **(a) 都按默认值。** 第 14 节的 32 项决定在 2026-10-21 22:3x 全部按默认值生效（负责人原话"都按照默认值"）。所以：试点就是默认顺序
  SpreadsheetBench → OfficeQA（不是我建议的 → ALFWorld）；开发机上残留的 D3/D14 进程不动，"没有残留 ALFWorld 进程"那项检查按命令行排除它们、
  记"无法判断"（#3）；冒烟只用夹具题（#6）；ALFWorld、SearchQA 上不跑第二个安慰剂（#9）；测试集只在最后读一次（#12）；其余各项同样取默认。
- **(b) 宗旨不改，由负责人定死。** 这是**协同进化**：考官一侧（写检测器、出题的一侧）靠**查证**（research：到固定的公开资料里找依据）产出验证题和
  测试题来进化。考官出题的路径里**必须有一步查证**，原样沿用 v3 冻结的查证机器：固定参数的英文维基百科接口，加上开跑前按 SHA-256 钉死的文档存档
  （Python 3.11、openpyxl、LibreOffice Calc 的帮助页和公开任务卡）；查证员由 GLM-5.3 扮演；每个请求最多 3 轮 × 每轮 3 个检索词、最多读 3 页、
  最多 8 次模型调用；每条检索结果和每个页面都在单元目录下只写一次地存档；引文必须逐字出现在存档页面里（第 7.2 节）。查证给的是**素材和参数**，
  不是答案：每道生成题的**真值仍由固定代码算出**（Codex F8 不变）。原因：v3 那种"考官自己算答案"的前向题在 v3 冒烟里 9 道只有 4 道合格，
  v1、v2 冒烟是 12 道里 9 道、10 道（第 7.2 节）。
- **(c) 模型与两条链。** 冒烟只查管线，用哪个模型都行，照登记仍用 elucid 上的 deepseek-v4.1-flash-1017。**正式运行（试点与整条链）用两个做题
  模型、两条并行的链**：**链 G** 的做题模型是 GLM-5.3（走 v1、v2、v3 的 GLM 链用过的冻结 BigModel 通道），**链 D** 的做题模型是
  deepseek-v4.1-flash-1017（elucid，第 4.1 节）；两条链的方法角色（工程师、考官、查证员等）都是 GLM-5.3。每条链有自己的账本作用域和上限，
  登记的每条链上限对**每条链**都适用，所以试点总额翻倍：默认试点做题估计 4,620 万–1.712 亿 token（最大工作量 2.07 亿），做题上限 3.6 亿
  （每条链 1.8 亿）；GLM 方法角色上限 6,000 万（每条链 3,000 万）（附录 A 的 T11）。两条链各用自己的消耗账，看到的是**同一批题**：这是同一
  批题上的重复运行，不是两份独立证据（第 3.4、11 节；只是说明，不是新的决定）。

1. **这是什么。** 一个新协议，名字叫 `fivebench-execskill-v1`（"五个 bench、可执行技能、第 1 版"）。学到的 Skill 不再是一段
   文字，而是一个"程序包"：几条小程序（叫"过程"），每条自带一个判断"这道题要不要启用我"的小程序（叫"适用条件"）。
   做题模型外面套一层固定代码（叫"壳"），壳在发请求前后运行被启用的过程。过程只能做三件事：往提示里加一段整理好的
   信息；从题面里抽数字、替模型做精确计算（最多多问模型一次）；把某些动作标成"不建议"（ALFWorld）。**过程改不了模型的
   最终回答**，也改不了答案格式要求。
2. **两边都进化。** 工程师（GLM-5.3 扮演）读失败记录写过程；考官（GLM-5.3 扮演）写"失败检测器"和"出题程序"。
   两边都有改不动的锚：参考答案、模拟器、程序算出的真值。考官出题前**必须先查证**（沿用 v3 冻结的查证机器），查证只给素材与参数，
   真值仍由固定代码算出；这条宗旨由负责人定死（第 7 节开头）。
3. **没有可复用的验证集：每次决定只用一批一次性的验收题（取自训练池）。** 每个版本"收不收"只在一批本路线从没用过的训练题上
   决定一次，四组同时段逐题交错：新包、旧包、只有任务卡、安慰剂（触发规则相同、内容取自一份事先冻结的"别的题"的输出，所以对这道题
   没用）。新包必须同时胜过旧包和安慰剂。这批题就是一次性的验收子集，用过就作废；但 SpreadsheetBench、OfficeQA 的题以前被别的方法
   反复用过（3.1 的表：两种口径都是 0 道没用过），所以验收结果是**选择证据**（"这个版本在没用过的训练题上胜过父版本"），**不是独立的
   泛化证据**——后者只来自最后的测试读取。生成题**永远不当验收标准**，在试点里也不当筛子（第 7 节解释原因）。这句措辞关系到论文的
   主张，列为负责人决定 #31。
4. **实话（题量决定的）。** 按您认可的顺序，第一步 SpreadsheetBench（表格编程题，91 道可用）、第二步 OfficeQA（财政
   公报计算题，74 道）只认得出约 10–12 分以上的提高；一条真实 +5 分的改进被收下的机会只有约 17%（SpreadsheetBench）和 24%（OfficeQA）
   （估计；用一个明确的二元正态模型同时算两个对比，随相关、A\* 占比、安慰剂效应、守卫变化的范围是 8%–54%，第 6.6 节）。最可能的结果
   是"两步都不收"（真实 +5 分时概率约 0.63，范围 0.27–0.82，估计）。这不等于"过程没用"，只等于"这个题量认不出"。另一句实话：决定用的
   单侧 5% 检验在"均值为零但分布偏斜"时实测会多收，|A\*| = 30 时最高约 16%，150 时约 6%–8%（附录 A 的 T9，第 6.4 节）。
5. **建议（负责人决定 #1；22:3x 已按默认值决定试点 = SpreadsheetBench → OfficeQA，本条建议不执行，只留作记录；本条的费用都是每条链的数，
   两条链合计见上面 (c)、第 9.3、11 节与附录 A 的 T11）。** 试点改成 SpreadsheetBench → ALFWorld（文字家务游戏）：ALFWorld 有 3,514 局没用过的
   训练局、模拟器判成败、任务卡下约一半失败，验收 150 局能认出约 10–11 分（估计，含按房间整组的设计效应），代价做题约
   0.55–1.42 亿 token（估计；登记的最大工作量 1.81 亿，上限 3.0 亿）。默认仍按您认可的 SpreadsheetBench → OfficeQA（约 0.23–0.86 亿
   token，估计；最大工作量 1.04 亿，上限 1.8 亿）。上限比上一版（1.35 亿 / 2.3 亿）高：Codex 审查发现上一版只按"预期工作量"定上限，
   登记允许的最大工作量（每题最多 2 个孪生格、难度带 3 轮探针、自测 2 遍）和账本"下一次完整预留"的余量都没算进去（第 9.3 节）。
6. **考官一侧的诚实预期。** 在试点题量下，失败检测器在 SpreadsheetBench/OfficeQA 上"无法判定"；在 ALFWorld（建议方案）上机会
   也不大：检测器只看"第 10 步之前还没结束的局"的前 10 步（结局与胜负标记都去掉；"残差格"即没被固定类别覆盖的作答记录，也按这同一份
   视图定义，见 7.1），写和验的两半按**房间**切开，每半只有 8 个房间（登记的最低数），按房间整组重抽的下界很宽。出题程序的"预测效度"

   报告考官一侧时固定列出查证路径：查证请求数、合格发现数、各族生成与准入的题数、预测效度状态（第 7.2 节）。

## 2 学到的东西长什么样（对象与规则）

### 2.1 过程（被学习的部分）

每条过程是一个 Python 模块（≤ 6,000 字节；模块顶层只许 import、常量（字面量 ≤ 2,000 字符）、函数定义），加一份记录：
编号 `p-<来源bench>-<步>-<n>`、来源 bench、说明（≤ 600 字符，只给人看，不给做题模型看）、声明的钩子、声明的上限、
回放测试、血统（父过程、工程师调用的请求哈希）、`excluded_benches`（缩小适用范围用，默认空），以及内容哈希。
程序包 = 有序的过程列表（≤ 24 条，源码合计 ≤ 64,000 字节）+ 父包哈希，按内容寻址、只写一次。

**钩子（封闭集合）：**

| 钩子 | 什么时候跑 | 能做什么 |
|---|---|---|
| `applies(view)` | 每道题开始一次（ALFWorld：每局开始一次，在登记的"开局视图"上） | 只返回真/假，决定启用 |
| `before_call(view, state)` | 问答/表格：第一次请求前 | 返回**有类型的字段**（事实列表、表格、候选、警示），壳用固定表头渲染成一段说明 |
| `bindings(view)` | 问答：第一次请求前（精确计算类过程） | 从题面抽出带名字的数值，每个数值和它的原文引语必须逐字出现在题面里（固定代码核对），否则丢掉 |
| `sheet_feedback(view, run_report, state)` | 表格：程序在公开输入上试跑一次之后 | 给出有类型的修改建议，并决定是否请求**一次**修改调用 |
| `alf_before_step(view, state)` | ALFWorld：每步请求前 | 有类型的字段 + "不建议的动作"列表（只标注，不删除，模型仍可输入） |
| `alf_after_step(event, state)` | ALFWorld：每步执行后 | 只更新状态 |

结构性保证（壳没有这些接口，所以做不到）：改系统提示、改格式要求句、改/抽取/重写最终回答、替模型选动作或换动作、
看参数以外的任何东西。

### 2.2 任务卡与格式护栏（冻结，不学）

- **任务卡** = v3 I-ds 链起点用的五份 GLM 写的指令（`dl:/data/coevo5-20261019-v3-pre/texts/texts.json`；长度与哈希前缀：
  searchqa 1,846 字符 `48b10afc…`、officeqa 2,926 `2e92500a…`、livemath 2,068 `9cb3d860…`、spreadsheetbench 2,907
  `48a5df7f…`、alfworld 2,301 `5ae6ea9b…`，实测 [CM 2.10b]），是已知最强的文字基线（cal-1：ids-full 154.5 对 seed-only
  153.5 对 parent:A 135.75，200 道 SearchQA × 4 次，实测 [FP F42]）。**只给当前 bench 的那一张**：v3 把五张全给，别的
  bench 的答案格式建议在 OfficeQA 上造成 −9.5 到 −33 分（E4/E9 实测 [FP F51-F52]）。
- **格式护栏** = 每个 bench 固定的一句格式要求，只作指令：SearchQA/OfficeQA "Return the concise final answer inside
  <answer>...</answer>."、`LIVEMATH_CONTRACT`、`SHEET_CONTRACT_V2`、ALFWorld "Act in the text environment. Return a single
  action inside <action>...</action>."（backends.py:35, 53-56, 381-382, 730）。**不做任何输出改写**（改写就是"答案修补"，
  不算学到的 Skill）。每格核对：问答的送分回答与模型回答逐字节相同；表格的送分程序就是冻结抽取函数从模型回答里抽出的程序。
- **ALFWorld 动作规范化（只到第 1 级，所有组都开）**：取 `<action>` 标签内文本（没有就取整段回答），去掉前缀 "action:"、
  首尾引号空白和末尾句号、忽略大小写，**与某个可选动作完全一致**才换成那个动作，否则原样执行。**不在整段回答里搜索
  "最早出现的可选动作"**——那会执行模型自己否定过的命令，是动作修补（D3 里带记录器的组 41.0% 步骤靠它救回，对照组 13.2%，
  25/26 次成功用过它，dl:/data/feasibility/D3/critic-result.json:4 [审查 MA-M11]）。这一点改动了工作假设 A9（见第 16 节）。
  每步记录规范化方式，每组报告第 1 级规范化的比例。
- **有类型的说明 + 词表筛**：过程不能直接给模型写自由文字；它返回字段，壳用固定表头渲染（例如 "Facts extracted by a
  helper program (may be incomplete):"）。字段里出现登记词表中的答案格式指令（如 answer/respond/output/return/json/
  "only the"/"just the"/bare/"single letter"/round/"decimal places"/units/<answer/<action/```，SpreadsheetBench 另免
  "format" 一词）时，该字段被丢弃，并记一次**过程故障**（计入 2% 上限）。

### 2.3 路由器与壳（固定代码）

- 路由器每道题（ALFWorld 每局）开始时在隔离箱里把所有适用条件跑一遍，记启用日志。ALFWorld 的路由视图登记为
  `{initial_observation, admissible_commands_at_reset, task_text}`，由一次零调用的预先重置写进题目文件，做题时逐字节核对哈希
  [审查 EA-E11, MA-M15]；永远不给模型写的代码路径或题号。
- 一条过程的适用条件出错 = 这道题不启用它（记 `predicate_fault`）；过程本身出错 = 这道题从出错点起不带它继续做
  （"失败即放行"，记 `procedure_fault`）。两者都计入 2% 故障上限，**都不算基础设施故障**，不会让运行暂停（第 4.4 节的新表行）。
- 空程序包时，壳与冻结的 `backends.solve` 做零调用等价测试，比较两个**投影**：(a) 每个请求的哈希（系统提示 + 用户内容）；(b) 预测去掉
  本协议新加的 `shell` 键之后的其余部分。问答、表格：(a)(b) 100% 相同。**ALFWorld 例外**（Codex F23）：冻结循环执行从回答里抽出的原文
  （backends.py:752-762），本协议执行第 1 级规范化后的动作（2.2），回答一旦不是恰好合法的动作，后面的环境转移和请求都会不同；所以 ALFWorld
  只在每一步回答都恰好是合法动作（`how = tag_exact`）的局上比 (a)(b)，规范化另有单独测试，本路线的 ALFWorld 数字与 v3 不可比（第 16 节 C-A9）。
- 说明放在用户 JSON 的最后一个键 `procedure_notes`；系统提示（基础 + 格式句 + 任务卡）在 S'、S、P 各组逐字节相同。说明总长上限：
  问答/表格 4,000 字符，ALFWorld 每步 1,500 字符；超出时按包内顺序整条跳过（确定性，所有组同样处理）。

### 2.4 精确计算往返（A10）

1. 精确计算类过程用 `bindings` 抽出带名字的数值；壳渲染成固定说明并附登记原句："If you need arithmetic, you may write
   <calc>EXPRESSION</calc> tags (at most 8) using these names or plain numbers; they will be evaluated exactly and returned
   to you once."
2. 第一次回答里有合法 `<calc>` 标签时，壳用**固定的精确计算器**求值（分数算术；只许数字、名字、+ − × ÷、整数指数
   |e| ≤ 12、括号、abs/round/min/max/sum；嵌套 ≤ 20 层；任何中间结果分子或分母超过 4,096 位就判 `computation_failed:magnitude`；
   每个表达式 ≤ 300 字符），然后**最多多发一次**请求，用户内容 = 第一次的内容 + 第一次回答 + 计算结果 + 登记原句
   "The expressions above were evaluated exactly. Use these values if they are relevant and give your final answer in the
   required format."。
3. 计算失败时结果写 `"not evaluated"`（安慰剂组也一律写这个，见 6.3）；第二次回答送达且未截断就作为最终回答，否则退回第一次
   回答（记 `second_call_fallback`）；第一次回答已截断就不发第二次（按截断判错）。注意：工作假设 A10 写的是"计算失败就退回父回答"，
   本稿改成"计算失败时仍发第二次、结果写 not evaluated，只有第二次没送达或截断才退回"，理由是让真组与安慰剂组的调用规则相同；
   这是对 A10 的偏离，第 16 节 C-A10b 列出。
4. 两次调用的用量都记进这一格。这一格的判定（送达、截断、判分）只看**决定性回执**（实际作为最终回答的那次）；强制停止（预算、账本、
   假设破坏、清理）要扫描**全部**回执；两次里最差的送达状态**单独记录**（`worst_delivery`），按组报告，不改变这一格的判定。冻结的预检查
   只看最后一个回执（`preflight` 在 outcomes.py:207-228，经 `_delivery`（:256-263）读 `receipts[-1]`，:258），第二次没送达时会在新的判定包装层运行之前就把一个有效的第一次回答判成
   "未知"（cells.py:196 先调预检查），所以预检查复制进 `outcomes_ext` 改写（4.4 P5，Codex F12）。

### 2.5 表格题的试跑与修改往返

- 壳在第一次回答后，把抽出的程序在公开输入上试跑**一次**：用一个一次性容器，命令行和环境变量**逐字节复制冻结的
  `_native`**（pids 128、nofile 256、tmpfs 256m、OMP/OPENBLAS=1 等，backends.py:169-178），用一个复制的试跑脚本返回最后一行
  报错（≤ 500 字符）；结果存进格记录，重放时读回，不重跑 [审查 FA-F10, FA-F2, EA-E6]。
- 过程看了试跑报告可请求**一次**修改调用；修改调用带上原程序、壳自己的报错信息和过程给的有类型建议。修改回答送达、未截断且抽得出
  程序就用它，否则退回原程序（记 `second_call_fallback`；与 2.4 同一规则：送达但截断的修改回答也不用）。表格的"公开输入"以**只读挂载文件**交给隔离箱，绝不内嵌进协议消息（开发机实测 89 个训练工作簿：中位数
  10,238 字节，最大 599,328 字节，8 个超过 48 KiB [审查 EA-E1]）。
- 并发锁只在每次容器执行期间持有 native 锁，绝不跨越一次模型调用（冻结 cells.py:126-132 的 `on_reply` 抢锁在两次调用的格里会
  死锁，[SB G3; 审查 FA-F9, MA-M8]）；单元测试：3 个 native 锁、12 个工作线程，不死锁。

### 2.6 隔离箱（A3）

- 安全边界**只有容器**；语法检查和导入白名单只是卫生和确定性层（D6 的进程内运行器不是边界 [FP F33]）。
- 镜像：钉死的 native 镜像 `evolve-skill-native:smoke-20260928`（摘要 `0a0a5dcb…`，内有 sympy 1.13.3、pandas、numpy、openpyxl，
  实测 [LO F29-F30]），不新建镜像。
- 容器参数复制冻结 `_native` 的整套加固再收紧：`--network=none --read-only --user=65534:65534 --cap-drop=ALL
  --security-opt=no-new-privileges=true --pids-limit --memory=<M> --memory-swap=<M> --cpus --ipc=private --log-driver=none
  --ulimit nofile/core --name execskill-sbx-<uuid> --pull=never`，工作脚本以只读方式挂载并钉死哈希；启动 docker 命令的子进程
  环境只留 `PATH`（开发机交互 shell 会导出无关的 `OPENAI_API_KEY`，.bashrc:148-150 [LO F18]）；每个容器强制删除后只核对
  **它自己的那个名字**已不存在（冻结 `_native` 同样只核对自己的 uuid 名字，backends.py:158、:190）；整个 `execskill-sbx-` 前缀"一个不剩"
  只在单元排空（全部工作线程结束）后检查一次——六个工作线程本来就会同时存活，逐个关闭时查前缀会误报 `CleanupUnconfirmed`（Codex F14）。
- 生命周期：每格（问答/表格，只在有过程或安慰剂时）或每局（ALFWorld）一个容器，**用到才启动**；容器里**每次请求 fork 一个
  全新子进程**执行（每个（过程，题目）一个全新命名空间；隐藏状态不可能跨请求、跨题目留存；状态只能通过显式的 `state`
  参数由宿主保存）。子进程：把 0/1/2 号文件描述符重定向到 /dev/null，结果走专用管道；`RLIMIT_CPU`、`RLIMIT_AS`（数值由冒烟实测
  的常驻内存加余量确定）、`RLIMIT_FSIZE=0`（不能写文件）、墙钟上限按**每次请求**计（适用条件 2 秒、钩子 5 秒），父进程到时杀掉；
  `oom_score_adj` 调高，内存不够先杀子进程。
- 内存（遗漏 O12）：开发机 15 GiB、7 核。同时存活的隔离箱容器最多 6 个（一个专用名额池，容器活多久就占多久；ALFWorld 每个局锁一个）；
  SpreadsheetBench 单元最多 2 个存活隔离箱加 3 个 native 容器（每个上限 4 GiB），只有 S0 实测 native 峰值常驻内存 ≤ 2 GiB 时才允许，否则
  native 名额从 3 降到 2；SpreadsheetBench 与 ALFWorld 不同时跑。各容器内存上限之和的最坏情况：ALFWorld 单元约 10.5 GiB（含 6 个环境进程，
  每个按 ≤ 1 GiB 假设），问答单元 4.5 GiB，SpreadsheetBench 单元 13.5 GiB（附录 A 的 T8）。
- 确定性：工作进程用 `python -s -B -P`、`PYTHONHASHSEED=0`、线程数环境变量 = 1（`-I` 会忽略 PYTHONHASHSEED [审查 MA-M3, EA-E4]）；
  工程师检查阶段每个调用在**两个不同哈希种子的新工作进程、两种题目顺序**下各跑一次，结果哈希必须一致。
- 禁用名单（按名字禁，不只禁导入）：exec/eval/compile/open/input/`__import__`/getattr 系列/globals/vars/id/hash/print、任何双下划线属性、
  os/sys/subprocess/socket/time/random/pathlib/io/pickle/importlib/threading/ctypes 等模块，以及库里能偷偷执行代码、读写文件、取时钟或
  随机数的入口：`sympify`、`parse_expr`、`pandas.eval/query/read_*/to_*`、`numpy.load/save/fromfile/random`（只许
  `numpy.random.default_rng(seed)` 并显式给种子）、`openpyxl.load_workbook`（工作簿只能通过壳提供的固定读取函数拿到）、`Timestamp.now`、
  `datetime.now/today` [审查 FA-F5, EA-E3]。需要符号计算时用壳提供的固定 `safe_sympify`。
- 任何崩溃、超时、超内存、输出格式不对、超上限、协议错乱、工作进程死亡，都算**正在执行的那次请求所属过程的故障**；工作进程
  重启一次、不再加载出错的过程，继续做题 [审查 FA-F3, EA-E5]。只有"镜像不在、docker 起不来、容器删不掉"才是隔离箱不可用
  （`SandboxUnavailable`，暂停，负责人决定）。

## 5 一个 bench 上的一步（父包 S）：八个小步

每个小步是一个"单元"（复制的 `run_unit`：加锁、attempt-N 目录、只写一次的 `unit.json`）；暂停后不会自己恢复。

**5.1 跑题。** S 在跑题段上跑登记的次数，每格写完整轨迹（启用日志、每步视图、原始回答、规范化方式、说明、计算/修改往返、
全部回执、裁判结果）。若 S 里继承来的过程在本 bench 跑题段上启用 ≥ 10% 的题，任务卡组 C 也在跑题段上跑 1 次，作描述性
"入场读数"（S − C），不进任何决定 [审查 ME-F11]。基础设施未知 > 1/10 暂停。

**5.2 考官诊断（考官进化的前一半）。** 跑题段对半分成"写的一半"和"验的一半"（ALFWorld 按**房间**分，跑题段 16 个房间各半 8 个；其余 bench
按题；种子 `execskill-v1:detsplit:<unit>`）。固定的机械类别（零参考答案，单元测试，
不算考官进化）：问答 `no_answer_tag, json_answer_untagged, multiple_answers, truncated_or_suspected, empty_reply`；表格
`no_program, excel_formula_only, fence_glued, program_exception_on_public_input`；ALFWorld `step_budget_exhausted,
revisit_empty_receptacle≥3, repeated_action_loop, nothing_happens_share>0.2, inadmissible_share>0.2, level1_canonical_share`。
**定义残差时，机械类别只在检测器看到的同一份遮掩视图上计算**（ALFWorld：只在第 10 步前没结束的局上、只看前 10 步，所以 `step_budget_exhausted` 和按整局计的循环、
占比类计数不参与残差定义，只作描述性统计；问答、表格：答案内容与运行状态遮掉后仍能算出的类别）[一致性检查 C2]。考官只针对在这份
视图上**没被任何机械类别或已收检测器覆盖**的失败写新检测器（≤ 3 条，≤ 2 次调用）；候选写完先封存哈希，再碰验的一半；验收规则见 7.1。

**5.3 考官出题（考官进化的后一半）。** SearchQA 不出题（没有程序真值），只进化检测器。其余 bench 规则见 7.2。出题**必须先查证**（负责人定死的

本步按种子分成 G_self 用的一半和 G_acc 用的一半，封存哈希后才进入 5.4。出题程序的代码
在本步冻结；用于测预测效度的 G_acc 要等工程师写完以后，由登记员把**冻结的出题程序**用在验收段 A\* 的公开题面上生成，工程师
从来看不到 [审查 FE-F1, ME-F5]。

**5.4 工程师改过程（Skill 端进化）。** 一次提案（≤ 3 处改动），每处改动依次过固定检查，第一处失败给一次修改机会，再失败就丢掉：
- C1 解析；C2 语法与禁用名（2.6）；C3 大小与上限；

  [审查 FA-F12]），对照跑题段参考答案语料（`leakage.findings/mechanical`），命中交一次裁定调用，否决就丢；另加三条静态禁令：
  LiveMath 元选项（源码或输出里出现 `STRONGER_OPTION` 原句 "One of the remaining options is correct, but a stronger result can be
  proven." 的任何片段、或 "stronger result/statement" 字样、或按选项位置/字母规律作答的代码）[审查 EE-F1, FA-F13, ME-F1, MA-M20]；

- C5 隔离箱加载；C6 零崩溃：在本路线**已存的全部跑题轨迹**（本 bench 和前面的 bench）上，每个钩子在两个新工作进程里各跑一遍，
  无故障、结果一致；
- C7 回放测试（固定的性质种类，不许模型自己写判断函数；`return True` 式的空测试不可能）：每处改动 ≥ 1 个测试对应它声称修复的失败

  动作标成不建议、不许对已通过的表格题请求修改；ALFWorld 的状态类过程必须和固定的参考记录器（D3 的手写记录器，固定代码）在
  ≥ 97% 的步上一致；计算类过程的 `bindings` 必须逐字出现在题面里 [审查 FA-F6, MA-M12, EA-E9]。回放只证明"不崩、确定、做了它
  声称的事"，**不证明能修好**，报告里只作卫生项；
- C8 格式护栏没被碰：重渲染后系统提示哈希不变，回答通道不变；C9 说明字段过词表筛，超限即故障。
- 候选 S' = S + 存活的改动。没有存活的改动 → 本步结束，验收段不消耗。

**5.5 自测（不是验收，只查"会不会坏格式、会不会崩"）。** S' 与 S 在本 bench 的 G_self（≤ 60 道生成题 × 1 次）和前面各 bench 留下的

**5.6 验收。** 第 6 节。验收前把 S'、安慰剂（含供体语料的输出）、拿掉对照抽签、A\*、G_acc 全部封存。

|---|---|---|---|---|
| 新增过程 p | 验收段里 p 会启用的题 | 加上 p 的效果 | S' 拿掉 p（p 存在 vs 不存在） | S 加上 p 的替身 |
| 修订（旧 p → 新 p'） | 旧 p **或** 新 p' 会启用的题 | **替换**的效果（新换旧） | S' 拿掉 p'（新版本存在 vs 不存在；与"替换"不是同一个量） | S 里旧 p 换成 p' 的替身 |
| 撤掉过程 p | S 里 p 会启用的题 | **撤掉**的效果 | "恢复孪生格"：在随机一半启用题上给 S' 恢复 p | 父包里的 p 换成 p 的替身 |
| 缩小范围（p 不再用于 bench b） | b 上 p 原来会启用的题 | 缩小范围的效果 | 在随机一半上恢复原范围 | 同撤掉 |

- 一轮的 A\* = 各处改动的 A\* 的并集；路由在发送前用公开视图零调用算出。
- **只有一处改动、且它是"新增过程"时**，S' − S 在它的启用题上就是孪生格要估的量，可以不另跑孪生格；修订、撤掉、缩小范围的估计量不同，
  不能省（6.5）。

### 6.2 同时段交错

一轮里所有格（各组 × A\* 的题 × 次数，加拿掉对照、加 G_acc）放进一个种子顺序，一个线程池发送，绝不按组排序（cal-1/D1 的做法，
step.py:105-121）。替身的内容在派发前已从供体语料算好（6.1），所以没有任何格要等别的格的轨迹。为了让"需要隔离箱的组"和"不需要的组"不在时间上错开，ALFWorld 每局不管哪一组都先拿同一种局锁和隔离箱锁
（任务卡组跑一个空包工作进程）；每轮检查各组"开始发送时间"的中位数相差不超过本轮时长的 5%，超过则本轮"未定"[审查 ME-F28]。
每格记派发与完成时间；按组、按 15 分钟报告简短回答比例、答案格式比例、回答长度（同一文本的简短比例在 cal-1 里按 15 分钟从 5% 到
96% 变化，D11 实测 [FP F45]）。OfficeQA 两段时间、ALFWorld 4 块、SearchQA 4 块，块内交错，统计按块分层。

### 6.3 每道题的分数

每道题每组取各次 v2 完成口径的平均；候选组 S' 把"未知"和 `unknown_fault` 都算错，对照组把"未知"算对（v3 的保守约定，
stats.py:19-28 [CM F38]）；所有组都没送达的题退出所有对比（`shared_unanswered`）。

### 6.4 判据（交并检验，一批只决定一次）

**估计量、零假设与主检验（Codex F1）。** 估计量 = A\* 上的**平均配对差**：每道题先对各次取平均（所以每道题的差在 [−1, 1] 之间），再对题
取平均；零假设 = 平均差 ≤ 0。**主检验 = 单侧配对 t 检验**（对每道题的差）：有块时分层（各块平均按块大小加权，方差按块合并，自由度 = 题数 −
块数）；ALFWorld 做按房间"整组稳健"的 t 检验，即在**房间平均差**上做按局数加权的 t 检验（块由整房间组成，自由度 = 房间数 − 块数）。名义 5% 是
**大样本近似**：在"均值为零但分布偏斜"的零假设下实际误收概率会偏大，附录 A 的 T9 用精确枚举给出实测值（Codex 的例子"+0.25 占 80%、−1 占
20%"：|A\*| = 30 时 12.3%，41 时 6.6%，150 时 5.9%；平局多、偶尔大跌的分布：30 时 16.0%，150 时 8.1%；对称分布约 5%）。因此决策最小题数从 15
提到 **|A\*| ≥ 30**（ALFWorld 还要 ≥ 20 个房间，3.3）。sign-flip 置换检验（只在"差值正负对称"时严格；Codex 的例子在 15 道题时多收到 16.7%）和
Wilcoxon 符号秩检验（检验的是"差值关于 0 对称"而不是均值，偏斜时误收可到 40%–90%，T9）都作为**登记的敏感性分析**报告，**永远不决定**。

**收下 S' 当且仅当以下全部成立**（判据记作 J1–J7，J = "判据"）：
- **J1**：d = S' − S 在 A\* 上的单侧配对 t 检验 p ≤ 0.05（分层与按房间的做法如上），且折算到整批的平均差 ≥ 0.02（可行性试跑 D1 测到的最小值
  [FP F41]）；
- **J2**：e = S' − P_y 同样的检验 p ≤ 0.05（替身有害时按 6.1 的规则：决定只看对比 1，水平收紧到 2.5%）；
- **J3 故障**（Codex F22 的精确公式）：**故障题** = 验收段 A 里的一道题，只要在 S' 或 P_y 的任何一次运行里，任何一条变动过程出过至少一次故障
  （路由阶段的适用条件故障、执行阶段的过程故障、重执行的 `unknown_fault` 都算；同一道题多次故障只算 1 道；没发送的题只可能有路由故障）。
  故障比例 = 故障题数 / |A|（分母是整个验收段 A 而不只是 A\*，[审查 FA-F16]）≤ 2%。孪生格与 C、S 组的故障单独报告，不进这个比例。
  边界（附录 A 的 T10）：SB |A| = 60、OQ 50 → 最多 1 道故障题（2 道就不收）；ALF 150 → 3 道；LM 100 → 2 道；SQ 1,000 → 20 道；
- **J4 格式**：按**题**计数。一道题对某组算"格式违规"，当它在该组任何一次运行里违规（问答：没有可用的答案标签；LiveMath：不是单个字母；
  表格：没交出程序；ALFWorld：一局里可选动作占比 < 0.9）[审查 EA-E8, FA-F18]。要求：S' 的违规题数 ≤ S 的违规题数 + max(2, ⌈0.02 × |A\*|⌉)
  （全是整数比较，不再混用格数与百分点；|A\*| ≤ 100 时余量是 2 道，150 时 3 道，1,000 时 20 道，T10）；
- **J5 仪器**：每组基础设施未知 ≤ 10%（否则暂停）；重发后仍推理不一致 ≤ 1%（否则暂停）；共同未答 ≤ A\* 的 10%；开始时间平衡（6.2）；
- **J6 重复组**：每个登记的"同文本重复对"（第一步：S 与 C 逐字节相同；有出题程序的 bench 的后续步骤：S 与重复组 S_dup，7.2）双侧 t 检验
  p < 0.01 → 暂停（交错或确定性坏了），不出决定；
- **J7 LiveMath 专用**（只在正式链；两个试点都没有 LiveMath 步）：决策只在**没有元选项的题**上算；另在含元选项的题上跑一次"遮住题干
  只给选项"的探针（S' 与 C，各 1 次）：若 S' 的遮题准确率比 C 高 ≥ 10 分且单侧 p < 0.05，判"走捷径"，不收。**探针题的来源（遗漏 O7）**：
  129 道含元选项题按固定顺序切成两半，前 65 道进跑题段，后 64 道是 J7 探针集，由验收单元登记消耗（用途 `accept_probe`），绝不复用跑题段
  已消耗的题（复用会触发 `ConsumptionConflict`）；具体数字在正式链增补登记里定。

两个对比都要成立是交并检验，不需要多重校正；误收概率**在登记的模型下每个对比约 5%（大样本近似）**，整个交并检验不超过两个对比里较大的
那个；偏斜零假设下的实测值见附录 A 的 T9（|A\*| = 30 时最高约 16%）。C 只描述（S' − C、S − C，双侧 95% 区间）。
整条链 5–9 个决定、每个名义 5%，全局零效应下至少误收一次的概率约 0.23–0.37（= 1 − 0.95^k，k = 5–9；估计，决定之间独立，附录 A 的 T9；偏斜时更高）；报告写明决定个数。
验收决定是**选择证据**；独立的泛化证据只来自测试读取（8.1、8.2）。

### 6.5 随机拿掉对照（A11，因果归因）

- 对每条变动过程 p（启用题数 |F_p| ≥ 10）：在它启用的题里按种子随机选一半 W_p，加跑一个孪生格（同样次数、同一顺序里交错）。孪生格按 6.1 的
  改动类型表定义：新增、修订 → "S' 拿掉 p"（p 存在 vs 不存在；修订时这**不是** S' − S 估计的"替换"效果）；撤掉、缩小范围 → "恢复孪生格"（在
  W_p 上给 S' 恢复 p）。τ_p = W_p 上 [带 p − 不带 p] 的平均，自助法 95% 区间。因为是在启用的题里随机拿掉，τ_p 是"p 在它会启用的题上的因果效果"
  （FlowEvo 的配对撤除 [RW §2]）。只有一处改动且它是"新增过程"时，S' − S 在它启用的题上就是这个效果，不另跑；其余类型不能省 [Codex F6]。
- **最大工作量（Codex F18）**：每道题最多 2 个孪生格；超过时按优先顺序取：先本步的变动过程，再按启用题数从多到少取继承来的过程；没轮上的
  记"本题未拿掉"，τ 只在拿掉了的题上算。
- **继承来的过程**（来自前面的 bench）在本 bench 验收段启用 ≥ 15 道时，同样拿掉一半，得到"前向迁移"的因果估计，**不碰测试集**
  [审查 ME-F11]。
- τ 永远不进决定、不用来剪枝、不给任何角色看。单条过程在 25/50/100/200 道启用题上只认得出约 19/14/10/7 分（估计 [spec-measurement §7.3]），
  多数会写"无法分辨"。
- **孪生格的规模与费用（单列，遗漏 O2）**：验收里每条启用题 ≥ 10 的变动过程拿掉一半启用题（预期按每道 A\* 题 0.75 个孪生格（SB、OQ）、
  0.5 个（ALF））；做题费用预期 SB 约 0.17–0.62M、OQ 约 0.59–1.9M、ALF 约 2.4–5.4M；登记的最大工作量（每题 2 个）是 SB 1.64M、OQ 5.07M、
  ALF 21.6M，上限按最大工作量定（9.3）。最后测试读取里每题最多 2 条（同样的优先顺序；预期每道启用题 0.5–1.0 个孪生格）：默认试点约
  0.8–11.0M、建议试点约 2.2–14.6M（估计，附录 A 的 T4、T5）。这些已含在第 9.2 节的合计里。

### 7.1 失败检测器（A7）

- 检测器是一个只读轨迹的判断程序，**看不到参考答案，也看不到直接决定对错的字段**：问答与表格看题面和回答，但最终答案标签里的内容、
  程序在公开输入上的运行状态被遮掉 [审查 FE-F2, FA-F7, ME-F13, MA-M13, EE-F9, EA-E10]。（ALFWorld 失败局全部跑满 50 步，124/124 [FP]；
  早停只在赢或结束时发生，backends.py:768-770；所以"步数 = 50"一条就能"完美"预测失败。）
- **ALFWorld 改成"路标"预测（Codex F10）**：只给"前 10 步"仍会泄漏——前缀长度 `min(T, 10)` 本身就告诉检测器这局是否在 10 步内结束。登记：
  检测器任务 = 在**第 10 步执行前仍在进行的局**里预测最后成败；视图**固定长度**：前 10 步的（观察、动作）对，去掉一切终局观察和 `won`/`done`
  标记（第 10 步之后的观察不给）。10 步以内就结束的局**不进**检测器的验收，按结局（赢 / 结束未赢 / 基础设施）单独计数报告；基础设施截断
  （"未知"）的局也排除。单元测试：短的成功局（T ≤ 10）永远进不了视图；在视图里搜终局文字（如 "You won"）一无所获；"步数 = 50"式检测器
  看不到步数，收不下。
- 在验的一半上，**只在残差格上算**：残差格 = 在检测器看到的**同一份遮掩视图**上，没有任何机械类别、也没有已收检测器报警的格（ALFWorld：
  机械类别也只在上述合格局的前 10 步上算，所以"走满 50 步"不会把失败局排除出残差；草案按整局算，会让残差里一个失败局都不剩，任何 ALFWorld
  检测器都按构造收不下 [一致性检查 C2]）。单元测试：所有失败局都走满 50 步时，一个只看前 10 步、真有区分力的检测器仍然可以被收下。
- **切分、重抽与多重性（Codex F11）**：写/验两半 ALFWorld 按**房间**切（同一房间的局不会分到两边），每半至少 8 个房间，否则直接"无法判定"；
  其余 bench 按题切。考官写的候选检测器（每步 ≤ 3 条）在碰验的一半之前**先封存哈希**。收下当且仅当：报警 ≥ 10 格且来自 ≥ 6 道题（ALFWorld
  还要来自 ≥ 4 个房间）；按题（ALFWorld：按房间）整组自助，零假设"查准率 − 残差格基础失败率 ≤ 0.10"的单侧自助 p 值经 **Holm 校正**（同一步
  的 m ≤ 3 条候选，族水平 10%：第 j 小的 p 与 0.10/(m − j + 1) 比较）后成立；残差失败里的查全率 ≥ 0.15；和已有检测器的报警集合重合度（Jaccard）
  在**整个**遮掩后的验的一半上、去残差**之前**算（在残差上算的话，和已收检测器的重合按构造为 0），要求 < 0.8；无故障、两次运行一致。
  模型写的标签永远不当证据。
- 题量太小时直接写"无法判定"：SpreadsheetBench、OfficeQA 在试点大小下验的一半只有 12–16 道题，几乎不可能达到下界（[spec-measurement K6]）。
  ALFWorld（建议方案）验的一半约 30 局、8 个房间，其中只有第 10 步时还在进行的局可用，按房间整组重抽的下界很宽，机会不大（估计）。
- 收下的检测器按 bench 留存；在同一 bench 后续步的验的一半上连续两次不达标就撤掉。

  - **只写一次的存档**：每份检索结果、每个页面正文按哈希命名、在用之前写进单元目录（research.py:395-407；`write_json` 即只写一次的
    `write_immutable_json`，skillopt/continual_eval/core.py:60-61）。
  - **引文逐字核对**：引文在空白规范化后必须逐字出现在它所指页面的存档正文里，否则这条发现作废、请求继续（research.py:19-20、:342-346、:510-531）。
  - **查证员永远看不到题目**：请求只含查证问题与素材要求，发出前用固定代码做泄漏检查（research.py:20-22）。
  - **两种新请求**（v3 只有"验证规则"和"前向素材"两类，:65-66）：`family_material`（某个变换族的素材）和 `parameter_choice`（某个族的参数取值：结论里的
    每个取值都要有逐字引文支撑，超出该族登记范围的取值丢掉）。每步每 bench 最多 24 个查证请求（附录 A 的 T11），每条合格发现最多派生 10 道题；
    合格发现按种子 `execskill-v1:research-split:<unit>` 分成 G_self 一半、G_acc 一半，素材互不重叠，在工程师动手之前封存哈希。
  - **各族怎么用查证**：OfficeQA——查证找到的公开数值表就是固定题型模板的表；LiveMath——查证到的一条定义或定理实例化带参数的题型模板；
    SpreadsheetBench——公式定义的改动只许用查证过的 LibreOffice Calc 函数（引文出自钉死的帮助页存档）；ALFWorld——查证（已知的失败模式）只能用来
    写挑选条件，结果只报"挑选效度"；SearchQA 不出题、不为出题查证。查证没找到合格素材时，该族本轮不出题，记 `no_material`（不是失败，也不让考官补）。
  - **为什么真值仍由固定代码算、不让查证员或考官自己算**：v3 的前向题由模型在查证素材上自己写题、自己算答案，结果 v3 冒烟 9 道里只有 4 道合格（5 轮
    里 2 轮没找到素材，5 道算术前后不一致被丢掉，留下的 4 道也很平凡、和规则无关），v1、v2 冒烟分别是 12 道里 9 道、10 道合格；v3 正式运行一个前向题
    集都没建成（[CM F36、F37]，design/coevo5-method.md:262-277、:867-869）。所以本协议让查证只给素材和参数，真值交给下面各族的固定参考函数。
- **只许用登记员定义的"变换族"，每个族的真值由固定的参考函数或模拟器给出（Codex F8）**；考官写的程序只**挑单元格和参数**，不写答案、
  不写真值表达式 [审查 MA-M14]。上一版可能"按构造合格"：复现一个 OfficeQA 原答案，不能证明扰动后的算式仍对；精确求值考官给的 LiveMath
  表达式，不能证明它回答了生成的题；表格资格检查把参考工作簿当作预测、拿它和自己比（qualify.py:38-41、:101-102），只证明判分引擎能读。
  - OfficeQA 族：表格**来自查证**（英文维基百科页面里合格的公开数值表：2–60 行、2–15 列、至少一个数值格，research.py:59、:328-334），套进固定
    题型模板（两格之差、两格之比、百分比变化、若干具名表格单元之和），答案由固定代码从**（可能经扰动的）单元格**算出（精确计算器，
    写明舍入）；考官只挑单元格与扰动幅度；被扰动的数字必须逐字出现在改后的表格里，答案不许直接出现在题面里（D6 有 2/7 题把答案写进了题面
    [FP F30]）；
  - LiveMath 族：带参数的题型模板，模板的数学内容来自查证到的一条**逐字核对过**的维基百科定义或定理（≤ 1,500 字符，research.py:58）；固定检查器在隔离箱里**独立地解出**生成的这道题（sympy，按题目结构求解，50 位精度），考官只给参数，不给
    答案；恰好一个选项等于解出的值，解不出的丢掉；正确选项的字母按题号轮换（每个字母 20% ± 5%）；**不许出现元选项**；
  - SpreadsheetBench 族：用**公式定义**的单元格改动，公式里每个函数都要有一条合格的查证发现（引文逐字出自开跑前钉死的 LibreOffice Calc 帮助页存档）；期望的单元格值由 recalc 引擎按公式重算（这是语义真值），**然后**再单独做两次 v7 判分的
    资格检查（这只是引擎检查，零模型调用 [SF F24]）；字面值答案没有参考变换就不能跟着改，这类改动不收 [SF R5]；
  - ALFWorld：没有环境生成器，只能从没用过的现成局里**挑选** [SF R9]；查证（已知的失败模式）只能用来写挑选条件。这一类单独报告为"挑选效度"：同样大小的一组按种子随机挑的局作
    零模型对照，要求挑出的局在目标特征（例如目标物位置类型、需要打开的容器数）上确实偏移；**不计入考官一侧的主张** [审查 FA-F8, FE-F2]；
  - SearchQA，以及建设时没有可用变换族的任何 bench：只做"挑选 / 改写"，**不产生生成题真值**。
- 语义真值（上面的参考函数）与判分 / 引擎资格（冻结判分能不能读这道题）分开记录，任何一个不过就丢。
- 四道关：**真值**（固定参考函数或模拟器算出）；**难度带**（父包在 30 道探针题上 1 次的通过率在 20%–80% 之间；最多改两次参数，所以最多
  3 轮探针，已计入 9.2 的最大工作量）；
  **捷径**（LiveMath 遮题干只给选项、OfficeQA 去掉表格只给问题、表格题去掉工作簿，2 次都答对的题丢掉；一个题集里被丢比例 > 25% 就整套不用）；
  **标签规律**（只许用题目自身内容和程序真值，不许利用训练标签的规律）。四关都过叫"准入"，只是工程，不算进化。
- **预测效度**（考官的主打指标，但**不是门**；Codex F9 后重写）：
  - G_acc = 冻结的出题程序在验收段 A\* 的公开题面上生成（每道 A\* 题 1 道，大小见 3.3；工程师没见过，[审查 FE-F1]），在验收那一轮里由
    **S'、S、P_y、C 四组**各做一遍（1 次），与真题交错；
  - **证据单位 = 一轮验收**，每轮只取**一对**数：(d_gen, d_real) = S' − S 在生成题上与在真题上的差。同一轮里的几个对比共用结果、彼此有恒等式
    （例如 S′−P_y = (S′−S) − (P_y−S)），不能当成几个独立证据；P_y − S 也不是"已知为零"（替身可以有用或有害，6.1），不再当阴性对照。每轮报告
    d_gen 与 d_real 的轮内协方差（同一批 A\* 题配对出来的）；
  - **阴性对照 = 登记的"重复组"**：两组完全相同的包，在生成题和真题上都应为零。第一步 S 与 C 逐字节相同，免费；有出题程序的 bench 在后续步骤
    里加一组 S_dup（与 S 同一个包、同一交错顺序，A\* 与 G_acc 上都跑），每个 bench 跑一次（OfficeQA 第二步约多 1.0–3.2M 做题，附录 A 的 T4）；
    ALFWorld、SearchQA 没有出题程序，不加；
  - **检验**（同一个出题程序累计 ≥ 8 轮之后才做）：跨轮的 Spearman 等级相关（d_gen 对 d_real）与符号一致率，单侧置换检验（在轮之间打乱 d_gen，
    10,000 次，seed 20261021）；
  - **状态互斥，优先顺序 被否定 > 成立 > 无法评估**：(1) 被否定：≥ 8 轮，且 [≥ 2 轮里 |d_gen − d_real| 超过 2 个合并标准误（合并标准误计入轮内
    协方差：√(se_gen² + se_real² − 2·cov)），或重复组在生成题上的差的 95% 区间不含 0]；(2) 成立：≥ 8 轮、没有被否定、Spearman 相关 > 0 且置换
    p < 0.05、重复组在两边的 95% 区间都含 0；(3) 其余一律"无法评估"。不足 8 轮时不论分歧多大都只写"无法评估"[一致性检查 C12]；
  - **事先写明**：试点每个 bench 只有一轮，**预测效度"无法评估"**；正式链若每个 bench 也只访问一次，同一个出题程序永远凑不满 8 轮，同样
    "无法评估"（第 13、20 节如实披露）；
  - 用途：只有"效度成立"的出题程序，其题集才可以在**以后的步骤**里当筛子用。试点里不会发生。
- **考官怎样"进化"、怎样报告（负责人 22:3x 规则 (b)）。** 考官的进化有两条路：(i) 检测器（7.1）；(ii) 经查证的出题规格（每步可以换族参数、
  换查证请求、换素材）。报告"考官这一步进化了什么"时，每 bench 每步固定列出查证路径：查证请求数（按种类）、合格发现数与没找到的原因（找不到页面、
  轮数或调用用完、引文不逐字等）、每个族生成与准入的题数（真值、难度带、捷径、标签四道关各丢多少）、`no_material` 的族、G_self 与 G_acc 的大小、
  预测效度状态（成立 / 被否定 / 无法评估）。这些计数是**过程记录**，不是效果证据。
- 考官"进化成功"只有两种：按 7.1 收下的检测器；"效度成立"的出题程序。都没有就照实写"考官一侧没有进化成功"。

## 8 读测试集与迁移读数（事先定死）

### 8.1 一次多组读取（A12）

- 试点只在**最后读一次**，五个测试集都读，**每道测试题每组跑 1 次**（遗漏 O3）。组：F（最终包）、C（只有任务卡）、P_F（F 里每条过程都换成配对替身，
  供体 = 各 bench 跑题段的父包轨迹）、T_F（**文字对照**：每条过程换成冻结时写好的文字说明，**只在它的适用条件成立的题上、放在同一个位置、长度在原说明的
  ±20% 内**显示，不执行任何过程代码；各钩子的具体做法见下表 [审查 FE-F10, ME-F8; Codex F20]）、拿掉对照 F∖p（每条启用的过程在它启用的题里随机
  拿掉一半，每题最多 2 条，按 6.5 的优先顺序）。

  **文字对照组 T_F 按钩子的做法（Codex F20）**——文字说明由 5.7 的钉死提示词在冻结时写好：

  | 钩子 | T_F 显示什么 | 调用规则 |
  |---|---|---|
  | `before_call`（说明类） | 在过程说明出现的同一位置显示文字说明（±20% 长度；原说明各题长短不一时按该过程在跑题段的中位长度） | 一次调用，与 F 相同 |
  | `bindings`（精确计算类） | 文字说明 + 同一句 `<calc>` 邀请原句，**不给**任何抽出或算出的数值 | 同一触发规则：模型写了 `<calc>` 就按 2.4 发第二次（壳的固定计算器只算纯数字表达式；没有名字可用） |

  | 过程在某题上没输出 | T_F 在该题也不显示 | — |

  所以 F − T_F 估计的是**这两种实现方式之差**；两组给模型的动态信息与调用机会不同，它不是"执行本身"的纯效果（8.2）。
- **结构性零共享**：一道测试题上如果 F 的请求和 C 逐字节相同（没有过程启用），F、P_F、T_F、拿掉对照都直接共用 C 那一格（同一请求，
  可交换），不另发；这既不偏，又省钱 [审查 EE-F4]。

  输出去不掉这些文件。所以评测走专用的持久化适配层：测试格的正式记录**只存**请求与回答的哈希、裁判结果、判分 token 与格式标记；原始预测与回执
  只放在该 attempt 目录里的**临时重放区**，判分（含重执行）完成后删除并记下删除清单的哈希，永不进入封存记录；封存之前，用登记的测试内容
  "金丝雀"（每个测试集固定抽几段原文，只存其哈希片段）在该单元的**每个**产物里搜索，命中即暂停。

  解封试点测试分数。只冻结"继续/停止"一个字不够：解封后看到的分数仍可能影响后面的题量、实现、过程或报告方式。按这个顺序做时，正式链最后一次读取

### 8.2 读数（固定顺序）

记学过的 bench 集合为 L（试点的两个）。相似关系表沿用负责人 10/17 确认的（coevo5-registration-v6 §1.1）：SearchQA–OfficeQA、
OfficeQA–LiveMath、OfficeQA–SpreadsheetBench；ALFWorld 与谁都不相似。
- **Q1 本 bench**：L 中每个 bench 上 F − C，单侧配对 t 检验（6.4 的主检验；sign-flip 与 Wilcoxon 作敏感性），对 |L| = 2 做 Holm 校正。
- **Q2 相似 bench**：只描述（估计值、95% 区间、每条过程的 τ、启用率）。测试集每题 1 次时 OfficeQA 只能分辨约 6.6–7.7 分、LiveMath 约
  10–11 分 [DP F17]，"相似也涨"认证不了。
- **Q3 不相似 bench，合并不劣检验**：不相似 bench 上 F − C 的等权平均，单侧 95% 下界 > −5 分（负责人 10/17 说的"约 4–5 分"，不按把握倒推
  放宽 [审查 ME-F7]）。事先告知：默认试点下不相似的只有 ALFWorld，真实差为 0 时这个检验通过的把握约 0.37（估计），所以很可能写
  "不劣没有确立"；同时报告实际下界。若过程在不相似 bench 上启用的题 < 10%，报告"按构造不起作用（启用 x%）"，不当成"不劣成立"。
  缺失数据按 v6 §12.6 的方向规则（有利结论要在完整个案和不利填补两种口径下都成立）。
- **代码 vs 文字（事先写明的风险；Codex F20）**：每个 bench 报 F − T_F（双侧 95% 区间）；估计量是"这两种实现方式之差"（8.1 的按钩子表），不是
  "执行本身"的纯效果。事先预期：代码形式的过程主要在本 bench 有用；表格数字簇之外的迁移约为零（Break It Down：代码技能跨任务迁移比文字差；GRASP：
  验收门只提高同分布成绩 [RW §2]）。读法只看区间、不看点估计：95% 下界 > 0 → "代码实现优于文字实现"；95% 上界 < 0 → "文字实现优于代码实现"；
  在非本 bench 上 F − T_F 的单侧 95% 下界 > −5 分（与 Q3 同一个界）→ "代码实现的迁移不比文字差"，单侧 95% 上界 < +5 分 → "文字实现的迁移不比
  代码差"；其余一律"无法分辨"。
- **每条过程的标签**（只用于报告；对"过程 × bench"整个家族做 Holm 校正 [审查 FE-F6, ME-F10, EE-F7]；Codex F21 后改成**按优先顺序取一个主标签**，
  其余成立的描述照样列出，描述之间不互相排斥）：

  | 优先 | 主标签 | 条件（τ 的区间都是 Holm 校正后的） |
  |---|---|---|
  | 1 | "在别处有害" | 任一非本 bench 上 τ 上界 < 0 |
  | 2 | "通用" | 至少一个非本 bench 上 τ 下界 > 0，且其余每个它会启用的 bench 上不劣（下界 > −5 分） |
  | 3 | "只在本 bench 确立了益处" | 本 bench 上 τ 下界 > 0；别处的效果仍不确定（**不**写"在别处没有迁移"：不显著不等于没有） |
  | 4 | "按构造不能在别处起作用" | 在所有非本 bench 上启用率 < 5%（只描述"没机会起作用"，不描述效果） |
  | 5 | "没有可测的效果" | 以上都不成立 |

  启用率只用于第 4 行这个"有没有机会"的描述，永远不单独决定效果。
  另报每条过程在各 bench 上对格式标记的拿掉对照（它是否改变了答案格式）。

### 8.3 每个准确率旁边都要报的东西

每组每 bench：v2 完成口径（主读数）、官方、官方完成口径、宽松分；各类"未知"计数；截断、`over_nominal`、推理不一致；格式标记（标签有无、
标签数、JSON 答案、boxed、单个字母、末行兜底、交出程序、只有公式、代码块粘连、可选动作占比、第 1 级规范化占比）；过程故障；启用率；
每 15 分钟的简短回答比例。绝对准确率一律标"本时段"。

## 17 术语表（给负责人）

- **过程**：工程师写的一小段程序；壳在做题前后运行它，做三类事之一：加一段整理好的信息、抽数字并替模型精确计算、把动作标成不建议。
- **适用条件**：每条过程自带的判断程序，只读题目公开内容，决定这道题启不启用它。
- **路由器**：固定代码，每道题开始时跑一遍所有适用条件，记"启用日志"。
- **壳**：包在做题模型外面的固定代码；运行过程，但改不了模型的最终回答。
- **程序包 / Skill**：过程的有序集合；S = 父包（上一步传下来的），S' = 候选包，F = 试点结束时的最终包。
- **任务卡**：每个 bench 一段冻结的作答说明（v3 I-ds 起点用的五份 GLM 写的指令），只给当前 bench 那张。C 组 = 只有任务卡。
- **格式护栏**：每个 bench 固定的一句"答案写在哪里"的要求，所有组相同，不学。
- **动作规范化（第 1 级）**：把 "action: go to X" 这类写法对齐到完全相同的合法动作；不做其他猜测。
- **安慰剂 P_y / P_i、供体语料**：P_y 把过程的内容换成它在"供体"上的输出（供体 = 父包在跑题段的轨迹，派发前零调用算好并封存；同类但对这题
  没用）；P_i 换成无关文字。用来排除"随便多一段内容就涨分"；替身有害时这个解释排除不了，只报"胜过父版本"。
- **拿掉对照（孪生格）**：同一道题、同一时段，再做一遍拿掉某条过程的版本；两者之差是这条过程的因果效果。
- **A\***：验收段里"至少有一条变动过程会启用"的题；只在这些题上决策，其余题不发送、不消耗；少于 30 道（ALFWorld 少于 20 个房间）时这一轮不跑。
- **结构性零共享**：两组发出的请求逐字节相同的题，只做一格、两组共用。
- **消耗账**：只能追加的记录；每道题第一次发送前写入，写过的不再用。
- **同时段交错**：几组的所有题放在一个随机顺序里一起发，消除时段差异。
- **MDE（最小可检测效应）**：在登记题量下有 80% 把握认出的最小提高（百分点）；比它小的认不出，不等于没有。
- **交并检验（IUT）**：两个比较都要过才收；每个用 5% 门槛，整体误收不超过两个比较里较大的那个（名义各约 5%，偏斜时实测见附录 A 的 T9）。
- **配对 t 检验**：用每道题组间差的平均与标准误判断平均差是否大于 0；本协议的主检验。名义 5% 是大样本近似，"均值为零但分布偏斜"时实测会多收
  （附录 A 的 T9）。
- **sign-flip 置换检验**：把每道题的组间差随机翻正负号很多次，看实际平均差有多极端。它只在"每道题的差正负对称"的假设下严格；均值为零但分布
  偏斜时会多收（Codex 的例子：15 道题时 16.7%），所以本协议只把它当敏感性分析。
- **Wilcoxon 符号秩检验**：按差值大小排秩的检验；它检验的是"差值关于 0 对称"，不是"均值为 0"，偏斜时可能严重多收，只作敏感性分析。
- **不劣检验**：问"是不是没有比对照差超过 5 分"。
- **Holm 校正**：同时做很多个检验时，按从严到松的顺序调整门槛，控制"至少错一次"的概率。
- **检测器 / 机械类别 / 残差格**：检测器是考官写的、读作答记录判断"属于哪类失败"的程序；机械类别是固定代码的类别（如"没有答案标签"）；残差格是
  没有任何机械类别和已收检测器报警的格，新检测器只在这些格上算查准率和查全率。
- **查准率 / 查全率 / Jaccard**：报警里真失败的比例；真失败里被报警的比例；两个检测器报警集合的重合度。
- **出题程序 / 准入 / 难度带 / 捷径检查**：考官写的程序给出"改题方案"，固定代码算出真值；四关都过叫准入；父包通过率在 20%–80% 之间叫在难度带里；
  遮住题干或表格也能答对的题被剔除。
- **预测效度 / 阴性对照 / 重复组 S_dup**：生成题上"新包比旧包好多少"是否和真题一致，以一轮验收为一个证据单位，≥ 8 轮才检验；阴性对照是两组
  完全相同的包（第一步的 S 对 C；之后加的重复组 S_dup），两边都应为零，用来检查方法本身不出假信号。
- **变换族**：登记员事先定义的改题方式（如"两格之差"），真值由固定代码从改后的数据算出；考官只挑单元格和参数。
- **评分器 v2 / 完成口径**：官方载体（答案标签、程序、动作）可用时只用它；只有它不可用时才看 JSON 写出的答案，所以多写一种格式不会多一次猜的
  机会；只会把官方判错改判对；截断、空回答、格式无效都算错。
- **决定性回执 / worst_delivery**：一格有两次调用时，实际作为最终回答的那次叫决定性回执，这一格的判定只看它；两次里最差的送达状态另记为
  worst_delivery，只报告。
- **选择证据 / 独立的泛化证据**：验收决定说明"这个版本在一批没用过的训练题上胜过父版本"（选择证据）；只有测试读取才是独立的泛化证据。"没有可复用的
  验证集"指每批验收题只用一次，不是说没有用来挑选的题（负责人决定 #31）。
- **最大工作量**：登记允许的最多格数（每步 ≤ 3 处改动、每题 ≤ 2 个孪生格、难度带 3 轮、自测 2 遍等）；各级上限按它算（9.2、9.3）。
- **路标视图（ALFWorld 检测器）**：只用第 10 步前仍在进行的局，给固定长度的前 10 步，去掉终局信息（7.1）。
- **正式链增补登记**：试点之后整条链的补充登记（顺序、题量、允许的调整、上限）；要在解封试点测试分数之前写好（负责人决定 #32）。
- **推理 token**：模型正式回答前"想"的部分；本协议关掉，每次回执核对为 0。
- **账本、预留、B、M**：每次调用前按上界预扣 token；M 是请求里写的长度上限，B 是账本按来预留的上限；回答超过 B 会让账本全局停止。
- **隔离箱 / 容器 / 子进程**：运行模型写的代码的封闭环境；不联网、只读、无特权；每次请求一个新子进程。
- **elucid**：新做题接口在代码里的名字。**GLM-5.3**：扮演工程师、考官与查证员的模型；也是链 G 的做题模型。
- **链 G / 链 D**：负责人 22:3x 规定的两条并行正式链；链 G 的做题模型是 GLM-5.3（冻结 BigModel 通道），链 D 的是 deepseek-v4.1-flash-1017（elucid）；
  各自的账本作用域、上限、消耗账，同一批题（3.4、4.1、11）。
- **查证（research）/ 查证员 / 合格发现**：查证 = 到固定的公开资料（英文维基百科接口、钉死哈希的文档存档）里找依据；查证员 = 扮演这件事的 GLM-5.3；
  合格发现 = 带逐字核对过的引文的结论。考官出题必须先查证，查证只给素材与参数，真值由固定代码算（7.2）。
- **`family_material` / `parameter_choice` / `no_material`**：两种新查证请求（某个族的素材、某个族的参数取值）；查证没找到合格素材时该族本轮不出题，记 `no_material`。
- **单元、attempt、暂停、重做**：每个小步是一个单元；暂停后由负责人决定终止或在新 attempt 目录里重做。
- **SB / OQ / LM / SQ / ALF**：SpreadsheetBench / OfficeQA / LiveMath / SearchQA / ALFWorld。**v3**：上一版协议 `fivebench-coevolution-v3`，结果冻结。
