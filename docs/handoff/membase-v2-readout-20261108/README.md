1. **只发记忆内容，比什么都不加强很多，集中在三处。** SearchQA 两条链三种记忆都显著，+7.8 到 +21.0 个点；OfficeQA 上 G 链三种都显著，+19.8 到 +23.3，D 链 M_knn +14.5、M_expel +6.4 显著，T_dc 不显著；D 链 ALFWorld 三种都显著，+29.1 到 +40.3。

## 限制

- 跨运行参考是两次不同的运行，v1 在 11/06、v2 在 11/07 到 11/08，不配对，中间可能有服务漂移，只能描述，不能算差值的区间。
- 跨运行参考里 v1 的数字取自旧的合并读数 `/data/membase-20261106-ops/report-20261106/readout.json`（sha256 前缀 `62c07d40`）。这份旧报告里没有运行根的身份，它和 v1 运行根 `/data/execskill-20261106-membase-v1` 的对应是按操作员声明写的，没有独立核实；哈希只证明报告文件本身没变。
- 记忆是在带任务卡的练习过程里建的，所以“只发记忆”不等于“完全没有任务卡的影响”。
- 同文本波动用 v2.24 同一批面板测到的值：G 链 SearchQA ±1.7、OfficeQA ±6.3、ZebraLogic ±8.2、表格题 ±7.2、ALFWorld ±4.4；D 链 ±1.8、±3.9、±5.1、±5.6、±5.3。它是同一段文字重跑时差值的 95% 波动幅度，不是上限：v2.24 里 G 链 OfficeQA 同一段技能重读就出现过 −6.4 [−12.7, −0.1] 和 +6.4 [+0.8, +12.0]。这次每格只读了一次，单格超过它只是必要条件；离它最近的是 G 链 ZebraLogic T_dc（+10.5 对 ±8.2）和 D 链 OfficeQA M_expel（+6.4 对 ±3.9，换一种算法区间下限正好是 0），要在多次读数里重复出现才算可靠。
- 表格题 G 链 v1 只有任务卡是 72.5%，v2.24 同一面板的任务卡是 66.7%，同一张卡两次运行差 5.9 个点，还在 ±7.2 的同文本波动以内；ZebraLogic 上同样的请求两次运行也差到 8.0 个点。跨运行的差距不超过同文本波动时都不能当证据，表格题和 ZebraLogic 的波动最大，这两处的跨运行比较最不可靠。
