# Evolve-Skill 阶段汇报（9/28–10/16）

## 问题

能否让模型从做题经验中自己改进 Skill（附在系统提示后的一段文字指南），做到跨数据集泛化，并且不依赖验证集。

## 设置

- **做题模型**：GLM-5.3，deepseek-v4-flash 复现。
- **数据集**：SearchQA、OfficeQA、LiveMath、SpreadsheetBench、ALFWorld。10/13 之前用 BigCodeBench、KOR-Bench，后被 OfficeQA、LiveMath 替换。
- **对照**：
  - 空 Skill；
  - 任务说明指令：模型只读公开的任务说明，一次写成，不看任何做题结果；
  - SkillOpt、GEPA：已有方法，用验证集挑选修改。

## 主要结果

1. **已有方法只在一个数据集上有效。**
   - SkillOpt、GEPA 在五个测试集上只提升了 SearchQA：291 → 338/400（+12 点）。
   - 其余四个数据集的变化都在噪声内。
   - 我们的主方法（评分细则诊断失败原因，不看答案）在 SearchQA 测试集上 341/400，和基线的 347/400 没有检出差异。

2. **一份任务说明指令就拿走了几乎全部增益。** SearchQA 975 道新题上的正确率：

   | Skill | 正确率 |
   |---|---|
   | 空 | 0.70 |
   | 任务说明指令 | 0.83 |
   | 从经验学到的 | 0.82–0.84 |
   | SkillOpt（用验证集） | 0.84 |

   - 在指令之上再学一步：+0.1 点（95% 区间 −1.6 到 +1.8）。
   - OfficeQA：指令 +18.9 点，几乎都来自格式错误消失（21 → 0）；6 次带检验的学习，一条修改都没收下。
   - LiveMath：指令只有 +1 点。

3. **起作用的是作答格式，而格式会跨数据集造成伤害。**
   - GLM-5.3 上，LiveMath 学到的"只答选项字母"让 SearchQA 掉了 63.6 点。
   - SearchQA 的格式提示被强行用到别的数据集上，测试集上 KOR-Bench 从 187 降到 152，ALFWorld 从 120 降到 93。
   - deepseek-v4-flash 上没有这种伤害。

4. **生成题代替不了验证集。** 学到的 Skill 在生成题上比指令高约 12 点（p=0.0002），在 74 道真题上三个模型都没有差别（p>0.1）。

5. **逐条检验规则，也没选出有效内容。**
   - 选出的规则在 24 道留出题上相对指令少对 0.67 题，效应未建立。
   - 各个 Skill 之间的差别，几乎全是格式的随机翻转（比如答案带不带 %）。

6. **换更弱的做题模型，差距不会被放大。**

## 结论

- 真实增益来自"本数据集的作答格式"。一份不看结果的指令就能拿到它，它也是跨数据集伤害的来源。
- 噪声比效应大：同一输入重新提一份修改，124 题上的分差中位数是 6 题；真实效应只有 1–3 题。
- 生成题不能当真题的替身。

## 下一步

- **实验**：
  - 五个数据集依次进化：SearchQA → OfficeQA → LiveMath → SpreadsheetBench → ALFWorld。
  - 每一步都在五个测试集上评测。
  - GLM-5.3 出主表，deepseek 复现。
- **方法：Skill 与"考官"一起进化。**
  - Skill 分成共享部分和各数据集的分区。
  - 每条新规则单独检验，再配上迁移题和边界题，决定放进共享部分还是限定在本数据集。
  - 评分细则由文字项和代码项组成，修改要有联网查证（DeepResearch）支持。
- **两条链**：从空白出发；从任务说明指令出发。
- **对照**：No-Skill、任务说明指令、SkillOpt、GEPA。
- **要证明三件事**：
  - 不用验证集也不差于 SkillOpt、GEPA；
  - 跨数据集的伤害更少；
  - 能否超过一份任务说明指令，正面回答。
