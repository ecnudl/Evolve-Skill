## What each fix does

**Defect 1, `asset_sha256`** (`sheet.py:217-220`):
- The private fields now bind both written files: `{str(input path): sha256, str(answer path): sha256}`. Keys are
  absolute and equal to the strings in `public.input_files` and `private.test_files`. This is the pool items' shape
  (`fixtures.py:360-361`; frozen `datasets.py:258-259`).
- The hashes are read from disk after both files are written and before `engine.qualify`.
- Effect: the frozen v7 scorer's re-check passes (`sheet_numeric_adapter.py:93-94`). Without the binding, every
  scoring became `native_scoring_input_error:ValueError` (`backends.py:566`), a configuration pause
  (`coevo5/qualify.py:63-64`). That applies to the engine qualification, the band probe and the G_self cells alike.

**Defect 2, the reference's formula caches** (`sheet.py:208-216`):
- The generated reference is the qualified engine's recalculation of the edited answer workbook: the source reference
  with the new literals, saved as `literal-answer.xlsx`, then `engine.recalc`, and the receipt's `output_base64` bytes
  become `answer.xlsx`.
- So every formula keeps its text and carries the engine's value as its cache. The frozen drift guard then finds
  them (`sheet_recalc.py:610-612`, `spreadsheet_compat.py:246-260`).
- `truth.expected_cells` are unchanged: they are still the engine's values from the truth recalculation (step 3).

**The input** (same loop):
- I checked which files the family edits. It writes the new literals into BOTH workbooks. Step 2 requires every target
  to be the same numeric literal in the input and the reference, and `perturbation_noop` guarantees at least one
  change. So a kept item's input is always edited.
- Per the registrar's rule ("otherwise it is recalculated the same way"), it becomes `engine.recalc(literal-input.xlsx)`
  output bytes. Its formulas, if any, carry the caches they have after the edit (openpyxl's save had dropped them).

**Receipt check** (`_recalculated`, applied to all three recalculations):
- A receipt that is not available → `Drop("recalc_failed")`, as before.
- An available receipt must be bound to the sha256 of the bytes sent (`input_sha256`, hashed before the call) and to
  its own output bytes (`output_sha256`). Otherwise → ValueError. This is the frozen `evaluate_pair` binding
  (`sheet_recalc.py:595-602`) and engines.py's "not bound" rule.
- engines.py's stop rules are not duplicated: unconfirmed cleanup → `CleanupUnconfirmed`; scorer environment →
  `SandboxUnavailable`; identity and zero-call binding. In a run they have already applied, because `engine.recalc`
  is `engines.Recalculation`.
- Native-slot discipline: each recalculation is one container run under one `spreadsheet-native` slot, held by
  engines.py around the run only. They run in sequence: truth, input, reference, then the 2 qualification scorings.
- The zero-call rule is unchanged.

## Readings and deviations (for the single Codex round)
1. **No "verbatim input" branch.**
   - The registrar's verbatim case ("when the family does not edit the input") cannot occur for this family's kept
     items, for the reasons above. Code for it would be dead.
   - The docstring states why both workbooks are recalculated.
2. **The truth recalculation is now bound too.** `_recalculated` also checks the first receipt (input and output
   hashes). This changes nothing on the production path: the frozen receipt's `output_sha256` is computed from its own
   bytes, and engines.py already binds `input_sha256`.
3. **`expected_cells` kept from step 3; no new consistency drop.** Observation for the record:
   - openpyxl writes floats with `"%.16g"` (checked on dl, openpyxl 3.1.5: `0.30000000000000004` is written as `0.3`).
     So an edited value that needs 17 significant digits is rounded in both generated workbooks (consistently).
   - `expected_cells`, computed with the full-precision formula value, can then differ from the reference's own caches
     in the last digits.
   - Nothing scores against `expected_cells`: the scorer compares with the reference workbook, rounded to 2 decimals.
   - In the real check, the caches equal `expected_cells` exactly in 6/6 cases. Pre-existing behaviour, not changed.
4. **Cost.**
   - Two more container runs per parameter set that reaches step 4 (about 3.5 s each on dl).
   - In the real check: 27-30 s per source item for 2 parameter sets, including both qualifications.
5. **Files.**
   - Each item folder now also holds `literal-input.xlsx` and `literal-answer.xlsx`, next to the existing
     `edited-reference.xlsx` and `recalculated-reference.xlsx`. All are host-side.
   - The solver copies only `input.xlsx`'s bytes into a fresh directory (`solver._inputs_dir`).
6. **New admission condition (pilot risk to note).**
   - The source item's INPUT must now pass the frozen screen and recalculation. The pool qualification only judged
     references. A refusal drops the parameter set as `recalc_failed` (counted by reason, never silent).
   - All 6 fixture inputs passed. Real run-slice inputs were not tried: the assigned single real check is on fixtures.
7. **A non-dict receipt** now gives `recalc_failed` with its text. Before, `(receipt or {}).get` raised
   AttributeError on a truthy non-dict.
