## Decisions and deviations from the plan (with reasons)

1. **Ledger root.** Every route-B scope set names the frozen root `overall`. Section 9.3 wants scope names that start
   with the chain (`G:`/`D:`), and the frozen `rooted` (budget.py:59-64) forbids non-`deepseek` names under the
   `deepseek` root. v3's meaning of OVERALL (GLM-5.3 tokens only) is therefore not carried over. Solver tokens and
   role tokens are kept apart by per-chain totals `<c>:solver` and `<c>:glm`, and every call names exactly one total
   (endpoint checks this). The `overall` cap is the sum of the chains' caps (default 2 x (180 + 30) = 420M), so it
   never binds first. The pre-22:3x design names (`deepseek:xs:*`) are not used.
2. **Scope layout.** Step kinds: `<c>:xs:<bench>:<k>:<run|examiner|selftest|accept>`. Test read: `<c>:test`, one per
   chain (bench and k are None). Roles: `<c>:xs:<bench>:<k>:role:<engineer|examiner|examiner:research>`. The `role:`
   segment keeps the role scopes apart from the solver scope `…:examiner`; the plan's `…:examiner:research` remains a
   suffix. The describer and the leakage adjudication call have no registered cap, so they are charged to the
   engineer scope, which keeps the registered 8.6M per-step ceiling. Smoke and probe use chain `"smoke"`:
   `smoke:solver`, `smoke:glm`, `smoke:probe`.
3. **Redo accounting.** A redo (attempt N >= 2) is charged to `<c>:redo` (the redo reserve) and to
   `…:<kind>:attempt-N`, not to the first attempt's scope. That scope's cap is min(step cap, redo reserve). `caps()`
   declares attempts up to MAX_REDOS + 1 = 3. The ledger enforces the reserve in tokens only. The rule "a second redo
   needs the owner's recorded cap decision" must be enforced by count in recovery, and the owner raises `<c>:redo` with
   `Budget.raise_cap`.
4. **Additions to the plan's API.** In budgets: `caps()`, `smoke_caps()`, `probe_caps()`, `ROOT`, `STEP_KINDS`,
   `KINDS`, `ROLES`, `TOTALS`, and the `sleep` keyword on `endpoint()` (used by tests). Before building an Endpoint,
   `endpoint()` raises ConfigurationError in five cases: an undeclared scope, the root not first, not exactly one total,
   B < client M, or no slot pool. In slots: `Holdings`, `pools()`, `limited()`/`UnitCap` (the SpreadsheetBench limit of
   2 live sandboxes), `level()`, the `log_every_s` keyword on `hold_short`, and the `holdings`/`clock`/`log` constructor
   keywords. These avoid global state and keep the clock simulable. `hold()` refuses the per-call sandbox pool and
   `hold_short()` refuses every other pool. Model slots stay in the frozen Endpoint; only the pool object passed to it
   is ordered.
5. **Additions to protocol.** `record()`, `verified()` and `RECORD_HASH` (registry, supply, exclusion and package use
   them now). Implementation-time registrations (plan §11), to be frozen by sha before S2:
   - `NOTE_HEADERS`: only the "facts" header is verbatim from §2.2; the other four are my wording.
   - `NOT_RECOMMENDED_PREFIX` and `REPAIR_FRAME`.
   - The lexicon: `LEXICON_TERMS` (tag forms first, so the most specific term is reported), `LEXICON_EXEMPT` for
     SpreadsheetBench "format", and the matching rule `LEXICON_MATCH`.
   - The run-root files: `CANARIES = shared/test-canaries.json`, `EXCLUSION_CONSENT`, `OWNER_CONTINUATION`,
     `FORMAL_ADDENDUM`.
   Other choices in protocol:
   - `PROBE_ROOT` follows registration §9.3 and `PROBE_LEDGER = PROBE_ROOT/ledger` follows plan §10 step 4; both
     are kept.
   - `SMOKE_ROOT` = `/data/execskill-20261021-pre/smoke` follows registration §10 (line 881), where the plan says
     `--root /data/execskill-20261021-pre`. The registration wins.
   - The owner-#9 option and the recommended pilot are recorded as data only.

## Integration notes for later rows (no change to anyone's file needed)

- Build the pools once per process with `slots.pools(protocol.SLOT_ROOT)` and give that dict to the setting's
  `slots`. Model calls then go through `budgets.endpoint(setting, scopes, client=..., max_tokens_bound=B)`. Use
  `protocol.ledger_bound(...)` for solvers and `ROLE_MAX_TOKENS` for roles.
- Call `Budget.declare(budgets.caps(PILOT))` at the pilot start, `smoke_caps()` on the smoke root and `probe_caps()` on
  `PROBE_LEDGER`.
- Code must not call a model while it holds a native slot, and must not take an episode or live slot while it holds a
  model or native slot. `assert_order` refuses either case with ConfigurationError.
