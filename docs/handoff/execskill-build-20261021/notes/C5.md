## Public API (new or changed)
- `client.unit_tag(chain, unit) -> str` returns `"<chain lower>-<sha256(unit)[:12]>"`. The chain is 1-8 letters or
  digits.
- `client.Worker(*, docker=None, limits=None, hashseed=0, live=None, per_call=None, scratch=None, image=IMAGE,
  tag=None)`.
  - With `tag`, containers are named `execskill-sbx-<tag>-<uuid4 hex>`. Without it, they keep the registered
    `execskill-sbx-<uuid4 hex>`.
  - New attributes: `restarts` (`[{"cause": "oom"|"gone"|"start_failed", "container", "procedure"}]`) and `cleanups`
    (`[{"container", "seconds"}]`).
- `client.drain_unit(chain, unit, *, docker=None) -> None` checks only that unit's containers and raises
  `CleanupUnconfirmed`.
- `client.cleanup(name, *, docker=None)` makes up to `CLEANUP_TRIES` = 3 tries of `rm --force` plus an exact-name
  `ps`. Each command is bounded by `CLEANUP_SECONDS` = 10 s, with `CLEANUP_PAUSE_SECONDS` = 1 s between tries.
- `client.drain_check(prefix=PREFIX, *, docker=None)` retries only a failed listing, up to 3 times. A listed container
  raises at once.
- `client.NAME` accepts both name forms. `client.TAG`, `CHAIN_TAG`, `START_TRIES` = 2, `UNAVAILABLE` and `RETRIED` are
  new constants. In `argv_template` the name placeholder is now `execskill-sbx-<chain>-<unit12>-<uuid4>`.
- `worker.set_dumpable(flag) -> int | None`. The ping gains `"dumpable"` (0, or None without prctl).
  `worker.run_call(...)` keeps its signature, and its child now runs in its own process group.
- `judge.select_answer(bench, reply)` keeps its signature. On SearchQA the precedence changed, see below.
- `acceptance.schedule(sealed)` keeps its signature but returns a new order. The J5 record
  `guards.J5.balance = {"ok", "statistic": "median_delay_spread", "spread_s", "raw_spread_s", "order_spread_s",
  "duration_s"}`, or `{"ok": False, "reason"}` when a start or finish time is missing.

## What changed, and against which frozen code it was checked
- **Safety 3** (client.py:120-235, :471-491)
  - Tagged names and `drain_unit` (A5-2 option 2).
  - Bounded removal retries, with every confirmed removal's latency recorded.
  - Callers are not wired yet (ticket C5-1). Untagged workers behave as before.
  - The frozen `_native` likewise confirms only its own exact name (continual_eval/backends.py:158, :190).
- **Safety 4**
  - Worker (worker.py:369-383, :431-468, :470-496, :686-695):
    - Each call child calls `setpgid(0, 0)`, and the parent sets it too.
    - On timeout, over-cap or a missing EOF, the whole group is SIGKILLed. After every call, what is left of the
      group is killed while the exited child still holds the group id: `waitid(WNOWAIT)`, then `killpg`, then
      `wait4`, so a pid is never reused under us.
    - As PID 1 in the container, the worker reaps orphans.
    - The parent ignores SIGINT and runs `prctl(PR_SET_DUMPABLE, 0)` through ctypes. `PR_GET_DUMPABLE = 3` and
      `PR_SET_DUMPABLE = 4` come from linux/prctl.h.
    - Found while testing: in a non-dumpable process, `/proc/self/*` belongs to root (the kernel's
      `task_dump_owner`). So under uid 65534 the child's write of `oom_score_adj` 1000 would fail silently, because
      `_child` swallows the OSError. The child therefore sets dumpable to 1 just for that write and back to 0 before
      any procedure code runs. This is verified as uid 65534 on dl (kernel 5.10.25) by
      `test_safety_4_a_call_child_is_non_dumpable_yet_gets_oom_score_adj_1000`.
  - Client (client.py:514-527): a refusal of a `call` now raises `_Lost` (P1). A refusal of `ping` or `load` stays
    `ConfigurationError`.
- **Safety 5** (client.py:367-412, :450-469, :548-590)
  - On `_Lost` the client asks docker before removing anything. If the worker hit end-of-file, it first lets the
    docker client exit (≤ 10 s). Then it runs `docker inspect --format {{json .State}}`, and if that fails,
    `docker version --format {{.Server.Version}}` (the query manifest.py already uses) and `docker image inspect`.
  - Docker down or the image gone is P4: `sandbox_daemon_unreachable` or `sandbox_image_missing`.
  - OOMKilled, or a vanished container while docker and the image are present, gets one replacement and one retry
    of the call with the procedure still loaded.
  - Anything else, and a second loss, is P1 `worker`, and the procedure is dropped. The message now says
    `docker: <cause>`.
  - A failed start, including a missed 20 s ready ping, is retried once unless docker or the image is gone.
- **Statistics 6** (judge.py:47, :108-123, :170-177)
  - The SearchQA official carrier is the frozen `extract_answer`: the last tag, else the last non-empty line
    (envs/searchqa/evaluator.py:28-39). It is imported, not copied.
  - The carrier counts when it is not itself a JSON object and its frozen `normalize_answer` (evaluator.py:19-25) is
    not empty. Only then is it used. The JSON rescue applies only when the carrier holds no answer.
  - `coevo5/checks.py:12-21` `last_answer` uses the same regex (`re.S | re.I`, strip), so OfficeQA and LiveMath are
    unchanged.
  - Mutation sites (09) and (16) are kept verbatim, exactly once.
- **Statistics 8** (acceptance.py:165-205, :405-438)
  - Each block has one order over every cell (arms × items × runs, twins, G_acc, probe): the sha256 of (SEED, round
    tag:block, set, item, run, arm), the form of `coevo5/step.py:79-80`.
  - The probe items are dealt over the blocks in their seeded order, instead of forming a "first block".
  - J5 balance is re-derived: a cell's delay is its actual start minus the block's k-th earliest start, for the k-th
    cell of the seeded order. The arms' median delays must lie within 5 % of the round's duration. The registered raw
    spread is recorded next to it.
  - `runner`, `dispatch`, `decide` and `settle` keep their interfaces. The B3 integration test still passes: cells
    sorted by dispatch time equal the schedule, and `J5.balance.ok` holds.

Side effect: the worker file and the argv template's name placeholder changed, so the manifest's
`sandbox.worker_sha256` and `docker_argv_template_sha` change too. Both are computed at manifest time, which is fine
before launch.

## Deviations, with reasons
1. **J5 deciding statistic.** It is the spread of the arms' median start delays, not the registered spread of median
   start times. Under the registered uniform order the raw statistic fails by chance in most rounds (A9-2). The
   review's paired fix was "revert to one uniform seeded order and re-derive the balance guard". The raw value is
   still recorded (C5-3 item 1).
2. **Probe items dealt over blocks.** The registration has no rule for this. LiveMath, the only bench with a J7 probe,
   has one acceptance block, so in v1 the deal is moot.
3. **"Non-empty" SearchQA carrier.** It means non-empty after the frozen SQuAD normalisation and not wholly a JSON
   object. Otherwise a ```json fence or a multi-line JSON object would lose the registered JSON channel. J4 flags are
   unchanged (C5-3 item 3).
4. **Container name format.** It now carries chain and unit, as decided. Only tagged workers use it (C5-3 item 4).
5. **"3 tries, 10 s".** Read as 3 tries, each command bounded by 10 s, 1 s apart. The worst case is about 62 s
   (C5-3 item 5).
6. **Unconfirmed removal while docker does not answer.** It is folded into that P4, because §2.6 lists an
   unremovable container under P4 and the root cause is the daemon. The container stays in `unconfirmed`, with its
   live slot held. While docker answers, `CleanupUnconfirmed` stays a stop.
7. **Restart once, per call.** "Container gone" (docker and image present) is treated like an OOM kill (C5-3 item 6).
8. **Group kill after every call**, not only on timeout. The review (findings 4 and 17) asks that no descendant
   outlive a call.
9. **Children lift non-dumpable** for their own `oom_score_adj` write. Without this, the registered oom_score_adj
   1000 silently disappears in the container.
10. **Safety minor 13 fixed by the way.** The live slot leaked when the spawn raised a non-OSError. The container is
    now attached right after its slot is taken. Test: `test_safety_minor_13_...`.
11. **FakeDocker.**
    - `kill_worker` now kills every process of the container, as the end of the container's pid namespace does,
      because call children have their own groups now. The container stays listed as exited.
    - New injections: `daemon_down`, `transient`, `corrupt` as a list, and the modes `refuse`, `oom`, `gone` and
      `daemon`. `run` serves `inspect` and `version`.
12. **Existing tests changed.**
    - `test_sbx09_a_failed_restart_is_sandbox_unavailable` now needs `fail_starts = 2`, because of the start retry.
    - `test_t_acc_2_one_seeded_order_never_by_arm_with_every_arm_at_the_same_pace` asserted the unit-blocked order and
      `spread_s <= 4`. It was replaced by three T-ACC-2 tests of the one order and the re-derived guard.
    - The "late S'" (−1000 s) and statistics-4 (−5000 s) imbalance tests stay undetermined unchanged.
13. **Not done** (other owners, or outside this row):
    - wiring tags and `drain_unit` into units and chain (C5-1);
    - pre-check containers and the S2 leftovers row (C5-2);
    - restarts and cleanups in cell records (C5-4);
    - S0 escape-probe rows and S0 measurement of rm latency, hook timing and `dumpable` from the pinned image (A13);
    - safety minor 17, the fork failure.
