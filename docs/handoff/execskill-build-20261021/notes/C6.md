## Public API
- `manifest.setting_of(m, chain, *, path=None, docker=None, transport=None) -> units.Setting`
  - `chain` is in `RUNS` = ("G", "D", "smoke").
  - G and D use their own ledger, `budgets.ledger_root(root, chain)`; `chain.run` declares `chain_caps`.
  - The smoke uses `<root>/shared/ledger`, with `budgets.smoke_caps()` declared here.
  - The smoke requires evidence "smoke" and the chains require a pilot manifest.
  - The solver is the chain's; the smoke uses chain D's model through the elucid client. Every role is GLM-5.3.
  - `branch` and `longest` come from the verified solver block.
  - `extra` holds `verify`, `drain`, `slot_root`, `manifest` (the `path`) and, for G and D only, `test_read_estimate`.
  - It refuses a lexicon or prompt hash that differs from the code.
- `manifest.services_of(m, chain, *, setting, transport=None) -> step.Services`
  - `registry`: under `history_root`.
  - `sources`: research over the pinned archive (index hash checked), Wikipedia through `protocol.GATEWAY`, and the
    store `<root>/shared/research/<chain>`.
  - `workers`: `functools.partial(sandbox.with_worker, **setting.sandbox, live=, per_call=)`.
  - `checker` and `engine`: None (ticket C6-1).
- `manifest.prompt_sha() -> {"describer", "engineer", "examiner": {"policy", "detectors", "generators"}}`. The new
  manifest field `prompt_sha` is stamped by `make` and checked by `check` (A10-1 item 6, C6b-1 §3).
- `units.for_unit(setting, chain, bench, unit) -> Setting`
  - `sandbox["tag"] = client.unit_tag(chain, unit)`.
  - ALFWorld runs with `workers = min(workers, 6)`.
- `units.drainer(setting, chain, unit) -> callable | None`: binds `setting.extra["drain"]`; None when the Setting
  binds no drain.
- `units.run_unit(unit_root, *, run, identity, work, evidence, drain=None)`
  - The drain runs after the work ends, both on completion and on a pause.
  - Its CleanupUnconfirmed pauses the unit as a stop, so no unit.json is written.
- `step.parent_of(setting, chain_root, chain, k)`; `step.run_unit_spec(manifest, *, spec) -> 0|3|5`
  - The spec is {"chain", "k", "bench"}, with `ORDER[k-1] == bench`.
  - The chain's own ledger declares `chain_caps` first, as `chain.run` does.
- `step.SHEET_VALIDITY`: the accept result's `validity` on SpreadsheetBench (C1-3).
- `evaluation.twin_unit(bench) -> "test/<bench>"`
  - `test_plan` draws its twins under it and refuses a unit that is not `<chain>/test/<bench>`.
- `evaluation.evaluate(..., reset=None, drain=None)`
- `evaluation.donor_corpora(chain_root)`, `evaluation.frozen_texts(chain_root, final)`,
  `evaluation.placebo_arm(final, corpora, *, bench, unit, runtime, workers)`
- `evaluation.run_unit_spec(manifest, *, spec, docker=None, transport=None, panel=data.test_panel, reset=None) -> 0|3|5`
  - The spec is `chain.launch_child`'s {"chain", "bench", "package_sha256", "unit_root"}.
  - Consent is checked first.
  - The arms are F, C, P_F and T_F.
  - The unit's own tagged Setting is used, the endpoint is on `<chain>:test` with B, and the unit is drained.
- `chain.run_manifest(manifest, *, chain, path, docker=None, transport=None) -> run's status`
- `chain.terminate_manifest(manifest, *, chain, decision)`
- `readout.report(manifest, *, out) -> {chain: record hash | "not_read"}`
  - One `readout-<chain>.json` is written per chain that read.
  - Procedures are given as {id: `Procedure.origin`}, the B5 contract.
  - A chain that has neither read nor ended is refused, and nothing is written then.
- `runcli.run|terminate|step_unit|evaluate_unit|report|seal_addendum(args) -> int`; `runcli.HANDLERS`;
  `runcli.add_arguments(subparsers)`.

## Deviations (with reasons)
1. `services_of(m, chain, *, setting, transport=None)` takes the Setting. Its workers then share the Setting's one
   `slots.pools` set (one Holdings, safety-6) instead of a second set.
2. The adapters are named `chain.run_manifest` and `terminate_manifest`. `chain.run` and `terminate` keep their
   Setting signatures, which other modules and tests use. `run_manifest` needs `path=` because the read children are
   started with the manifest file.
3. The pools contract is `data.pools`, JSON item lists ordered by `supply.order`, not the frozen `data.pool`. The
   frozen version requires the v3 pool sizes and has no route-B order (C6-3).
4. The roles' GLM credentials come from the G solver block's repository. A smoke manifest therefore lists a G block
   too.
5. C5-1 tagging is bound by the caller, not by module changes:
   - `_Step.unit` gives every unit a tagged Setting (`for_unit`) and a tagged worker factory
     (`partial(services.workers, tag=)`);
   - router, replay, detectors, the engineer's C5 check and rounds get every worker from these;
   - no module constructs a Worker on its own (checked with grep);
   - the drain is opt-in through `setting.extra["drain"]`, which only `setting_of` binds; engineering fixtures run
     without a drain.
6. P_F donors are paired per item (`donors.pair` seeded by `<unit>:<item>`), because the read's items are known only
   inside the unit.
7. T_F texts are the freeze units' descriptions, hash-checked against `final.describer`.
8. `test_plan` keeps its `unit` parameter, now checked to be `<chain>/test/<bench>`, so it is not dead.
9. `_smoke_pools` compares only the measurements that both records carry: the self-test has no native peak, and the
   manifest has no start latency or view count.
