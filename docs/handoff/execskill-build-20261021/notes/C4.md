## Public API

No library API is added. The test module has these parts:

- `pilot(tmp_path_factory)` is a module fixture. For `name in CHAINS` it runs
  `chain.run(settings[name], name, learn=functools.partial(step.learn, services=services), launch=Pilot(canaries).launch)`.
  Then it writes `shared/owner-continuation.json`, seals the formal-chain addendum (`evaluation.seal_addendum`) and calls
  `evaluation.continuation_check` and `evaluation.unseal` for each chain. It returns a namespace with `root, shared,
  tmp, results, settings, ledgers, solvers, glms, registry, research_root, canaries, sb_items, waited, addendum,
  labels, opened`.
- `Pilot.launch(setting, spec) -> chain.EXIT_COMPLETE` is the read child, run in process. OfficeQA gets a real
  `evaluation.evaluate` with arms F, C, P_F and T_F. The other four benches get a stand-in `evaluation` record that
  names its run, chain and package.
- The 11 tests:
  `test_both_chains_complete_the_pilot_and_accept_the_same_procedures`,
  `test_step_one_spreadsheetbench_runs_every_sub_step_and_its_generator_is_not_admitted`,
  `test_step_two_officeqa_researches_generates_and_keeps_only_the_valid_change`,
  `test_the_acceptance_rounds_seal_every_registered_arm`,
  `test_every_decision_again_from_its_cell_records_and_sealed_record_alone`,
  `test_every_record_is_versioned_labelled_and_stamped_with_its_chain`,
  `test_both_chains_consume_the_same_slice_items_in_their_own_namespaces`,
  `test_each_chain_ledger_settles_every_reservation_on_its_own_scopes`,
  `test_no_test_text_in_any_training_side_artifact`,
  `test_the_read_shares_structural_zeros_and_seals_hashes_only`,
  `test_the_owner_continuation_unseals_and_the_readout_tables`.
- Mutation suite: the three entries above, each `(path, old, new, [named test])` in `MUTATIONS`.

## What the pilot runs

Both chains run on one temporary root. Each chain has its own real `Budget` ledger (`budgets.ledger_root(root, chain)`).
Each has its own FakeSolver behind the real client of its model. G uses `glm-5.3` (`GLM_SOLVER`). D uses
`deepseek-v4.1-flash-1017` with the registered per-bench `ELUCID_MAX_TOKENS` and `ELUCID_READ_TIMEOUT`. Each chain also
has its own FakeGLM behind the real `Roles`. One `Registry` holds both chains' consumption namespaces.

The fakes:
- FakeDocker runs the real sandbox worker for the engineer's checks C1-C9, the detectors and the describer's replays.
- FakeSandbox hooks give the cells the same outputs the engineer's sources compute.
- FakeNative stands in for the SpreadsheetBench pre-check and native run. A fixture verdict replaces the frozen
  recalculating scorer for SpreadsheetBench only; every other bench goes to the frozen `backends.score`.
- FakeResearch gets a second eligible numeric table, so the OfficeQA findings split into a G_self half and a G_acc half.

The steps:
- **Step 1, SpreadsheetBench (empty parent).** The sub-steps run in order:
  - run;
  - diagnose: one detector;
  - generate: the scripted policy requests no research, so the generator is `not_admitted`;
  - engineer: one `sheet_feedback` procedure survives;
  - self-test: `no_generated_items`;
  - accept: S', S, P_y, P_i and C; no twin, no G_acc, no S_dup;
  - freeze: the describer.
- **Step 2, OfficeQA.** The inherited procedure fires on half the run slice, so the card arm runs beside S.
  - Research covers two tables: at most 8 calls per request, every page archived, every table quoted verbatim from its
    archived page.
  - The generator is admitted on the G_self half.
  - The engineer proposes three changes. The valid one survives. The crashing change fails C6 and the leaking change
    fails C4 (adjudicated); each is dropped after its one fix.
  - The self-test runs on G_self.
  - The acceptance draws A* and seals the donor corpus: run-slice donors only, zero faults. It runs P_y, P_i, the
    withholding twins of the inherited procedure, G_acc (the frozen generator on the G_acc half) and S_dup.
  - Freeze.
- **Test read.** OfficeQA is read for real, with structural zeros shared: every fourth test page names its first column
  "Term", so the new procedure does not fire there. The read unit holds hashes only, its transient store is deleted, and
  its canary scan finds 0 hits.
- **After the read.** The owner's continuation file is written and the formal-chain addendum is sealed before the
  unseal. The unseal labels the read `interim_read_addendum_before_unseal`, with later reads `confirmatory`. Then the
  readout runs.

## Fixes uncovered by the test

1. **`skillopt/execskill/step.py` `_g_acc` (first C4 run).**
   - Problem: the frozen generator's specs name their G_self material, and `research.split` never puts one material in
     both halves. So `examiner.build(specs, <g_acc half>)` looked up a material that is not there (`examiner.py:627`,
     KeyError) for every admitted OfficeQA generator at the acceptance.
   - Fix: each frozen spec is rebound to every usable material of the g_acc half whose kind matches the spec's family
     (`generators.MATERIAL_KINDS`). The `_g_acc` docstring cites ticket C1-3 and this test.
   - Open: G_acc items share ids with G_self items (ticket C4-1).
2. **Test only.** The step 2 test asserted a `material_id` key on generated items. The registered item field is
   `material` (`generators/families.py:154`, plan §2.5).
3. **Test only: cost.** The test texts of the read had two lengths, 168 and 170 characters, because "Year |" was
   replaced with "Period |". The scan hashes every window once per distinct length. "Term |" has the same length as
   "Year |", so there is now one length. The test asserts this, and the canary test went from about 130 s to 61 s. A
   five-canary sample saves nothing when all canaries share one length, so that interim approach was dropped.

No other execskill file was changed.

## Deviations from the plan

1. Plan §8.2 also names a SpreadsheetBench -> ALFWorld pilot with FakeAlfEnv. This row's binding pilot is
   SpreadsheetBench -> OfficeQA, and FakeAlfEnv is not used. ALFWorld appears only as a stand-in read unit. ALFWorld's
   in-memory routing at the test read is covered by `test_execskill_evaluation.py::test_isolation_2` (FakeAlfEnv
   sessions).
2. The pilot has no restoration twin. Step 2 only adds a procedure, so the router draws withholding twins of the
   inherited procedure. Restoration twins are covered by T-ROUTE-5 (`test_execskill_router.py:120-133`).
3. The read units of the four other benches are stand-in records, so the readout tables cover OfficeQA only. The
   reasons: SpreadsheetBench needs the test qualification, LiveMath needs sympy (absent on the host), ALFWorld needs the
   environment, and SearchQA's panel is not needed for the pilot.
4. SpreadsheetBench programs never run: FakeNative stands in for the native runner, and a fixture verdict replaces
   the frozen recalculating scorer.
5. The SpreadsheetBench generator is not admitted: the scripted policy requests no research, and ticket C1-2 means
   there is no shortcut view. So step 1 has no generated items, no band or shortcut probe, no self-test cells and no
   G_acc.
6. Mutation (21) is checked on its "after dispatch" half only (`donors.verify`). The "from acceptance items" half has
   no single mutation site, because `donors.donor_corpus` never receives an acceptance item; T-PLACEBO-6 scans the
   sealed text for acceptance-item text, and the e2e now asserts that the donor items are run-slice items. Mutation
   (27) has two entries: 27a, a changed archive file accepted on open, and 27b, a redirect to another host followed.
7. Research store files are raw fetched documents in the copied v3 store format, so they carry no version or
   `evidence`. In the pilot they sit outside the run root. The canary scan covers them; the versioned-record scan does
   not.
