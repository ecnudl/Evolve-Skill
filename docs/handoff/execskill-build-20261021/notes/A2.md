## Public API
`skillopt/execskill/client.py`
- `solver_client(model, *, config, transport=None) -> scripts.weak_solver_probe.Client | ElucidClient`
  - `"glm-5.3"` (chain G): `config` = exactly `{"repo", "proxy"}` -> the frozen `Client(repo, "glm-5.3",
    proxy=GATEWAY, max_tokens=65536, read_timeout=2400, transport=transport)`, no route.
  - `"deepseek-v4.1-flash-1017"` (chain D, smoke): `config` = exactly `{"env_path", "proxy", "max_tokens",
    "read_timeout"}` (the bench's nominal M and read timeout) -> `ElucidClient`.
  - any other model, other config keys, `proxy != GATEWAY`, or a credential the frozen client refuses ->
    `ConfigurationError` (imported from `skillopt.coevo5.outcomes`).
- `class ElucidClient(weak_solver_probe.Client)`
  - `__init__(self, env_path, *, proxy, max_tokens, read_timeout, transport=None)` (does not call `super().__init__`)
  - `_receipt(self, status, data, attempts, started) -> dict`; inherited unchanged: `body(system, user)`,
    `call(system, user) -> receipt`.
  - request body: `{"model", "messages": [system, user], "max_tokens": M, "temperature": 0,
    "reasoning_effort": "none"}`, no `thinking`; no `X-Session-Id`; `trust_env=False`; gateway proxy only.
  - receipt keys added on every receipt that carries a reply of the registered model: `reasoning_tokens` (int, None
    when absent, `"invalid"` when not a non-negative int), `visible_completion_tokens` (completion minus reasoning;
    None without valid usage or with an invalid/inconsistent count), `over_nominal` (completion > M); on reasoning:
    `ok=False, error_type="thinking_mismatch", subtype="reasoning_mismatch"`.
- constants: `GLM_SOLVER`, `ELUCID_MODEL`, `ELUCID_HOST`, `ELUCID_PATH`, `ELUCID_RESPONSE_MODEL_IDS`,
  `REASONING_EFFORT`, `THINKING_MISMATCH`, `REASONING_MISMATCH`, `INVALID`, `ENVELOPE_ERRORS`, `CONFIG_KEYS`.

## Deviations from the plan (with reasons)
1. `solver_client` has an extra keyword `transport=None` (tests only; with None the construction equals v3's). The
   plan's `config` is made concrete: exactly the per-model keys of `CONFIG_KEYS`; glm-5.3's M/timeout are not
   configurable (REG §4.1 chain G table: 65,536 / 2,400 s on every bench).
2. glm-5.3 requires `proxy == GATEWAY` (the frozen client would also accept None; REG §4.1 and T-CLIENT-6 require the
   gateway).
3. Frozen refusals (`SystemExit`, or `OSError` reading the credential repository) become `ConfigurationError` (ONE
   exception set) carrying the frozen message, which holds no secret.
4. Extra receipt key `reasoning_tokens` (the evidence behind a mismatch and for the smoke's leak counts); `subtype` only
   on mismatch receipts.
5. The three added keys exist only on receipts carrying a reply of the registered model: transport/HTTP/envelope
   receipts and ALL chain G receipts (frozen client) lack them -> consumers read them with `.get(...)`.
6. Strict reading of "reasoning_tokens in {absent, 0} and no reasoning_content": a non-integer count, a non-dict
   `completion_tokens_details`, or any reasoning_content other than null/"" (also whitespace or a non-string) is a
   mismatch.
7. The registered echo set is a constant in `client.py` (the plan's `ElucidClient` signature has no parameter for it);
   if S1-a sees another echo, that is a v1.1 code amendment, not a manifest setting.
8. The credential file must also name `ELUCID_MODEL == "deepseek-v4.1-flash-1017"` and be a real path (`safe_path`,
   as v3 bound its env files).
9. Fakes take a test directory (`FakeSolver(root, ...)`, `FakeGLM(root, ...)`): their receipts come from the REAL
   clients over `httpx.MockTransport` (not hand-built dicts as in coevo5_fakes), so the shape cannot drift. Keys are
   request SHA-256 / regex / default rather than "(bench, request_sha256)": a request does not name its bench, and its
   hash already pins the bench's system prompt.
10. The S1-e control probe (no `reasoning_effort`) is not a client option, so production construction cannot send an
    unregistered body: smoke (A13) subclasses `ElucidClient` and overrides `body` to drop `reasoning_effort`.
