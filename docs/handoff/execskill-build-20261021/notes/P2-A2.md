## Deviations (with reasons)

1. G_acc cells of a redone block stay on `...:examiner` (no attempt sub-scope, no redo reserve): the registrar chose
   "as registered"; the redo reserve is sized from the accept row without G_acc (see the headroom above).
2. `acceptance.runner`'s `examiner` defaults to None (G_acc then runs on the round's context): integration B3 (not
   mine) calls `runner` without it; the step always passes it, and a mutation dropping it from the redo runner fails
   the step test.
3. The series is per set AND arm (the registration says per arm, "按组"): G_acc and LiveMath's J7 probe are other items
   than A*, so their reply lengths would distort A*'s first-window median. The reference median is per set and arm.
4. `series` imports readout's and evaluation's private helpers (`_windows`, `SHORT_ANSWER`, `_completion_tokens`)
   inside the function: `readout` -> `evaluation` -> `manifest` -> `step` -> `acceptance` is an import cycle at module
   level. Ticket P2-A2-1 offers public aliases.
5. `answer_tag_share` is readout's definition (`format.tag_present`); on SpreadsheetBench and ALFWorld it is 0.0 by
   construction (their judge format has no tag). Not changed here (readout.py is not mine): ticket P2-A2-1. It decides
   nothing, but the first pilot decisions (SpreadsheetBench) would show a false zero.
6. The PR-C12-1 step test hands the step its generated set through a patched `step._build` (a real SpreadsheetBench
   generator needs LibreOffice recalculation and researched function material); everything after it -- band probe,
   shortcut probe, cells, the solver shell, pre-check, execution on the real input files, the gate, the ledger -- is
   the real code behind the usual fakes (FakeSolver/FakeGLM behind the real clients, FakeNative, fixture scorer).
