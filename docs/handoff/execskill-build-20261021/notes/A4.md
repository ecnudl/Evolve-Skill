## Deviations from the plan, with reasons
1. **Registry as a class.** The plan has module functions `register(chain, …)`. The code has
   `Registry(root, *, evidence)`: the task needs the root as a parameter so tests use a temporary directory, and
   every line needs an `evidence` label. Lines carry the §2.7 fields plus `evidence`. `attempt` is a keyword, and
   items are passed as item dicts so the registry can bind `item_hash`.
2. **Redo semantics.** The same unit repeating a state it already holds is a no-op: register on registered or
   dispatched, dispatch on dispatched, decide on decided, release on released. This is "a redo reuses its own
   registration" (REG §3.4). A backward move by the same unit raises `ValueError`. Another unit raises
   `ConsumptionConflict`. Released items are free again for any unit.
3. **`searchqa_tail` signature.** Added `cache_sha256` (REG §3.1: the HF cache is pinned by hash) and requires
   `start == manifest count + 1`. `exclude = {"ids", "questions"}`: all native ids (pool, test and reserve; ids only,
   from the pinned split manifest) and the pool's questions.
   - Blocks A-D are replayed by the manifest's ids. Every skipped row must have a frozen skip reason, and the
     per-reason counts must equal `skipped_before_full`. The test and reserve questions cannot be read without
     TestAccess. The 10/12 draw had 0 duplicate-question skips, so ids are enough.
   - Remaining limitation: reserve items are excluded by id only. Their question text is in no pinned input
     (`data.DEV_MACHINE` pins only the test-400 panel). The test-400 question-level exclusion runs in
     `exclusion.exclude_tests`.
4. **`alfworld_items(data_root, pool_games)`.** The plan has `pool_ids`; this takes `{pool id: game file}`.
   Excluding pool games needs their files, and ids alone cannot identify them. The new ids are also checked against
   the pool ids.
5. **`prereset(items, cut, *, reset)`.** The reset is injected: production uses `alfworld_reset(data_root, runtime)`
   (not unit-tested, since it needs the real ALFWorld env; it runs in S0 `make-items`), tests use a fake. `cut` is the
   slices dict. New: `routing_view()` is the single definition of the routing view. Its `task_text` is the last
   "Your task is to:" line of the reset observation. A6 should import it, so the sha256 asserted against the live
   reset view is computed the same way.
6. **`slices` sizes are named per bench (`supply.SLICES`).** LiveMath input names are `run_absent`/`run_present`; the
   output is `run`, `accept`, `accept_probe`. SearchQA `smoke` is the last N of the pool order, taken out first. The
   tail's acceptance slice is a separate call on the tail order.
   - ALFWorld takes games round-robin over the slice's rooms, at most 5 per room. This spreads 150 acceptance games
     over all 40 rooms (M_BAR 3.75, calc T1).
   - `select` is an upper bound (REG: "≤ 200").
   - Room groups for a recount other than 108 use the floor of the registered proportions; the rest is spare.
     REG §3.1 does not fix the rounding.
7. **`alfworld_test_identity(pinned, supply, *, access, consent)`.** The plan has `(access, *, consent)`; this also
   needs `pinned` to read the test panel and `supply` to check disjointness. In both runs `consent` is the consent
   file's path, and it is validated before the access is used. A test split other than `valid_unseen` raises
   `ValueError` with counts only ("stop and report"). Non-disjointness is returned as `disjoint: false`.
8. **`exclude_tests` returns counts and hashes only.** `dropped` holds the sha256 of each dropped supply id, and
   `exclusion_sha256` is its digest. The new `apply_exclusion(supply, record)` gives the kept supply, so no record
   carries item text or ids.
9. **Added `supply_record`/`write_supply`.** This is the registrar's write-once supply file (REG §1: supply files
   live under `/data/execskill-history/`); the id -> game-file mapping lives only there.
10. **Constants come from A1's `protocol.py`.** It landed while A4 was working; `kind`/`record`/`verified` stamp
    and seal every record. Local definitions remain only where `protocol.py` has none: `registry.PURPOSES`, the
    frozen builder's manifest names (`FRESH_VERSION`, `FRESH_BLOCKS`), `RELEASE` and `TASK_PREFIX`.
    `supply.SLICE_NAMES` lists the slice names per bench; it is distinct from `protocol.SLICES`, which holds
    `(items, runs)`. New: `supply.registered_sizes(bench, part)` maps the registered constants onto `slices`, and a
    test pins the registered numbers.
