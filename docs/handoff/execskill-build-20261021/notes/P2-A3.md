## What each part does, against the row

- **(1a) skip.** The record is still made once, inside the first read child, under the lock, after `consent()` and
  before its attempt (row (4), unchanged). The training-side pools are the ones the manifest pins in `data.pools`,
  read when the record is made; a pool that differs from its pin is refused before any test set is opened. A test text
  of at least 24 characters that occurs verbatim in the same public field of an item of the same bench's pool is not
  eligible; the other texts keep their seeded order, so the selection stays seeded and deterministic. The record keeps
  only the counts (`skipped`) and the pin hashes (`training_pools`), never a text.
- **(1b) release.** `recover` (I1's CLI) writes the owner's `recovery.json`; a decision `release <sha>` naming the
  record hash of the scan paused in that attempt lets the next scan that finds exactly the same hits pass; the marker's
  `canary_scan.release` = {attempt, scan_sha256, recovery_sha256}. Never automatic: without the owner's file, with a
  file not `by: owner`, with free text, or with a release naming any other scan, a scan with hits pauses as before.
  Another chain's scan is its own (each chain's scan needs its own release).
- **(3) pool.** Five processes on dl (`scan_workers()`), two CPUs left. Measured 2.7x, not the registrar's estimated
  5x (below). The record does not depend on the number of processes (tested: identical records with 1 and 3
  processes, identical results with 1, 2, 3, 5 processes over 42 files; the e2e's 54 MB root ran through the pool).

## Deviations, with reasons

1. **Pools from the manifest, by keyword.** `make_read_canaries` takes the manifest's `data.pools` as a required
   keyword `pools` (no default), so a caller that forgets the training side fails loudly instead of skipping nothing.
   Consequence: the e2e fixture line of ticket PR-C31-2 and `integration_b5` need `pools=` (tickets P2-A3-2, P2-A3-3).
2. **LiveMath in the pilot.** The pilot pins only `protocol.ORDER` (SpreadsheetBench, OfficeQA). LiveMath's test texts
   are still canaries, but there is no pinned LiveMath pool to compare with: `training_pools.livemath = None`,
   `skipped.livemath = 0`. A LiveMath duplicate can only be met by a hit and the owner's release.
3. **"Occur verbatim" = contained.** A test text is skipped when it equals or is contained in a training text of the
   same field (the scan matches substrings, so a contained duplicate would hit just the same). Other fields (e.g.
   OfficeQA `context`) and other benches are not checked, as the row says "same field".
4. **A refused release releases nothing instead of raising.** `recovery.json` is write-once (`write_json` refuses a
   different second write), so a malformed or wrong release could not be corrected and a raising unseal would block
   the chain for good. The next scan with hits pauses in a new attempt, its status names the refused release, and the
   owner decides there. `recover` refuses such a release before writing it, so only a hand-written file gets here.
5. **A release stays in force until the next pause.** An interrupted scan, or an accepted scan whose marker was not
   yet written, does not use it up: the next scan with exactly the same hits passes too. Any other hits pause anew.
6. **New fields.** `scan.json` gains `hits_sha256`; the marker's `canary_scan` always has `release` (None when clean).
   No canary record or scan exists outside tests yet, so these are v1 implementation-time registrations (as the row).
7. **Pool details.** Only for roots of at least 1 MiB (starting the spawn workers costs more on small ones); `spawn`
   start method (as the frozen backends; no fork of a threaded parent); 8 contiguous runs per worker so a unit's
   repeated texts stay in one process's cache; `scan_workers()` honours CPU affinity.
8. **`release_check` follows I1's CLI rule** (written concurrently at 13:39): the first word `release` is reserved;
   I compared both on I1's test cases (identical accept/refuse sets). Ticket P2-A3-1 removes the second copy.
