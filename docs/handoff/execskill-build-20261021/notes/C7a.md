## Public API (`skillopt.execskill.fixtures`)

- `make_fixtures(out_dir, *, p99_workbook_bytes=None) -> dict`: returns the sealed record of kind `fixtures` (version
  `fivebench-execskill-v1-fixtures`, evidence `engineering_fixture`). It writes:
  - `<out>/{officeqa,livemath,spreadsheetbench}.json`: JSON lists of pool items `{benchmark, task_id, family_id,
    part="engineering_fixture", public, private}`, ids `fx-<bench>-00..19`;
  - the workbooks `<out>/spreadsheetbench/<id>/1_<id>_input.xlsx` and `1_<id>_answer.xlsx`;
  - `<out>/fixtures.json`, write-once.

  Record fields: `registration, seed, tag, benches{bench: {file, count, items[{task_id, sha256, truth}],
  set_sha256}}, set_sha256, p99{requested_bytes, task_id, input_bytes, answer_bytes} | null, crash_subset`.
  - Item hashes are the frozen `item_hash` of the item with workbook paths made relative to the root. The workbook
    bytes enter through `private.asset_sha256`. So a second directory gives the same record, and an identical
    rewrite is accepted.
  - With `p99_workbook_bytes`, `fx-spreadsheetbench-19` gets a second sheet `Padding` until its input is at least
    that size. The reference has the same padding. For example, 400,000 requested gave 404,148 bytes.
- `verify(out_dir) -> record` recomputes every item, workbook and set hash and raises ValueError on a difference.
  Also: `load_items(out_dir, bench)`, `item_sha256(item, root)`, `portable(item, root)`,
  `xlsx_bytes(data, cells, padding=())`, `officeqa_items()`, `livemath_items()`,
  `spreadsheetbench_items(root, *, p99_workbook_bytes=None)`.
- `FX_CRASH_SUBSET` / `crash_subset()`: `{officeqa: (fx-officeqa-15, -17), livemath: (fx-livemath-01, -05),
  spreadsheetbench: (fx-spreadsheetbench-15, -19)}`. These are the first two of each bench in the seeded sha256 order
  of (SEED, TAG, "fx-crash", task id), the `data.ranked` rule. `fingerprint(text)` and `crash_source()` are described
  under deviation 3.
- `fixture_package() -> Package`: step `smoke/fixture-x`, evidence `engineering_fixture`, order fx-note, fx-bindings,
  fx-print, fx-crash, fx-sheet-repair, fx-alf-tracker. At the time of writing its sha256 is `a13a7f64…7db`; it moves
  with route-B serialization changes.
  - Every hook kind (`applies, before_call, bindings, sheet_feedback, alf_before_step, alf_after_step`) is declared.
  - `policy.check` returns [] on all six sources.
  - Each procedure has a predicate, a description and replay tests.
- `fixture_placebo(items, *, unit, package=None) -> {task_id: {"procedures": {id: sham}}}`, the shape `placebo.arm`
  reads. It works for items of any smoke bench (SearchQA included).
- `replay_trajectories(out_dir) -> {cell: sealed trajectory}`:
  - every fixture item as a first request: token "fail" on even numbers, "pass" on odd. SpreadsheetBench items carry
    a stored pre-check report: an exception (`KeyError`) when "fail", `ok` when "pass";
  - two synthetic ALFWorld episodes, `ALF_FAIL` and `ALF_PASS`.

  Also: `public_input_dirs(out_dir, scratch) -> {cell: dir holding only input.xlsx}` and
  `cell(bench, task_id) = "fx/<bench>/<task_id>"`.
- `sandbox_suite() -> (bundle, cases)`, plus `SUITE_SOURCES`, `SUITE_EXPECTED` and `HEALTHY`. Each case is
  `{id, fn, args, timeout_s, action, inputs, expected{class, fault}}`.
- `determinism_hashes(worker, package, views, *, reverse=False) -> {"<bench>/<k>/<proc>/<fn>": value_sha256 |
  "fault:<kind>"}`.
- `add_arguments(subparsers)`, `make_fixtures_cli(args) -> 0`. The CLI prints record path, record_sha256,
  set_sha256, counts, p99, crash_subset and package_sha256.

## Deviations (with reasons)

1. **P is the irrelevant-text placebo, not the yoked P_y.** P_y needs a donor corpus of sealed run-slice trajectories
   (`placebo.build_y`), which only a real run has.
   - `fixture_placebo` shows one fact (`PLACEBO_FACTS = 1`) of the item's registered irrelevant text in every note
     slot that X has. The text comes from `placebo.irrelevant_text(task_id, unit)`, v3's eight control texts.
   - On ALFWorld it shows one such entry per step, with one discouraged command drawn at dispatch.
   - It is not length-matched to X's notes.
   - If S2 wants P_y, its driver can build it with `placebo.build_y` from X's own S2 trajectories after X has run.
2. **Printing is expected `no_fault` with the value intact, not a procedure fault.** Every call child has fds 0/1/2 on
   /dev/null (plan §4), so stdout is harmless by design. `fx-sbx-workbook`, which reads the p99-padded public
   workbook, is a measurement case and is also expected `no_fault`. Every other suite case is a procedure fault, and a
   healthy probe must answer before and after each one (the cell completes).
3. **fx-crash recognizes its subset by a text fingerprint.** The subset is chosen by item hash (the seeded sha256
   rank, recorded in the fixtures record). The procedure itself matches a 32-bit FNV-1a fingerprint of the task text,
   because a sandboxed procedure may not import hashlib or call `hash()`. `fingerprint()` computes the same value on
   the host, and `crash_source()` embeds the subset's fingerprints as a constant. A collision on a SearchQA item has
   odds of about 6 in 2^32.
4. **fx-bindings fires only on OfficeQA,** the one fixture bench with a table. LiveMath and SpreadsheetBench get notes,
   not bindings.
5. **Two-seed determinism runs on the routing views with no state** ("what the shell runs first"), not on later
   ALFWorld step views. The only faults it may show are fx-crash on its registered items; in the test that is
   `livemath/1/fx-crash/before_call`.
6. **Workbook bytes depend on the openpyxl version.** They are byte-deterministic for openpyxl 3.1.5, the dl env
   (fixed zip and document times; cached `<v>` values inserted). Another openpyxl version may write other bytes, which
   changes the set hash, though the record and `verify` stay self-consistent. Run `make-fixtures` on dl in the pinned
   env.
7. **The v7 recalculating qualification of the 20 SpreadsheetBench fixtures was not run** (it needs LibreOffice in
   the pinned image). They were checked only with the frozen cache-only comparison and target resolution above. The
   formulas are SUM, AVERAGE (the data makes the mean an integer), COUNTIF, MAX and row products, all with integer
   results, so recalculation should equal the cache. This stays unverified until the S0 `sheet` row.
8. **The padded item is also in the fx-crash subset.** `fx-spreadsheetbench-19` is both the p99-padded item and in the
   subset, by the seeded draw. This is harmless (fx-crash raises only in `before_call`), but its fx-crash fault is not
   a p99 effect.
