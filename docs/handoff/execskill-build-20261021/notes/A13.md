## Deviations from the plan, with reasons

1. **Manifest identity fields.** The plan's §2.9 `record_hash` is `record_sha256`, and the manifest carries
   `evidence`. Plan §2 and the hard rules require both on every record, through `protocol.record` and `verified`.
2. **Solver clients keyed by chain.** `clients.solver` is `{chain: block}`, following owner rule 22:3x (two chains
   from one manifest). §2.9 shows one block. `M`, `B` and `read_timeout` are `{bench: int}`, because chain D's values
   differ per bench. `check_clients` recomputes every field except B from `protocol`. B must be at least M; on branch N
   it depends on S1's longest reply.
3. **`in_image_pip_freeze_sha256`** is the digest of the five library versions the worker's ping reports (python,
   numpy, openpyxl, pandas, sympy). The plan says "via one sandbox ping", and the ping does not run `pip freeze`. A
   full freeze would need another container argv. `in_image_libs` holds the versions themselves.
4. **`measured`** holds `vsz_kib`, `rss_kib`, `view_bytes_p99` and `native_peak_rss_kib`. The last one is the plan §5
   memory rule input (native slots 3 → 2).
5. **smoke.py judges, it does not dispatch.** The stage functions judge the measured inputs of their stage, and
   `record` stores the result write-once. The registered runners (rounds, units, step) must dispatch the S1 probes and
   the S2, S-N1, S3 and S4 cells. That dispatch is **not implemented** (see "Missing").
6. **The S-N1 noise anchor** (per-bench SD of a same-text paired difference) is an input of `smoke-make`, recorded in
   the spec. `protocol` registers no per-item value; REG §3.3 gives per-contrast anchors in points. **Open item for
   the registrar.**
7. **`smoke-result.json`** is written once, when every stage has a record. Before that, `smoke-summary` reports and
   writes nothing.
8. **`verify_unit`** turns a code mismatch into `ConfigurationError` (stop kind `configuration`), so the chain
   terminates instead of crashing.
9. **The D3/D14 pattern** `/feasibility/(D3|D14)(/|\s|$)` was taken from the registered trace roots
   (`/data/feasibility/D3/...`). No such process ran on the datatools machine at 03:41, so the operator should confirm
   the pattern at S0 on the machine where the workers run.
10. **Test placement.** The pre-launch tests are in `tests/test_execskill_manifest.py`; the row owns no separate file
    for them.
11. **Mutation coverage.** The suite has 16 mutations, one more than the task's 15:
    - (1)-(9) and (11)-(15) from the original list.
    - (17), preflight reads the last receipt.
    - (25), S1-e counted as production. This one checks this row's own `smoke.py`.

    (10) needs `evaluation.py` (A12), which is not in the tree yet. (16), (18)-(24) and (26)-(30) are not included.
    Several of them target A12's modules: (19), (20), (29).
