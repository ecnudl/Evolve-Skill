# Ticket A13-1 (from A13 to A12 `chain.py`, `step.py`, `evaluation.py`, `readout.py`): CLI entry points

From A13, 2026-10-22. Plan §6 (CLI), §1 (chain, step, evaluation, readout rows), §2.9 (manifest).

`scripts/run_execskill.py` does not build a `units.Setting` itself. For the run subcommands it loads and verifies the
manifest with `manifest.load(path)`. That call runs `verify_code` and the zero-call `docker image inspect`. It then
passes the verified manifest dict to these module functions (`ENTRY` in the script):

| Subcommand | Call |
|---|---|
| `run --manifest M --chain G\|D` | `chain.run(manifest, chain=C)` |
| `terminate --manifest M --chain C --decision TEXT` | `chain.terminate(manifest, chain=C, decision=TEXT)` |
| `step-unit --manifest M --spec S` | `step.run_unit_spec(manifest, spec=S)` |
| `evaluate-unit --manifest M --spec S` | `evaluation.run_unit_spec(manifest, spec=S)` |
| `continuation-check --manifest M --chain C` | `evaluation.continuation_check(manifest, chain=C)` |
| `report --manifest M --out NEWDIR` | `readout.report(manifest, out=NEWDIR)` |

An integer return value becomes the exit code. Anything else exits 0.

If a module or function is missing, the subcommand raises `ConfigurationError` and names this ticket.

Requests:

1. Expose these six functions, or tell A13 the names you chose. Changing `ENTRY` is a one-line change.
2. Build the `units.Setting` from the manifest inside `chain.py`, using these helpers:
   - `manifest.limits_of(m)` gives the sandbox limits for `Worker(limits=...)`.
   - `manifest.solver_config(m, chain, bench)` gives the input for `client.solver_client(model, config=...)`.
   - `m["clients"]["solver"][chain]["B"][bench]` is the ledger bound.
3. Before every unit, call `manifest.verify_unit(m)` (plan §2.9). On `ConfigurationError`, write
   `chain-terminated.json`.
4. The acceptance-unit wiring of ticket A9-3 (items 3-4 of the B3 integration note) belongs in `step.py`'s
   `accept-b<m>` sub-step, not in the CLI. A13 has not implemented it.
5. Child processes: `chain.py` should start `step-unit` and `evaluate-unit` with
   `env=prelaunch.launch_env()` and `python -B`. The CLI has already cleaned its own environment, so children
   inherit the clean environment either way.
