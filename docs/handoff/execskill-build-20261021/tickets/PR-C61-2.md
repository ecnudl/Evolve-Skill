## Defect 1: the generated private fields carry no `asset_sha256` → configuration pause

`generators/sheet.py:183` writes `private_fields = {"test_files": [answer], "answer_position": ...}`. The frozen v7
scorer re-checks every reference against `private["asset_sha256"]` before it scores
(`continual_eval/sheet_numeric_adapter.py:93-94`, "Reference asset changed"); `backends.score` turns the ValueError
into `native_scoring_input_error:ValueError` (`backends.py:566`), and the frozen qualification check pauses on that
prefix (`coevo5/qualify.py:63-64`, `Pause("configuration", ...)`).

Observed: `generators.generate(sheet.FAMILY, ...)` with the production engines → `Pause("configuration",
"native_scoring_input_error:ValueError")` at the item's first engine-qualification scoring. The same pause would hit
every later scoring of a generated SpreadsheetBench item (band probe, G_self cells), because they score the item's
`private` too. Pool items bind both files (`fixtures.py:360`; the frozen panel loader keeps `asset_sha256` keyed
by the materialized paths, `continual_eval/datasets.py:258-259`).

Fix: `private_fields["asset_sha256"] = {str(paths["input"]): sha256(input bytes), str(paths["answer"]): sha256(answer
bytes)}` (the pool items' shape), computed after the files are written and before `engine.qualify`.

## Defect 2: the generated reference has no formula caches → every item `engine_qualification_failed`

`generators/sheet.py:176-181` loads the original workbook with formulas and saves it with openpyxl, which drops every
formula cache (`<v>`). The frozen v7 scorer's drift guard compares the engine's recalculation of the reference with
the reference's own caches (`continual_eval/sheet_recalc.py:610-612`); a reference formula cell without a cache is
"unavailable: formula cache not established" (`spreadsheet_compat.py:246-260`), so every scoring is
`unknown: reference_native_cache_drift_or_unavailable` and the item is excluded (category
`reference_cache_mismatch`) → `Drop("engine_qualification_failed")` for every parameter set.

Observed: with Defect 1 patched by hand (the same task plus `asset_sha256`), `engine.qualify` gave qualified 0,
excluded `{"gen:g-check-1:0": "reference_cache_mismatch"}` (2 scorings, 0 model calls); the generated `answer.xlsx`
had no cached value in its answer cell D2.

Verified fix candidate: recalculate the generated `answer.xlsx` with the same engine (`engine.recalc(answer)`, one more
container run under the native slot) and use the receipt's `output_base64` bytes as the generated reference (fresh
caches from the qualified engine; numeric literal texts restored by the frozen v5 step). Observed: with
`asset_sha256` of that file, `engine.qualify` gave qualified 1/1 (2 scorings, 0 model calls). An alternative is to
write the caches into the sheet XML as `fixtures.xlsx_bytes` does (`fixtures.py:291-312`). Either way, the expected
values in `truth.expected_cells` stay the engine's. Note: the generated input workbook loses its formula caches in the
same save (the fixtures' inputs have no formulas; real SpreadsheetBench inputs may have them), a fidelity point for
the same decision.

## Why the existing tests do not see it

`tests/test_execskill_generators.py::FakeEngine.qualify` accepts any task (T-GEN-3), and
`tests/test_execskill_engines.py` fakes `backends.score`; only a real v7 scoring checks `asset_sha256` and the caches.
A regression test could run `sheet.apply` with a fake recalculator and the REAL frozen `sheet_numeric_adapter._context`
asset check, or assert directly that `private_fields["asset_sha256"]` binds both written files and that the
reference's answer cells carry caches (`openpyxl.load_workbook(answer, data_only=True)`).
