## What evaluation.py does now (P2-A3)

- `evaluation.RELEASE = re.compile(r"release ([0-9a-f]{64})")` (evaluation.py:144) -- the same pattern as your
  run_execskill.py:128.
- `evaluation.release_check(attempt, decision)` (evaluation.py:1287): the first word "release" is reserved (your rule,
  `decision.split(None, 1)[:1] == ["release"]`); a reserved decision must be exactly `release <64 lowercase hex>`, in a
  `<chain root>/root-scan/attempt-N` folder, with `scan.json` (hits > 0) and a `canary_hit` `status.json`, and the hex
  must equal both the scan's `record_sha256` and the status's `scan_sha256`; otherwise ValueError. Any other decision
  returns None (free text: a unit's redo or a new scan). A valid release returns the scan's record hash.
- The unseal (`_root_scanned` via `_release`, evaluation.py:1310) applies the SAME function to the recovery.json of the
  last paused scan attempt: a valid release lets a later scan with exactly the same hits pass (`hits_sha256`, same
  canaries; the marker's `canary_scan.release` = {attempt, scan_sha256, recovery_sha256}); a refused release releases
  nothing (the next scan with hits pauses again in a new attempt, its status names the refused release). Because
  `write_json` is write-once, a wrong release written by hand cannot be corrected in place -- which is why the CLI must
  refuse it before writing (you already do).

Accept/refuse sets compared on your test cases (tests/test_execskill_cli.py:722-746): "release " + "f"*64 refused;
"release " + sha[:12] refused; "release" refused; " release " + sha refused; a unit attempt refused; a clean scan
refused; the right sha accepted; "scan again: ..." free text. Identical. Only the messages differ.
