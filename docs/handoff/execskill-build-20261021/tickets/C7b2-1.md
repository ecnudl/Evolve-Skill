# Ticket C7b2-1 → C6 (step.py, units.py) and the main agent: S4 cannot run `step.run_step` on the smoke ledger

From C7b-2, 2026-10-22. Registration §10 S4; plan §10 step 7.

`step.run_step(setting, chain, bench, k, parent, *, services)` requires `chain in CHAINS` (G or D). Its endpoints come from
`units.solver_endpoint` / `units.role_endpoint`, which charge `budgets.solver_scopes(chain, bench, k, kind)` /
`budgets.glm_scopes(chain, role, bench, k)`, i.e. `D:xs:searchqa:1:run` etc. The smoke Setting
(`manifest.setting_of(m, "smoke")`) declares only `smoke_caps()` (`overall`, `smoke:solver`, `smoke:glm`), so
`budgets.endpoint` refuses every step endpoint ("Undeclared ledger scopes") before anything is sent; with chain "smoke"
`units.solver_endpoint` fails on `CHAINS["smoke"]`. `run_step` also has no SearchQA slice registration for the smoke
cut (`step._slices` reads `SLICES`; S4 needs run 20 / accept 40 = `protocol.S4_SLICES` on the 60 smoke items
220-279 of the SearchQA tail file, see `smoke._slice`).

Needed (one of):
1. a smoke mode of the step: `run_step(..., chain="smoke")` whose solver endpoints use
   `budgets.solver_scopes("smoke", None, None, "smoke")` with chain D's model and B (`protocol.ledger_bound`), role
   endpoints `budgets.glm_scopes("smoke", role, None, None)`, consumption namespace `smoke` (registry.NAMESPACES has
   it), the S4 slices, and the unit roots under `<smoke root>/units/S4/`; or
2. a registered decision that S4 runs on a temporary per-chain-shaped ledger inside the smoke root (D scopes with the
   smoke's 14M as their cap), recorded as a v1 implementation-time registration.

Until then `smoke.run_stage(..., "S4")` refuses ("not run by run_stage"). `smoke.FaultSwitch` (C3) and
`smoke.s4_ministep` exist; the drill function that writes the owner-format `recovery.json` is not written either.
