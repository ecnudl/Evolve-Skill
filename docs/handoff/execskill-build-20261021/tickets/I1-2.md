## Done on I1's side (ticket C7d-2, binding part)

`manifest.services_of` returns `manifest.Services`, a frozen subclass of `step.Services`. Its `checker` is always
`generators.livemath.WorkerChecker(self.workers)`: it is made in `__post_init__`, and made again whenever
`_Step.unit` re-binds `workers` to the running unit's tag (step.py:242, `dataclasses.replace(services,
workers=functools.partial(services.workers, tag=...))`; `replace` runs `__init__` and so `__post_init__`). A
WorkerChecker over other workers is replaced; any other checker (a test fake) is kept. Every LiveMath solve therefore
already runs under the generate unit's tag. Test:
`tests/test_execskill_manifest.py::test_c7d_2_the_livemath_checker_follows_the_units_tag_bound_workers`.

## What remains (step.py, yours)

correct, but slower. The addendum asks for "a session around `examiner.build`". Proposed patch in `step._build`
(step.py:485-492 at 14:30); `nullcontext` is already imported (step.py:84):


`_build` runs inside the generate unit's `work`, while `_Step.unit` has `st.services` re-bound (step.py:240-250), so
the session's worker carries the unit's tag and is drained with the unit. `WorkerChecker.session` refuses a nested
session ("One checker session at a time"), so `examiner.build` must not open one itself (it does not today).

Suggested test (yours): a LiveMath `_build` with a fake worker factory that counts opened generator workers: one
worker for a build of several specs, tagged with the generate unit's tag.
