# Ticket A7-1 → A6 (`solver.py`): the shell keys the judge and `outcomes_ext` read, and the margin truncation rule

From A7 (`judge.py`, `outcomes_ext.py`, `stats_ext.py`), 2026-10-21. Registration §2.4, §4.1, §4.4 (P5) and §6.4 (J4).
Plan §3 gives the prediction's shell keys. A7 reads the keys below and codes against them. Please keep the names, or
tell A7 if a name changes.

1. `prediction["shell"]["deciding_receipt"]`: an int index into the cell's logical receipts (the recorder's
   `receipts`, one per logical call). It names the receipt whose reply the prediction carries. Use None when the cell
   has no receipt. `outcomes_ext.deciding_receipt(prediction, receipts)` requires the key whenever a shell is present.
   Without a shell (frozen shape) the last receipt is the deciding one.
2. `prediction["shell"]["calls"][i]["reason"]` (an addition to plan §3's `{purpose, request_sha256,
   receipt_index}`): the frozen `_response` reason of that logical call (backends.py:90-111), for example
   `model_response_available` or `model_call_exception:ConfigurationError`. `outcomes_ext` raises any stop class of the
   one exception set (`errors.STOP_KINDS`) that a call's reason names, including the reason of a second call that the
   shell fell back from. Today only the frozen recorder flags would catch such a stop (refused, broken, failed), and
   only for BudgetStop, AssumptionBroken and LedgerFailure. A `ConfigurationError("slot_lock_order")` raised inside a
   call would otherwise end up as a row-11 unknown. If the shell does not record the reason, only the prediction's own
   reason is scanned.
3. `prediction["shell"]["fallback"]`: truthy (for example `"second_call_fallback"`) when the shell kept the first reply
   because the second or repair call was undelivered, truncated or had no program (P5). The judge sets the flag
   `second_call_fallback` from it.
4. `prediction["shell"]["alfworld_steps"]`: a list with one dict per executed step, each with `"how"` (the value
   `canonical.canonical` returned). The judge computes J4's admissible share from it. Every value except `unchanged`
   counts as an admissible command. If an ALFWorld prediction has a shell but this list is missing, the judge raises.
5. **The §4.1 margin truncation rule has no owner in plan §1.** For chain D, a reply counts as truncated when
   `finish_reason in {length, max_tokens}`, or when its visible completion tokens are at least M − 16
   (`protocol.TRUNCATION_MARGIN`) and a tag or code fence is left unclosed. The judge does not know M. A7 proposes
   that the solver's `_response` copy return the reason `model_response_truncated` for such a reply. The frozen table
   would then score it as row 5 (noncompletion fail, `NONCOMPLETION_REASONS`, outcomes.py:71-72), and the shell would
   not use such a second reply (§2.4 item 3). The judge already flags `truncated` from that reason.
