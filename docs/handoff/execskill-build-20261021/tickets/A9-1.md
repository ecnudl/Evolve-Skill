## 1. Blocking for SpreadsheetBench: donors have no pre-check report when the parent has no `sheet_feedback`

Registration §6.1 runs `sheet_feedback` "on the donor's stored pre-check report". The shell only runs the pre-check
when a `sheet_feedback` procedure is enabled (`solver.py:621-623`, `if shell.enabled(("sheet_feedback",))`). So when the
parent S has no enabled `sheet_feedback` on a run-slice item, its trajectory has `shell.precheck = None`. That is the
usual case for the FIRST sheet procedure, the most likely SpreadsheetBench edit. `donors.donor_corpus` then gives that
donor no sheet advice, and the P_y sham for a new `sheet_feedback` procedure is empty: P_y shows nothing where S'
shows advice, so J2 no longer tests the content.

The decision needs the owner or main agent. Two options:

- (a) A6: on SpreadsheetBench run-slice cells, run the pre-check on every delivered program and store the report,
  even with no `sheet_feedback` enabled. This adds one container run per cell and no model call. The request and the
  prediction are unchanged, so T-SOLVER-1's projection still holds, but `native.cases` counts change.
- (b) A8/A13: at sealing time, the registrar pre-checks the donor's stored first program on the donor item's public
  workbook. This uses the sandbox and no model call. `donors.donor_corpus` would take a `precheck(trajectory) ->
  report` callable for trajectories without a stored report. A9 can add this in an hour once (b) is chosen.

Until then `donors.donor_inputs` reads `trajectory["shell"]["precheck"]` only. A donor without a report gives no sheet
advice, which is the registered rule.
