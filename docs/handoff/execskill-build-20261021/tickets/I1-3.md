# Ticket I1-3 → registrar: `recover` and an attempt without a pause record (registrar addendum 15:5x, R6 (c))

From integrator I1 (phase 2b part (c)), 2026-10-22. Not applied: the change as worded would strand interrupted
attempts. Does not block the pilot.

## What R6 (c) asks

"`recover` refuses an attempt directory that holds no pause record" (`scripts/run_execskill.py` `recover`, which
writes the owner's write-once `recovery.json`).

## Why it was not applied literally

The units rule copied from coevo5 (`skillopt/execskill/units.py` module docstring, lines 4-9) is: "an attempt after a
pause **or an interruption** runs only once the owner's decision is recorded in the earlier attempt
(`recovery.json`)". An interrupted attempt has `started.json` but no `status.json`: the process was killed, the
machine went to sleep, or an evaluation child died mid-attempt. Its unit cannot start a new attempt until the owner
runs `recover` on it. A refusal keyed on `status.json` (the pause record) would leave such a unit with no way forward
except hand-writing `recovery.json`.

## The hazard R6 (c) points at

Today `recover` accepts any `attempt-N` directory whose unit has no `unit.json`. That includes an attempt that is
still running (no `status.json` yet). A `recovery.json` written into a running attempt makes that attempt's later
pause look decided: the next relaunch opens a new attempt although the owner never saw that pause.

## Options (registrar's choice)

1. Refuse while the attempt is running and when it never started: probe the unit's lock without blocking
   (`coevo5.cells.exclusive(<unit root>/.lock)`, which every unit and read unit holds while it runs:
   `units.run_unit`, `evaluation.py:893`). Refuse when another process holds the lock, and when the attempt holds no
   `started.json`. Accept a paused attempt (`status.json`) and an interrupted one (`started.json`, lock free). The
   root-scan attempts (`<root>/<chain>/root-scan/attempt-N`) need the same check against their own lock. The probe
   takes the lock for a moment, so a relaunch racing with it fails with "Another process owns" and can be rerun.
   About 30 lines plus tests (a held lock, a never-started attempt, an interrupted attempt, a paused attempt) and
   one mutation entry.
2. Refuse only an attempt that never started (no `started.json`, no `status.json`). This does not cover the running
   attempt.
3. Keep `recover` as it is and add a pilot-runbook line: run `recover` only on an attempt that `monitor` lists under
   "open" while no `run`, `step-unit` or `evaluate-unit` process of that chain is alive.

I1 recommends option 1, or option 3 as the zero-code fallback before the pilot.

## Status

Open. Nothing changed in `recover`.
