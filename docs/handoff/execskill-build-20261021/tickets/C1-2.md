# Ticket C1-2 → A6 (`solver.py`) and the main agent: SpreadsheetBench shortcut probe "no workbook" needs a solver view

From C1 (examiner row), 2026-10-22. Registration §7.2 (shortcut gate: "表格题去掉工作簿"); plan §1 examiner row.

The SpreadsheetBench shortcut probe runs the card arm on each probe item twice WITHOUT the workbook. An item solved in
both runs is dropped, and a dropped share above 25 % rejects the set. The copied solver cannot build such a view:

- `solver._sheet_view` (solver.py:150-153) always sends `workbook_preview` built from `view["input_files"][0]`;
- solver.py:176 requires `input_files` for every SpreadsheetBench item;
- the frozen preview comes from the same file (continual_eval/backends.py:342 `_sheet_preview`).

A generated item cannot express "no workbook" through its public fields alone. Request: a registered shortcut mode
for SpreadsheetBench cells, e.g. `solver.solve(..., shortcut="no_workbook")` or a routing-view flag. It must:

- hide the workbook preview, and any sheet content, from the model;
- still run the produced program on the real input file, so the official scorer can grade the output;
- record the mode in the cell record.

Until then `examiner.shortcut_variant` raises `ConfigurationError("spreadsheetbench_no_workbook_variant ...")`.
`examiner.gates` then records the SpreadsheetBench shortcut gate as `not_run`, so no SpreadsheetBench generated set
can be admitted. OfficeQA (question only) and LiveMath (options only) variants work: they are plain public-field
blanks.
