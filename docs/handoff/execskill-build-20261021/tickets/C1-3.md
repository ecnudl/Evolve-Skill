# Ticket C1-3 → main agent (`step.py`, owner decision): how G_acc is generated "on the A* public views"

From C1 (examiner row), 2026-10-22. Registration §3.3 (G_acc sizes), §5.3, §7.2 (predictive validity, FE-F1);
`acceptance.prepare(generate=...)` (acceptance.py:96-122); ticket A9-3.

The registered families draw on researched material (OfficeQA tables, LiveMath definitions), not on an item's public
view. So `examiner.g_acc(items, astar, *, bench, generator)` reads "generated on the A* public views" as follows:

- the frozen generator's G_acc set is `examiner.build(..., set_name="G_acc")` on the g_acc research half, keeping
  only items its gates kept;
- in the seeded order `execskill-v1:examiner-probe:<generator>:g_acc`, these items are paired one to one with the A*
  items, at most `G_ACC[bench]`;
- the A* views fix only the size and the pairing (the blocks). No role sees a G_acc item.

This fits `prepare`'s contract ([{"id", "source_item"}], one per A* item). Please confirm, or register another
reading.

SpreadsheetBench is open:

- `spreadsheetbench.formula_edit` edits named cells of the source workbook a spec was written for. `sheet.apply`
  (generators/sheet.py:123-175) needs that item's reference workbook. Frozen specs therefore do not transfer to an
  A* workbook.
- Writing edits for A* workbooks would show A* public views to the examiner before acceptance.
- Options:
  (a) build SpreadsheetBench G_acc from the g_acc half's own source tasks (pool items outside A and outside the
      test pool) and pair them with A* like the QA benches;
  (b) no SpreadsheetBench G_acc, so validity is `not_evaluable` there.
- `step.py` must also choose which source tasks the generator payload shows. It must never show an acceptance or
  test-pool item.
