S-E6 compares, for EVERY scope cap of `budgets.caps()` (incl. each chain's test read), measured tokens per cell x the
measured ledger/actual ratio x the MAXIMUM-schedule cell count (calc T4-T6) + one full next reservation

slices and `G_ACC`, not T4-T6's counts per (bench, kind) and for the test read, and no registered "largest request
bytes per bench" for R. Deriving them in smoke.py would be a second, unregistered copy of the calc.

cells per bench, copied by value from `docs/handoff/execskill-calc-20261021.py` T4-T6 (no value changes, hashed into
the manifest like the other constants), and a rule for R's request bytes (the S2/S-N1/S4 cells' largest measured
request bytes per bench is the natural one; registrar's call). Then `run_stage(..., "SE6")` is a zero-call reader of
the S2/S-N1/S4 records and the smoke ledger.
