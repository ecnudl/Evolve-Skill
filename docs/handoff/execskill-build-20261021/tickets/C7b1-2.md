# Ticket C7b1-2 → main agent (exporter) and C6 (manifest.py): the SearchQA pool export and the per-call slot size

From C7b-1 on 2026-10-22. It concerns tickets C6-3 and A5-1, registration §3.4 and §10.

## 1. The pool export

No built command exports the pools that both of these need:

- `data.pools` (C6-3), for the pilot.
- `run_execskill.py smoke-items --searchqa-pool F`, for the smoke.

The smoke's SearchQA slice is the last 280 items of the SearchQA pool in `supply.order`. The pool has 600 items, and
`supply.registered_sizes` needs at least 580. The v3 training panel (`data.paths.train`) alone holds only 400 items
(partition development). The remaining items sit in the v3 val half, and build agents may not open that half. So
`smoke-items` takes an exported pool file by path:

- Format: a JSON list of `{task_id, public, private, ...}`.
- Producer: the operator, through an approved exporter.

C7b-1 did not read the val paths, and did not run `smoke-items` on real data.

## 2. The per-call slot size

The S0 memory guard follows A5-1:

- Σ slots × peak RSS ≤ 0.7 × MemAvailable.
- If that fails, per-call slots go 4 → 2, then live slots 6 → 4.

`s0.limits` derives and records this as the `guard` field of `<root>/s0/s0-limits.json`. However, a reduced per-call or
live slot count is not a manifest field. `slots.pools(sizes=)` accepts it, but `setting_of` registers only the native
change from 3 to 2. So when the guard is not met at the start sizes, the S0 measurements row fails and writes no pins.

On 2026-10-22 the guard was met: 1,146,384 KiB ≤ 7,762,974 KiB, with MemAvailable 11,089,964 KiB.

**Needed:** a manifest field `slots`, as `{per_call, live, native}`, read by `setting_of`. `s0-collect`'s pins would
then add it next to `limits` and `measured`.
