# Ticket P2C-1 → I1 / registrar: `step-unit` runs a step without the first-call confirmation

From P2C, 2026-10-22 16:xx (registrar addendum 14:10, row 7).

`chain.run` now makes the chain's one confirmed first call (`chain.first_call`) before step 1, and every relaunch
reuses `$PILOT/<c>/confirm.json`. The pilot runbook launches chains only through `run` (`chain.run_manifest` ->
`chain.run`), so the pilot path is covered.

`run_execskill.py step-unit --manifest M --spec S` (`runcli.step_unit` -> `step.run_unit_spec`, ticket A13-1 item 5)
is a second entry point that runs one step of a chain in a child process without going through `chain.run`. It
declares `budgets.chain_caps(chain)` only and never calls `chain.first_call`. Used on a fresh chain, it would start the
SpreadsheetBench run unit (up to 16 concurrent cells) with no confirmed first reply.

Options (pick one):

1. In `step.run_unit_spec`, after the ledger declaration: declare `budgets.first_call_caps(chain)` as well and call
   `chain.first_call(setting, chain)` (it returns the stored `confirm.json` when the chain has one, so a child of a
   confirmed chain makes no call; a failure raises `Pause("first_call_unconfirmed")`, which the function maps to
   `EXIT_PAUSED`). Add a test beside `test_execskill_runcli.py`'s step-unit test and a mutation entry.
2. Or record that `step-unit` is never an entry point for a chain without `confirm.json` (runbook section 6.3), and
   have `run_unit_spec` refuse such a chain (`require((chain_root / chain.CONFIRM).exists(), ...)`).

Not built by P2C: `step.py` / `runcli.py` are outside the row-7 scope of the addendum and the choice is the registrar's.

## Status

Decided by the registrar (addendum 2026-10-22 15:3x) and applied by I1 in phase 2b (c), close to option 2:
`step.run_unit_spec` calls `chain.confirmation(root, run, chain)` before anything is touched. It requires
`<root>/<chain>/confirm.json` to exist and to be a verified `first-call` record of this run and chain that passed;
otherwise `ValueError` ("no confirmed first call" / "A first-call record of another run"), and no ledger, attempt or
unit file is written. `chain.first_call` reuses the same check for its relaunch reuse. `step-unit` also declares
`budgets.first_call_caps(chain)` beside `chain_caps`, so its ledger matches the one `chain.run` declares. Test:
`tests/test_execskill_runcli.py::test_step_unit_runs_one_step_of_the_order_and_maps_its_pause_to_the_exit_code`
(missing, another run, another chain, not passed, then a pass); mutation entries 56 and 57. Pilot-runbook rows 7 and
§6.3 updated.
