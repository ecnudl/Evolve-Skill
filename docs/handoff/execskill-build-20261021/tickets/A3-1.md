# Ticket A3-1 -> A1 (`skillopt/execskill/protocol.py`: `LEXICON_MATCH`, `LEXICON`)

From: A3 (`notes.py`). Kind: a registration question. It needs an owner/A1 decision before S2. A3 changed no code
outside its row.

`notes.py` applies the registered rule exactly as `protocol.LEXICON_MATCH` states it:
- matching is case-insensitive;
- a term that starts and ends with a letter matches on word boundaries, and its spaces match any whitespace;
- any other term matches as a substring.

`tests/test_execskill_notes.py::test_matching_rule_is_the_registered_one` pins this rule. It has two consequences:

1. **Inflections are not matched (false negatives).** The screen lets these through: "answers", "answered",
   "responds", "outputs", "returned", "returns", "rounded", "rounding", "formatted", "formats", "decimal place".
   So a note such as "Rounded to two places, in millions" reaches the solver. The only backstop is the J4 format
   guard on the real batch (REG §6.4).
2. **Ordinary words in verbatim item text are faults (false positives).** A `facts`, `table` or `bindings` field
   that quotes the item is dropped and counted as one procedure fault. Examples: "Total return on investment",
   "in units of 1,000", "The Return of the King", "round lots". Each such fault counts toward the J3 2% fault cap
   (REG §6.4: items of A with >= 1 fault of a changed procedure, divided by |A|). So a procedure that quotes
   OfficeQA tables faithfully can be refused by J3 even though it never wrote a format directive.

Request: either confirm the rule as registered (A3 keeps it), or register one of these options:
- (a) **Stems.** A term that ends with a letter also matches with the suffixes `s|es|ed|d|ing`. This closes 1.
- (b) **Exempt verbatim text.** Do not screen a binding's `quote` and table cells that are verified verbatim
  against the item's public text, because their content is the item's, not the procedure's. This closes 2 for
  those fields only. A procedure can still write directives in `facts`, `candidates` and `warnings`.

Either option is a small change in `notes._pattern` / `notes.screen`, plus the `LEXICON_MATCH` text in
`protocol.py`. Both change `notes.lexicon_sha256()` and `protocol.LEXICON_SHA256`, so the choice has to be made
before S2 (plan §11).
