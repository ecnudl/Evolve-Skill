# Ticket A5-2 (from A5 to A12 `chain.py`/`units.py` callers, A13 ops, and the registrar): prefix-wide drain check vs two concurrent chains

Needs a decision before the formal run (chains G and D). It does not block B2.

`sandbox.client.drain_check(prefix="execskill-sbx-")` is implemented as registered (REG §2.6, plan §4, Codex F14):
after every worker of a unit has exited, no container whose name starts with the prefix may remain, else
`CleanupUnconfirmed`. Plan §5 and REG §4.1 / §11 also let chains G and D run concurrently: QA units may overlap,
and the `execskill-sandbox-live` pool is machine-wide. When one unit drains while a unit of the other chain still
has live containers, the prefix-wide check lists those containers and raises a spurious `CleanupUnconfirmed`. That
error is a stop.

Options (pick one, then write it into the registration or the formal addendum):
1. Call `drain_check` only at a point where no other route-B unit runs, for example a chain-level drain when both
   chains are idle.
2. Add a per-unit component to the container name, `execskill-sbx-<unit tag>-<uuid4>`, and drain with
   `drain_check(prefix="execskill-sbx-<unit tag>-")`. This changes the registered `--name execskill-sbx-<uuid>`.
   `drain_check` already takes `prefix`, so only the naming in `Worker._ensure` and `client.NAME` would change
   (owner A5).
3. Check exactly the names the unit started (`Worker.names` of all its workers), and run the prefix-wide check
   only at chain end.

A5 kept the registered naming and made no change.
