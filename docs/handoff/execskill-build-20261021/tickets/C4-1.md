# Ticket C4-1: G_acc and G_self items share their item ids

From: C4 (completion, end-to-end test), 2026-10-22. To: the owner of `skillopt/execskill/examiner.py` (C1) and the main
agent. Protocol `fivebench-execskill-v1`; registration §7.2 and §3.3; plan §2.5.

## What happens

`step._g_acc` builds the frozen generator's G_acc items through `examiner.build(..., set_name="G_acc")`. The
generate unit built the G_self items through the same call with `set_name="G_self"`. `examiner.build` numbers its items
from 0 on every call (`results, count, used = [], 0, Counter()`), and `generators.generate` names an item
`"gen:%s:%d" % (generator, number)` (`generators/__init__.py:74`). So the first G_acc item and the first G_self item of
one generator are both `gen:g-officeqa-2-1:0`, the second ones both `...:1`, and so on. The two items differ in content,
`set` and `material_id`.

The e2e pilot (`tests/test_execskill_e2e.py`) runs this path for OfficeQA. Today nothing joins the two sets by id:

- the self-test cells hold G_self ids only, in the `selftest` unit;
- the acceptance cells hold G_acc ids only, in the `accept` unit;
- `validity.round_pair` reads one round's cells;
- generated items are not in the consumption registry.

So no number is wrong today. But a generated item id names two different items, and any later join by id breaks: a
validity pass over the self-test and acceptance cells together, or a readout of generated items across sets.

## Requested change

Give `examiner.build` a `start` keyword (default 0), passed on to `generators.generate(start=...)`, so the item numbers
of one generator never repeat across its sets. `step._g_acc` would then pass a start past the generator's G_self
numbers, for example the made count of the G_self build recorded in the generate unit.

An alternative is a set-qualified id, `gen:<generator>:<set>:<n>`. That changes the registered item shape of plan
§2.5 and `examiner.g_acc`'s prefix check.

## Not changed by C4

`examiner.py` is C1's file, and the id form is part of the generated-item record (plan §2.5). C4 fixed only
`step._g_acc` (the frozen specs are rebound to the g_acc half's materials, see note C4).
