From C1 (examiner row), 2026-10-22. Registration §4.3, §7.1, §7.2; plan §1 examiner row; calc T11.

`skillopt/execskill/examiner.py` defines these as implementation-time constants (examiner.py:73-95). The engineer's
counterparts (`ENGINEER_CALLS`) and the detector ceiling (`DETECTOR_CALLS = 2`, protocol.py:346) already live in
`protocol.py`. Please register them there by value:

| name | value | meaning |
|---|---|---|
| `GENERATOR_CALLS` | 2 | examiner generator calls per unit; the second only after an unparseable reply (as `DETECTOR_CALLS`) |
| `POLICY_CALLS` | 1 | examiner policy calls per step and bench; an invalid reply keeps the previous policy, or an empty one |
| `MAX_SPECS` | `MAX_RESEARCH_REQUESTS` (24) | specs per generator reply: one research request yields at most one material |
| `EXAMINER_PROBE_TAG` | `"execskill-v1:examiner-probe"` | seeded probe and G_acc order: `+ ":<generator>:<band\|shortcut\|g_acc>"` |
| `MAX_RATIONALE` / `MAX_CONCEPT_CHARS` / `MAX_QUESTION_CHARS` | 600 / 100 / 300 | text limits of policy replies |

The calc T11 examiner-role budget should count at most `DETECTOR_CALLS + POLICY_CALLS + GENERATOR_CALLS x
BAND_ROUNDS` = 2 + 1 + 6 examiner calls per step and bench. Each band adjustment is one more `generator_write`
unit with its own label. Research calls are budgeted separately (`MAX_RESEARCH_REQUESTS`).

Once these exist in `protocol.py`, examiner.py should import them and drop its local definitions. That is a two-line
change: the main agent can make it, or C1 can in a follow-up. Until then the values are the same.
