# A10-2 -> A9 (donors.py): donor_inputs refuses an ALFWorld episode whose last step request got no reply

Raised by A10, 2026-10-22. Coded around in A10: `replay.inputs_of` has its own tolerant rule.

`donors.donor_inputs` requires `len(views) == len(actions)` ("One request per stored ALFWorld step"). The shell appends
an `alfworld_steps` entry only after a usable reply: in `solver._solve_alfworld`, `response is None` returns
`shell.unknown(...)` before `shell.steps.append(entry)`, while the request itself is a logical call of the trajectory
(`trajectories.build` keeps every call of the final solve). Such an episode stores n+1 step requests and n steps, so
`donor_corpus` raises `ValueError` on a run slice that contains one (a truncated or filtered step reply is enough).

Suggested rule (what `replay.inputs_of` does): keep every step request's view; the action is the stored step's (None
for the unanswered last request); an event exists only for a step with an action and a following request. The
unanswered request then still gets `alf_before_step` (as the shell called it before the request was sent).
