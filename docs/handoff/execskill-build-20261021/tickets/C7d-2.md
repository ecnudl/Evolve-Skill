# Ticket C7d-2 → integrator (I1) / owner of `manifest.services_of` and `step.py`: wire the LiveMath checker into `step.Services` (closes the checker half of C6-1)

From C7d, 2026-10-22. Ticket C6-1 (checker half), row S3 (notes/C7d.md).

`generators/livemath.py` now has the adapter `WorkerChecker(workers)`. It was added; nothing existing changed, and
`CHECKER_SOURCE` is unchanged. `workers` is the `Services.workers` factory: `workers(package, *, kind, hashseed=0,
inputs_dir=None)`, a context manager that yields a started worker. `solve(spec)` runs the registrar's checker in a
generator-kind worker. Inside `with checker.session():` one worker serves every solve; outside a session each solve
opens and closes its own worker. `checker.solved` records each outcome (op, ok, exact, digits, fault). Evidence:
S3 uses it, `tests/test_execskill_smoke_roles.py` tests it, and a throwaway run in the pinned image on dl (8
instances, sympy 1.13.3, every exact value equal to its 50 digits; notes/C7d.md) ran it for real.

Request:
1. Bind the checker to the unit's tag. `step._Step.unit` replaces `services.workers` with the tag-bound partial. A
   checker built once in `services_of` would keep the untagged factory, so its containers would escape
   `drain_unit`. Simplest fix, in `step._build`: `checker=st.services.checker or (livemath.WorkerChecker(
   st.services.workers) if st.bench == "livemath" else None)`. The alternative: `_Step.unit` also replaces
   `checker`.
2. Wrap each `examiner.build(...)` of a LiveMath set in `with checker.session():`. One container then serves the
   set's solves; without it, every solve pays for a container start (in the dl run, one session with its start
   and 8 solves took 9.5 s).
3. Leave `services_of`'s `checker` at None (step-built), or document the choice in C6-1.
