# Rubric 的形式与粒度：配对反馈研究（设计与读数规则，2026-10-14 夜，写于任何结果之前）

负责人 20:30 的问题：rubric 是具体代码好还是文本好；rubric 怎么和 Skill 对应——全局一个、每个 Skill 一个、每个
bench/任务类型一个，还是把 Skill 聚合分类后每簇一个。约束：不改研究目的、不改方法主流程。

## 1 在主流程里 rubric 的位置，以及这项研究改变了什么

主方法（learning v10）的流程：训练执行 → rubric 驱动的验证器给失败行写反馈 → analyst 提案 → 候选 → 门。rubric
只影响第二步的**反馈文本**。因此"哪种 rubric 好"在主流程里的含义是：**同一批训练执行、同一个 analyst、同一个
选择集，哪种反馈形式提出的候选更好**。这正是 10/8–10/9 的 L3 配对反馈研究（`feedback_study/matched_feedback.py`）
测的东西；本研究是它在扩展任务上的重实现，臂更多（`feedback_study/rubric_form.py`，协议
`fivebench-rubric-form-study-v1`，与冻结的学习代码分开绑定）。流程不变，只在反馈这一环放不同的 rubric。

## 2 臂（8 个候选臂 + 父 Skill）

| 臂 | 反馈 | 回答的问题 |
| --- | --- | --- |
| `scalar` | 只有对/错 | 对照 |
| `labelled` | 失败行附参考答案（v9 的反馈） | 有标签的反馈作为上界参照 |
| `default_text` | OfficeQA 的冻结默认 rubric（v10），模型判定 | 粒度：每个 bench 一个（现状） |
| `global_text` | 一份与 bench 无关的通用 rubric，模型判定 | 粒度：全局一个 |
| `cluster_text` | 一份按**题型分节**的 rubric（查表 / 四则 / 统计量 / 日期文本 / 图表），模型判定 | 粒度：每簇（任务类型）一个 |
| `format_text` | 宿主格式检查的**文字版**，模型判定 | 形式：文本 |
| `format_code` | 同一组格式检查由**宿主执行**（零调用） | 形式：代码（与 `format_text` 内容相同） |
| `compliance_code` | 从父 Skill 自己的规则导出的检查，宿主执行 | 粒度：每个 Skill 一个（本研究里是手工从 bzero 的文本导出，不是模型生成） |

"形式"的对比是 `format_code − format_text`：同一份检查清单，一个由宿主执行、一个交给模型判定。但两者不是只差
执行者：宿主对每条适用的检查都执行并逐条报告；冻结的 v10 判定器每行至多返回两条检查、须引题面原文、可以弃权。
所以它比较的是**两套反馈包**（"宿主执行的完整检查" vs "模型判定的 ≤2 条检查"），差异不能只归因于执行者或
判定噪声——这一点在协议里登记（`ANALYSIS["form_contrast"]`）。"粒度"的对比是 `global_text`、`cluster_text`、
`compliance_code` 各对 `default_text`/`scalar`。

文本臂的报告严格按 v10：判定提示、校准（检出 ≥1、通过对照 ≥5、误拒率 ≤0.25）、未授权则退回标量反馈并记录。
代码臂（`HostRubricVerifier`）用同一棵记录树、同一校准规则、同一报告形状，但每条检查由宿主从公开字段与回复算出，
零调用；任何检查都不读参考答案。analyst 的提示与 v10 相同（`_checker_note`：状态 + 验证文本；`labelled` 臂另附
参考答案）。某个臂的提案失败（analyst 的 JSON 被拒）时，该臂本块留在父 Skill，块继续（记录为 `proposal_failed`）。

宿主检查的内容（`format_checks`）：答案标签存在；标签内是一个值；题目要求的小数位数；题目要求的方括号列表；
题目要求的美式长日期；"绝对差"不为负。零调用核对（1,996 条已记录的 OfficeQA 行）：触发 130 次，其中 127 次是
失败行（精度 0.98），但只覆盖 571 个失败中的 127 个（召回 0.22）——代码检查准而窄。`compliance_checks`（bzero
的 6 条可检查规则）同 10/14 下午的合规分析。

## 3 设置

- 模板：`oq-v10-z41-gv`（OfficeQA，父 = 零样本指令 bzero，训练抽样 48 题，选择集 = 124 道生成题 / 38 个家族，
  v10 的恢复策略）。研究自己的预算（`BUDGET`），冻结 v10 清单由模板重建。
- 块数 6（种子 20261014 派生每块的 rollout、提案顺序、评测顺序）。每块约 48 次训练求解 + 4 文本臂 × 48 判定
  + 8 次提案（各约 10 次调用）+ (1 + 至多 8) × 124 次选择集求解 ≈ 1,300–1,400 次调用，约 30–40 分钟。
- 运行：`scripts/run_rubric_form_study.py prepare/run/status/report`，F 的原生锁串行；LiveMath 评测队列 z9c 设有
  块间让锁点（`z9c.yield`），本研究在其间隙运行，不中断任何已开始的块。

## 4 读数规则（事先定下）

- **确证统计**只有一个：每个事先登记的对比，按块计算候选通过数之差，做精确的块级符号翻转检验（双侧）；6 块时
  最小 p = 2/64 = 0.031，所以只有 6 块方向一致才能"支持"。登记的对比（`ANALYSIS["contrasts"]`）：
  形式 `format_code − format_text`；粒度 `cluster_text − default_text`、`global_text − default_text`、
  `compliance_code − scalar`；以及各臂 − `scalar`。多个对比不作多重校正，**只有全部 6 块同向的对比才单独报告为
  "支持"**，其余只作描述。
- 描述统计：按位置配对（同一块里同一题）的胜/负数合并全部块（同一块里的位置共用一个候选，不独立）、未知敏感界。
- 验证器指标：每个 rubric 臂的授权块数、合并的检出率与误拒率（代码臂 = 宿主检查，文本臂 = 模型判定）。
- **读法边界**：一个父 Skill、一个 bench、生成题选择集（比真题容易，见 10/14 的生成题门结果）、候选从未过门、
  从未留出评测。"臂 A 比臂 B 好"只意味着"在这些块上，A 的反馈提出的候选在选择集上得分更高"。
  `format_code − format_text` 若为正且 6 块同向：宿主执行的完整检查包优于模型判定的 ≤2 条检查包；为负则反之；
  含零则不能区分。它不是"执行者"单因素的对比（见第 2 节）。
- 同一块里两个臂提出**相同文本**的候选时只评一次、共用结果（记录 `shared_evaluations`）；提案失败只在 analyst 的
  JSON 被拒、解析不全或候选超长时容忍，预算耗尽或未送达的调用让研究 pending。
- 对 `labelled`：它用了参考答案，是"有标签反馈"的上界参照，不是可部署的方案。
- 不做"至少一个臂有效"的合并结论；不把候选得分当作方法效果；不改主流程。

## 5 它回答不了的部分（留给负责人）

- 每个 Skill 一个 rubric 的**模型生成**版本（analyst 同时提 Skill 与 rubric）需要新的学习版本；本研究用手工导出的
  合规检查代替，只能说明"按 Skill 规则做检查"这一粒度的信息量。
- "把 Skill 聚合分类后每簇一个 rubric"：今天的学到的 Skill 只有三个 bench 各几份，聚类必然按 bench 分开；本研究用
  **题型**作簇（OfficeQA 内部五类），是这一想法在单 bench 内的最小实现。
- LiveMath 没有可执行的中间量，代码 rubric 只剩格式；SearchQA 已无余量。所以本研究只在 OfficeQA 上做。

## 6 修订（2026-10-14 23:05，写于串联研究的任何结果之前）

六块的 OfficeQA 研究在第 2 块因冻结恢复策略的"成本未知的尝试"上限（每个账本 64 次；今晚的 HTTP 重试率 2–5%）而
pending，第 1 块完整封存；六块的 SearchQA 研究在第 1 块因一次判定调用三次尝试都失败而 pending。冻结策略不能改，
所以改为**一块一个研究、串联运行**（队列 z17；`--series` 标签让每个研究有自己的块计划与协议哈希），事后用
`rubric-form-series-reader-20261014.py` 按块合并：只合并协议除标签与块数外完全相同的研究；同一封存块不得重复计入；
pending 的研究保留、不续跑，其已完成的块计入、成本计入。

**读数的披露**：这是一个"有界尝试的串联"而不是原来的六块实验——报告尝试数、完成数、pending 数与原因、成本；
推断以"完成的块"为条件；OfficeQA 的第 1 块来自六块研究（标签 None），其块计划推导与串联研究只差标签，一并合并
并注明。确证统计仍是块级符号翻转；完成块数不足 6 时只作描述。
