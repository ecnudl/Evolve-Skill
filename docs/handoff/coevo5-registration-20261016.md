## 1 链与推断范围

| 链 | 起点 | 做题模型 | 作用 |
|---|---|---|---|

- 顺序固定：SearchQA → OfficeQA → LiveMath → SpreadsheetBench → ALFWorld（理由见提案 §1.1，是我们看过开发数据后定的）。
  结论只适用于这个顺序。
- 方法内部的角色（分析、判定、诊断、修订、出题、查证）在所有链里都用 GLM-5.3；deepseek 链只换做题模型。
- **推断范围**：每条链只跑一条历史。所有读数是"这几条实际跑出来的历史"的结论，不是"这个方法每次都会这样"；
  E 链与 I 链、两个做题模型之间不是彼此的重复。区间只反映测试题的抽样不确定性，不含学习过程本身的随机性。
- deepseek 没有配对的基线，所以 deepseek 链只和它自己的第 0 步（No-Skill 或任务说明指令）比较，标为"换做题模型的稳健性"，
  并注明方法角色固定为 GLM-5.3。
- I 链的起点是**五份指令合在一起的整份文本**（文本冻结在清单里）。关于 I 链的结论只针对这份整体，不推广到"超过每个 bench
  单独用自己指令时的水平"。

### 2.1 SpreadsheetBench：资产合格与判分合格

10/6 的测试评测里，279 题中有 93–111 题的结果是"无法判定"，主要原因是判分器验证不了标准答案本身（参考工作簿在冻结的
重算引擎下与它自带的缓存值对不上，或重算失败）。所以本协议把两件事分开，都在用到之前固定：

- **资产合格**：输入与参考工作簿都在、sha256 与记录一致、大小在限制内、答案位置一致。训练侧是 10/5 冻结的开发 80 题与
  val 40 题；测试侧是 10/5 冻结的 279 题面板（当时因一个缺失或命名错误的文件排除 1 题）。
- **判分合格**：把每题的参考工作簿当作"回答"（每个用例的输出就是该用例的参考工作簿）交给冻结判分器
  （`qualified_lo_recalc_v7_v1`，同一镜像与 23 项引擎资格记录），在两个全新的判分目录里各判一次，不调用任何模型。
  两次都对每个用例判"通过"的题才合格；其余题按原因类别（参考重算失败、参考缓存不一致、读取视图无法验证、其他）计数后排除。
- **训练侧**在开跑前做（§14 第一批），合格题号写进清单。SpreadsheetBench 的本 bench 面板 ＝ 全部合格训练题 × 1 次；
  回归面板 ＝ 从合格训练题中按种子抽 60 题，不足 60 题时用全部合格题；两个面板的容差按 §5.5 的规则用实际题数算出，写进清单。
  合格训练题少于 30 题时，SpreadsheetBench 这一步只做训练执行、考官修订与诊断，不检验规则（记"面板不足"），也不设它的
  回归面板；链继续。合格训练题里历史 train 部分或历史 val 部分为 0 题时，基线无法按冻结实现运行这一步（冻结实现要求两部分
  都非空）：**不开跑**，记"开跑前不可行"，由负责人另定协议版本。
- **测试侧**在第一个评测步骤里、任何测试格判分之前做，同样只用冻结判分器、不调用模型；只记录合格题号、各原因的计数与哈希，
  没有人、也没有方法角色看测试内容。所有链用同一份合格名单，SpreadsheetBench 的测试分母就是合格题数（同时报告排除数与原因）。
  测试侧合格题为 0 时，在第 0 步评测发出任何调用之前停止所有链，记"主要读数无法评估"（它们都要用五个 bench 的宏平均）。
- **合格题上候选回答仍然判不了**（例如候选工作簿重算超时）：按 §5.4 的"产物未知"处理——同一份工作簿最多再判 2 次，
  仍判不了就保留为未知，不重新作答。

### 2.2 标注访问约定（本协议新定；历史协议的划分与身份不变）

- 在第 k 步，本方法可以用：第 k 个 bench 训练池（SpreadsheetBench 为合格部分）的题与参考答案；之前各 bench 回归面板的
  官方判分结果（只用对/错，不给分析模型、修订模型和查证模型看）。
- **还没轮到的 bench**：这条学习历史里还没用过它的任何真实题与标注；从第 0 步起只用它们的公开任务卡（I 链的起点指令、
  迁移题的题型说明）。但 bench 顺序与五份任务说明指令是我们看过各 bench 开发数据后定的，迁移题也模仿这些题型，所以
  "轮到之前的变化"（§12.4 的 N̄）是"这条学习历史还没用过该 bench 真实题时的迁移"，不是对完全陌生任务的迁移。
- 基线在第 k 步只用第 k 个 bench 的历史 train（学习）与历史 val（挑选），SpreadsheetBench 同样只用合格部分，不碰别的 bench。
- 到整条链结束，本方法和基线**可用的带标注题池相同**（五个训练池）。实际用到的不重复标注数不一定相同（本方法还会重复使用
  之前 bench 的回归面板），每一步分别报告：可用标注数、实际用到的不重复标注数、生成题的标注数、调用数与 tokens。
- **说法**：本方法"不设单独的留出验证分区"，不说"不用任何带标注的挑选数据"——门本身就用训练池里的真题。检验半（§4）是
  **训练侧、随过程自适应的挑选材料**：每步重抽；它的挑选面板决定细则修订收不收（§6），细则又影响分析模型看到的诊断，
  所以它不是分析模型没见过的验证数据。
- 与旧规则的关系：project-status §1 的"验证数据不进入分析、细则修订……"针对的是设了留出验证集的旧协议。本协议把历史 val
  并进训练池，这是登记好的例外；测试集的隔离不变。

## 3 Skill 的结构

- 一段英文 markdown，依次为 `## Shared principles` 与五个 bench 分区（`## SearchQA` 等）。每个 bench 分区的第一行是固定的
  适用条件，不学习：
  - SearchQA：`Applies when: the task gives a clue-style question with retrieved web search snippets and asks for a short answer.`
  - OfficeQA：`Applies when: the task gives U.S. Treasury Bulletin page text and asks a question answered from those pages.`
  - LiveMath：`Applies when: the task is a mathematics question with lettered answer options.`
  - SpreadsheetBench：`Applies when: the task asks for a Python program that modifies a spreadsheet workbook.`
  - ALFWorld：`Applies when: the task is a text household environment where you choose one admissible action per step.`
- 规则是条目（`- ` 开头），每条 ≤600 字符、不含空行和标题行。I 链分区开头是任务说明指令原文（标题降两级）。空节不渲染。
- **只增不改**：父 Skill 里已有的规则和 I 链的指令原文不删、不改；新规则接在所在分区的末尾，多条时按 §5.7 的优先级排列。
- 总长上限 **20,000 字节**（控制 ALFWorld 每个动作都要重发 Skill 的成本）。一条规则单独加入父 Skill 就会超限的，在门开始前
  丢弃（记"超长"）；多条合入时，不超限的子集在合在一起检验**之前**定下（§5.7），检验的就是最终要收下的那份文本，
  检验之后不再删减或改写。
- 每条规则的记录（编号、正文、位置、来源步骤、针对的诊断代码、触发题、检验数据、泄漏检查）放在 JSON 里，不进渲染文本。

## 4 每一步的流程（第 k 个 bench）

1. **训练执行**：当前 Skill（第 k−1 步的结果）做本步训练执行的题（§2）。
2. **分两半**：把这些题按固定种子随机分成**提案半**和**检验半**，按"至少失败一次"分层。分析模型只看提案半；
   门的触发收益只在检验半上算。不设固定的验证分区，两半每一步重新抽；检验半是训练侧的挑选材料（§2.2）。
3. **考官修订**（§6）：用提案半的不一致提出细则修改，在检验半的平衡面板上挑选。ALFWorld 不做（§6）。
4. **诊断**（§6）：两半的所有失败回答都打代码。
5. **规则提案**：分析模型（GLM-5.3）只看提案半的诊断，提出 ≤5 条规则（其中建议放共享部分的 ≤2 条）。每条写明正文、
   建议位置、针对的诊断代码（可以是"其他"）、理由。正文（规范化空白与大小写后）与父 Skill 已有规则或本步编号更小的提案
   相同的丢弃。
6. **泄漏检查与长度检查**：泄漏检查（§9）不通过的丢弃；单独加入会让 Skill 超过 20,000 字节的丢弃（记"超长"）。
7. **冻结触发题**：每条规则的触发题 T_r ＝ 检验半里至少有一个失败回答的诊断代码属于该规则针对代码的题。少于 4 题的规则
   不测，记为"支持不足"。T_r 与每臂要做的题、次数在门开始前写进本步清单。
8. **迁移题**（§8）：只给建议放共享部分的规则出；每条规则 4–6 道的迁移题面板在初筛前冻结。不足的在门开始前改为只按
   本 bench 位置测。
9. **初筛**、10. **复核**、11. **定下要合入的文本并合在一起检验**（§5.7）。
12. **合入**：收下的就是检验过的那份文本（§5.7），得到第 k 步的 Skill。
13. **评测**（§10）：第 k 步的 Skill 在五个测试集上各测一遍，结果封存。

方法组件出错时的固定处理：分析模型两次都没给出合法 JSON → 本步没有规则（记为方法失败事件），Skill 不变，链继续；
判定的单次调用不合法 → 在挑选面板上对新旧细则都记为判错（§6）、在诊断里记"其他"；诊断、修订、出题、一致性检查、
泄漏裁定的单次调用不合法 → 分别是代码记"其他"、不修订、该题丢弃、该题丢弃、该规则丢弃。

## 5 逐条检验 X v2（启发式门）

### 5.1 性质

- 这是一个**启发式**的挑选规则，没有数值上的误收率保证，本协议也不估计误收率（§5.8）。第 1 版里"误收率约 3–4%"的说法撤销。
- 它想排除的情形（零假设，文字表述）：规则对本 bench 的作用，和"在同一位置插入一段长度相近的无关文字"没有区别。
  对照文字是固定写好的，不是针对失败写出来的，所以两者不能互换。
- 每一轮都是新的模型调用（各臂各题都重新做）。种子只决定抽题和执行顺序，不决定模型输出；同一条规则在两轮之间的
  持续效应不会因为重跑而消失，所以两轮不是独立的两次检验。
- 第 1 步训练执行的回答**不**作为门的比较对象：门里父 Skill 每轮都在同样的题上重新做。

### 5.2 臂与对照

- **父 Skill**：每轮重新做本 bench 面板、回归面板，以及本轮所有共享候选迁移题面板的并集。
- **规则臂**：父 Skill 加一条规则（接在所在分区末尾）。建议放共享部分且迁移题有效的规则，初筛时测两个臂：放共享部分、
  放本 bench 分区。共享臂只做**它自己的**迁移题面板；放本 bench 分区的臂不做迁移题。
- **对照**：无关文字，位置与规则相同。每轮 4 段：放本 bench 分区的一组、放共享部分的一组（只在本轮有共享臂时才测），
  文字相同、位置不同。初筛用前 4 段、复核用后 4 段（文字见 `skillopt/coevo5/protocol.py`，记入清单）：
  - 初筛：俳句的 5-7-5 音节；十六进制颜色的写法；菜谱先列配料；拉丁铭文的人名地名。
  - 复核：五行打油诗的韵脚；开尔文温度的写法；国际象棋记谱；编织图样。
- 对照只做同位置所有规则 T_r 的并集；共享位置的对照还做本轮所有共享候选迁移题面板的并集。对照不做整个面板：不伤害的判据以父 Skill 为准
  （§5.5），不需要对照。

### 5.3 题集（门开始前全部冻结）

- 本 bench 面板 F_k：本步训练执行的那些题（§2 表），每臂次数见表。
- 规则 r 的触发题 T_r ⊆ F_k（§4 第 7 步）；其余题 R_r ＝ F_k 去掉 T_r（包括提案半，以及别的规则的触发题）。
- 回归面板：之前每个 bench 一个（§2），每题 1 次。第 1 步没有。
- 迁移题：每条共享候选一份 4–6 道的面板（两种题型各 2–3 道，§8），初筛前冻结，每臂 2 次。
- 一题属于多条规则的触发题时，各规则分别计算，不去重。
- 同一轮里，所有整臂（父 Skill、规则臂、合在一起的臂）做完全相同的本 bench 面板与回归面板、相同次数；迁移题：每个共享臂
  只做它自己的面板，合在一起的臂做它所含共享规则的面板，父 Skill 与共享对照做本轮所有共享候选面板的并集；对照只做
  §5.2 规定的子集，同组各段相同。

### 5.4 结果类别、重做与缺失

每个格（一臂、一题、一次）记两个结果：**官方结果**（冻结判分器的原样输出：通过、未通过或未知，连同原因）与**完成口径
结果**（本协议按下表重新归类）。门和读数都用完成口径；官方结果一并保存、报告。原则：**已经交付的回答不会被新的回答替换**；
没有交付回答时可以原样重发同一请求；同一份产物（SpreadsheetBench 生成的程序或工作簿）可以重新执行或重新判分。

**有序判定表**：按行号顺序，取第一条适用的。代码 `skillopt/coevo5/outcomes.py` 逐行实现；离线测试逐行覆盖，并用冻结后端
加模拟环境测几种情形同时出现的格。表与各行的原因清单记入清单。

- "这个格的所有记录"：做题结果的原因、每个用例的生成原因、判分结果的原因、每个用例的判分原因。冻结后端会在某些情形下

SpreadsheetBench 的每个用例（一个输入工作簿）依次：

- **9a 生成**：没写出 `output.xlsx`、写出的文件超过 8 MB → 未通过（产物缺失或无效）；程序抛出异常（`native_exception:*`）
  → 未通过（程序缺陷）；运行超过 300 秒 → 同一程序重新执行，最多 2 次，仍超时 → 未通过（程序缺陷）；执行环境故障
  （docker 或镜像不可用、沙盒回执无效、执行不可用）→ 同一程序重新执行，最多 2 次，仍故障 → 未知（基础设施）。
- **9b 工作簿结构**（判分前由本协议检查）：能 base64 解码；大小在 1 字节到 8 MB 之间；是 zip 包，解压后总大小不超过 128 MB；
  含 `[Content_Types].xml` 与 `xl/workbook.xml`；冻结版本的 openpyxl 能以只读方式打开，且至少有一张工作表。任一项不满足 →
  未通过（产物无效）。
- **9c 判分**（同一批工作簿）：判分器给出通过或未通过 → 同官方。参考一侧出错（`reference:*`、参考缓存不一致）或判分环境
  故障（docker 或镜像不可用）→ 同一批工作簿在新的判分目录里重判，最多 2 次，仍失败 → 未知（基础设施）。候选一侧的其他
  判不了（重算超时或出错、含判分器不支持的内容、读取视图无法验证、判分证据出错等）→ 同样重判最多 2 次，仍判不了 →
  未知（产物）。
- **9d 合成整题**：任一用例最终未通过 → 整题未通过；否则先做需要的重新执行（同一程序在所有用例上重新执行并重新判分），
  再做需要的重判；用完次数后仍有未知 → 整题未知（未知用例全是"产物"时记产物，否则记基础设施）；全部通过 → 通过。
- 两点理由：合格题的参考工作簿在资格检查里两次判过（§2.1），所以它此时出错是环境问题，按基础设施算。"结构无效"
  （没有交付有效的工作簿，未通过）与"判不了"（交付了结构有效的工作簿、但冻结判分器验证不了它的内容，未知）分开。

- ALFWorld 一局里某一步的调用没有交付回答时，调用包装按第 4 行原样重发这一步的请求，这一局接着进行；重发用完仍没有 →
  这一局按第 4 行记未知。
- 做题客户端自己在一次调用里有有限次重试（传输错误与 HTTP 429/5xx 最多再试 3 次）；读超时设为 2,400 秒，使最长的回答
  （65,536 tokens，历史上 10–19 分钟）也能完成。第 4 行的重发在这之后。
- 判据一律用**保守值**：对每一臂、每题，L ＝ 未知按未通过算的平均通过率，H ＝ 未知按通过算的平均通过率。
  对规则（和合在一起的臂）用 L，对父 Skill 和对照用 H。
- **一臂未知过多**：规则臂或合在一起的臂在一轮里的未知格（任何类别）超过 10% → 该臂记"未判定"，不收；本步继续。
- **一轮基础设施未完成**：父 Skill 或任一对照的基础设施未知格超过 10% → 本轮记"基础设施未完成"，链按 §13.4 暂停。
  训练执行、每一步每个 bench 的评测适用同样的 10% 规则。
- 各臂未知格的数量、类别和原因按臂报告，看是否有差别。

### 5.5 判据（每轮）

记 Σ_X L(a) 为臂 a 在题集 X 上逐题 L 之和，H 同理，单位是题。

- **C1 触发收益**：Σ_{T_r} L(r) − Σ_{T_r} H(父) ≥ 1，且 Σ_{T_r} L(r) 严格大于同位置 4 段对照的 Σ_{T_r} H 的最大值。
- **C2 本 bench 不伤害**：Σ_{R_r} L(r) − Σ_{R_r} H(父) ≥ −t_k。
- **C3 之前 bench 不伤害**：对之前每个 bench b 的回归面板，Σ L(r) − Σ H(父) ≥ −t_b；并且违反该 bench 固定格式检查
  （SearchQA、OfficeQA：有答案标签；LiveMath：答案是单个字母；SpreadsheetBench：有代码）的格数，规则比父 Skill
  多出不超过 2（规则的未知格算违反，父 Skill 的不算）。各 bench 分开判，不把收益和伤害加在一起。
- **C4 迁移收益**（只对放共享部分的臂）：在它冻结的迁移题面板上，Σ L(r) − Σ H(父) ≥ 1，且严格大于共享位置 4 段对照的最大值。

**容差的规则**（单位：题）：在 §5.6 的简化模型里（τ ＝ 1.0，种子由 bench 与面板大小决定，`coevo5_power_sim.calibrate`），
让无害规则在两轮内被误拒的模拟概率 ≤0.05 的最小整数。本 bench 面板按"面板减去 8 道触发题"算。由此：

| | SearchQA | OfficeQA | LiveMath | SpreadsheetBench | ALFWorld |
|---|---|---|---|---|---|
| t_k（本 bench 面板） | 7 | 6 | 9 | 9（按 120 题；资格检查后按实际题数重算） | 5 |
| t_b（回归面板，60 题） | 5 | 7 | 9 | 6（同上；不足 60 题时按实际题数） | — |

例：SpreadsheetBench 回归面板若只有 52 题，按同一规则 t_b ＝ 6；40 题时为 5；30 题时为 4。这些容差只是挑选规则的参数，
不代表门能拦下多大的伤害；伤害只在测试集上量（§12）。

  自己的小扰动（τ ＝ 0.3 或 1.0，结果相近）；规则把它触发题中比例为 f 的题的通过概率提到 ≥0.9。

  下降不超过 H 点、在难题上更少；C2 假设恰好 8 道触发题：

### 5.7 两轮、落位与合入

1. **初筛**：所有"支持足够"的规则臂（共享候选测两个位置）、父 Skill、对照。
2. **定位置**（初筛之后、复核之前）：共享臂过了 C1–C4 → 放共享部分；否则本 bench 臂过了 C1–C3 → 放本 bench 分区；
   都没过 → 不收。
3. **复核**：只测上一步定下位置的规则，新的调用、后 4 段对照，判据相同。没过 → 不收（复核里不再降级）。
4. **优先级**（初筛结束时就算好，不看复核）：初筛里 Σ_{T_r} L(r) 减去同位置对照最大值的差，越大越先；相同时规则编号小的先。
5. **定下要合入的文本**（复核通过 ≥2 条时，在合在一起检验之前）：按优先级从高到低，把复核通过的规则依次接到父 Skill 的
   最终位置（分区末尾）；加入后超过 20,000 字节的那条跳过，继续看下一条。得到的文本 S 在检验开始前固定。
6. **合在一起检验**（S 含 ≥2 条规则时）：新一轮，测父 Skill 与 S：
   - 对 S 里的每条规则 r：Σ_{T_r} L(S) − Σ_{T_r} H(父) ≥ 1；
   - 本 bench 面板去掉 S 里所有规则的触发题后，满足 C2；
   - 每个回归面板满足 C3；
   - S 里的共享规则在各自的迁移题面板上 Σ L(S) − Σ H(父) ≥ 1。
   全部满足 → 原样收下 S。否则（包括"未判定"）→ 只收优先级最高的那条复核通过的规则。S 只含 1 条 → 直接收下这条。
7. 只有 1 条复核通过 → 直接收。没有 → 本步 Skill 不变（评测记录按 §10 复用）。
8. 收下的文本都原样检验过：单独收下的就是复核里检验的那份文本；合在一起收下的就是 S。检验之后不删减、不改写。

### 5.8 多重比较

- 误收的范围：一条链里检验的所有规则（最多 25 条）以及位置与合入的选择。门不提供单条规则或整条链的误收率保证，
  本协议也不估计这个误收率。
- **只作描述的对照诊断**（零额外调用）：每轮对每组同位置对照，轮流把其中一段当作"规则"、另外 3 段当对照，在每条规则的
  T_r 上按 C1 判一次，报告单轮的通过比例。这个比例不是误收率的估计：真实规则面对 4 段对照，是针对失败写出来的，
  还经过两轮、位置与合入的挑选。
- 门的结果与测试集上的效果分开报告；只有测试集上的读数（§12）作为效果证据。

### 5.9 宽松匹配诊断（只描述，不进门、不进主张）

- 只看最后一个答案标签里的文字，不在整段回答里找：
  - SearchQA：规范化后标签内文字等于某个参考答案，或包含它且总词数不超过该参考答案词数 ＋ 3；
  - OfficeQA：标签内恰好有一个数字，去掉千分位、`$`、`%` 与单位词后与参考答案数值相等；非数值答案比较规范化字符；
  - LiveMath：标签内恰好有一个独立的 A–E 字母，且等于正确选项；
  - SpreadsheetBench、ALFWorld：没有。
- 报告"宽松 − 官方"的差，叫"宽松匹配差"，不说成"格式造成的部分"。去掉百分号和单位可能改变含义，这是已知局限；
  离线测试列出这些失效情形。

## 6 考官：细则、判定与修订

- **细则**：每个 bench 一份，另有一份通用细则。每项包括编号、文字、可选的代码检查、依据。代码检查只能从固定的检查库里选、
  填参数：`answer_tag_present`、`answer_single_letter`、`answer_pure_number(allow_percent)`、`answer_no_percent`、
  `answer_no_letters`、`answer_max_words(n)`、`code_present`。
- **初始细则**：GLM-5.3 只读公开任务卡各写一次（与任务说明指令同源，同一提示），程序校验格式，开跑前冻结进清单。
  通用细则全程不改。
- **判定**（不看参考答案）：先跑细则的代码检查，有不过的 → 判"未通过"并给出该项编号；都过了 → GLM-5.3 按文字项判通过
  或未通过（给出违反的项）。回答不合法（不是规定的 JSON、项编号不存在）的判定记为"不合法"。
- **修订**（第 k 步，只改第 k 个 bench 的细则；ALFWorld 不做，因为它的轨迹里直接写着成败）：
  1. 用当前细则判定本步所有回答。
  2. 取提案半里判定合法、且与官方判分不一致的回答，最多 20 个（两种不一致各半，按种子抽），交给修订模型提出 ≤3 处修改；
     每处要有查证引用（§7）或提案半里的训练题证据，没有就丢弃。
  3. **挑选面板**（在任何判定之前固定）：检验半里每题取一个回答（按种子），官方通过、未通过各取最多 20 个。少数一类不足
     8 个 → 本步不修订（记"样本不足"）。
  4. 新旧细则都判定面板上的**全部**回答；**不合法的判定记为判错**（两份细则同样处理），所以两者的分母相同，都是整个面板。
     估计量是**平衡准确率**（两类各自判对的比例的平均）。新细则平衡准确率高 ≥0.05、且多判对 ≥2 个才收下。
     同时报告两份细则各自的不合法比例。
- 修订后的细则只影响**本步**的诊断；第 k 个 bench 之后不再用它。门的判分与格式检查（§5.5 C3）是固定的，细则怎么改都不影响。
- **诊断**：两半所有失败回答——先跑固定格式检查和细则的代码检查，不过的记该检查的代码（按登记顺序取第一个）；都过的
  交给 GLM-5.3（这时给参考答案；ALFWorld 没有参考答案，给任务与轨迹）从细则的文字项里选一个代码，或"其他"。
- **报告**：所有修订尝试（提出、收下、拒绝及原因）；挑选面板上修订前后的平衡准确率与不合法比例——这是**挑选用的测量**，
  修订被收下时在这个面板上必然变好，不能当作"考官变准了"的独立证据。本协议不做独立审计，所以考官进化只作描述，
  Skill 的提升不归因于考官进化。

## 7 查证（DeepResearch）

- 查证模型 GLM-5.3 写搜索词、挑页面、下结论；程序执行检索与下载，核对引用。
- **来源（本协议冻结，不可替换）**：
  - 英文维基百科搜索接口（固定的接口地址与参数）。每个页面记录最终标题、修订号（revid）、跟随过的重定向；
    消歧义页丢弃；标题含 "Jeopardy" 的页面丢弃（SearchQA 的题目出处）。不访问其他网站。
  - 一份存档文档清单：Python 3.11 官方文档的相关页面（decimal、fractions、math、statistics、datetime、re）、
    openpyxl 文档的相关页面、五个 bench 的公开任务卡（只保留任务说明与判分说明部分，去掉示例题）。
    开跑前下载、存档、记 sha256，写进清单；查证时只在存档里检索。不收任何 benchmark 论文或数据集页面。
- 每个问题最多 3 轮检索、每轮最多 3 个搜索词、一共最多读 3 个页面。所有搜索结果列表和页面正文都存档。
- 结论里的每条引用必须逐字（空白规范化后）出现在存档页面中，否则结论作废。
- 查证模型只看训练题、生成题与细则，看不到测试题和之前 bench 的回归面板。
- 用在两处：细则修订的依据（§6）；SearchQA 式迁移题的证据（§8）。

## 8 迁移题

- 只给建议放共享部分的规则出。题型是问答类 bench 的格式，由公开任务卡描述（生成器看不到这些 bench 的任何题）：
  - SearchQA 步：OfficeQA 式、LiveMath 式；OfficeQA 步：SearchQA 式、LiveMath 式；LiveMath 步：SearchQA 式、OfficeQA 式；
    SpreadsheetBench 步与 ALFWorld 步：SearchQA 式、OfficeQA 式。
- 每种题型最多 2 次生成调用，每次要 3 道题，按顺序取前 3 道有效的。
- **有效**的条件：
  - OfficeQA 式：一张生成的小表、问题、参考答案、一个算式。程序用精确有理数计算算式（按题面写的舍入），结果等于参考答案；
    算式里的每个数都是表里的一个单元格；另一次独立调用（只给表和问题）写出的算式算出同一个值。
  - LiveMath 式：问题、A–E 五个互不相同的选项、答案字母、一个算式。算式的值恰好等于一个选项，且就是答案字母；
    另一次独立调用确认算式算的就是题目问的量。
  - SearchQA 式：出题模型先写线索与参考答案；查证（§7）为它找证据，引用的逐字片段作为这道题的检索片段。参考答案
    （规范化后）逐字出现在某个片段里；另一次独立调用只看线索和片段，答出的答案与参考答案一致（SearchQA 官方规范化）。
  - 格式不合（字段缺失、超长）的丢弃。
- **面板大小**：每种题型有效 2 道或 3 道都可以；两种题型合起来 4–6 道，就是这条规则的迁移题面板，在初筛前冻结，C4 和
  合在一起检验用的都是这份面板（不同规则的面板大小可以不同，各自固定）。某种题型有效题少于 2 道 → 这条规则在门开始前
  改为只按本 bench 位置测（§4 第 8 步）。
- 迁移题按所模仿 bench 的官方判分器判分（同样的系统提示与答案格式）。
- 迁移题只用来决定规则放在哪里。它们是按规则生成、用来挑选的材料，不作为"规则能迁移"的证据；迁移的证据只看测试集。
  报告每种题型的生成数、有效数与被丢弃的原因。

## 9 泄漏检查（规则写入前）

- 对象：规则正文。比较对象：本步本 bench 训练池的全部题与参考答案（不含测试集；检查程序拿不到测试数据）。
- 规范化：NFKC、小写、标点换空格、合并空白。
- 机械检查（任一命中即丢弃）：
  1. 与任何一题的题面（含选项、任务说明）共享连续 8 个词；在本 bench ≥5% 的题里都出现的 8 词串不算（模板语句）。
  2. 按答案类型：
     - 文字答案（SearchQA；OfficeQA 的非数值答案）：≥2 个词的参考答案作为整词序列出现；单个词的参考答案在 ≥5 个字符时
       作为整词出现。
     - 数值答案（OfficeQA）：规则里的某个数与某个参考答案数值相等，且该答案有 ≥3 位有效数字；1900–2030 的四位整数年份
       不查。
     - LiveMath：选项字母不查；正确选项的内容（去空白后 ≥4 个字符）作为子串出现。
     - SpreadsheetBench、ALFWorld：只做第 1 项。
- **裁定**：机械检查通过后，GLM-5.3 用固定提示判断"这条规则是否陈述了某道具体题目的事实，或把某类具体题目对应到某个
  答案"；回答"是"或不合法 → 丢弃。裁定的提示、回答与结论都存档，复查时以存档为准。
- 规则的来源记录（题号、证据）只在 JSON 里，不进渲染的 Skill。

## 10 评测

- 每条链第 0 步（起点）和每一步之后，在五个测试集上各测一遍，每题 1 次；SpreadsheetBench 只测判分合格的题（§2.1）。
- **第 0 步现做，不复用 10/6 的历史分数**：E-glm、SkillOpt-glm、GEPA-glm 的第 0 步都是 GLM-5.3 下的空 Skill，用同一份
  现做的记录；I-glm 的第 0 步是五份指令的整体；deepseek 的两个第 0 步各自现做。
- 某一步的 Skill 与上一步逐字节相同 → 直接复用上一步的评测记录（标为复用），不重做。
- SpreadsheetBench 测试侧合格题为 0 → 按 §2.1 在第 0 步评测之前停止。
- 结果类别、重发、重新执行与重判同 §5.4；某一步某个 bench 的基础设施未知格超过 10% → 按 §13.4 暂停。主口径是完成口径；
  同时报告官方口径（只算已知）与每格未知数及类别。
- 所有方法的测试评测都用同一个评测运行器、同一个做题客户端与设置。
- 结果封存（§0）。测试集的历史接触如实标注：SearchQA 测试集在 10/6、10/8 用过，SpreadsheetBench、ALFWorld 的在 10/6
  用过（当时的方法与本方法不同，但它们不是全新的确认集）；OfficeQA、LiveMath 的测试集从未打开。

## 11 基线

- **SkillOpt v9、GEPA**：用冻结实现（`skillopt/continual_learning`；需要的适配放在 `coevo5` 里包一层，不改冻结代码），
  同一顺序、从空 Skill 出发；第 k 步用第 k 个 bench 的历史 train 学习、历史 val 挑选（SpreadsheetBench 只用判分合格的部分）；
  每一步之后用同一个评测运行器测五个测试集。只在 GLM-5.3 上跑。
- **比较的是完整算法**：基线带着冻结实现自己的学习规则一起比较，这些规则与本方法不同，如实写明：
  - 学习期间做题回答被截断时，v9 用 `max_tokens` 131,072 重新请求一次（`continual_learning/recovery.py`）；本方法记为未通过。
  - 冻结账本在中断后重放已完成的调用；GEPA 在一次运行内缓存同一候选在同一题上的评测（`cache_evaluation=True`）。这是 §0
    "不用回答缓存"的例外，只发生在基线学习期间。
  - 自己的 Skill 长度上限 32,000 字节（v9 沿用 v7 提高后的上限，`continual_learning/recovery.py`；本方法 20,000 字节）。
  - 自己的预算与接受规则：每步最多 3 轮迭代、8,000 次评测调用、128 次反思调用、12,000 次接口调用、6,000 万已报告 tokens，
    8 个并发做题进程；v9 在 val 上做两遍的符号检验后才接受。
- 学习期间基线的做题模型、推理档位、`max_tokens`（截断恢复之外）、温度与评测运行器逐项核对一致，记入清单。这只对齐了名义
  设置，不能把两者的差异归因于"用不用验证分区"。
- 学习结束后，所有方法的测试评测都用同一个评测运行器（§10）。
- 五个 bench 上的基线适配都要在主实验开跑前完成、过审、冻结（§14）。
- No-Skill 与"五份指令整体"就是各链的第 0 步（§10）。

## 12 读法（事先定死）

### 12.1 记号

- A_m[s][b]：方法 m 第 s 步（s＝0…5）的 Skill 在 bench b 测试集上的准确率（完成口径）。σ(b) 是 b 在顺序里的位置
  （SearchQA 1、OfficeQA 2、LiveMath 3、SpreadsheetBench 4、ALFWorld 5）。
- 宏平均 M_m[s] ＝ 五个 bench 的 A_m[s][b] 的等权平均（单位：百分点）。

### 12.2 主表

每条链一张表：行是第 0–5 步，列是五个 bench，格子是"对的题数 / 总数（未完成数，未知数）"，另列宏平均；
每步收下的规则数（共享 / 本 bench）。

### 12.3 主要检验（固定顺序，前一个成立才检验下一个）

非劣界 δ ＝ 3 个百分点（宏平均）。这是事先定的实用界限，不保证保住任务说明指令增益的任何比例。按历史翻转率粗算，
宏平均配对差的标准误约 1.4 点；两种方法真正相同时，证出"不差于"的概率约 55%——所以"不确定"不等于"更差"。

- **P1**：M_E-glm[5] − M_SkillOpt-glm[5] 的 95% 区间下端 L > −δ（不差于）。
- **P2**：M_E-glm[5] − M_GEPA-glm[5] 的 L > −δ。
- **P3**：遗忘 F̄（§12.4）：F̄_E-glm − F̄_SkillOpt-glm 的上端 U < 0（遗忘更少）。
- **P4**：F̄_E-glm − F̄_GEPA-glm 的 U < 0。

P1、P2 的结果分三类（L、U 为 95% 区间的下、上端）：**不差于**（L > −δ）；**差于**（U < −δ）；**不确定**（其余）。
"优于"（L > 0）不进主要检验，只作为**探索性**结果报告。每一类都要按 §12.6 的方向规则核对缺失。

### 12.4 公式与次要读法（都报 95% 区间，不做多重校正，标"次要"）

- 学到的增益：G_b ＝ A[σ(b)][b] − A[σ(b)−1][b]。
- 遗忘（带符号，正数＝变差）：F_b ＝ A[σ(b)][b] − A[5][b]，b 取前四个 bench；F̄ ＝ 四者等权平均。
- 轮到之前的迁移（带符号，正数＝变好）：N_b ＝ A[σ(b)−1][b] − A[0][b]，b 取后四个 bench；N̄ ＝ 四者等权平均。
  这些 bench 在轮到之前，这条学习历史里还没用过它们的任何真实题（§2.2）；顺序与指令是看过开发数据后定的，迁移题也模仿
  这些题型，所以 N̄ 不是对完全陌生任务的迁移。
- 只报、不用于主张：每个 bench 的 F_b、N_b；截断版（每项取 max(0, ·) 后平均）；每步宏平均与每个 bench 的完整轨迹。
- 次要比较：
  - **从空白能学到指令的水平吗**：M_E-glm[5] − M_I-glm[0]，同样的 δ 与三类结果。
  - **超过指令了吗**：M_I-glm[5] − M_I-glm[0]，L > 0 写"超过"，否则"未建立"。只针对五份指令的整体（§1）。
  - N̄_E-glm 与两个基线的差；各 bench 的差（描述）。
  - deepseek：M_E-ds[5] − M_E-ds[0]、M_I-ds[5] − M_I-ds[0]、M_E-ds[5] − M_I-ds[0]，以及 F̄、N̄；不与任何基线比较。

### 12.5 什么算成功，什么算失败

- **方法没动**：E-glm 少于 2 步收下过规则 → 记"方法几乎没有更新"。此时 F̄、N̄ 接近 0 是不更新的结果，P3、P4 不作解释。
- **没学到东西**：M_E-glm[5] − M_E-glm[0] 的 L ≤ 0（按 §12.6 有利主张的规则核对）→ 记"学习增益未建立"。
- **基线太弱**：某个基线的 M[5] − M[0] 的 L ≤ 0 → 对它的"不差于"没有信息量，照实标注。
- **主张 1 成立**：P1、P2 都是"不差于"，且方法有更新、学习增益成立。
- **主张 2 成立**：主张 1 成立，且 P3、P4 都成立（学到了东西，又比两个基线遗忘更少）。
- **整体成功** ＝ 主张 2 成立。其余任何组合照实写哪些成立、哪些没有。

### 12.6 统计细节

- 自助法：10,000 次，种子 20261017，百分位区间。每个 bench 内按题有放回重抽（OfficeQA 的题如果带出处文件字段，按出处
  文件整组重抽）；同一次重抽的题号同时用于所有方法、所有步骤，所以轨迹是配对的；共用的第 0 步记录在比较中自然配对。
- **缺失，按主张的方向**：每个读数用同一组重抽算三遍：
  - (a) 只用相关记录都已知的题（配对地去掉）；
  - (b) 不利补全：每个未知记录取让读数朝"不利于该主张"的方向变化的值；
  - (c) 有利补全：与 (b) 相反。
  有利的主张（不差于、遗忘更少、学习增益成立、超过指令、探索性的优于）要求 (a)、(b) 都成立；"差于"要求 (a)、(c) 都成立；
  否则写"不确定"。
  - 一个记录被几处共用（共用的第 0 步、逐字节相同而复用的评测记录）时，它只有一个补全值，方向由它在读数里的合计系数
    决定；所以共用记录在差值里照样抵消。
  - 截断版等非线性的描述量，直接在补全后的记录上计算，不假设读数是线性的。
- **没有题可用**：某个读数在某个 bench 上没有可用的题（例如 (a) 配对去掉后为空）→ 这个读数记"无法评估"；不删 bench、
  不改宏平均的权重。
- 每题只做 1 次：能比较 Skill，不能单独说明做题模型自身的重复性。

### 12.7 考官（只描述）

各步修订尝试与结果、挑选面板上的平衡准确率与不合法比例（标"挑选用"）；迁移题的生成数与有效率；查证的引用核对通过率。

### 13.2 硬上限怎么执行（预留制）

- 一本全局账本记录所有 coevo5 的 GLM-5.3 调用（包括 §5.4 第 4 行的每次重发）。一次尝试的上界 a ＝ 请求（系统提示＋用户内容）的
  UTF-8 字节数 ＋ 512 ＋ `max_tokens`；每次发出调用之前先**预留** R ＝ 4a（4 是做题客户端一次调用里最多的尝试次数）。这个
  上界假设每个 token 至少一个字节、回答不超过 `max_tokens`；任何回执报告的输入 tokens 超过"字节数＋512"或输出 tokens 超过
  `max_tokens` → 假设不成立，整个运行暂停（§13.4）。
- 只有"已结算 ＋ 所有未结算的预留 ＋ R"同时不超过本步上限、所属链的上限和总上限时才发出；否则等在途调用结算；没有在途调用
  仍然超过 → **预算停止**，这次调用不发出。
- **结算**（回执回来后，逐次尝试；做题客户端的回执列出每次尝试的状态码或异常类型，用量只属于最后一次尝试）：

  | 尝试 | 计入 |
  |---|---|
  | 报告了合法用量（输入、输出、合计都是非负整数） | 报告的输入＋输出 |
  | 连接没有建立（ConnectError、ConnectTimeout、PoolTimeout） | 0 |
  | HTTP 4xx（含 429） | 0 |
  | 其他所有尝试：读写超时、连接中途断开、代理错误、HTTP 5xx、HTTP 200 但没有合法用量（包括返回了别的模型、回执格式不对、交付了回答却没报用量） | a |
  | 这次调用没有回执（进程中断） | 整份预留 R |

  只有能确定请求在生成之前就被拒的（前两种）按 0 计；其余缺用量的一律按上界计，所以每次调用的结算不超过它的预留。
- **基线的学习步**（冻结学习器自己发调用，不经过本账本）按冻结账本的硬规则算最坏用量：每次调用的提示不超过 240,000 字节
  （冻结账本拒绝更长的，`continual_learning/ledger.py`），回答不超过 131,072 tokens（截断恢复的上限），所以一次尝试的上界
  A ＝ 240,000 ＋ 512 ＋ 131,072 ＝ 371,584。冻结账本在已报告用量达到 6,000 万后不再接纳新调用；接纳时在途调用最多 8 个、
  每个最多 3 次尝试（基线客户端 1＋2 次重试）；没有用量的尝试累计最多 64 次（接纳前为每个在途调用按 3 次预留）。所以一个
  基线学习步最坏 ＝ 6,000 万 ＋（8 × 3 ＋ 64）× A ≈ 9,270 万，开始前在全局账本里**整份预留 9,300 万**。该步结束后按冻结
  账本的记录逐次尝试结算：有合法用量的按报告值；其余每次尝试按"该调用的提示字节数＋512＋该调用的 `max_tokens`"；有意向
  没有回执的调用按 3 倍计；任何报告值超过对应上界 → 暂停（§13.4）。基线的评测步用上面的预留制。

### 13.4 暂停、终止与部分结果

- **暂停的情形**：一轮基础设施未完成（§5.4）；训练执行或某一步某个 bench 的评测基础设施未完成；清理未确认（§5.4 第 3 行）；
  配置错误；预算停止；预留假设不成立。
- **单元**：每条链按顺序由单元组成，每个单元做完时一次性写下记录。本方法每一步：(1) 训练执行；(2) 门之前的方法工作
  （§4 第 2–8 步：分两半、考官修订、诊断、规则提案、泄漏与长度检查、冻结触发题、迁移题）；(3) 门的每一轮（初筛、复核、
  合在一起检验各算一轮）；(4) 合入（不调用模型）；(5) 每个 bench 的评测。基线每一步：(6) 学习步（冻结学习器的一次完整
  运行）；(7) 每个 bench 的评测。第 0 步每个 bench 的评测也各是一个单元。
- 暂停或进程中断之后什么都不会自动继续。负责人只能二选一：
  - (a) **终止**这条链；
  - (b) **授权继续**：之前已经写下记录的单元保留；暂停时所在的那个单元（没做完的，或做完了但因基础设施未完成而暂停的）
    **整个重做**——单元里每个格、每次方法角色调用都重新发出，已经完成的部分也不沿用（基线学习步用新的输出目录从头运行
    冻结学习器）；新尝试放在新的子目录；然后按顺序继续。因清理未确认而暂停的，授权前先确认清理：所有链停止发出新的沙盒与
    判分工作、等在途的执行结束，然后确认开发机上没有**任何状态**的 `continual-eval-*`、`skillopt-sheet-recalc-*` 容器，
    也没有遗留的 ALFWorld 工作进程；有就删除、再确认并记录。确认不了 → 保持暂停或终止。
- **哪次算数**：重做并做完的那一次就是这条链的轨迹；被中断的尝试存档、计入花费、在报告里列出，不进入任何读数。一次授权
  只重做一个单元；重做又被中断时，再次二选一。不属于上述单元的中断（例如清单核对不一致）→ 终止。
- 决定只能依据基础设施信息（未知格的数量与原因、花费），不看任何分数；封存的测试分数不打开。这是 §0"开跑后的重跑只能
  作为新版本"的唯一例外：在同一个运行目录里、按事先定的规则进行，不在两次尝试之间挑选。
- 预算停止时，选 (b) 还需要负责人提高相应上限；这记为一次**协议偏离**（写明数额与理由），在报告里列出。总上限同样只能
  这样提高。
- **停下的链怎么报**：已完成的评测照常报（标"链未完成"）；需要第 5 步的读数（P1–P4、F̄、N̄ 等）记"无法评估"，不用其他
  数据代替；所有尝试、偏离与花费都列出。

| 3（必改） | 分类表与代码不一致 | 改成有序判定表（取第一条适用的），代码逐行实现、测试逐行覆盖：回执的"没有交付"优先于后端原因（返回别的模型时不算截断）；判分失败按"参考一侧或环境 → 基础设施，候选一侧 → 产物"统一；工作簿结构检查加上解压大小与 openpyxl 能打开，"结构无效"（未通过）与"判不了"（未知）分开 | §5.4 |
| 4（建议） | 资格检查可能留下空的题池 | 基线需要的历史 train 或 val 合格部分为 0 → 不开跑；测试侧合格题为 0 → 第 0 步评测前停止；某读数在某 bench 上无题可用 → "无法评估"，不删 bench、不改权重 | §2.1、§10、§12.6 |
| 5（建议） | 授权重做与"原运行是主结果"矛盾，单元不全 | 单元列全（含门之前的方法工作、合入、基线学习步）；授权继续时只整个重做没做完的那个单元，重做并做完的那次算数，旧尝试存档计费不进读数；其余中断终止；写明这是 §0 的唯一例外 | §0、§13.4 |
| 6（建议） | 两处表述 | 每个共享臂只做自己的迁移题面板，父 Skill 与共享对照做并集；C1 表 4 道触发题、f＝0.75 改为 0.67–0.71 | §5.2、§5.3、§5.6 |
