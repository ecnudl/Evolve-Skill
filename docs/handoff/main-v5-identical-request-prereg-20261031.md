# 预注册：同请求题按平局计（`main-v5`、`zebra-pc-v14` 的第二分析）

写于 2026-10-31 03:1x（北京时间）。写的时候 `main-v5` 两条链都还没有任何测试目录（`/data/execskill-20261031-main-v5/{G,D}/test`
不存在），`zebra-pc-v14` 还没有启动，所以这两次运行的测试数字一个都没有被看过。

## 为什么要加

`main-v4` 的链末读数（结果账本 10/31 03:05）显示：在 SearchQA、OfficeQA、LiveMath、表格题上，F（链末包＋指令）和 C（只有指令）
每道题发给做题模型的请求都逐字节相同（链末包里只有 ALFWorld 程序，它们在这些题上被启用、但不写任何笔记），可两组仍各自独立
跑了一次。于是这几个 bench 上的 F−C 完全是同一文本重跑两次的差别：

| 链 | SearchQA | OfficeQA | LiveMath | 表格题 |
| --- | --- | --- | --- | --- |
| G：两次结果不同的题 | 19 / 400 | 36 / 172 | 22 / 125 | 57 / 204 |
| D：两次结果不同的题 | 8 / 400 | 20 / 172 | 7 / 125 | 28 / 204 |

G 链 LiveMath 的 F−C 是 +6.4 分（单侧 p = 0.044），却来自完全相同的输入。登记的测试读取只在“包在这道题上一个程序都不启用”时
才让 F 直接用 C 的格子（`cells.share_cell`，§8.1 的结构零）；程序被启用但不写笔记时不共享。

## 规则

在登记的读数（主分析，不改）之外，另报一个第二分析：

1. 对每个比较（F−C、各阶段包−C、F−B 等）和每道题：如果两组在这道题上的全部求解请求都存在、且请求哈希一一相同（单轮题是那一次
   调用；ALFWorld 是整局的每一次调用，顺序也相同），这道题的差记为 0（平局），不用两次独立运行的结果之差。
2. 其余题照常用登记读数里的结果。均值、区间与检验的公式与登记读数相同，只是上面这些题的差换成 0。
3. 报告时两种分析并列，并写明每个 bench 有多少道题按平局计；结论措辞以主分析为准，第二分析只用来说明“哪些差别可能只是重跑噪声”。

理由：请求逐字节相同时，两组在这道题上的处理没有任何不同，真实效应就是 0；把它记为 0 不引入偏差，只去掉重跑噪声。

## 适用范围与不变的部分

- 适用于 `main-v5`（链末各阶段读数，G、D 两条链）和 `zebra-pc-v14`（若收下程序，链末 F/C 读取）。
- 不改任何运行、代码、登记的读数或验收规则；只在读数之后用只读脚本（读格子记录里的请求哈希）另算。
- `main-v4` 已经打开的读数可以按同一规则重算作示例（四个非 ALFWorld bench 的 F−C 都变成 0），但它是看过数字之后的事后重算，只作说明。
