# Evidence-fidelity critique of `proposals/transfer.md` (lens 泛化评测优先)

2026-10-21. Critic: evidence-fidelity. Read-only: repository files, feasibility result/critic JSON, v3 code. No model calls, no SSH, no test pools opened.
Proposal line numbers below refer to `scratchpad/direction/proposals/transfer.md`. RL = docs/results-and-lessons.md; V6 = docs/handoff/coevo5-registration-v6-20261017.md; F/ = docs/handoff/feasibility-20261021/; OR = docs/handoff/overnight-report-20261021.md.

**Verdict: needs_revision.** The diagnosis (no readable learned-transfer result exists; OfficeQA is a weak hub; cross-window differencing is invalid) and most of the design (same-window item interleaving, card reference, ≥2 placebos, JSON-aware scoring, SearchQA-only source, sealed one-time test read, calibrate before evolving, do not run v4 as specified) are supported by the sources. But two headline sentences are false as written, one objective-1 argument rests on a claim a critic already refuted, the cost section repeats a receipts-vs-ledger comparison a critic already refuted, A7 is not a "known" text, and several resolution figures are stated more precisely than their sources allow.

## 1. Refuted or overstated claims (with exact source text)

**R1. "No learned text has ever been measured transferring" (l.7); summary_cn "至今没测过学到的文字能否迁移" (l.163).**
Learned texts have been moved to other benches and measured several times; what has never been shown is transfer *beyond a good instruction*.
- RL l.173 (v1 test, GLM-5.3): "相对空白：SpreadsheetBench 指令 +9.2 [+2.6, +16.0]、SkillOpt −2.0 [−9.6, +5.5]、E −7.2 [−14.7, 0.0]、GEPA −7.8 [−15.3, −0.5]"; "SearchQA 学来的写法伤害 SpreadsheetBench".
- The proposal's own C19 (F/E2/result.json `evidence`) is a learned-text transfer measurement: "Off-diagonal mean of the 4 targets: versus no Skill: +3.2 / +2.0 / +3.2 (E-glm / GEPA / SkillOpt); versus the cards: -3.2 / -4.4 / -3.2."
- RL l.206 (10/14, GLM): "对指令（Tango配对95%区间）…`oq_e41` −7.2 [−11.6, −3.5]、`lm_e41` −8.4 [−13.0, −4.5]、`e41s2` −8.0 [−12.3, −4.6]（损害）；`lm_z41` −63.6 [−69.5, −57.2]". The lm_z41 case (LiveMath "letter only" carried to SearchQA) is direct support for X6 and is omitted.
- RL l.209 (10/14, GLM, OfficeQA): "对指令：−5.4 [−17.7, +6.8]、−2.7 …、−1.4 [−11.1, +8.3]——区间都含0…对空Skill：+17.6 … +21.6".
- RL l.181 (10/16, deepseek): "SearchQA学到的Skill用在OfficeQA上 … train 50上0.609、0.767、0.800（9/1、9/1，p=0.021）"; vs the home Skill only cross-run: "只能读作'量级相近'".
- F/E4/critic-result.json `missing` 7: "The 10/13 cross-bench selection and foreign-text studies are not cited: SearchQA to BCB showed no transfer, and BCB to SearchQA gave +6-7, below a 3-line generic instruction."

**R2. "'Card + learned rule vs card' was never run on any target" (l.10, C6).**
C6's sources only cover cal-1 and the pilots. v1 and v3 ran every gated rule arm on each earlier bench's regression panel against the (card) parent.
- skillopt/coevo5/step.py l.18-20: "on a regression panel the parent runs ``PARENT_REGRESSION_RUNS`` times, a rule (or composite) arm once"; l.648-660: each rule arm's schedule is `runs_plan(focal, rule["trigger"], bench, regression=panels, …)` in `_round` (used by screen and confirm).
- V6 l.103: "回归面板 ＝ 从合格训练题中按种子抽 60 题"; l.218: "回归面板：之前每个 bench 一个（§2），每题 1 次"; l.287: "C3 之前 bench 不伤害：对之前每个 bench b 的回归面板，Σ L(r) − Σ H(父) ≥ −t_b".
- Card-parent chains had gated rules: docs/project-status.md l.216 (I-glm): "五步 25 条提案、13 条进初筛、2 条过初筛、0 条过复核"; l.183 (I-ds stage 3): "1 条支持够、初筛没过"; RL l.155: "第 4 步（SpreadsheetBench）那条过了初筛、复核没过 … 第 5 步（ALFWorld）1 条在初筛中".
- A measured rule-sized cross-bench bleed exists: docs/handoff/coevo5-midrun-analysis-20261019.md §3.12: "r2、r4 进入 Skill 后，OfficeQA 的 60 道回归题里分别有 4、5 个回答没写答案标签 …父 Skill 60 个全有；所以这两条也没过 C3 的格式项" (GLM-5.3, E-glm parent = scaffold + 2 rules).
- What stands: forward targets never ran (F/D12/result.json `evidence`: "0 forward panels in 10 chain-steps"); the backward cells are small (60 x 1) and were never analysed as transfer. They are a free T0 re-read the proposal omits.

## 4. Feasibility issues

1. T1 cap 45M is below the proposal's own ~2x reservation margin. At cal-1's ledger/receipt ratio (27.5M/14.0M ≈ 1.96) it would pause about halfway, as cal-1 did (E7 critic claim 8). Cap ≈80M.
2. Per-cell costs come from v3's mostly answer-only windows. Recomputed (estimate): T1 ≈41.5M, T3 ≈84M before ledger overhead, totals ≈200-360M ledger.
3. ALFWorld at 67 x 1 resolves only ≈11-14 points (estimate), so "no drop" on ALFWorld is close to uninformative.
4. The serving regime cannot be scheduled and its cause is unknown (D11). It may depend on dispatch composition (E6 critic). T1 rules (b)/(c) may be unevaluable, and OfficeQA may end descriptive-only.
5. B13/P7 changes every solver prompt and governs cross-section bleed ("follow only the section(s) whose 'Applies when' matches", spec l.99-102). If T2/T3 adopt it, T1 must use it too.
6. SearchQA pool arithmetic: per chain 3 x 100 never-reused proposal items + 300 acceptance items = 600 = whole pool. Acceptance items are necessarily reused across steps (adaptive). T1 uses 120, cal-1 200, the D1 pilot 130; only 59 were never used (E5 critic missing 7; E10 critic R1).
7. T2 adds two unvalidated changes at once: the D13 per-code proposer (D13 critic: best rule "照字面执行只能改对2道，还会把碰到的3道做对题改错"; tested only from the empty scaffold; cost underestimated) and D1 acceptance (unreviewed). A null T2 cannot be attributed.
8. "No validation set" depends on the owner's reading. F/D1/result.json point 11: "If the owner reads 'no fixed validation set' as 'no labelled real item may decide acceptance', neither v3 nor D1 qualifies." Using target training pools in T1/T1-V also needs owner sign-off.
9. T1-V: the 2.6k per cell mixes real-pool and generated cells under scaffold or one-card parents (E9 `cost_estimate`: "generated OfficeQA-style 670 / 1,294"). With the five-card parent it is ≈3.6k per cell, ≈4.6M before harder items, near the 5M budget. The OfficeQA-style D6 generator and "difficulty by construction" are untested. The independent program must sit in the agreeing pair (D6 critic). GLM per kept item ranges 2.7k-6.6k.
10. New engineering before T1/T2: single-source row (stage→bench hard-wired, step.py l.198 and other `ORDER[stage - 1]` sites; baseline.py l.93, l.268), JSON-aware scorer version, item-blocked interleaving dispatcher, D1 acceptance, firewall + hash audit.
11. Wall clock at ~880 cells/h with 6 workers (D1 point 10): T1 ≈7.7 h; T3 ≈12 h + ALFWorld. Both span regimes.
12. The D10 pivot (measurement paper) would consume the same one-time held-out read as T3 (D10 critic ②). The owner must choose one.
13. D1 and D12 have no critic review; D14 has only a report.
14. The self-gain co-primary on SearchQA will likely read "not established" (MDE ≈3.7, ×1.3 under Holm, vs learned effects ≤ +0.5 on the card parent in D1's replay). The owner should know this beforehand.

## 6. what_survives_cn

核心诊断和大部分设计站得住。v3（第 3 版正式运行）一条规则都没收下，向"还没轮到的相似数据集"的前向检查一次也没跑，所以"在一个数据集上进化、在其余数据集上评测"至今没有一个能读的学习结果。学到的文字在好说明之上的迁移从未被证实：以前几次搬运测量，只在和空白说明比时"涨分"，和好说明比是持平或掉分。整段说明卡的试跑显示，推人"只给答案"的文字会在 OfficeQA 上造成大伤害。登记的相似关系把 SearchQA、LiveMath、SpreadsheetBench 唯一的相似目标都押在题最少的 OfficeQA 上（74 道训练题加 172 道测试题，就是全部公开题）。跨时段相减不可信，必须同一时段逐题交错，以任务说明为参照，加至少两段安慰剂，并用 JSON 也认的评分。只有 SearchQA 的题量够当进化来源。测试题冻结后只读一次。先花小钱标定量尺、再花大钱进化，暂不按原样跑 v4（第 4 版方案），这些都有证据支持。"验证端在进步没有证据"也成立（判卷程序接近瞎猜，生成题饱和），但不能再用"出题方钻评分漏洞"当理由。需要改的有：两句说法（"从没测过迁移"、"任务说明加规则从没测过"）；A7 当已知有害文字；成本和上限的口径；ALFWorld 与 OfficeQA 的分辨力；6 分门槛的依据；T1 和 T2 的提示要一致；SearchQA 题目的重复使用；D1、D12、D13 未经审查或未验证的部分。
