### 3.1 B15-a: `RESEARCH_MAX_ROUNDS` vs the request loop — status: planned (open question §8.1)

**Finding (corrects the spec's premise).** `research.request` (research.py:578–664) iterates
`for number in range(1, RESEARCH_MAX_ROUNDS + 1)` and starts a round only while
`RESEARCH_MAX_CALLS - calls >= CALLS_PER_ROUND` (3: query, pick, conclude; line 595). With 8 calls, two FULL rounds
(6 calls) leave 2 < 3, so a third full round never starts — the normal path ends `calls_exhausted` after two rounds
(`tests/test_coevo5_research.py:226–229` pins this). But a round cut short by an invalid query or pick (1–2 calls)
leaves room for a third round, so `RESEARCH_MAX_ROUNDS = 3` DOES bind on that path (tests at 234, 239, 332 pin
`rounds_exhausted` with 3 rounds). The incoherence: three full rounds can never fit in 8 calls. The spec's direction
("set the constant to the real maximum") is followed: the real maximum of full rounds is 2.

**Design.** `RESEARCH_MAX_ROUNDS = 2`; a named `RESEARCH_CALLS_PER_ROUND = 3` (moved to protocol.py from research.py's
local `CALLS_PER_ROUND`); `RESEARCH_MAX_CALLS = RESEARCH_MAX_ROUNDS * RESEARCH_CALLS_PER_ROUND` (= 6). The loop is
unchanged. The `calls_exhausted` guard stays (the registered call ceiling, reachable when an owner changes one constant
without the other; a test monkeypatches it). Semantics: a request after a short round no longer gets a third round
(<= 6 calls instead of <= 8 on that path); a fruitless request's common terminal reason becomes `rounds_exhausted`
instead of `calls_exhausted` (no module reads these reasons — only research.py sets them; the smoke summary counts
requests and `found`). Pages (3) and queries per round (3) unchanged; `forward.py`'s material requests go through the
same `request`. Research volume can only fall; no cap depends on it.

Alternative (not planned; §8.1): 3 rounds / 9 calls — +50% calls on every fruitless request.

```python
    """``call(system, user, **options)`` answers from ``replies``: a list (in order) or a function ``(system, payload)
    -> receipt or value`` (a value is wrapped by ``reply``). Every request is kept in ``seen`` as (system, payload);
    v4 (P4): the sampling options a voting role sends (``temperature``) are kept in ``options``, one dict per call,
    parallel to ``seen``, so ``seen`` stays a pair for every existing test."""

    def __init__(self, replies):
        self.replies, self.seen, self.options = replies, [], []

    def call(self, system, user, **options):
        try:
            payload = json.loads(user)
        except ValueError:  # a plain-text user message (``Roles.plain``)
            payload = user
        self.seen.append((system, payload))
        self.options.append(dict(options))
```
