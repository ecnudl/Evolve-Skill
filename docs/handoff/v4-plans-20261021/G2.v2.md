## 1. P1 (G2 slice): the applicability judge -- status: **planned**

### 1.1 What changes, in one paragraph

**Today.** In `step.prepare` (lines 386-391), a rule's trigger items are the check-half items with a failed run
whose diagnosis code is one of the rule's codes. `_round` (lines 691-693) computes the C2 rest panel as the focal
panel minus the rule's trigger and evidence items.

**v4.** For a rule that passed `_admissible`, `prepare` asks a new GLM role, the applicability judge
(`applicability.judge`), about EVERY check-half item, passed and failed: does the rule's `when` hold on the item's
public input? The input is the bench's public task card plus `examiner.task_view(...)` with the diagnosis' context
bound, exactly what the diagnosis sees and never a reference. ALFWorld uses the first training run whose trace
starts with an observation. Each item gets three votes through G4's `Roles.vote`; the majority decides, and a tie
means not applicable.

**The frozen panels.** Both sit in the prepare record:
- `trigger` holds the applicable items. `MIN_TRIGGER` = 4 still applies; with fewer, the rule is
  `insufficient_support` and the counts are recorded.
- `not_applicable` holds the other check-half items.
- `rest` holds `not_applicable` minus the rule's evidence items (v3 §7).

**Downstream.** `_round` reads `rule["rest"]`. Every other scheduled focal item is `held`: no criterion reads it,
but it stays in the arm's unknown share. Per rule, the record carries `when_matched`, `when_precision`,
`when_recall` and the counts, for information only. A self-test revision must keep the condition (§1.11). C1-C4' are
otherwise unchanged: same runs, thresholds and controls.

### 1.3 NEW module `skillopt/coevo5/applicability.py` (complete)

Verified in a scratch tree (§9), against a G4-faithful shim of `reasoned` / `Roles.vote`.

```python
"""The applicability judge (registration v4 P1): a rule's trigger items from its condition, not from diagnosis codes.

A v4 rule reads "When <when>: <do>." (optionally "... Otherwise: <otherwise>."; ``analyst.render_text``), ``when``
being an observable condition on the task input the solver sees. v1-v3 (§4 step 7) froze a rule's trigger items as
the check-half items with a failed run of a targeted diagnosis code; v4 freezes them as the check-half items -- passed
and failed alike -- on which this judge (GLM-5.3, a method role) finds the condition to hold on the item's public
input: the bench's public task card and the task exactly as the examiner's diagnosis sees it (``examiner.task_view``
with the diagnosis' context bound, ``DIAGNOSE_CONTEXT_CHARS``; ALFWorld: the episode's initial observation from the
first training run whose trace starts with one), never a reference, an answer or a score. Each item is judged by
``ROLE_VOTES`` independent samples (P4, ``roles.Roles.vote``): reason-then-label JSON validated by
``roles.reasoned`` (the reason clipped to ``ROLE_REASON_CHARS`` for the archive, B5), the majority label; no
majority is "not_applicable". ``MIN_TRIGGER`` applies to the trigger set (``step.prepare``: fewer is
``insufficient_support``, the counts recorded). The rule's C2 "rest" panel is frozen with it (``panels``): the
check-half items judged not applicable, minus the rule's own evidence items (v3 §7). Per rule the record carries,
informational only (no gate criterion reads them): ``when_matched`` (the applicable items), ``when_precision`` (the
applicable items that are check-half failed items whose item code -- v4 B8 -- is one of the rule's codes, over the
applicable items) and ``when_recall`` (the same, over all check-half failed items of those codes). The fixed prompt
carries one worked example about an imaginary colour-sorting task (P2), hashed with the role's prompt identity like
the rest of it.

Cost (v4 §0): (rules judged, at most ``MAX_RULES``) x (check-half items) x ``ROLE_VOTES`` calls per step, once per
rule in ``step.prepare`` -- a self-test revision keeps the condition (``step.selftest``), so no text is judged twice;
``protocol.role_volume`` counts it. The judge is asked only for a rule that passed the leakage and length checks.
"""
from __future__ import annotations

from fractions import Fraction

from skillopt.continual_eval.core import require

from .cells import run_parallel
from .examiner import task_view
from .protocol import DIAGNOSE_CONTEXT_CHARS, MAX_WHEN_CHARS, MIN_TRIGGER
from .roles import reasoned

APPLICABLE, NOT_APPLICABLE = "applicable", "not_applicable"
LABELS = (APPLICABLE, NOT_APPLICABLE)
CHECK = reasoned("label", LABELS)  # P4/B5: {"reason", "label"}; other keys tolerated, the reason clipped

JUDGE_SYSTEM = (
    "You judge whether a condition holds for one task. A guidance rule for a language model that solves tasks has "
    "the form \"When <condition>: <action>.\"; you receive the condition alone, the public description of this kind "
    "of task (what the solver is told), and one task exactly as the solver sees it -- never its answer. Decide "
    "whether the condition holds for this task from its input alone: what the task asks, the material it supplies "
    "and how they are written. Do not solve the task, do not guess its answer, and do not judge whether the action "
    "would help. A condition that refers to something the solver cannot see before answering (the correct answer, "
    "whether an answer is right, a score), or that cannot be decided from the input, does not hold. Reply with one "
    "JSON object only, the reason before the label: {\"reason\": a short reason of at most 300 characters, "
    "\"label\": \"applicable\" or \"not_applicable\"}.\n\n"
    "Worked example (an imaginary colour-sorting task, unrelated to any task you will see). Condition: \"the task "
    "lists more than five colours to sort\". Task: {\"instruction\": \"Sort these colours from warm to cold: red, "
    "teal, amber, violet, lime, coral, navy\"}. Reply: {\"reason\": \"The instruction lists seven colours, which is "
    "more than five.\", \"label\": \"applicable\"}.")


def not_judged():
    """The panels of a rule the judge was not asked about (it may not be tested anyway: a leak or an overlength
    text) -- new lists on every call, so no two rule records share one."""
    return {"trigger": [], "not_applicable": [], "rest": [], "applicability": None, "when_matched": None,
            "when_precision": None, "when_recall": None}


def view(benchmark, public, *, trace=None):
    """The item's public input exactly as the diagnosis sees it (``examiner.diagnose_one``), never a reference."""
    return task_view(benchmark, public, trace=trace, context_chars=DIAGNOSE_CONTEXT_CHARS.get(benchmark))


def _observed(trace):
    """Whether a run's trace starts with an observation (``step._alfworld_texts`` reads the same)."""
    return (type(trace) is list and bool(trace) and isinstance(trace[0], dict)
            and isinstance(trace[0].get("observation"), str))


def views(benchmark, tasks, answers, items):
    """{item: its public view} for ``items``; ``answers`` (``step.answers``, by item then run) lend ALFWorld's initial
    observation: the first run whose trace starts with one (an item without any is shown an empty observation)."""
    traces = {}
    for answer in answers:
        if answer["item"] not in traces and _observed(answer.get("trace")):
            traces[answer["item"]] = answer["trace"]
    return {item: view(benchmark, tasks[item]["public"], trace=traces.get(item)) for item in items}


def judge_one(roles, card, when, item_view, *, label):
    """One item's applicability: the record of ``roles.vote`` (G4, P4) -- {"label", "majority", "tally", "invalid",
    "votes": [{"label", "reason", "valid"} per sample]}; no majority is not applicable. The message is bounded by
    construction: the view is the diagnosis' clipped view (at most 32,000 characters of OfficeQA pages), far under
    ``ROLE_INPUT_BYTES``."""
    require(type(when) is str and when.strip() and len(when) <= MAX_WHEN_CHARS,
            "A condition of 1-%d characters" % MAX_WHEN_CHARS)
    payload = {"task_card": card, "condition": when, "task": item_view}
    _, record = roles.vote("applicability", JUDGE_SYSTEM, payload, label=label, check=CHECK,
                           label_of=lambda value: value["label"], tie=NOT_APPLICABLE)
    return record


def judge(roles, bench, *, when, items, tasks, card, label, workers, answers=()):
    """The condition over ``items`` (the check-half item keys, sorted and distinct; ``tasks``: ``step.pool_tasks``;
    ``answers``: the training answers, which lend ALFWorld's observation): {"applicable": the items judged applicable,
    "not_applicable": the others (a tie included), "votes": {item: ``judge_one``'s record}} -- the two lists
    partition ``items``, in its order. Item ``i`` is labelled "<label>/<i>" (its samples "/v1" ...). The views are
    built here, for a rule that is judged, never before (a SpreadsheetBench view reads a workbook preview)."""
    items = list(items)
    require(items == sorted(set(items)) and set(items) <= set(tasks), "Sorted distinct pool items")
    shown = views(bench, tasks, answers, items)
    found = run_parallel(lambda item: judge_one(roles, card, when, shown[item], label="%s/%s" % (label, item)),
                         items, workers=workers)
    votes = dict(zip(items, found))
    return {"applicable": [i for i in items if votes[i]["label"] == APPLICABLE],
            "not_applicable": [i for i in items if votes[i]["label"] != APPLICABLE], "votes": votes}


def panels(verdict, *, failed_codes, codes, evidence):
    """A judged rule's frozen panels and condition statistics from ``judge``'s ``verdict``: {"trigger": the applicable
    items, "not_applicable": the others, "rest": those minus the rule's evidence (v3 §7; C2 reads it),
    "applicability": the counts, "when_matched", "when_precision", "when_recall"} (the last two exact fractions as
    strings, None when their denominator is 0). ``failed_codes``: {check-half failed item: its code} (v4 B8,
    ``examiner.by_item``); ``codes``: the rule's codes (v4 B1); ``evidence``: its cited items."""
    trigger, other = list(verdict["applicable"]), list(verdict["not_applicable"])
    judged, own, wanted = set(trigger) | set(other), set(evidence), set(codes)
    rest = [i for i in other if i not in own]
    targeted = {i for i, code in failed_codes.items() if code in wanted and i in judged}
    hit = len(targeted & set(trigger))
    counts = {"check_items": len(judged), "applicable": len(trigger), "not_applicable": len(other),
              "tie": sum(1 for r in verdict["votes"].values() if not r["majority"]),
              "evidence_in_check_half": len(own & judged), "rest": len(rest), "min_trigger": MIN_TRIGGER}
    return {"trigger": trigger, "not_applicable": other, "rest": rest, "applicability": counts,
            "when_matched": len(trigger),
            "when_precision": str(Fraction(hit, len(trigger))) if trigger else None,
            "when_recall": str(Fraction(hit, len(targeted))) if targeted else None}
```
