# 以泛化为中心的 Skill 进化：设计架构（2026-10-15，写于任何新结果之前，待负责人确认）

负责人 10/15 的五点：(1) 我们只盯着测试集准确率，没有围绕根本目的——泛化——去测试和进化；(2) 生成题可以比验证题
简单，但不能各方面都不如验证题，它可能更能引出有价值的反馈、帮助泛化；(3) 怎么实现、现在的流程是什么；(4) 会试更弱的
求解模型；(5) 给出最终架构，点头后审查上线。约束不变：不改研究目的、不改方法的主流程（训练执行 → 反馈 → analyst →
候选 → 决定），不读测试题，冻结的代码与产物不动，新行为用新版本与新目录。

## 1 现行流程（如实）

**一个学习阶段（v9 SkillOpt / v10 Rubric＋Research）**，每阶段至多 3 步，每步：
1. 训练执行：父 Skill 解训练题（OfficeQA 48 道真题）。
2. 反馈：v9 给失败行附参考答案；v10 给失败行附 rubric 判定文本（不见参考答案），只在 rubric 通过校准的步骤里给。
3. analyst（冻结的原生更新器：失败/成功小批各 8 条 → 合并 → 排序 → 至多 4 条编辑）提出候选 Skill。
4. 门：候选与父在选择集上比（OfficeQA 选择集＝24 道真验证题，或 124 道生成题）——初筛家族符号检验 p≤0.10 且净胜＞0，
   再各自重跑一遍复核 p≤0.05/3；过了才替换父 Skill。
5. 阶段结束写 learned.json；测试集只在单独的 `test` 子命令里、经负责人同意后一次性读取。

**rubric 怎么来**（v10，`verifier.py`）：规划器读 16 行训练记录（含宿主的对/错，不含原因）→ 决定是否改 → 合成器写一份
七字段的 rubric（机制、义务、适用范围、例外、所需证据、检查生成、不确定性）→ 用本步训练行校准（检出≥1、通过对照≥5、
误拒≤0.25 才授权）→ 判定器对每个失败行按 rubric 至多查两条、必须引题面原文。Research（查官方文档）只对 BigCodeBench
开放（`verifier.py:1039`），文本数据集上关闭。**rubric 不生成题目。**

**生成题怎么来**（`scripts/generate_officeqa_tasks.py`、`generate_searchqa_tasks.py`，10/13–10/14）：写题模型只看
一道训练题的公开页面，每道训练题至多写 4 道新题；OfficeQA 的新题不写答案，只写用到的数字（附逐字引文、必须是整个
表格单元格）、一个受限语法的算式和保留位数，**答案由代码精确算出**；确定性过滤（引文逐字、答案依赖每个数字、无舍入
平局、题面不含答案等）＋一次审稿模型的六项判定。SearchQA 的新题是同一批检索片段里的其它事实、答案逐字出现在片段里。
生成题**只当门的选择集**，不进入训练。

**测试与验证**：门（上面第 4 步）；配对研究（rubric 形式、绑定）在选择集上比较候选、不过门；跨数据集评测（G1，学到的
Skill 放到别的数据集）；测试集一次性读取（OfficeQA 172 题、LiveMath 评测块，都未读）。

**这个流程在泛化上的缺口（10/15 的零调用审计，台账 10/15 10:00 条）**：
- 门量的是"同一批页面上的新题"的准确率（生成题来自训练题自己的页面）——只是近迁移；跨数据集只在事后测、从不进入决定。
- 生成题门太容易：同一父 Skill 跑 12 次，124 道里 48% 次次都对、49% 时对时错、2% 次次都错；候选只多对 1.4 题——门看见
  的主要是随机性。真题上 28% 稳定失败（74 题、3 次运行），说明生成题"各方面都不如"真题：既不难，也不暴露系统性弱点。
- 反馈弱：文本 rubric 只能判形式与范围；对/错只有一位；生成题自带的推导（哪个单元格、什么算式、几位小数）从未被用作反馈。

## 2 设计

### 2.1 泛化在本设计里的三个层次（作为主要结果，而不是事后附带）
1. 近迁移：同一批页面上的新题（现在的生成题门）——最弱，只作参考。
2. **远迁移（主目标）**：与训练题**页面不相交**的新题与真题。
3. **跨数据集**：学到的 Skill 不伤害其它数据集（最好也有帮助）——进入决定，而不只是事后测。

### 2.2 数据角色（OfficeQA；SearchQA 同理）
- 训练题（OfficeQA 训练分区 48 道，几乎每道题的页面都不同：90 个页面里只有 1 个被两道题共用）按种子、按公报文件
  不相交地分成 **L（学习，32 道）** 与 **H（留出，16 道）**。H 的真题从不进入训练执行与反馈。
- **D（诊断题，进入训练）**：从 L 的页面生成，答案代码算出。
- **T（迁移题，只进入比较/门）**：从 H 的页面生成的新题 ＋ H 的 16 道真题。
- **跨数据集面板**：其它数据集的生成题（如 SearchQA 生成题 60 道），只用来查伤害。
- 真验证集（24 道）与测试集（172 道）不进入循环。

### 2.3 生成器 v2：诊断题（负责人第 2 点的实现）
生成题的价值分成两种角色、两套标准：**D 要"有诊断性"**（能暴露并定位一种可教的错误，可以比真题简单），**T 要"像目标分布、
有难度"**。D 按类别出题（都在现有算式语法内：数字、常数、四则、abs/min/max）：
- 精度与舍入（指定位数）；单位量级（页面是千/百万，题目要另一单位）；百分数约定（变化率 vs 百分点 vs 比率）；
- 版本/重复数字（同一序列在页面多处出现，题目指定哪一处——真题里"找错单元格/期次"的弱点）；
- 跨页（数字来自两页及以上）；简单统计量（均值、合计、差的均值）。
**难度校准**：父 Skill 对每道 D、T 题各独立跑 3 次。D 里只保留父 Skill 3 次中至少错 1 次的题（有诊断价值）；T 记录难度
分布，主分析用全部 T 题、次要分析用"父 Skill 不是次次都对"的子集。

### 2.4 反馈：全局文本 rubric ＋ 代码 rubric（负责人提出的最终形式）
- 真题行：**全局文本 rubric**（与数据集无关的那一份，模型判定，不见参考答案，沿用 v10 的校准与授权）。
- 诊断题行：**代码 rubric（宿主执行、零调用、知道真相）**。因为 D 题的推导是生成器给的，宿主可以对模型的答案做误差模式
  诊断：舍入不同（未舍入/截断/位数不对）、量级错（×/÷10、100、1000、10⁶）、百分数约定错（×/÷100）、方向错（取负、
  减数被减数对调、分子分母对调）、**用错单元格**（把算式里一个数字换成同行/同列的另一个印刷数字后正好等于模型答案）、
  其它（无法解释）。反馈文本：正确答案、所用数字及其页面引文、算式、模型答案属于哪种误差模式。
- 这是信息上的一个改变：v10 是"不给参考答案"的验证；D 题的答案是我们从训练页面自己算出来的，不是数据集的标签，也不
  碰验证/测试。v9 的"附参考答案"在 rubric 形式研究里并不比对/错好（573 对 588/744）——这里押的是"推导级、误差模式级
  的诊断，加上专门暴露系统性弱点的题"比单给答案更有用；第 3 节的主对比直接检验它。

### 2.5 analyst：不变
冻结的原生更新器与迁移前言（已要求"每条编辑注明适用的任务类型、不要把某个数据集的格式写成通用规则"）。

### 2.6 泛化门（不用验证集；第二阶段并入学习版本）
- 远迁移检验：候选与父在 T 上各评 2 次（降噪），**两遍合并**的家族符号检验（10/14 回放：合并规则在 15 个历史候选里
  收 10 个，冻结的两遍分开检验收 5 个）。
- 跨数据集不伤害：候选与父在其它数据集面板上比，单侧伤害检验；显著伤害则拒绝。
- 两者都过才接受。

### 2.7 循环外的泛化评测
真题留出（H 真题、真验证集、测试集一次性读取需负责人同意）；跨数据集矩阵；对照：空 Skill、零样本指令、v9、v10；
弱求解器维度（2.8）。

### 2.8 更弱的求解模型
冻结的 API 客户端只允许 GLM-5.3、思考开启、推理档位 low/high/max（`validator_pilot/api.py:81`、`:346`），现在用的 low 已是
最弱档，所以要写一个**新的客户端模块**（不改冻结代码）与新的协议记录。先做**只评测、不学习**的探针：同一批题（OfficeQA
124 道生成题＋74 道真题、SearchQA 168 道生成题），Skill 用空、零样本指令、2–3 份学到的候选，各跑 2 次；看 Skill 之间的
差距和"次次都错"的题是否明显变多。若差距拉开，第一阶段的配对研究再用弱模型跑一遍。

## 3 第一阶段（点头后：审查 → 冒烟 → 上线）：泛化反馈配对研究（OfficeQA）

协议 `fivebench-generalization-feedback-study-v1`（新目录、新协议，冻结学习代码一行不改）。

**准备（约 1 小时，约 800–1,000 次调用）**：生成器 v2 在 L 的页面上出 D、在 H 的页面上出 T；父 Skill 对 D、T 各跑 3 次做难度校准。

**go / no-go（事先定下）**：D 里"父 Skill 至少错 1 次"的题少于 30 道，或 T 里"父 Skill 不是次次都对"的题少于 25 道，就
停在这里、不跑配对研究，报告"生成器 v2 也没能做出暴露弱点的题"——这本身回答负责人的第 2 点。

**臂（每块共享一次训练执行：L 的 32 道真题 ＋ D 题）**：
| 臂 | 真题行的反馈 | D 题行的反馈 |
| --- | --- | --- |
| `scalar` | 对/错 | 对/错 |
| `scalar_repeat` | 对/错 | 对/错（与 `scalar` 输入完全相同的第二次提案＝块内噪声参照） |
| `global_text` | 全局文本 rubric | 全局文本 rubric |
| `code_diag` | 对/错 | 代码 rubric（误差模式诊断＋推导） |
| `global_code` | 全局文本 rubric | 全局文本 rubric ＋ 代码 rubric（＝负责人提出的最终形式） |

（实现时改成"文本层 × 代码层"的 2×2：文本判定器像 v10 一样判所有训练行，包括 D 题；代码层只作用于 D 题。这样
`global_code − global_text` 只差代码层，`code_diag − scalar` 只差代码层，两个主对比都是干净的单因素对比。）

**结果**：研究内只有 T——每个不同的候选与父 Skill 在 T（H 页面上的生成题）上各评 2 次。H 的 16 道真题与跨数据集伤害（SearchQA 生成题）**不在研究内**：研究结束后，用冻结的候选文本另做一次只评测的事后测量（`weak_solver_probe.py`，同一求解设置），单独报告、不进入登记的检验。（10/15 实现时的范围修订，写于任何结果之前。）
**事先登记的读数**：主对比 `global_code − global_text`（加上代码层有没有用）、`code_diag − scalar`（诊断反馈比对/错好不好）；
6 块，块级精确符号翻转，6 块同向才"支持"；每块同时报告 `scalar_repeat − scalar`（同输入噪声）；事后测量分开报告 H 真题、
SearchQA 面板；合规审计（编辑是否回应了诊断出的误差模式）只作描述。
**成本与时间**：每块约 1,400 次调用（OfficeQA 约 1,050、SearchQA 约 360）、45–60 分钟；6 块（一块一研究串联）约 5–6 小时、约 6,500 万 tokens。

## 4 后续（条件触发，各自再报告与点头）
- **第二阶段**（若 `code_diag` 或 `global_code` 被支持）：把 2.3–2.6 并入一个新学习版本（v12），在 OfficeQA 与 SearchQA
  （SearchQA 的诊断类别＝答案形式约定）上跑完整阶段，对照 v9/v10；跨数据集矩阵；方法冻结后再谈测试集一次性读取。
- **若都不被支持**：如实记为"在这个设计下没有建立候选得分的差别"（不等于"诊断反馈不改变候选"：6 块只能看见稳定的较大差，候选文本的变化另由零调用审计描述），并看弱求解器探针的结果。
- **弱求解器探针**：需要负责人给出型号（以及是否同一个 key），与第一阶段并行准备。

## 5 不变与改变
不变：研究目的；主流程；冻结的 analyst/更新器、求解器、评分器；不读验证/测试题。改变：训练材料多了自己生成、可验证的诊断题；
反馈＝全局文本 rubric＋代码 rubric；比较/门量的是页面不相交的远迁移与跨数据集不伤害；每个候选评 2 次、内置同输入噪声参照。

## 6 风险
- 强模型可能连 v2 的难题也"时对时错"而不"稳定做错"——go/no-go 会先测出来。
- 只用 OfficeQA（唯一能用代码算出答案的数据集）；SearchQA 的诊断只能到"形式还是内容"这一层。
- 16 道 H 真题太少，只作描述；远迁移的主体是 T 生成题。
- 生成器 v2 与误差模式诊断都是新代码，需要 Codex 审查与离线测试后才上线。


## 7 实现时的修订（2026-10-15，写于任何结果之前；Codex 审查要求）

- 生成按 L/H 分开两次：L 用生成器 v2（写题模型看到源问题，与 v1 相同——它们是学习者本来就看到的训练题）；H 用 `generate_officeqa_transfer_tasks.py`，**只给页面**，任何提示里都没有 H 的问题，审稿的"与源问题不同"一项随之去掉（v1 的精确重复检查仍在宿主上做）。
- 校准只在"完整的题 × 3 次运行清单"上被接受（`_calibration` 逐条核对探针记录与题池内容），清单哈希写进协议。
- 合并臂的验证文本：代码层在前、预留 1,000 字符，文本层用剩下的空间；代码层的文本把"期望答案、你的答案、诊断"放在最前，引文放最后。
- 代码臂的失败小批 analyst 系统提示附一段登记的说明（`CODE_NOTE`：生成题是"不给答案"的唯一例外，变体只是提示）。
- 候选若逐字带有生成题的答案（≥3 位有效数字）、算式（≥8 字符）或任一段 ≥24 字符的引文，就被拒绝（`rejected_derivation_leak`，该臂按父 Skill 计），保证推导永远到不了求解器。
- 误差模式只说"哪个变体复现了你的数字"，不断言原因；"邻近单元格"只在引文所在的那一行、那一列里找，锚点不唯一就不判。
- 题型类别是写题模型自己标的、审稿不核对：按类别的计数只作描述。

## 8 第一阶段的结果（2026-10-15 17:37）：按登记的 go/no-go 停止

诊断题 84 道（父 Skill 3 次校准：至少错一次 33 道，满足 ≥30）；迁移题 41 道（非次次都对 17 道，不满足 ≥25）→ 研究不跑。详情与同时完成的求解器强度探针见台账 10/15 17:37 条。可能的下一步（需负责人决定）：扩大 H（拆成 24/24，两侧都会贴近门槛）、更难的迁移题生成器、或把远迁移测量换成真题（OfficeQA 只有测试集足够大；SearchQA 有未读的新样本块）。
