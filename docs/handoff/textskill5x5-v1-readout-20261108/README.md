## 怎么理解

1. **相对任务卡几乎没有学到东西。** 只有上面结论里的两处提升，而且都只在自己学的那个 bench 上。
2. **技能比什么都不加好，但主要是“有一段说明”的作用。** 在 SkillOpt G、GEPA G、GEPA D 三次运行里，技能比什么都不加在 SearchQA 和 OfficeQA 上高 9.9 到 18.6 个点；任务卡本身就比什么都不加高 11.2 到 16.9 个点（D 链 13.4 到 16.8），所以这部分至少任务卡这样一段说明就能给，不是学出来的。这里只试过任务卡这一段文字。SkillOpt D 链是反例：空技能时和什么都不加一样，学完 ZebraLogic 后反而比什么都不加低 45.0 到 46.5 个点（SearchQA）和 8.1 到 8.7 个点（OfficeQA）。
3. **一段全局技能文字会互相干扰。** SkillOpt 和 GEPA 都只有一段全局技能文字，所有 bench 都发同一段。SkillOpt D 链：相对任务卡，SearchQA 掉 63 个点、OfficeQA 掉 22 个点，但其中约 17 和 13 个点在空技能的 s2 就已经掉了，是不发任务卡造成的；ZebraLogic 文字本身的作用看 s3 减 s2：SearchQA −46.5、OfficeQA −8.7、表格题 −11.3，区间都低于 0。同一段文字在 ALFWorld 上反而比空技能高 15.7 个点，区间高于 0，只是仍不如任务卡。11/08 15:4x 负责人问 SearchQA 的 −61.8 是不是运行故障，查明不是：这段 ZebraLogic 文字结尾有一节“输出格式”，要求每个回答都写成只含 `reasoning` 和 `solution`（按 House 1…N）的 JSON；SkillOpt 只有一段全局文字，SearchQA、OfficeQA 的回答照这个格式写，就既没有答案标签也没有 `answer` 字段，冻结的取答案规则取不到答案，只能算错（用评分程序对这种格式的人造回答试过，内容对也取不到）；这几格的读数单元全部完成、0 格判不了，每次调用多花的 token 约等于技能文字本身，链末 C_end 与同期 GEPA 的 SearchQA 正常。所以这是输出格式冲突造成的伤害，不是知识层面的干扰；诊断没有看封存的测试回答。负责人随后要求以最小代价得到正常数据，零调用的格式宽容重算（事后敏感性分析，所有组同一规则）在做。表格题对任务卡只有第 3 步的 −9.8 显著，链末 −6.9 区间包含 0。
4. **GEPA 在 D 链上没有测出帮助，也没有测出伤害**，但这不等于没有伤害：ALFWorld 五格的点估计全是负的，−3.0 到 −10.4，区间下限到 −23.8。GEPA 在 G 链表格题上掉 8.8 到 14.2 个点，同一段文字五次读数是 −14.2、−12.3、−13.2、−13.7、−8.8，其中 s3、s4 两格显著。
5. **表格题的差值要看两种计分方式。** 主读数对技能组最不利。所有组一律把判不了的格子算对时，按正确率粗算，SkillOpt G 链表格题的差值只有 −0.5 到 −4.4，GEPA G 链是 −3.4 到 −9.3。所以 SkillOpt G 链表格题的下降大部分是计分方式造成的，GEPA 第 3、4 步的下降在两种算法下都还在。G 链判不了的格子：C 2 个，B 12 个，技能组 7 到 16 个。
6. **一个不稳的迹象，不能当证据。** ZebraLogic 上任务卡和什么都不加的请求逐字节相同。如果以 B 为对照，SkillOpt G 链在 SearchQA 学到的技能在 ZebraLogic 上 s1 到 s3 是 +9.0 到 +9.5，区间高于 0、略超 ±8.2；以 C 为对照只有 +5.5 到 +6.0、区间包含 0。
7. **漂移很小。** 链末重读的任务卡 C_end 与起点 C 相比，十个格子的区间都包含 0。
