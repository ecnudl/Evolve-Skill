# 三个架构探针：结果与新架构方案（2026-11-09）

> **真实模型运行，只用练习题，没有读任何测试面板。** G = GLM-5.3，D = deepseek-v4-flash（northgate，关闭思考）。代码是本机 `execskill-arch` 工作副本里的 `scripts/arch_probes.py`（未提交），dl 原始输出在 `/data/arch-probes-20261109/`。本页数字由 `make_arch_readout.py` 从同目录的结果 JSON 生成，生成时间 21:5x。

## 先说结论

1. **任务卡继续放在系统消息里。** 卡片内容挪到用户消息末尾，10 组对比里没有一组显著变好；D 链 ZebraLogic 显著变差，降 28.0 分（95% 区间 -39.7 到 -16.3）。让写程序的模型看不到任务卡，只需不把卡片正文给它，用不着挪位置。
2. **题型分两层就够用。** 第一层按题目结构分（问答、谜题、表格、家务），五个 bench 分得完全干净；第二层在同一结构里按数据来源分，问答类分两组时 SearchQA 和 OfficeQA 几乎完全分开（ARI 0.978）。按话题继续细分没有意义。
3. **"离得远就当陌生题"只挡得住结构不同的新题。** 结构相同、来源不同的新 bench 会被当成老类型：OfficeQA 不参与聚类时，按 p90/p95/p99 三档门槛分别有 39、56、74 道（共 74 道）被归到 SearchQA 一类。所以一类的卡挂到别的题上之前，仍要做跨类型的"不伤害"检查。
4. **模型能自己选对技能。** 两个模型共 1440 次选择，选到别的 bench 技能 0 次，选干扰项 0 次；TriviaQA 的题全部选了 SearchQA 的卡。同时存在卡片和程序时，只给本类目录比给完整目录更常把两样都选上。
5. **方案**：路由按两层题型挂载本类技能；本类任务卡总是放进系统消息；程序类技能以"名字 + 说明"列给模型，由模型决定调用。详见第 4 节，请你确认后我再交给 Codex 实现。

## 1 探针一：任务卡放哪里

**做法**：同一张卡分成两部分。格式说明（例如"答案放进 answer 标签"）两组都留在系统消息里不动；内容部分在"系统"组放在系统消息里、格式说明前面，在"末尾"组接在用户消息最后。ALFWorld 是多轮游戏，"末尾"组每一步都把内容接在当步消息最后，历史里不重复堆积。卡片内容用历史任务卡的内容部分；ZebraLogic 没有历史卡，用 main-v9 G 链学到的那张卡。每道题两种摆法都跑，比较同一道题的对错。题量：SearchQA 200、OfficeQA 74、ZebraLogic 100、表格题 91、ALFWorld 20 局，每条链 970 格。

- ALFWorld 只有 20 局，区间很宽，只能说明"每步都接在末尾"能正常运行，看不出好坏。
- 花费：G 链 3,968,036 token，D 链 4,078,812 token。

## 4 新架构方案（请你确认）

1. **技能统一格式**：名字、说明（约 300 字，由模型读正文和几道练习题写成，冻结）、种类（任务卡或程序）、正文、所属题型。
2. **题型**：第一层按题目结构；第二层在同一结构里按数据来源聚成几组，每组至少约 30 道练习题；不按话题细分。同一 bench 里的子任务（如 ALFWorld 六种任务）先不拆，以后若要拆，由模型写分类规则、验收通过才用。每一步开始时冻结题型划分。
3. **挂载**：路由按题型把本类技能挂上。本类任务卡总是放进系统消息（探针一）；程序类技能以"名字 + 说明"列给模型，由模型决定调用（探针三）。完全不路由、让模型从全部技能里挑，只作对照实验。
4. **陌生题**：结构没见过的题，不挂任何学到的技能。结构见过、来源没见过的题，距离门槛挡不全（探针二），所以每张卡和每个程序在用到别的题型之前，要先在那个题型的练习题上过"不伤害"检查；继续保留每一步之后五个 bench 的读数。
5. **写程序的模型**：只看到现有技能的名字和说明，以及带卡运行的结果，看不到卡片正文。
6. **验收门**：只用练习数据，按题型分别过门；每个题型用同一请求重复跑测出噪声，门槛按噪声定；不设验证集。
7. **实现**：新写一个学习模块，复用现有解题外壳、打分、沙箱、账本和测试读取（像 v2.24 那样），不在 route B 上再叠一层配置。

## 5 花费、事故和局限

- 合计约 9,505,658 token：探针一 8,046,848，探针三 1,442,213，技能说明 16,597，探针二零调用。
- 技能说明前两次没过：要求 300 字时 GLM 写了 270 到 420 字，硬上限也是 300；把要求改成 450 字后它写到 440 到 600 字。第三次要求仍是 300 字、硬上限放到 450 字，7 条全过。前两次的输出原样存档在 dl。
- 表格题打分用的重算引擎资格证明绑定在 main-v10 的代码快照上，所以探针一从这份快照只读加载代码运行，快照没有任何改动。
- 探针一的启动包装脚本一开始少了一句保护，ALFWorld 用子进程启动游戏环境时会重新执行它，环境启动失败。D 链 40 格、G 链 1 格在调用模型之前就失败了，没有花钱；修好后续跑补齐。G 链停下时有 2 次调用正在进行，已按上限记账，这两格重跑。
- 练习池的 ALFWorld 只有 322 局带预先记录的初始画面，所以只从这些里抽题。
- 这些都是练习题上的探针，不是方法效果的证据；也不能拿来挑测试集上的配置。
