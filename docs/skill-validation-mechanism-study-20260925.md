## 问题与干预

目标是“相近思路的新任务提高，不适用任务少受干扰”，而不是每个 benchmark 最高分。本轮先回答较小、可归因的问题：**同一个父 Skill、同一批公开执行反馈、相同规则表示和更新预算，明确要求对比失败、正确替代解与条件反转，是否比普通经验归纳产生更有用的规则？**

两臂 `local` / `mechanism` 仅改变 system 中的归纳策略；都允许条件化规则，不是“本方法 vs 原生 SkillOpt”，也不是条件表示的消融。是否真的利用反例需要核查实际候选及引用，不能按分支名推断。

模型使用 BigModel `glm-5.3`，low reasoning、temperature 0；不发送随机种子。两臂相同输出上限不等于实际成本相同，记录完整 token 和 HTTP 尝试。

| 项目 | 预定配置 |
| --- | --- |
| 机制 | 输入／状态约束保持 |

| Solver | 相同初次生成、相同公开检查、最多一次公开修订；不挑选初稿/修订稿中成绩较好者 |

| 授权 | 全程 shadow；不签发新 Verifier / Skill / Cross-Domain 权限 |

相关规格选自747个结构及有限行为去重的宿主声明式候选，固定seed=20260925。开发/确认排除相同结构和有限行为别名，不代表语义完全独立。每个规格有三种契约：必须保留输入 `target_related`；必须原地修改 `near_miss`；允许任意输入状态 `boundary_control`。后者**不是无关机制**。

另12个算法契约分成开发/确认各6个：字符串、图、数论与区间等。它们仍是 Coding；图或算术子任务还可能共享底层机制。因此既不能称跨域验证，也不能用6个控制族证明不退化。

采用确定性任务目录，是为把“任务教师是否正确输出 JSON”与“更新策略是否有效”两个变量拆开；不宣称本轮验证了自主任务生成或历史目标课程。9/24 Generic/Targeted A–D 原样保留。

## 执行与解释

1. 宿主编译任务、冻结完整位置清单；先验证数据与统计接口，避免付费后才发现协议错误。
2. 在 Linux Docker 中交叉执行参考实现、公开检查与错误控制。44个结构/算法族全部合格才继续；失败不补题、不按模型成绩选择任务。
3. 每条历史从同一个空父收集最终产物及公开检查，形成全部配对摘要和最多10对详情；两个更新策略读取完全相同的白名单反馈。初稿失败和修订记录另行留档，目前不进入updater，因此修订已修好的问题可能不再成为学习证据。
4. 保存真实提案、解析结果与新候选；API失败、格式非法、NO_UPDATE各自保留，非候选继续用父版本，不重新提案到成功。底层API对429/5xx/传输错误每逻辑请求最多3次HTTP尝试，全部记录；这与重新抽取终态失败不同。
5. 冻结全部历史候选，才执行共同确认。`raw` 强制暴露所有规则，测内容本身；`conditional` 按执行前公开义务类型筛选，测条件禁用的作用。没有读取隐藏区域标签路由。
6. 按区域、领域、历史报告成功/失败/unknown，Candidate 对 Base / Current 以及 mechanism 对 local 的配对胜负。保留缺失分母、调用别名、成本、启用/空规则比例。

族聚类 bootstrap 只作描述，条件于当前学习历史，未校正多重比较。配置中的2pp非劣界、至少20个申明族/3条历史不是通过标准；非劣诊断始终 Pending，零回归和全回退均不能证明安全学习。

新接口应区分API实现题和已有产物修改题。后者至少有`new / retain / replace`三类明确义务，以及输入/文件状态证据；最终成绩分开报告新增功能、旧行为回归、旧规则是否正确废弃、交付/环境unknown。一个问题更难，不代表它测到了Constraint Preservation。

已只读核对[BigCodeBench官方说明](https://github.com/bigcode-project/bigcodebench)：其函数生成任务增加了库调用和复杂规范，适合补充API/契约诊断，但不能直接称多文件修改或约束保持benchmark。当前标准库、JSON-callable执行协议也不能原样支持其所有依赖及原生返回类型。下一步若接入，应先固定版本和兼容子集、保留原生测试语义，再建立有界新镜像；本轮没有安装全套依赖、执行该benchmark或报告其成绩。

元数据预检已固定Hugging Face revision `b74c0d0bf70d2c0bc459be537895cca163007f1a`；卡片声明5个版本split各1,140题，不能相加当作5,700独立题，Complete/Instruct也不是两套独立任务。尚未下载题目分片或核实ARM64/原生unittest兼容数。首次官方Dataset Viewer查询意外向研究子agent展示了`BigCodeBench/0–17`的答案/测试摘录，因此已明确登记这18个ID仅可用于开发或兼容性，不可再称严格未见确认；后续查询只投影元数据，无答案材料进入Solver/Research。[固定版本、暴露记录与接入验收](results/bigcodebench-readiness-20260925.json)

最终评测分两层：**先冻结Skill做任务族/项目隔离的迁移与非干扰矩阵，再做预先固定任务流的持续学习。** [AgentStream](https://arxiv.org/abs/2608.00155)区分Isolated、Sequential、Interleaved，不只是把分数混合平均。流式实验应先测试当前任务，再允许其开发反馈进入下一状态，并独立保留冻结最终审计；不能将已用于更新的同题成绩作为未见泛化。

主比较需同时给No-Skill、匹配模型/工具预算的SkillOpt基线、固定验证器学习、审阅反馈学习，以及获得相应校准权限后的Research反馈学习。除逐域等权均值，还要报告相关任务收益、保护任务损失、Candidate对Base及Current的配对方向、unknown、真实规则启用率与成本；强制使用和条件部署分开。任何一个保护域没有显著差异，不等于已证明非劣；应在取确认数据前固定可接受退化界、独立样本单位与功效规划。当前小型面板没有这项授权。
