# 下一轮可识别的 Cross-Domain Safe Skill Evolution 实验

这是新研究方案，不修改本轮协议，不依赖尚未完成的 source/D/E holdout。现有结果尚未验证方法成功：A 的安全策略零覆盖率、机制排序未稳定优于 Domain；B 的产物任务仍有满分天花板；C calibration 的 Full 来源 EM 有收益，但主要呈现答案表达适配，extractive 未通过独立来源收益筛查；D calibration 控制满分也不能识别有用的范围扩张。[首轮报告](../outputs/cross_domain/scope_mvp_gpt55_20260907/findings.md)、[来源逐题审计](../outputs/scope_evolution_v2/source_retention_gpt55_20260908_sessionfix/calibration_effect_audit.md)

下一轮的最小成功条件是：先有可重复、机制可解释的来源收益，再在非零使用率下保留它；扩大范围后，在真正任务族 OOD 的正例获得新收益，同时不靠全部 fallback 回避保护任务。Gate 是否有用、机制路由是否优于 Domain，必须分开检验。

## 1. 固定内容，把两个主对照拆开

Full 是 Skill 内容条件，source-only 是适用范围条件，二者不能混为互斥的“两个模型”。第一阶段固定成熟 Full 的同一份文本与 SHA256，不边换内容边比较范围。Base、环境 prompt/工具、预算、模型配置也在每个环境内固定；非来源环境采用原生任务接口，不把真实工具任务强行包装成 SearchQA trivia。任何新环境中的收益都需重新测量，不继承旧 EM。

| 策略 | 内容 | 激活方式 | 用途 |
|---|---|---|---|
| Base | 原先固定的 Base 配置 | 不使用候选 Full | 无 Skill 参照 |
| Source-only / Current | 同一 Full | 已提交的来源范围规则 | 已有收益与范围参照 |
| Unconditional | 同一 Full | 全部输入 | 强制泛化风险参照，不冒充正常 SkillOpt |
| M-ungated | 同一 Full | train/dev 固定的机制适用规则 | 分离路由本身的作用 |
| M-gated | 同一 Full | 同一机制规则，经跨域 gate 批准后扩张 | 待验证方法 |
| D-gated | 同一 Full | Domain 规则，经同一 gate 批准 | 机制路由的公平对照 |

**主对照一：M-gated vs M-ungated。** 内容与输入路由相同，仅改变扩大范围是否需要行为证据。必须同时报告相对 Current 的跨域新收益、来源保留及对 Base/Current 的保护检查。只比无条件注入更好、但与 Source-only 同为零跨域使用，不算成功；如果两者都没有风险或收益，则该对照在本数据上不可识别，而非 gate 已证有效。

**主对照二：M-gated vs D-gated。** 同内容、同模型/输入、同一 fit/confirmation 数据、同等调参次数、同一安全要求。Domain 使用输入预测的领域规则；不能把 evaluator 的真实 domain 标签偷偷给它或机制路由。若生产入口本来提供可信域信息，则应两者同样可见，并另列“已知入口”实验，不与 input-only 混报。

先比较各自预先冻结的正常 threshold + abstain 策略，再报告等覆盖率排序诊断。等覆盖率预算由开发集预先决定，并限制在两个方法都有可比较适用分数支持的范围；不能为了达到 50%/75% 而强迫低适用任务注入。不存在足够的共同可比范围时，应报告不可比，而不是抬高覆盖率。完整报告原始部署覆盖率；受限排序诊断不能替代全任务的部署结论。

## 2. 先做机制归因，否则不要给 Full 贴 RCE 标签

开发阶段先区分两个候选解释：答案槽位/输出合同适配，或事实/关系证据验证。只用新 train/dev，预先固定 Base、Full、去答案表达小节、去关系证据小节四个内容条件；删除小节不顺便改写其余内容。它们是独立内容消融，不进入上述“固定 Full、只变范围”的主比较。

归因至少需要三种证据一致：

- **指标分离。** 原 benchmark EM 是兼容性指标；另用独立于模型输出制定的 alias/答案对象判定或可执行 oracle，分开计“对象/关系正确”与“格式/粒度正确”。不能看见模型答案后临时增加合法 alias。
- **行为分离。** 逐一审查独立 dev 的 discordant pairs，统计是否改变事实/关系选择，还是仅改变称谓、单复数或输出投影。token 包含不是语义等价；无法判断的样例保留 unknown。
- **内容干预。** 若要称 RCE，应在新来源机制正例上看到删去 RCE 小节损失、以及符合关系约束的行为证据；不能仅凭 Full 对 Base 显著而某个消融不显著，就认定二者差值显著或完成因果定位。直接配对比较应预先固定；长度/注意力变化仍是局限。

只允许一个有证据支持的机制进入首个主实验。若 Full 的来源收益仅存在于宽松题意与狭窄 gold 的表达匹配，就将其保留为 benchmark 适配研究，不宣称通用 RCE。若改为新训练的 RCE/CP Skill，必须新建内容版本并重新通过来源筛查，不能继承 Full 的收益。

## 3. 有上限的 headroom / hardness 预筛

先由任务规范和独立 oracle 审核者确认：题意明确、参考答案唯一或合法集合完整、工具可用、输入包含所需信息。增加难度用多文件依赖、真实版本/别名映射、约束相互作用或证据干扰；不靠含糊格式、截掉关键证据、故意压低 token 上限或放大无关算术难度制造失败。

建议先固定以下开发预算，不通过就停止这一分支：

| 阶段 | 固定规模上限 | 继续条件 |
|---|---:|---|
| 来源 hardness 探索 | 3 个事先定义的难度档，各 24 题，只跑 Base | 至少一档 Base 正确率在 40%–90%，且错误中确有目标机制所致、而非 schema/API/缺信息问题 |
| 新来源 dev 与内容归因 | 独立 96 题，最多四个内容条件 | Full 比 Base 净增至少 3 题；可解释的目标机制改善至少 3 题；没有系统性任务规范问题 |
| 一个非来源任务族的迁移 pilot | 独立 48 题，Base/Full 两臂 | Base 有相同类型 headroom，Full 有至少 2 个净改善且错误类型与拟议机制一致 |

以上最多约 552 次目标调用，不含少量路由/生成开发调用；是进入大规模确认的点估计 futility 筛查，不是显著性或安全认证。每个阶段只有一次预先固定的终点；不跑到出现足够 wins 才停。对第二个难度/内容分支的重试次数也要先封顶，失败分支全部保留。

若上述阈值太弱以支撑后续功效预算，应停止或另立更大研究，而不是把 pilot 的成功当证明。不得按“Base 错且 Full 对”筛出最终题目；只能基于独立开发集选择整个难度档/生成规则，新的确认和测试保留该规则产生的完整分布。

## 4. 数据矩阵：任务族 OOD，而不是换一层领域名

先研究一个源域、两个目标环境，每环境预先定义 positive、机制相近但不适用的 near-miss、unrelated；再按需要声明的具体任务族分 cell。域外观与机制标签做交叉：目标域有同机制正例，来源域也必须有不同机制/不适用例子。任务标签只供验证分析，在线路由只看真实输入。

可以从真实仓库中的公开 API/内部实现映射、实际工作簿的公式依赖/显示名映射、版本化规则产物中的明确请求开始，而不是给同一份数字记录换上 coding/spreadsheet 标题。具体 oracle 分别检查实际符号/依赖/产物结果，环境 prompt 和工具预算冻结；不能只靠重命名随机实体制造所谓跨域。

划分单位是**生成模板/操作类型/来源项目**，不是题目随机 ID：

1. train/dev：直接定位、短依赖链等已知任务族；可用于反思、机制描述及难度开发。
2. scope-fit：新项目/资产中的一类独立变化，用于提出范围；不用于再次编辑 Full。
3. scope-confirmation：不同项目与结构族，用于批准/限制；不能把 fit 题再并入。
4. frozen test：未参与任务开发的模板/项目，包含更换请求目标、间接映射或例外处理方式的组合，以及至少一个未用于范围批准的真实目标任务族。

如果一个母任务生成多个请求变体，它们必须进入同一 split，并在统计上作为同一 cluster；不能将同一底层记录改措辞后当多个独立任务。公开数据也需按项目/实体/时间版本去重，并记录无法排除的语义重复和预训练曝光。

### 负迁移构造的风险

“先看 Skill，再专写它会错的陷阱”适合找反例，却会夸大自然风险、改变部署分布，还可能让路由器只学到 audit/replay 等表面词。主评测应由未看候选轨迹的任务作者根据真实工作目标写题；允许同一资产配对比较“当前决策”和“历史回放”，但两种请求都必须明确、合理，不能靠与系统指令冲突或错误 gold 强行诱发损失。

候选感知的 targeted stress set 另列，不与自然/公开任务混成一个总体胜率。风险为零时如实报告；不得继续只挑让 Unconditional 退化的任务直到 gate 显得有效。保护组是否无害、正例是否有收益是两个独立条件。

## 5. 验证门、样本量与停止规则

content_update 与 scope_expansion 分开：前者必须在来源战胜 Current；后者在实际内容不变、版本/执行合同可验证时，来源对 Current 要求保持而非再次正增益，但仍需新的来源对 Base 收益、跨域对双参考收益及全部保护检查。可信合同来自执行/证据管理层，不由 LLM 自行签发。[transition gate 说明](scope-transition-gate.md)

**46/96 不是功效预算。** 它们只是现有 Wilson gate 在“整个保护 cell 零改善零退化、reference 全对、无结构 identity”时，主/严格参数通过 NI 的数值起点。它们不是有真实损失时的所需样本量，不保证 positive gain，也不适用于把相关重复当新题。条件伤害还要分别有足够的 Base/Current 正确观测。[样本量审计](gate-sample-size-audit.md)

大规模运行前用开发 pilot 的联合三臂胜负分布及保守备选分布，模拟**整个 gate**在各 cell、双参考和路由覆盖率下的通过率，而不只模拟平均 EM 的单个检验。建议以 80% 功效、预先定义的最小有用收益 3pp 为规划目标；筛查统计规则、两项主对照及跨保护 cell 的多重比较控制必须同时固定。若预算不足以达到目标，应缩小声明的任务族数，或明确降格为 pilot，不能降低安全标准追求 Commit。

可从 source/每个目标 positive cell 256 题、每个 protected cell 192 题的独立 confirmation 预算做功效模拟，再按模拟结果在取数前固定最终 N；这些是规划起点，不承诺足够。冻结 test 必须另留新任务，不能靠 confirmation 加 test 凑数量，也不能将一题两次生成视为两题。多任务族相关性需按母任务/项目聚类；训练随机性至少用 3 个预先固定的独立训练 seed 检查，固定成熟 Full 的单候选研究则明确没有这层泛化证据。

只允许以下停止/继续行为：

- **无 headroom、无可解释来源收益、跨域 pilot 无收益：** 停止该候选分支，不打开确认/test 寻找转机。
- **API/数据完整性不足：** 中止并保留失败记录；按事先固定的整批重试/重新运行规则处理，不选择性补跑错误答案。分母与缺失敏感性同时报告。
- **confirmation 未通过：** keep current / restrict / reject，不开放该新范围。若修路由或内容，使用新版本、新确认样本，不能循环使用同一 confirmation。
- **保护区间跨越阈值：** pending，不把“未检出显著伤害”写成非劣。
- **仅 source-only 或零跨域覆盖：** 可以报告来源保留，不计为范围进化成功。Gate 优势和机制优势缺一项时分开报告，不合并成成功结论。

## 6. 数据流与最终判定

完整流程为：独立 oracle/任务族设计 → bounded train/dev 可学性与机制审查 → 内容冻结 → input-only 范围提案 → scope-fit → 独立 confirmation gate → 内容/路由/阈值/代码/分析计划冻结 → 未见任务族测试 → 全量配对报告。router masks 在相应目标结果生成前落盘；Base/Full 采用相同题目的共享轨迹离线重放时，明确这是 shared-draw 策略估计，随后对获批部署策略做独立在线执行检查，记录原生工具成功率、成本和延迟。

测试至少报告：来源绝对收益及对 Current 非劣；跨域 positive 对 Base/Current 的差值；各 protected cell 的条件退化及区间；各策略真实覆盖率、保留的 wins/仍发生的 losses、unknown/fallback；两个主对照的直接配对差值。净增益保留比例只在 Full−Base 分母为正且有充分证据时解释，分母不稳则优先报告绝对差值，不用不稳定比值宣称“保留 80%”。

验证方法成功需要非零且有用的范围扩大，并在独立测试上同时满足预先固定的收益/保护条件；M-gated 未优于 D-gated 时，只能支持门控/证据管理贡献，不能声称机制路由优越。单个成功例子、合成宏平均或两个条件的显著性不同都不够。

## 7. 公开冻结评测与 Rubric 的后续位置

先冻结至少一个来源公开 benchmark 和两个带客观 oracle 的非来源公开 benchmark 的名称、版本、官方 split、环境适配及主指标，再训练最终候选；当前 SearchQA 保留原 EM/F1 兼容性结果，其他任务使用各自原生评分，不把不同 EM 定义直接混平均。合成 OOD/targeted stress 只作独立诊断表，不冒充公开跨域 benchmark 复现。具体非来源 benchmark 的任务/许可/评分器需在新预注册阶段核实；不在未知可用性下承诺实验覆盖。

DeepResearch + Rubric 放在内容冻结前的开发/验证内环：仅研究开发域资料，生成结构化适用条件、反例及逐项评分依据；用独立人工标注与 hard oracle 的 calibration 子集测量误判率、伤害漏检率和 abstain 行为。评委对 Skill/策略名称盲化、同题基线与候选顺序随机化；rubric 不能看到最终 benchmark 测试问题、答案或分数，也不能自生成自认证。

只有 rubric 与独立证据校准合格，才允许它辅助提出 Restrict/Split 或解释 unknown；正式 Commit 仍由预先固定的行为统计与最终公开冻结评测约束。多轮研究需记录每个证据分区的消耗和版本，不将测试反馈重新投入下一轮后仍称同一测试集独立。暂不扩展自动 Split/层次化 ladder，先把上述一个机制、两个主对照做成可识别、可证伪的实验。
