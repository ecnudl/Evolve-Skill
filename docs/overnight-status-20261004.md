2. **评测报告**：KOR官方评分对格式过严（Unicode减号、`÷`、多米诺顺序），且14道黄金自相矛盾。五域矩阵的KOR单元建议并列报告无标签验证结果，并把这14题单列。

4. **共享API客户端加固（需用户批准的版本化改动）**：第六轮审查发现冻结客户端`validator_pilot/api.py`的两个性质——内容过滤归类会覆盖“流内模型不一致”的错误；流中途超时后的内部投递重试可能在丢弃一次错误模型的部分响应后再付费一次，且不出现在最终回执里。它被F与此前所有运行共用、并哈希固定在冻结评测源码中，今晚不改；探针运行器已对能看到的身份问题全部中止并记录剩余风险。建议另起新版本客户端：流消费时校验模型身份、身份错误不参与重试、过滤归类不覆盖身份错误，并在新运行中使用。
5. **GEPA的迭代预算（新，10/4 18:20）**：F为两种方法冻结同一预算`max_iterations=2`、小批次8题。官方GEPA只把小批次上严格更优的提案加入候选池，GEPA S1的两次提案都只是打平，因而无更新。若F结束后GEPA多数阶段无更新，“SkillOpt vs GEPA”主要反映的是这一预算设置而非方法潜力。建议届时另开新版本，只改GEPA迭代上限（例如让其实际调用量与SkillOpt对齐），其余冻结不变；需付费并经用户批准，旧运行保持原判。
