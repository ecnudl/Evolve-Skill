## 0 一分钟版本

- **研究问题**：能不能从任务经验里"进化"出 Skill（注入求解器系统提示的一段文本指南），让它在**不依赖固定验证集**的情况下
  **跨数据集泛化**，而不是在单个 benchmark 上过拟合。
- **目前最重要的事实**：一份合理的**零样本指令**（只看任务卡写出的指令，记作 `bzero`）拿走了几乎全部可得增益；"从经验学到的
  内容"相对它的增量在 SearchQA、OfficeQA、LiveMath 上**都还没有建立**。Skill 里真正起作用的是本数据集的作答约定与格式——
  这恰恰是跨数据集最不能迁移、甚至有害的部分。

## 1 目标与不可违背的约束（负责人定的）

- 目标（负责人 10/10 的尺度）：**跨数据集泛化＋不靠验证集也有好结果**；不追求每个 bench 最高分；不做按数据集的过拟合。
- 方法的大致流程**不能随意改**：训练执行 → 反馈（rubric / 验证器）→ analyst 提出 Skill 修改 → 候选 → 决定（门）。改动只能
  落在某一环的实现上，并按新版本、新目录、事先写好读数规则来做。
- 测试集只在方法冻结后、经负责人明确同意一次性读取（OfficeQA 172 题、LiveMath 评测块、SearchQA 新样本块 c/d 都**未读**）。
  **10/16 15:03 负责人同意**：五 bench 主实验每一步在各 bench 的测试集上评测（含 OfficeQA 172、LiveMath 125）。测试集只在方法与代码冻结后
  由评测步骤读取，设计、挑选、调参都不看。
  验证/测试数据不进入 Research、任务生成、rubric 修订、analyst、回放池或候选选择。
  （例外：五 bench 协同进化协议 coevo5 按登记 §2 把历史 val 并入训练池，不设单独的留出验证分区；测试集隔离不变。）
- 付费实验可以放开跑（GLM-5.3 那个 BigModel key，并发 ≤10）；**每次改代码都要先过 Codex 审查＋离线测试再上线**
  （命令见 §6.4；额度用完时用 `codexdl` 启动另一个账号的 Codex）。
- 不 commit、不 push、不建 PR，除非负责人要求（要发布时：推到 `ecnudl` 远端，research 分支与 main 同步，先在干净克隆里跑 CI）。

1. 先写设计备忘（`docs/handoff/<主题>-<日期>.md`），**在任何结果之前**定下臂、主对比与读数规则。

4. 在开发机上从上一快照复制出新快照，跑测试、做零调用干跑（prepare）。
5. tmux 队列（会话名 `ae-<名字>`，按确切名字操作：`tmux kill-session -t "=名字"`），用 `.go` 文件放行，在后台写日志与 EXIT 标记。
6. 用后台监视等事件，不要连续轮询；读数用零调用脚本。
7. 写台账条目（完整分母、模型、成本、数据来源、读法边界），更新[当前流程](current-workflow.md)和本文件，必要时刷新回滚快照。
