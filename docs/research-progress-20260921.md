## 2. 真实单轮更新：流程跑通，但收益不稳定

来源：[9/18 完整报告](skill-validation-single-round-results-20260918.md)。模型 `glm-5.3`，MBPP-sanitized 兼容子集，8 开发 / 4 校准 / 16 最终任务，同一父 Skill，每个最终条件重复两次。

| 条件 | pass | fail | unknown | 全尝试成功率 |
| --- | ---: | ---: | ---: | ---: |
| No-Skill | 30 | 2 | 0 | 30/32 = 93.75% |
| Parent | 26 | 4 | 2 | 26/32 = 81.25% |
| Candidate | 27 | 2 | 3 | 27/32 = 84.38% |

32 是 **16 个任务的两次测量**。Candidate 相对 Parent 第一遍 +2/16、第二遍 −1/16，不支持稳定提升；相对 No-Skill 没有确认的新增算法胜利。三种名义反馈最终相同，只产生一个 updater 请求和一个候选，不能据此比较 Research / 非 Research。

该实验用了 125 次模型请求、143,634 个终态报告 tokens。Research 综合响应解析失败，未形成新干预；校准 Pending，没有部署。事后单独执行发现原生断言漏掉单词边界错误，但这是人工诊断，不归功于 Research，不改写原始成绩。

## 3. 准入闭环：有效证据才允许推动更新

来源：[9/20 最小闭环报告](skill-validation-gated-loop-20260920.md)。四组预声明工程场景，162 次真实隔离执行，**0 次模型 API、0 次网页检索**；产物与 Research / updater 由脚本替身提供。

| 场景 | 工程验证器判定 | Skill 决策 | updater 次数 |
| --- | --- | --- | ---: |
| 新检查＋局部有用候选 | accepted | Restrict | 1 |
| 新检查＋有害候选 | accepted | Reject | 1 |
| 删除新增探针 | rejected | Pending | 0 |
| 校准样本不足 | pending | Pending | 0 |

工程校准控制中的两个输入副作用缺陷由旧检查 0/2 检出变为 2/2；正确义务误拒 0/10，Near-Miss 误用 0/4。它证明合法的新执行输入能改变门的行为，不证明自然模型效果。所有正式自然 Verifier Gate 仍为 Pending，工程模拟不能获得部署权。四组缓存回放新增调用为零，922 份 JSON 原样保持。

## 4. 较大自然面板：仍在开发采集，不是完成实验

来源：[协议](skill-validation-natural-pilot-20260920.md)、[初期报告](skill-validation-natural-results-20260920.md)、[开发归因诊断](skill-validation-natural-development-diagnostic-20260920.md)。HumanEval+ v0.1.10，自定义 64/24/24/40 分区，共 152 个任务；不是完整官方 pass@1。

| 条件 | 第一次执行已保存 | 第二次执行已保存 | 两次共计划 |
| --- | ---: | ---: | ---: |
| No-Skill | 64 | 20 | 128 |
| Current | 64 | 21 | 128 |
| 合计 | 128 | 41 | 256 |

本地实际保存 **169 个位置，剩余 87 个**，包括失败／解析问题／中断 unknown，不是 169 次正确回答。没有开发完成汇总，没有开始自然验证器对照、候选更新或最终评测。初期 96 位置的分数只保留为当时诊断，不当作整轮结果。

最后一段已闭合恢复以 4 并发、每 20 秒最多 4 个新逻辑请求运行，新增 67 次均获得成功响应、0 重试，已知 62,071 tokens；528 份原文件校验未变，无新增未闭合调用。用户要求暂停后停止，没有重抽原中断样本。

主要质量问题仍是：

- `/141` 公开 ASCII 字符要求与参考实现 Unicode 判断冲突；H 也可能误判，不能把全部 H fail 当模型错误。
- `/145` 暴露公开检查覆盖不足；高通过率可能来自弱检查，而非任务已解决。
- `/130` 的公开例提取已修复，但全量 H 超时仍是 unknown。
- `/47` 公开例冲突、`/148` 类型适配限制均保留在共同分母中，不靠删题提高成绩。

9/21 的远端健康检查和迁移尝试不是正式实验结果。`proxy_on` 只设置 shell 环境，而现有 API 客户端 `trust_env=False`；不能由代理开启后收到响应，就断言代理解决了 API 问题。部分临时检查复用了缓存键，服务器内嵌套 SSH 的执行预检也未通过。迁移和健康检查仍需验收，本次未将这些临时脚本作为正式恢复工具发布。

## 5. 下一步与公开证据

优先保持同一完整面板与有效回执，完成剩余采集；在允许 H 参与策略校准前处理契约争议并记录独立修订规则，不覆盖历史结果、不根据最终成绩改标准。随后依次比较固定反馈、等预算上限自适应、Research 自适应，加入 contract-only 以分离规则清理收益。

核心待证链条是：**新增合法检查 → 自然错误与回归的增量检出 → 更好的准入和结构化反馈 → 新任务、Near-Miss 与跨域保持收益。** 当前自然面板只测 Coding，且没有独立 verifier_audit 或部署所需 Near-Miss／保持面板；因此不能直接证明范围扩张。之后需新协议、新目标域证据与多条独立学习历史，不把两次重复当独立历史。

公开 [JSON 摘要](results/skill-validation-20260921.json)记录以上主要分母与本地源记录哈希。它是经核对的摘录，不是完整可独立复算的原始证据包；未公开内容包括模型原文、执行缓存、父 Skill 依赖及第三方数据快照。历史结论与各版本完整索引见[研究概览](research-overview.md)。
