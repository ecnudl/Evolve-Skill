# 从 SkillOpt 到 Cross-Domain Safe Skill Evolution：当前工作总览

更新日期：2026-09-09。本文是**继续下一版实验之前**的阶段快照，汇总已有实现、历史实验、可支持的结论和当前架构。后续新实验另设协议和报告，不覆盖本文引用的旧结果。

## 1. 一句话总结目前进展

我们已经从原版 SkillOpt 的单份 Skill 文本优化，推进到具备候选生成、适用范围诊断、三条件行为比较、执行反例核验、验证经验反馈和冻结评测的研究原型。

但必须区分两个事实：

- **已经确认的效果：**原版流程训练出的 SearchQA Skill 在本地完整测试及新的同任务留出集上有来源收益。
- **尚未确认的效果：**机制路由优于 domain 路由、验证器进化改善检错、Skill 与验证器协同带来稳定收益，以及跨真实领域安全泛化。目前均未得到充分证据。

最新实验确实跑通了两轮协同闭环；但是候选没有净源收益、全部未获部署批准，尚未形成“持续提交有益 Skill”的链。

## 2. 基础仓库是什么，哪些能力本来属于 SkillOpt

本地基线提交为 `d3ce15068d6d256e68f6fc971e126dc85e97636e`，包含 v0.2.0 发布后的一系列上游改动，并非只停留在原始 v0.1.0。

SkillOpt 的训练对象是 Markdown Skill，而非模型权重。默认研究主流程是：

1. 目标模型携带当前 Skill 执行训练任务，得到答案、轨迹和评分。
2. 优化模型反思成功与失败，提出文本修改。
3. 聚合、排序并按文本学习率预算选择修改。
4. 应用 add/delete/replace，产生候选 Skill。
5. 在 selection split 上比较候选和当前版本，决定是否接受；维护 best Skill 与拒绝历史。
6. 可在 epoch 边界进行 slow update、meta memory 等更新，最终用冻结产物评测。

主要代码为 `skillopt/engine/trainer.py`、`skillopt/gradient/`、`skillopt/optimizer/`、`skillopt/evaluation/gate.py`、`skillopt/envs/` 和 `skillopt/model/`。SearchQA、SpreadsheetBench 等 benchmark adapter、模型后端和 SkillOpt-Sleep 是上游已有能力，不能算成本研究新增。

原项目本身已有迁移研究，不能简单说它“完全不研究泛化”。我们的新增问题更具体：**把适用范围作为独立状态，以候选对应的行为机制组织证据，并让验证方法也随开发经验更新；不是仅凭一个 selection 总分或 Skill 自述扩大部署。**

本地还完成过兼容 API 后端、Qwen 支持与复现相关工程适配。当前研究实验通过独立入口运行，没有用新方法替换默认 SkillOpt trainer，也尚未完整接回其所有公开 benchmark。

## 4. 已经做过哪些实验，得到哪些结果

### 4.1 完整 SearchQA 单种子复现

使用 Freerouter `gpt-5.5`，400 train／200 selection／1400 test，seed=42；40个普通训练步骤、4个 epoch，普通更新接受4次、拒绝36次，另有最终 slow update 接受。中途暂停后恢复并完成。

| 指标 | 初始 Skill | 最佳 Skill | 差值 |
|---|---:|---:|---:|
| Selection EM | 73.50% | 86.50% | +13.00个百分点 |
| Test EM | 1105/1400，78.93% | 1214/1400，86.71% | +7.79个百分点 |
| Test F1 | 89.22% | 92.57% | +3.34个百分点 |

测试配对为123次改善、14次退化；EM 差的配对 bootstrap 95%区间约为[+6.21, +9.43]个百分点。

这是本地配置下的完整单种子同任务复现，不是论文全部实验复现。初始评测有一次429计零；共同排除后1399题的净改善仍为109。续跑时 step buffer 未完整恢复、输出上限与推理参数传递也有差异，均保留在复现报告中。最终最佳版本来自 slow update，不能误标成普通第40步的收益。

来源：[复现报告](../outputs/repro_searchqa/full_gpt55_seed42/reproduction_report.md)。

### 4.2 首轮跨域安全范围实验

使用 `gpt-5.5`。40 train、40 dev、640 validation、360独立 test；测试每题两次生成。Coding／Spreadsheet／Rule 是受控任务的不同应用表述，不是真实多工具 benchmark。

| 条件 | 严格 EM |
|---|---:|
| Base | 99.58% |
| 无条件注入 Constraint Preservation 候选 | 95.83% |
| 无条件注入 Evidence Verification 候选 | 95.69% |
| 来源门及安全策略 | 99.58%，但覆盖率0% |

两个候选来源 dev 均无收益，正常来源门也已拒绝。因而安全策略胜过“强制注入已拒绝候选”，不等于胜过正常 SkillOpt。

部分 Constraint Preservation 下降来自题面数组形状歧义，不能全部解释成负迁移；预先固定的形状敏感性指标下，Evidence Verification 仍有2次改善、24次退化，存在把历史审计任务误套为“选当前最新记录”的可查反例。机制路由没有显示优于 domain 路由。

随后72次产物编辑可学习性先导中，Base train/dev 均36/36，按预定天花板条件停止，未开留出或进化候选。

来源：[跨域实验报告](cross-domain-experiment-results-20260907.md)。

### 4.3 固定成熟 SearchQA Skill：收益复核、路由与章节归因

冻结历史完整 Skill，在与旧划分 ID 不相交的新数据上评测；校准128题，留出256题，另有48道留出合成控制题。

| 新来源留出条件 | EM |
|---|---:|
| Base | 199/256，77.73% |
| 完整 Skill | 214/256，83.59% |
| Domain 路由 | 213/256，83.20% |
| 机制路由 | 212/256，82.81% |
| 仅抽取小节 | 202/256，78.91% |

完整 Skill 对 Base：20改善、5退化，+5.86个百分点，95%配对区间[+1.95, +9.77]。两种路由来源覆盖率同为96.48%，保留净收益分别93.33%、86.67%，但**都没有拦截这5次来源退化**。控制题 Base／完整 Skill 均48/48，无法估计跨域收益或减害。

删除 Evidence Selection 章后212/256；删除答案表达章及 SLOW_UPDATE 后206/256。相对 Full 的区间都包含零，不能断言具体章节的确定因果贡献。路由和内容消融复用了同一批 Base／Full 回答，不能当作多份独立重复证据。

来源：[来源与路由报告](cross-domain-experiment-results-20260907.md)、[复现说明](retention-routing-mvp.md)。

### 4.4 Coding Rubric 先导

改用 PJLAB `glm-5.3`。将有版本来源的 SkillEvolBench 项目改编为9个受限单模块任务，90条自然产物、18条受控产物。这个改编成绩不是官方 SkillEvolBench 成绩。

三个候选都生成，但0次接受；部分来源收益主要是交付格式差异。固定 V0 在30个留出自然产物上有2次误放行、8次unknown；前置确定性交付检查的事后重放降为1次误放行、2次unknown，真实回滚错误仍漏检。

“仅反馈”和“反馈＋资料”修订分别因格式与资料获取问题未形成有效 Rubric。后续资料传输修复3/3成功，只证明连接修复，不代表 DeepResearch 方法成功。JSON 模式小样本回归也未显示稳定收益。

来源：[Coding先导报告](validator-pilot-results-20260908.md)。

### 4.5 扩大重复与验证器修订实验

32个任务、8个作者任务族，3个条件、每题4次回答，共384次目标调用。原有限 oracle 上，留出16题×4次：No-Skill 63/64、通用提示63/64、机制 Skill 64/64。

表面优势仅各1次回答；两个对照的任务族 bootstrap 区间均含零。全32题的4个实际调用轮次中，机制 Skill 对 Base 差值为[+6.25, −3.125, 0, +3.125]个百分点。基于已有回答的5题批次重采样83.90%持平；这是条件重采样，不是额外模型实验或未来胜率。

在相同56个留出产物上，反馈修订 Rubric 对受控错误有局部改善，但自然部分相对原标签的正确判断净减少9次，而且存在 PASS／FAIL 重复翻转、引用起始代码而非当前候选的问题。

更重要的后验更正是：`quoted_record` 原测试漏掉了 Skill 新引入的引号契约回归。追加有限穷举后，该题 Skill 4/4变为3/4，与 Base 3/4持平；原先部分“judge误拒绝”其实指出了真实缺陷。旧总体成绩不回写，也不能把后验检查包装成新的确认性测试。

来源：[重复与修订报告](validator-scale-results-20260908.md)、[契约审计](validator-quote-contract-audit-20260908.md)。

### 4.6 最新：Skill—执行式验证器两轮协同闭环

PJLAB `glm-5.3`、并发4；48个新构造任务、24个操作族、两个执行流。固定／进化验证器两策略，各做两轮；冻结后24题×5条件×3次重复×2流，共720次回答。

修正版完成1160次逻辑请求，约53分钟；715条留出回答可评分、5条截断缺失，未重抽。源码、任务和所有分支在留出前冻结。

开发结果：Base源调用47/48通过，8个候选均无净源收益，全部Restrict、0 Commit。验证器真实差异记忆与校准经验进入下一轮优化请求；但部署 Skill 和下一轮父 Skill 始终为空。

| 最终条件 | 实际使用内容 | 均衡宏观分数 |
|---|---|---:|
| No-Skill | 空 Skill | 95.14% |
| 固定验证器的批准版本 | 空 Skill | 96.53% |
| 进化验证器的批准版本 | 空 Skill | 97.92% |
| 强制使用固定分支末轮候选 | 未批准候选 | 95.49% |
| 强制使用进化分支末轮候选 | 未批准候选 | 95.14% |

前三行没有实际 Skill 处理差异，不能解释为方法提升；两项预设对照区间也都跨零。固定／进化末轮候选分别对 Base 为3胜3负、5胜5负，配对宏观差都为零，两执行流方向反转。

144次反例提案产生4条真实差异收据，只对应2份代码／2道任务。一份代码公开测试全过而被额外探针检出，说明反例执行有增量价值；它发生在空记忆阶段，不能当作验证器进化收益。

首版执行器漏掉题面承诺的标准 `divmod`，错误影响了训练反馈，因此完整保留首版并从空状态重跑修正版，而非只改分数。两版及健康检查合计2322次请求、服务端已报告约590万token，不是账单。修正后全仓测试3192 passed、6 skipped。

来源：[协同实验报告](coevolution-results-20260909.md)、[工程更正说明](coevolution-runtime-correction-20260909.md)。

## 5. 当前方法架构：两大板块，六个运行模块

研究定位是“Skill 学习”与“验证方法学习”协同，而不是让每一个 benchmark 都取得最高分。当前最新可执行版本可以拆成以下六个模块。

| 模块 | 输入 | 输出 | 谁读取输出 |
|---|---|---|---|
| ① 任务／执行环境 | 可见新要求、旧程序、输入域、Skill | 当前回答、公开执行日志、开发侧完整诊断 | Skill优化器、执行验证器 |
| ② 局部 Skill 优化器 | 当前Skill、开发轨迹、历史验证经验 | 一个候选Skill文本及版本哈希 | 配对执行与门控 |
| ③ 行为证据采集 | 同题的Base／Current／Candidate回答 | 源收益／退化、公开检查、候选引用和探针输入 | 验证器与门控 |
| ④ 执行式验证器 | 可见契约、当前候选代码、局部验证记忆 | 输入／引用合法性、真实差分反例或未复现收据 | 门控、验证经验更新 |
| ⑤ 更新决策与状态 | 来源比较、gate比较、可用性 | Commit／Restrict／Reject、部署Skill、候选历史、下一版验证记忆 | 下一轮任务与优化器 |
| ⑥ 独立冻结评测 | 全部学习分支的冻结状态、新留出任务 | 五条件回答、聚类配对统计、覆盖／缺失／成本 | 最终研究报告；不反馈本轮学习 |

一轮真实数据流为：

1. 用当前 Skill 和 Base 执行本轮开发任务。
2. Skill优化器读取开发轨迹与当前验证记忆，提出局部候选。
3. 在相同源任务和新的 gate 任务上执行候选，与 Base／Current 配对。
4. 验证器只读取可见契约及当前代码，提出有引用依据的输入；宿主隔离执行参考和候选，不采用模型编造的预期值。
5. 相同有效探针重放到三条件，封存门控决定，然后才开放完整 gate 私有审计。
6. 只有 Commit 才更新当前部署 Skill；进化验证器从开发证据更新有限记忆，固定验证器不更新。
7. 下一轮再次执行；结束后统一冻结，再开最终留出，不按留出结果挑选或重写Skill。

最新代码仍有一个关键结构问题：**当前部署版本同时担任下一轮学习父版本。** Restrict 的候选虽然保存到历史，却没有继续作为局部工作版本修订；这正是下一版要拆开的状态，而不是已有完善实现。

早期跨域 gate 的目标位置仍是第⑤步：决定候选是否扩大 scope，而不是候选刚写出来时就给它通用权限。其证据最终应包括来源、不同domain同机制、同domain异机制、无关任务；最新 Coding 闭环还没有接齐这些真实领域适配器。

## 6. DeepResearch 与 Rubric 目前处于什么位置

已经有：固定 Rubric、开发反馈修订、官方资料计划／抓取／快照接口、可执行反例、证据引用校验、有限验证记忆。

还没有：自主开放式 DeepResearch 持续研究新 domain、可靠的 Rubric 独立晋级门、经过证据验证的跨真实 domain scope 扩张。

DeepResearch 的预定职责是研究任务规范、识别验证缺口、提出有来源的检查方案，并检查当前 Rubric 是否与工具能力／契约匹配。它不能自己宣称 Skill 通用，也不能取代最终独立 benchmark。Coding 的测试、构建与运行信号用于校准它，而不是把软评分与硬测试不一致一律判为软评分错。

## 7. 目前可以说与不能说的话

可以说：

- Skill 文本优化能够在本地 SearchQA 配置及新同任务留出上获得可复核收益。
- 不加区分地注入局部经验会出现错误泛化；机制名称和章节标题不等于已验证机制。
- 小批次持平、少数一次性改善、judge波动、oracle盲点均真实存在。
- 执行式反例可以补充公开检查；开发证据已真实进入下一轮 Skill 提案。
- 当前需要同时解决收益来源、验证可靠性与部署边界，不能用全部回退掩盖没有学习成果。

不能说：

- 我们已经优于 SkillOpt／SkillCommit 等方法，或达到跨 benchmark SOTA。
- 机制路由已经优于 domain 路由。
- DeepResearch或验证记忆进化已经被证明有效／无效。
- 未观察到伤害等于安全，或置信区间跨零等于统计等效。
- 合成应用表述迁移等于真实跨领域agent泛化。

## 8. 下一阶段直接推进的实现与实验

本节是下一版计划，不属于上面已完成的能力。

1. **拆分学习状态与部署状态。** 引入有局部证据支持的 working Skill、获准部署的 approved Skill，以及待补证／有害候选的隔离历史。范围检查不足不得抹掉已经合格的局部工作版本；已知伤害优先记录，局部版本也不能无条件接受所有提案。
2. **接入新的多文件Coding任务。** 保留真实模块边界、跨文件调用、旧接口与显式替换要求，独立执行公开与私有测试；使用全新项目族，不把任何已经查看的旧留出集继续当未见数据。
3. **运行新版本对照。** 比较耦合父版本与解耦局部学习，固定预算、重复完整学习历史并在冻结后评测；另外在同一批冻结代码上给固定／进化验证器相同探针预算，分离检错能力与求解器产物变化。
