# V8：Research 候选的独立校准（事前协议）

日期：2026-09-13。

仅在独立 Research 结构诊断产生合法且完整可追溯的 Rubric 后开始。格式通过不是有效性证明；若没有合法产物，则零校准调用、保留旧验证器。旧 V7 与第一次诊断结果均不修改。

## 校准对照

使用 V7 事先保留、从未在该次 V7 运行发出模型校准请求的 6 个 Coding 校准家族。它们与 Research 开发证据家族分离。历史私有 oracle 自检不作为模型判断数据；不复用过去模型 draw，不使用 V7 final。

每项目 4 种宿主控制产物：正确参考、等价正确、语义缺陷、约束保留缺陷。它们不是自然模型错误发生率。每产物 4 个重复 block，每 block 请求 old_a、old_b、new 三次独立反例输入提案，共 288 次调用。固定模型 PJLAB glm-5.3、4 workers、每次 HTTP attempt 至少间隔 10 秒、429 后共享冷却 30 秒，每调用上限 6,000 tokens。模型仅见公开任务和当前待验证代码，不见隐藏测试、reference 或 good/bad 标签。

更保守的 10 秒间隔在本场首次 API 前确定，依据是先运行的反馈工程实验观察到接口限流，而不是校准评分；所有 channel 使用同一策略。反馈场的已冻结 3 秒策略保持不变，两场模型调用串行运行。

主对照为等调用预算的 old_a＋old_b 对比 old_a＋new；单次旧/新作为辅助。old_a 在两政策中精确共享，不能当独立重复。反例必须合法，并在冻结 OS 沙箱执行当前产物及独立参考；只凭输入看起来合理或文档引用不算发现错误。

## 独立性与授权

用统一 one-use registry 事先登记 candidate、family、artifact、block；同分片不能事后用于调参再重选。所有校准反馈和标签只供宿主评分，不交给 Research/Skill 优化器。研究假设与文档引用不因结构校验变成语义真理。

沿用既有 V6/V7 事前门槛：配对校准支持且家族级精确双侧 p≤0.05 才授权下一轮开发反馈。否则保留旧验证器；拒绝候选不等于方法永远无效。API/输出格式/参考争议/基础设施缺失显式 unknown，不算发现语义缺陷。

6 家族只支持探索性校准，不能证明普遍安全，也不能据此声称跨域 Skill 收益。此实验不批准 Skill scope、不运行公开 benchmark、不把校准分数回流选择新 Rubric。完成后重复运行应纯离线且不增加 API 请求。
