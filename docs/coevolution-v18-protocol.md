# V18：公开任务中的共同证据更新与分层 Skill

2026-09-17，首次 V18 模型调用前登记。保留 V1–V17 原始代码与证据。

## 动机与边界

V17 pilot 在凌晨 01:39 正常完成开发筛查：No-Skill 11/12，仅一个结构族出现一个语义失败，未达到继续门槛。24 次逻辑调用均闭合且无 API 终止错误。07:34 才合盖，所以不是休眠中断。本版不重跑 V17，也不调低它的停止阈值；改用已有公开任务中的自然错误检验跨域更新。

研究问题：用两个领域的真实执行反馈更新 Skill 时，分离共享过程与领域局部规则，是否比整段重写更少干扰原有能力，同时仍能改善目标域？独立 core-only 条件检查收益是否来自共享内容，避免把域级隔离称为机制泛化。

本轮是公开任务兼容子集上的两域适配／干扰控制探索，不是未见领域验证、完整多轮协同进化、canonical MBPP 排名或统计安全认证。两个域均进入开发。Research 与验证器进化暂不新增干预，原生 oracle 固定。

## 数据、历史与预算

- 模型 PJLAB glm-5.3；4 workers；HTTP 尝试间隔至少 10 秒；沿用有界传输重试。每题一次求解、4096 output tokens，无执行反馈后的答案修订。
- 固定复用 V9 已审计来源的 h1、h2 两份真实学得 SearchQA Skill。h0 与初始占位文本相同，按“是否真实更新”这个已有属性排除，而非按本次成绩挑选。这只有两个既有学习历史，不冒充充分覆盖随机性。
- 每域 development 12、confirmation 12、final 24，共 96 道新预留题。SearchQA 从完整固定 Arrow 缓存取 dev=train、confirm/final=validation；Coding 来自固定 MBPP-sanitized，分别 train/validation/test。
- 一次性依据 ID／规范化问题哈希、既有静态兼容约束、历史曝光及旧预留排除进行确定性选取，seed=2026091702。不得按模型错题、参考运行成绩补抽或换题。保留 unknown 在全尝试分母。
- 开发与确认各域 12 题共用两条父历史，但实际请求包含 history，不在两历史之间复用抽样。同历史、同题、同 Skill 字节精确复用并披露别名。
- 最大计划逻辑请求 820：开发 96、Skill 更新 4、确认 240、最终 480；硬上限 896，不自动提高。本版不再按 headroom 筛查追加题目直到成功。全流程只跑这一个固定实验，工程异常暂停而非删失败重试。

## 一次共同证据分叉

每个父历史先在两域 development 上配对运行 No-Skill 与父 Skill。反馈绑定实际 API 与原生执行回执，区分错误、未知及交付失败。开发 QA 可给原生答案标签；Coding 可给已执行断言及观测，但不提供参考程序。模型可见任务来自原解题投影，QA 保持原生上下文截断。

两个更新器收到完全相同的父 Skill 和事实，只改变输出表示要求，各一次调用、4096 output tokens：

| 更新方式 | 产物 | 含义 |
|---|---|---|
| whole | 一个 ≤6000 字符的条件化 Skill | 整段重新组织两个域的规则 |
| layered | core ≤1400 字符；coding_patch ≤2800 字符 | 共享过程与 Coding 局部规则分开；来源 adapter 是原父文本，逐字保留 |

更新必须返回严格 JSON；无效产物原样回退父 Skill，记录无效，不修复／截断／重抽。提示要求 When/Procedure/Avoid 组织；解析器保证字段、类型、长度与控制字符，不把标题是否存在当作语义质量保证。完整共同反馈超过 320000 字符即工程停止，不选择性截断。

所有条件保留求解器原生输出合约：

| 最终条件 | SearchQA 输入 Skill | Coding 输入 Skill |
|---|---|---|
| no_skill | 空 | 空 |
| parent | 原父文本 | 原父文本 |
| whole | 新全文 | 同一新全文 |
| core_only | 共享 core | 同一共享 core |
| layered | core＋原父文本 | core＋coding_patch |

即使源 adapter 不变，新增 core 仍可能干扰来源行为，不能先验声称不退化。分层与整段的比较是表示／提示／域级注入的联合干预；相同输出预算不等于相同输入 tokens、上下文长度或实际总成本。

## 准入与冻结评测

在 confirmation 对 whole、core_only、layered 分别逐历史、逐域准入：对 No-Skill 与 parent 均没有观测配对损失，且相对两个参照都至少有一次配对成功增益，该域才批准。任一相关 unknown 不批准；不满足则该域部署回退空 No-Skill。不得跨域抵消损失。

这些是小样本经验门，不是非劣证明或风险上界。候选共用一次确认集，不因结果修改内容、阈值、样本。所有历史、候选、门控结果写入不可变 final_freeze 后才允许宿主物化 final，解题模型永远不见测试／答案。

无论准入与否，均完整评测五组 raw 条件。准入后的部署结果用同批 raw/Base 轨迹按冻结域映射重放，单独标明 shared-draw 诊断、实际候选使用比例；不伪装成新在线重复或 Skill 内容收益。

## 统计与判断

报告每域原生任务成功率（QA EM、Coding 所有原生断言通过）、两域等权平均、最差域、相对 Base 与 parent 的逐题胜负及 unknown 类别。主要对照为 layered−whole 与 core_only−parent，同时必报对 No-Skill 的绝对收益。

按规范化问题／任务簇在域内 bootstrap 1000 次（core 模块固定 seed），保留每题的全部历史和条件；逐历史也报告方向。不把断言、重复历史、缓存别名当新独立任务。区间条件于这两个观察历史，未作多重比较校正；单函数题的簇不代表仓库级工程家族。

- layered 更好但 core_only 无收益：只支持当前分层适配／干扰控制，不证明共享机制已通用。
- core_only 在两域有收益且损失可控：为共同过程的跨域可用性提供初步行为证据，仍需新域独立验证。
- 只有 gate 保护：只报告部署范围控制；全部回退不得称 Skill 泛化成功。
- No-Skill 更强或历史方向相反：如实报告，不在同一 final 上反复迭代到正结果。

最终报告自动进行这些分支解释。任何后续优化必须另设最终题；不无限自动开启新一轮或提高预算。

## 原生执行、恢复与审计

Coding 复用已验证的 V11 OS 隔离执行器／原生断言解释器，参考程序仅宿主沙箱校准。参考不可执行不替换题，统一 unknown；没有模型代码直接访问仓库或凭据。SearchQA 复用 SkillOpt 原生提示、6000 字符上下文截断、EM/F1。

独立 `outputs/coevolution_v18/`，不改旧 frozen 源码。请求／执行 intent 先于外部动作持久化；有回执可从闭合点重建，未闭合请求拒绝盲目重发。每 30 秒监督心跳；明显挂起／时钟异常则请求暂停，等待在途收尾并保留原始记录。完成后禁用 API、凭据、网络和 native 执行，全量离线重建并要求目录字节不变，再生成报告。

每次新进程先串行重放已有闭合请求，首个真正的新传输请求成功后才并发；该首次请求若终止失败，保留其 unknown 回执并暂停，不为未发送的其他任务创建悬空 intent。显式恢复也不重抽该已闭合失败。
