# V6 冻结实验协议：重复验证、保留旧检查与原生跨域任务

本轮在新的独立输出目录运行，不修改 V5 源码、评分或晋级决定。沿用 PJLAB `glm-5.3` 与现有凭据，全局最多四并发，最多 900 次逻辑请求；API 传输最多三次 HTTP 尝试，格式错误不语义重抽。默认三条学习历史、每份校准产物四个重复 block。

## 研究问题与边界

1. 单次探针漏检与产物/项目层面的稳定退化是否一致？同等两次探针调用预算下，保留旧检查并加入新研究策略，能否优于重复旧策略？
2. 来源任务学出的候选 Skill 在未见任务上是否有益/有害？只在任务明确要求局部修改并保留约束时使用，能否降低无条件使用的损失，代价是什么？
3. 对事前固定的开发错误代码，结构化执行反馈是否比只有分数更有助于修复？

这是合成、原生执行的工程研究，不是公开 benchmark 或完整方法有效性证明。任务是新编写的小型程序、工作簿公式图和规则库；不能宣称模型从未见过类似问题。V5 协同引擎保留，本轮先将验证器研究和跨域候选诊断作为受控、解耦实验：来源 Skill 学习始终使用固定 V0；校准结论不回流当前学习，也不自动批准部署。

## 事前固定面板

- 开发：3 个不同 Coding 算法家族。三个学习历史都用这些任务，区别是各自的真实执行和提案轨迹；不把它们当作 9 个不同任务。
- 校准：6 个全新 Coding 家族，每族参考、独立等价实现、语义错误实现、输入保持错误实现各一份，合计 24 个唯一代码哈希。错误实现通过公开样例，在私有测试及合法输入中存在真实失败；完整真值只由宿主使用，绝不传给探针模型。
- 最终：Coding、Spreadsheet、RuleReasoning 各 9 个实例。每域覆盖同机制局部修改、近似但不适用的完整替换、无关的独立计算/只读推理，每类三个参数实例。Coding 计 3 个结构家族；原生表格和规则的局部修改/完整替换共享初始底座，因此每域保守合并为 2 个底座簇，总计 **7 个最终簇**，不是 27 个独立项目。
- 开发、校准、最终底座/家族互不相交。全部任务、真值、合同、参考产物、样例、源码哈希在首次调用前封存。私有真值可由宿主执行预检，但不能作为模型输入。

## 来源 Skill 的两轮进化

每条历史：Base 执行 → V5 结构化开发反馈 → 优化候选 → Base/Current/Candidate 同题配对 → 来源门控 → 下一轮。始终保持 Working/Approved/Repair Parent 区分。没有跨域批准片时不会产生跨域 Approved。

优化提示明确聚焦 Constraint Preservation 假设，要求保留有效约束、识别完整替换、不迁移源领域输出格式；这不是由路由器认证的通用能力。模型看到真实开发产物、合同、原生执行事实和未证实修复建议，不能改变评分义务。相同任务/Skill/历史共享求解请求，避免重复计算冒充独立重复。

最终候选固定取每条历史最后一个格式有效提案，不按最终分数择优。如果没有有效提案则留空，并报告覆盖率。即使未被来源门控批准，也可作为**明确标注的反事实实验干预**进行比较，不混同生产部署授权。

## 实验 A：等预算验证器组合

先从开发反馈生成一个新的有界 Research 提案：竞争解释、至多三页官方资料、证据分析、Rubric 检查策略补丁。每阶段最多 6,000 tokens。QA 检查项改变或格式无效时，使用事前登记的 V5 冻结 Coding 提案作备用；报告必须明确实际来源，不能将备用冒充新研究成果。义务、native oracle 与证据权限仍固定。

提案选定并封存后，才开始校准。每个代码产物的每个 block 独立请求三次：旧策略 A、旧策略 B、新策略。每次最多四个合法输入，调用顺序确定性打乱，全局四并发。

| 条件 | 使用探针 | 调用预算 |
| --- | --- | ---: |
| old_single | 旧 A | 1 |
| new_single | 新 | 1 |
| old_double（主基线） | 旧 A＋旧 B | 2 |
| portfolio（主方法） | 旧 A＋新 | 2 |

主比较是 old_double 对 portfolio。两个组合共享旧 A，明确按配对处理；每个输入必须实际执行。任何组件检出真实违反合同的行为都保留；缺失探针不能凭组合变成通过。对重复输入去重统计，多次尝试不当作更多任务。

完整 24 产物 × 4 block × 3 搜索 = **288 次探针调用**；派生四种策略共 384 条评分记录。以源码哈希、真实请求、产物、block 和冻结设计绑定，缺项必须为明确 unknown，不能事后丢样。

### 聚合和诊断门

先在每个产物内平均四次执行，再在家族内聚合，再比较家族。报告错误检出率、正确实现误拒绝、unknown、逐次漏检与产物平均退化的区别。whole-cluster bootstrap（10,000 次）与精确双侧 sign-flip 仅为探索性诊断；六个簇很少，不作安全证书或因果遗忘判断。

诊断门输出 Support/Hold/Reject，始终 `activate=False`。完整事前设计、至少六簇且每簇两类真值、至少四 block；主比较检出增益的项目 bootstrap 下界需严格大于零，正确产物误拒绝率不得提高，各项目按好/坏分别计算的 unknown 率不得提高。单个坏产物某次漏检不是独立否决条件；已观察的误拒绝或 unknown 退化仍明确报告。

如果 bootstrap 区间排除零但精确检验不显著，必须披露二者不一致；Support 仍只是筛查建议，不能写作统计可靠提升。当前不根据结果修改规则或重复使用此校准片调参。

## 实验 B：原生跨域候选与公开合同路由

Coding 在原隔离执行器中运行代码；Spreadsheet 实际编辑公式并重算隐藏输入，安全 AST 解释器不调用 eval；RuleReasoning 实际修改规则并由确定性前向推理求闭包。只读任务不向模型修订阶段泄露答案。所有求解条件均为一次生成＋一次公开反馈修订，每次 8,500 tokens，不补齐失败格式。

最终三条件：No-Skill、Always Candidate、Contract-Routed Candidate。路由只读题目公开的 `change_scope`、`preserve_obligations`、`supersedes_old_policy`：明确局部更新且有效保留义务时使用；完整替换、独立新实现、只读、矛盾/未知合同均回退。不读取 domain、task ID、隐藏 group、答案或最终成绩。它是**固定显式合同路由对照**，不是学习出来的机制识别器，也不证明 Skill 的机制已被认证。

先封存三个 Skill 和全部路由，再执行最终题。路由条件复用该题同历史的 Base 或 Candidate 真实产物，不产生伪独立调用。默认 27 题 × 3 历史 × 2 实际干预 = 162 条不同求解位置，324 次模型调用，三策略共 243 条逻辑评分。

主报告同时列出任务均分和家族/底座均衡收益，给出领域宏平均、最差领域变化、负迁移、Skill 使用覆盖率、unknown、格式失败和保持案例损失。先按题平均历史，再按底座簇聚合；原生表格/规则共享底座的两类合同不拆成独立项目。每域簇数很少，区间只能探索性解读。最终数据永不回流优化。

## 实验 C：可执行反馈修复

预先选择三个开发任务提供的初始错误代码，不等碰到模型生成失败才临时选样。宿主执行确认错误后，每个历史都对同一代码分别给出仅原生分数或完整结构化事实反馈，各一次 8,500-token 修复机会、确定性打乱顺序；共 3 任务 × 3 历史 × 2 = 18 次调用。

这是人为编写的错误开发夹具诊断，不冒充 Agent 自然失败分布。报告完整修复、原本通过案例退化、unknown、调用预算，按三个家族聚合。校准或最终失败不能用于替换这些样本。反馈队列自动导出真实证据，但人工评分保持 pending。

## 使用与断点

```bash
conda run --no-capture-output -n skill python scripts/coevolution_v6.py prepare --output outputs/coevolution_v6/glm53_native_portfolio_20260911_v1
conda run --no-capture-output -n skill python -u scripts/coevolution_v6.py run --output outputs/coevolution_v6/glm53_native_portfolio_20260911_v1
conda run --no-capture-output -n skill python scripts/coevolution_v6.py report --output outputs/coevolution_v6/glm53_native_portfolio_20260911_v1
```

每目录只运行一个进程。使用同一参数和目录恢复；已有请求不可重抽，未决预约阻止静默恢复。源码变更必须启用新版本/新输出目录，不抹去旧结果。总调用上限 900，主流程通常约 711 次，非法交付或缓存共享会减少次数；HTTP 重试和未返回 token 成本另列。最终报告所有已做/未做实验与实际启用状态，不以工程测试替代研究结论。
