# 阶段二开发与工程验收报告（2026-09-18）

## 结论

**阶段二的最小工程链路已打通，尚未完成真实方法效果验收。** 已能做有界 Research 提案、条件化检查、隔离执行、固定三条件比较、独立校准和审计，并保留失败与断点。未启动阶段三的 Skill Gate、Skill 更新或大规模训练。

本轮最重要的结果是：检查器能补充执行证据，失败提案会被拒绝，fixture 不会获得自然数据准入；**没有证据表明 Research 已优于无 Research，更没有跨域泛化提升结论。**

## 1. 开发了什么

沿用 `skillopt/skill_validation/`，没有复制新的 VXX，也没有修改冻结历史代码或阶段一的五个源码指纹依赖文件。

| 部分 | 新增能力 |
| --- | --- |
| Research | 相同开发视图下的问题规划、按问题选择官方资料、条件化配方提案；允许 no_update／失败／拒绝 |
| Coding 检查 | 公开输出检查、调用前后输入状态保持、显式重复一致性关系；不调用隐藏 oracle 补答案 |
| 运行与回放 | 固定镜像的 Linux Docker 执行；无网络、非 root、只读、资源限制；持久请求／回执和失败关闭 |
| Verifier Gate | 按共同任务义务比较检错、误拒、覆盖率、Near-Miss 与三条件方向；冻结后一次性校准，再独立审计 |
| 集成入口 | 固定产物导入导出、三组比较、离线 smoke、可选 PJLAB／glm-5.3 接口测试 |

实际顺序：**冻结产物与分区 → 相同 development 证据 → 提案 → 冻结验证管线 → calibration → 独立 audit。** H 保存在宿主文件中，仅开发缺口摘要通过明确接口进入 Research；校准与审计不进入提案模型。

本轮修复了 JSON 指数溢出、缺少 token 用量时的崩溃、共享缺失记录跨组累计、缓存／回执绑定、子目录符号链接，以及完整替换配方和引用来源说明的歧义。没有放宽正确性或校准门槛来获得通过结果。

### Fixture 面板到底是什么

共 **6 个任务契约、3 个操作族、9 组三条件记录、27 个产物**。开发用排序，校准用稳定去重，审计用字典阈值过滤。每个分区包括一个普通契约的两个 repeat（预设回归／修复方向），以及一个要求原地修改的 Near-Miss 契约。

这些代码、Skill 占位文本和 H 标签是人工构造的工程控制，**不是模型自然演化产物**。repeat 不算新的独立任务。原地修改是否真正完成缺少对应检查时，保留 unknown，不能以返回值正确冒充全部义务通过。

校准与独立审计各自得到以下相同的工程结果；表中分母是共同义务或预注册控制项，不是独立样本量：

| 验证器 | 预设保持错误检出 | 正确义务误拒 | Near-Miss 误用 | 义务覆盖 | unknown |
| --- | --- | --- | --- | --- | --- |
| fixed | 0/3 | 0/12 | 0/3 | 9/18 | 9/18 |
| adaptive_no_research | 3/3 | 0/12 | 0/3 | 15/18 | 3/18 |
| adaptive_research | 3/3 | 0/12 | 0/3 | 15/18 | 3/18 |

固定验证器对输入保持返回 **unknown，不是错判为正确**。增加输入状态检查后，这部分获得了可执行证据。两个自适应分支使用脚本提案，刻意没有给 Research 安排独占能力；0 次真实模型调用、0 次真实资料检索。

因此，此表只证明实现按预期工作。自然数据分母仍为 0，两个候选验证器均 **Pending**，未获得部署或跨域使用权限。

## 3. 真实模型接口测试

使用本地 PJLAB 配置、`glm-5.3`、单并发、streaming、low reasoning；每轮最多四次逻辑调用、每次输出上限 2,048 tokens。仅在合成 development 视图上提出 Rubric，不执行产物、不使用校准／审计数据。

| 接口测试 | 实际 HTTP 请求 | 合法提案 | 输入／输出 tokens |
| --- | --- | --- | --- |
| 首轮 | 4/4 返回成功、无重试 | 0/2 | 11,663／2,122 |
| 澄清接口契约后的复测 | 4/4 返回成功、无重试 | 2/2 | 10,481／1,679 |

首轮无 Research 提案错误引用了任务身份；Research 提案引文与文档文本不逐字匹配，均被原有校验拒绝。之后只澄清完整配方替换、引用来源和字面匹配要求，并增加回归测试；**原失败记录没有覆盖，解析器和 Gate 没有放宽**。

复测两组均提出 `public_examples + input_state`。Research 分支读取两份官方 Python 资料，并附带两条通过来源匹配的引文；这不证明引文逻辑蕴含、检查可靠或 Research 优于另一组。两轮合计 **8 次 API 请求、25,945 tokens**；两轮各自回放均新增请求 0。

这是小样本接口验收，不是提案成功率的统计实验。模型随机性、任务难度和预算差异尚不能通过这两轮排除。

## 4. 尚未完成与下一步

1. **先收集并冻结真实三条件产物。** 当前 adapter 只支持 Python／JSON 函数，不是完整仓库 benchmark；需要实际项目执行与公开契约适配，以及多样正确解、真实回归和 Near-Miss。
2. **先测 Research 的独有信息增量。** 固定相同产物和共同义务，对比 fixed／等预算无 Research／Research；区分 H 已提供的诊断与研究资料新增证据。重点看额外检出与误拒，不只看提案是否合法。
3. 再补任务级规范／产物驱动探针及更丰富的条件化检查。当前只在三个预注册配方中组合，引用匹配不等于逻辑蕴含，不能称为完整自主 DeepResearch。
4. 前述证据足够后，再进入 **3A 冻结候选的 Skill 决策回放 → 3B 单轮反馈驱动更新**；暂不开展复杂路由、自动 Split 或多轮协同进化。

更完整的边界与命令见 [主线说明](skill-validation-mainline.md)。容器只保护宿主；同进程观察不防主动伪造。当前输入保持仅检查前后 JSON 状态，不覆盖对象身份和不可见副作用。
