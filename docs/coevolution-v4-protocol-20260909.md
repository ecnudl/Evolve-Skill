# V4 冻结协议：多文件执行修复 × 验证器独立晋级

本协议在首次 V4 模型请求前冻结。历史 V3 源码、输出和结论不修改。

## 研究问题与范围

本轮先检验工程闭环：完整失败反馈和稳定交付后能否产生可保留的 Skill；验证策略进化是否改善同一代码产物上的错误发现；受限官方资料研究相对仅反馈是否带来增量。

这不是跨 Domain 最终有效性实验，也不是 SkillOpt 或 SkillEvolBench 官方结果复现。任务来自已固定的九个 SkillEvolBench 项目，此前用于过适配 pilot。本次恢复多模块边界，但仍排除文件系统、完整 Docker/仓库操作、文档与覆盖率等原始流程。六个学习项目与三个 gate 项目分开；最终检查使用这三个已暴露项目的独立输入，不声称是未见过的新项目。最终公开 benchmark 必须在以后单独冻结和执行。

## 固定对照

- A `fixed`：固定 V0 验证器。
- B `feedback`：开发失败反馈生成 V 候选，经独立校准决定晋级。
- C `research`：开发失败反馈 + 有上限的官方资料研究生成 V 候选，经相同校准决定晋级。

三组都使用相同 Skill 优化器、两次调用执行器、Local Gate、Scope Gate、任务顺序、训练重复数。V 的候选不直接替换当前 V。B/C 每次最多三次、每次至多 6000 tokens 的模型调用，C 至多三页官方资料；无研究触发或取回失败要显式记录，不能称为有效 DeepResearch。预算上限匹配，不人为消耗未使用额度。

使用现有 PJLAB `glm-5.3`，四并发，temperature 0 / low reasoning，单目录一个执行进程。整个 run 最多 1600 个逻辑请求；每个最多三次已有传输尝试。不因答案错误、格式错误或得分低重新采样。中断后未解决的请求 reservation 停止，不盲目重试。不修改 `.env`、Clash 设置或路由。

## 学习与执行

两条学习历史 × 三轮；每轮两个新学习项目，重放所有先前学习项目。每个任务条件两次完整执行；相同历史、阶段、任务、重复和 Skill 内容共享同一请求，policy 名称不进入目标请求。

每次完整执行固定为：原始多文件补丁 → 沙箱公开测试 → 一次修订（允许 KEEP）。公开测试即使全通过也保留同等修订机会。私有测试、参考实现不进入任何 solver 请求。交付失败作为已观察失败，基础设施不可用作为 unknown。

Working 只接受 Local Gate 通过的候选；Approved 还需 Scope Gate。被拒候选及完整失败证据成为 repair_parent，供下一轮优化器修改，绝不自动执行或部署。完整证据包含实际产物、输入、期望/实际、合同及哈希；上下文超限时选择完整证据包而不截断代码。所有证据留盘，模型只接收明确标出的有限子集。

Local：来源任务相对 Base 与 Working 都有正的平均测试增益，hard 成功数不降，来源 preserved 检查无配对损失，旧任务所有检查无配对损失。Scope：Local 通过，累计 1/2/3 个 gate 项目上相对 Base 和 Approved 的公开检查与已验证额外探针均无配对损失。探针也进入 Local/replay gate，不再只用于 scope。known harm 优先于 unknown；探针不可用不抹掉独立有限测试证据，但不提供额外安全证明。不存在放宽 gate 直到出现 commit 的后验修改。

## 验证器研究与校准

Vt 在整轮冻结。只在第 0、1 轮结束后提出 Vt+1，下轮才生效。

验证器输出至多四个合法 JSON 输入，使用固定合同 clause ID + 代码行范围代替脆弱的精确摘录。主程序独立检查适用输入，并在隔离环境运行参考实现与代码产物；模型不能提供 expected 或自签 verdict。相同合法输入也运行 Base/Current/Candidate。

研究仅由具体开发行为失败/验证缺口触发。允许 `docs.python.org` 与 `developer.mozilla.org`，使用现有受限取回、快照、内容哈希和引用核验。任务明示合同优先于通用文档。不得搜索 benchmark 答案或隐藏测试。这里是 bounded documentation research，不等同于已完成通用自主 DeepResearch agent。

每次晋级：在同一个当轮 gate 项目的参考实现、正确等价实现、两个受控错误实现上，每个重复两次，并加上 Base 的自然产物。修订输入排除整个当轮校准项目及所有校准代码哈希；原代码、标签和逐项校准输出都不进入生成/修订提示。比较 old/new 同一批产物；至少四个 good、四个 bad 观测且各至少两个独立代码哈希。自然产物通过有限测试不等于已知正确，这些产物的额外发现单列诊断，不算晋级中的误杀；自然产物已失败可作为 bad。正确等价实现的探针分歧需审计，不能未经核实就声称真实误杀。

晋级采用保守配对规则：不新增正确产物拒绝、不新增 unknown、不把旧检出的缺陷变成漏检/unknown，并至少提高一次检测或减少一次 unknown。重复次数仅检验采样稳定性，不算独立项目，也不是统计安全证书。校准属于开发选择，不能同时作为独立最终验证器收益证据。失败时继续使用 old V。

## 冻结后评估与报告

Skill、Validator、源码、任务和历史全部哈希冻结后，三个 gate 项目的 disjoint final 输入各跑两历史 × 三次。评估 No-Skill、三组 Approved，以及三组 Working（后者为明确标注的强制使用诊断，不冒充部署）。最终结果绝不回流学习、研究或晋级。

报告 hard 正确率、测试通过比例、分项目/历史指标、配对输赢、交付失败、unknown、活跃 Skill 覆盖、晋级次数、检出/漏检/unknown、资料实际成功引用与使用、token 与 HTTP 账本。三项目 cluster bootstrap 仅探索性描述，重复抽样不作为增加项目数量。相同空 Skill 共用请求导致的零差异称为结构性相同，不声称统计等价。来源高分及其他 Domain 少退化仍是后续正式评估目标，本轮不能替代。
