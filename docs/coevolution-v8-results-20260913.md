日期：2026-09-13。反馈配对实验、Research 独立校准及离线验收均已完成；本轮模型进程已退出。

## 本轮新增

- 公共结构化反馈：记录实际错误阶段、错误类型、公开约束和执行回执；解析/交付缺失与语义失败分开，unknown 不视为已确认语义失败。
- 同初始回答的反馈配对实验：generic 与 structured 各一次修订，等模型调用预算，所有初始回答保留；新增 8 个开发任务家族、16 题、4 次重复，192 次调用。
- 独立 Research patch 结构诊断与校准桥：Rubric 只有在真实反例执行与独立筛查后才可能用于下一轮开发反馈；不因 JSON 合法直接启用，不批准 Skill scope。
- 所有实现独立放在 `skillopt/coevolution_v8/`，未修改冻结 V5/V6/V7 或旧实验结果。

当前数据流分成两条：公开任务与共享初始回答 → 简略/结构化公开反馈 → 各一次修订 → 两臂完成后才做隐藏评分；开发失败证据 → Research 检索与 patch 提案 → 独立 Coding 校准 → 决定是否允许下一轮开发反馈。`skill_feedback` 已提供给后续优化器的开发投影接口，但本轮没有把它接成新的 Skill 学习闭环，也未运行新 Skill 的公开 benchmark 对比。

16 题、8 个家族、4 次重复，共 64 个共享初始回答、128 次独立修订，192 次逻辑调用。所有初始回答保留。完成后离线复核与独立原生审计均通过：全部 192 个阶段重新核验交付状态与公开/隐藏评分，记录一致；其中 172 个有效产物重新执行检查、20 个缺失产物按原规则保留，另重执行 16 个参考产物。33 个冻结源码、205 个 HTTP attempts 及其限流记录闭合；1386 个运行文件字节不变，审计零新增模型调用。该复核验证既有 oracle 的可重现性，不额外证明任务代表性或 oracle 的外部有效性。

| 修订反馈 | Coding（32） | Spreadsheet（16） | Rule（16） | 领域等权宏平均 | 最差领域 |
| --- | ---: | ---: | ---: | ---: | ---: |

| 结构化 structured | 90.63% | 87.50% | 100% | 92.71% | 87.50% |

- 配对为 **10 胜、2 负、52 平**。8 家族等权差值 +12.50 个百分点，簇 bootstrap 95% 区间 [1.56,23.44]，但精确双侧 sign-flip **p=0.125**。不能只挑 bootstrap 排除零就宣布显著。

- 190/192 次 API 成功；2 个终止失败均发生在初始生成，原因是固定重试耗尽后的 429。128 次修订全部 API 成功。共 205 个 HTTP attempts，接口报告 389,201 tokens；不删除失败、不补抽。

## 已完成：Research 独立校准，保留旧验证器

在反馈模型进程退出后串行运行：6 个独立于研究来源的 Coding 校准家族、每家族 4 个控制产物、4 blocks；比较 old_a＋old_b 与 old_a＋new，共 288 次新调用。使用 PJLAB `glm-5.3`、4 workers、HTTP 至少间隔 10 秒、429 冷却 30 秒；更保守限流在本场首次调用前确定，各对照一致。

每政策有 96 个产物×block 位置，其中好/坏各 48；同一产物的重复不是独立新任务。old_a 在主对照两臂中精确共享，因此不是 384 次独立调用。下表为全部尝试，unknown 保留在分母中：

| 验证政策 | 坏产物检出 | 好产物误拒 | unknown（全部 96） |
| --- | ---: | ---: | ---: |
| 旧验证器一次 | 41/48（85.42%） | 0/48 | 17/96（17.71%） |
| 新验证器一次 | 43/48（89.58%） | 0/48 | 17/96（17.71%） |
| 旧＋旧（主基线） | 45/48（93.75%） | 0/48 | 20/96（20.83%） |
| 旧＋新（主方法） | 46/48（95.83%） | 0/48 | 19/96（19.79%） |

主对照仅净增 1 次检出，即 +2.08pp；6 家族簇 bootstrap 95% 区间 **[−4.17,+8.33]pp**，精确双侧 **p=1.0**。总体 unknown 少 1 个，但两个不同家族的好/坏类别各出现一次局部 unknown 增加；事前门要求不能被其他家族的改善抵消。因此结果为 **Reject / 不激活候选，保留旧验证器**，不是“平均分略高就更新”。这里的局部增加是有限样本中的观测，不能断言由 Rubric 语义退化因果导致。

在这份控制面板上，所有政策未检出的坏例均为 unknown；获得可判定结果的坏例已全部检出。没有观察到好产物误拒，但主对照两臂各有 17/48 好产物 unknown，不能将零误拒当作普遍安全或全部正确接受。冻结组合规则是“任一实际检出即检出；否则须两次均可判定才算未检出”，所以增加搜索次数也可能增加好产物的 unknown。

额外敏感性诊断：三通道均 API 成功的共同位置有 71/96；进一步要求探针均合法后剩 61/96，含 34 个坏例位置、27 个好例位置，仍覆盖 6 家族。四政策在该共同子集上全部检出 34/34、误拒 0/27、unknown 为 0，未观察到纯检测差异。它说明本批差异与返回/探针可用性有关，但这是移除 35 个位置后的事后诊断，不能替代主检验、证明无条件等效或用于挑选新 Rubric。

实际 254/288 次 API 成功，331 个 HTTP attempts、34 个终止结果；另有 22 个 API 成功但探针格式/输入不合法。232 个合法输入提案，其余 56 个无可执行探针：21 次输出耗尽、22 次格式/输入问题、4 次响应问题、9 次传输问题。它们不被记为发现语义缺陷，不补抽。该可用性水平限制了对验证策略本身的解释。

接口报告 692,135 tokens：old_a 219,886、old_b 208,749、new 263,500；主对照分别为 428,635 和 483,386，调用数相同但实际 tokens 不同。13 个调用无 usage，失败中间尝试的消耗也可能未返回，不能当账单。

完整只读审计通过 288 个组件、37 个冻结源码、331 个 HTTP attempts、私有登记与门控重算；另将模型和原生执行入口禁用后完成纯离线 replay，校准/登记/两份诊断目录合计 1591 个文件字节不变。校准审计复核已有真实执行回执，不重新执行参考 oracle，不能额外证明其外部有效性。

结果 hash：`fc47ce4307a575c33f276a8246b5b13e1a4c52fa589bd563c42339d7672e81e2`。独立审计 hash：`6954636d45fe7b5bab8ba2c570b9d068b8c7f8daae9ce1468cd846233f043045`。协议见 [反馈实验](coevolution-v8-feedback-protocol.md) 和 [校准实验](coevolution-v8-research-screen-protocol.md)。
