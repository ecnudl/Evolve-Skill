# V14：约束反例反馈 + 证据关联的局部 Skill 更新

预注册日期：2026-09-15。正式模型请求前冻结本文件、源码、任务及执行协议；V12 数据与评分不改写。

## 研究问题

针对 V12 表格轨迹中暴露的交付失败，以及公开样例未覆盖单位、边界、顺序、依赖约束的问题，
检验“可执行约束反例 + 有证据引用的局部更新”这个组合，是否优于普通执行反馈后的全文改写，
尤其能否改善 Spreadsheet，同时保持较好的多领域组合表现。不是要求每个领域 SOTA。

## 三个条件

1. No-Skill：空 Skill。
2. Independent：当前任务规范、公开义务、同样的实际开发轨迹反馈，整体重写 Markdown Skill。
3. Constrained：上述信息 + 开发专用约束反例的实际执行结果；每轮最多两个有证据引用的局部操作。

两种学习条件从空 Skill 开始，每轮各一次优化器调用，最多 4096 输出 token；完整 Skill 最多 6000 字符。
局部规则最多六条，每条包含 mechanism / when / procedure / avoid / claim_type / evidence_refs。
证据检查保证引用存在且行为/规范/交付类别相符，不保证自由文本在逻辑上完全受证据蕴含。
无效候选保留父版本，记录失败，不重新抽样。无事后候选挑选、不按最终分数回滚。

这是组合干预：额外 oracle 查询、上下文信息和更新形式同时改变，**不是等 oracle 预算的单因素消融**。
所有臂最终求解器相同；本轮不隔离每个子组件的贡献，也不是原生上游 SkillOpt 优化器的直接对照。

## 数据流与共同求解协议

开发任务 → No-Skill / Current Skill 各生成并执行 → 一次公开反馈修订 → 完整开发检查
→ 独立反馈投影（区分 API、交付与语义结果）→ 优化器 → 下一轮 Skill。
Constrained 额外将实际产物交给源任务绑定的四个约束反例，再将回执与义务映射给局部更新器。
这些义务/反例是固定的人工程序化构造，**不是 DeepResearch 自动生成，也没有验证器协同进化的效果声明**。

共同求解器每条轨迹恰好两次模型请求，每次最多 8500 输出 token。Native 生成标准产物，修订采用
严格的 `action: keep/apply`；Coding 支持 FILE 模块输出和修订 `action: keep`。
修订请求失败或交付解析失败、而初稿合法时，保留初稿，最终检查该真实产物，同时保留失败回执。
合法但语义错误的修订不会回退；禁止借隐藏检查选择最终产物。

## 固定样本与重复

正式训练：2 轮 × 每轮 2 Coding + 2 Spreadsheet = 8 个开发任务，每个领域四种新编写结构。
所有开发任务至少 2 个公开检查、6 个隐藏检查；另各 4 个义务反例。
正式最终集：Coding、Spreadsheet、Rule Reasoning 各 8 个新编写任务族，每族一个任务，共 24 题。
Rule 不进入训练；正式最终任务族不进入训练或在线 smoke。
包括允许负数、新规则取代旧规则等任务，避免以全局裁剪或一律保留旧行为取巧。

3 个独立学习/评测调用组。每组真实重新调用 No-Skill，不共享其随机响应。
同一组内相同任务 + 完全相同 Skill 文本才允许精确复用同一轨迹；不当作新独立抽样。
所有六份学习 Skill 在任何正式最终调用之前共同冻结。
每组最终任务/臂调用次序按预先固定种子打乱；跨组不同调用身份。
三组反映实际观测变异，但不能单独分离 Skill 文本差异与求解器采样方差。

独立性单位是手工结构族，不是检查数、模型请求数或三次重复。结构族之间 IID 仍是假设，
尤其 Rule 共享同一 Horn-rule 执行语言；不能把它们称为独立领域或自然总体随机样本。
数据全部为新编写的合成原生执行任务，不是公开 benchmark，不复用 V12 最终题目和答案。
题目是否过易必须按原结果报告，不能看到正式分数后调难度、筛题或重新运行较差结果。

## 统计与事前判定

最终固定网格：24 题 × 3 组 × 3 条件 = 216 个评分位置；相同文本别名不增加独立样本量。
主要终点两项：Constrained − Independent 的三领域宏平均、Spreadsheet 成功率；两项 Holm 校正。
先平均同一任务的三组，再按任务族汇总、领域等权；按领域分层对任务族 bootstrap 5000 次。
配对符号翻转：至多 16 个非零族时枚举；更多时预定种子 20,000 次 Monte Carlo（+1 修正）。
报告置信区间及校正 p，不把正点估计或单独 bootstrap 区间误说成证明。
八族/领域仍是小型试验，非显著不证明无差异，零损失不证明安全或非劣。

同时描述每领域与 No-Skill 差值、最差领域分数、最大领域下降、逐题增益/损失、
真实语义失败、交付失败、执行未知、共同交付回退及三个调用组变异。
Constrained 即使提高平均分，只要明显恶化其他领域，也不宣称达成安全泛化目标。
效果明确后再用等反例信息的全文改写、无额外反例的局部更新等消融分离组件贡献，
并在补齐安全执行与公式重算环境后迁移至真正公开 benchmark。

## 预算、故障与审计

模型：仓库已有 PJLAB glm-5.3；4 个工作槽，HTTP 尝试全局至少间隔 10 秒，429 共享冷却。
沿用原已验证传输策略，最多三次传输尝试；不做语义重抽样。
正式正常最多约 540 次逻辑调用（开发 96 + 学习 12 + 最终 432），硬上限 640。
额外反例只消耗原生执行，不新增模型请求，但单独记账，不能说验证预算相同。
smoke 1 组 1 轮，只用开发结构的新 smoke ID：2 开发 + 2 冒烟最终题，最多 64 逻辑调用。
smoke 仅校验工程协议，不作为效果证据；正式协议/源码快照冻结后禁止按最终观察修改。

滚动窗口最多四个求解任务；PAUSE 后不再启动新任务，排空已有任务再退出。
每次请求和执行保存意图与回执；中断后意图未闭合则停止，不能悄悄重跑或删除坏结果。
临时 caffeinate 只避免空闲休眠，不改系统电源策略，合盖/网络中断仍可能影响请求。
结束后检查全部 API/原生执行引用闭合，并进行零 API、零原生执行、文件不变的完整重放。
