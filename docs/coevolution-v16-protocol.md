# V16：仅修正文档展示接口的协同进化 pilot

状态：首次 V16 模型调用前登记。继承 [V15 冻结协议](coevolution-v15-protocol.md) 的全部科学设计、预算和限制；本文件仅列出明确差异。旧 V15 源码、协议、模型回执、判定和最终成绩全部保留，不修改、不重判。

## 为什么另登记

V15 smoke 中，Research 实际读取了两页官方文档，但模型把可见原文中的换行替换成空格，导致两条出处真实的引文不符合严格原始字符串匹配。该提案仍按旧协议记为无效；这不是 Research 方法无效的证据。

大批 V15 pilot 已登记但在任何模型调用前暂停，原自动队列停止。V16 在相同、尚未运行的 pilot 任务和设计上执行。V15 smoke 最终成绩不能指导 V16 任务、阈值或策略选择，不合并两版本成绩，也不把重复 smoke 当独立科学样本。

## 唯一行为改动

原始获取模块、官方页面 URL、原始 HTML/文本快照和其哈希全部沿用 V15。先取 V15 已截断的最多 3500 字符可见摘录，再执行 `" ".join(text.split())`，形成单独封存的展示文本。不能先规范化再重新取 3500 字符，否则会增加可见内容。保存原始 bundle hash、原始摘录 hash、展示文本 hash 和投影版本。

模型获得该展示文本；引用仍须是实际展示文本中的 12–300 字符精确片段。不能对模型输出做宽松模糊匹配，不能事后把旧 API 回执改成新输出。引文仍只证明出处，不证明语义蕴含、适用性或校准有效性。

验证器 state、探针执行、独立校准、共同反馈、Skill 更新器、任务、oracle、随机种子、计算预算均不改变。新的 policy 提案绑定独立 V16 版本和真实请求身份，不伪造旧模型调用。

## 开始前的工程检查

1. 单元测试验证空白规范化、严格引用边界、原文与展示快照不可变、错误输入、开发证据隔离、四轮三历史闭合和完成后零 API 回放。
2. 单独登记一次 Research 交付诊断：只用已经闭合的 V15 开发证据，重新实际调用一次提案，不看最终分数；最多 1 次逻辑调用，标准传输重试保持有界。诊断不参与 pilot 成绩，也不按策略内容/校准收益挑选重跑。
3. 只有交付诊断有效且工程检查通过才启动 pilot；若交付仍失败则保留失败并停下，不重采样至通过。该前置门检验实现可用性，不以方法得分为条件。

## pilot 保持原设计

3 条历史、4 轮、4 个条件：No-Skill / fixed / adaptive / adaptive_research。8 道开发任务、6 道独立校准任务、18 道最终任务（每域 6 个结构家族）；Rule 完全不进入学习与校准。相同干预仅在同一历史中作透明别名，不作为独立重复。

所有历史/checkpoint 冻结后才进行最终与 checkpoint 小片评分；不允许最终标签回流。总逻辑调用上限 1536，PJLAB `glm-5.3`，4 workers，HTTP 尝试间隔至少 10 秒。Research 是两页固定官方资料的有界研究，不是自主 DeepResearch；不宣称等总成本、统计安全或公开 benchmark 效力。

如果无验证策略被接受，则没有发生有效协同干预；如果只改善引用交付，只报告工程收益；即使某个 Skill 比 Base 高，也不能据此归因于验证器进化。大批运行结果不决定事后修改校准条件或选择性删样本。

## 代码和运行隔离

V16 直接复用 V15 的 tasks/runtime/evidence/learning/analysis/原生校准；只隔离必要的 orchestration、proposal 和 presentation 入口。报告复用相同只读证据审计。所有 V15 和 V16 依赖同时进入新协议 source hash 与可重建源码快照。

输出限于 `outputs/coevolution_v16/`；每批独立目录。监督器、显式暂停、休眠提示、不可变 intent/receipt、禁止自动重采样和完成后无 API/执行回放要求与 V15 相同。没有自动换模型或预算增加。
