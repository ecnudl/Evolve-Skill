## 后续评测入口修复

此前长流式仅接在恢复入口，常规`continual_eval`仍默认非流式/read120。新增显式`continual-eval-v2`：共同配置把stream/read300/wall1800/`completed_response_v1`传给真实CachedAPI，并冻结到协议和服务身份；BigModel GLM-5.3允许预算不超过65,536。v1保留原schema、16k上限与旧传输默认，旧运行只能使用原冻结源码续读。

输入仍是冻结任务面板、共同模型预算和空Skill检查点；输出仍为逐位置预测、原生评分和成本，没有增加Skill方法独占能力。[配置例子](../configs/continual_eval/noskill_long_stream_v2.example.json)的8192仅是示例预算，所有panel为null，不能直接视为已准备或已运行的实验。新入口已完成离线HTTP模拟、缓存不重抽、schema/哈希和旧协议兼容测试，尚未启动统一预算的全量新基线。

SkillOpt/GEPA的`continual_learning`尚未迁移到该传输协议；不能把评测端修复称为整个学习链已修好。常规runner也未获得恢复器的精确协作暂停能力。下一轮真实方法比较须先统一学习/评测配置、确定有限预算及交付失败统计口径，再冻结新输出目录，不无限加长或反复采样到答对。
