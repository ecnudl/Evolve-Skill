# V7 冻结协议：证据校验接入后的下一轮协同进化

日期：2026-09-11。本协议必须在首个模型请求之前冻结；V5/V6 结果和源码不改。

## 研究问题与界限

主要问题：相同初始 Skill、相同开发产物、相同探针调用次数下，新 Research 策略产生的反馈，是否让下一轮候选 Skill 在冻结后获得更好的跨域表现、较少负迁移？

这是合成原生任务上的两轮诊断，不是公开 benchmark、stock SkillOpt 复现或已经成功的安全范围扩张。两个学习历史与参数变体不能替代独立项目家族。

## 数据流

1. 开发任务 → Base 两阶段执行 → 精确绑定实际产物和宿主执行回执 → 提出共同初始候选 Skill；记录来源门，不把候选当作批准 Skill。
2. 初始候选重新执行开发任务。Research 事前固定读取 history 0 的三个真实父候选产物，以及三个宿主错误代码夹具；history 1 不额外扩充研究上下文。两类来源明确区分，经完整证据视图送入三阶段有界 Research，不按运行结果挑选。
3. Research 研究官方资料，只提出 Coding Rubric 的搜索策略变更；论断必须绑定产物/检查/回执。引用出处不等于语义正确；补丁 check_id 唯一。不使用 V5 备用提案。
4. 新提案先冻结，再用独立校准面板比较旧 A＋旧 B 与旧 A＋新。每个位置主对照均两次调用；旧 A 是共享轨迹，不是独立重复。
5. 下一轮反馈在同一个初始候选产物上生成：固定分支收到旧 A＋旧 B；研究分支收到旧 A＋新。两分支都使用相同证据视图，保留全部完整配对反馈。随后分别提出和执行下一轮候选 Skill。
6. 只有校准通过的新验证器进入下一轮 active 分支；未通过的新策略仍可在事前声明的 shadow 实验分支中运行，不能冒充被批准更新。若 Research 无有效提案，不运行新策略校准，不伪造新分支，shadow 与 fixed 精确复用。
7. 两分支候选、验证器选择与固定合同路由全部冻结，再做最终原生跨域评测。最终数据不再返回学习。来源门与跨域反事实表现分开报告。

## 固定规模与预算

- PJLAB `glm-5.3`，4 个 worker，最多 700 个逻辑请求，每个最多 3 次固定传输尝试。使用已有 `.env`，不改凭证或代理。
- 全局每次真实模型 API HTTP attempt 至少间隔 3 秒；429 触发 20 秒共享冷却，Retry-After 最多 60 秒。重试与成绩无关，不增加语义重采样。少量官方文档获取是独立的 Research 资料请求，不计作模型调用。
- 2 个完整学习历史。开发 3 家族；校准 6 个新家族，各 reference/equivalent/semantic/preservation 四份代码，4 个重复 block、3 个实际探针通道，共 288 次请求。
- 最终计划 18 题：Coding、Spreadsheet、RuleReasoning 各 6 题，结构簇数分别 3、2、2。共享底座合并，不按题目名称夸大独立样本。
- 求解每次均为生成＋一次公开反馈修订。所有条件提供一致格式提醒，解析器不放宽；不补齐或重写模型输出。不因格式错误选择额外样本。
- 若开发题仍出现 Base 满分，仅报告实测难度不足，不反复根据模型结果调最终题。

## 门控和统计

验证器只在 V6 独立校准屏障返回 Support，且六项目簇的精确双侧比较 p≤0.05 时进入下一轮开发反馈。它不批准跨域 Skill 部署。沿用屏障要求：错误检出增益区间下界大于 0、没有新增正确代码平均误拒绝、没有项目/类别 unknown 上升；至少 6 簇、4 block。小样本屏障不是通用安全保证。

最终策略为 No-Skill、固定验证器候选、研究反馈候选 shadow、校准选择的候选、校准选择＋合同路由候选。后两者精确复用相应求解轨迹，无第三次抽样；这些都是候选反事实，不是 Approved 部署。没有独立 scope approval 的情况下，实际 Approved 保持 Base。

主研究比较为研究反馈候选与固定验证器候选，报告每领域和宏平均、双方产物可用配对胜负、全部尝试得分、最差领域、负迁移率、范围覆盖和真实调用成本。额外事前登记“两个求解阶段 API 内容均成功返回”子集，仅用于判断接口/响应差异，不能替代主结果或视为因果证据。HTTP 成功不代表内容交付成功：正确、语义错误、产物格式缺失、传输缺失、响应内容缺失（例如截断或不完整 SSE）、原生 oracle 不可用分别记账。

所有推断先在结构家族内合并参数实例和学习历史，再做配对 cluster bootstrap 和精确 sign-flip；仅 7 个最终簇，结论必须克制。重复探针不被当作新任务。等调用次数不代表等 token 或费用。
