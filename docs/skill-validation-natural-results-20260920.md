# 条件化 Skill 更新与独立验证：实验报告

日期：2026-09-20。本页保留初期 **96 个开发位置**的诊断，不是整轮最终结果。代码与工程验收完成；自然实验遭遇 API 故障，并发现参考审计与公开契约冲突。**9/21 发布补记：后续已保存 169/256 个开发位置，最新状态见[发布汇总](research-progress-20260921.md)；下面的阶段性分数不外推到全部 169 个位置。**

## 本次改进

- **改变 Skill 更新方式**：不再默认保留父 Skill 的全部规则，采用 Preserve / Repair / Restrict；明确任务契约优先、适用前提、例外和 abstain。加入仅看公开契约的对照，区分“纠正格式或要求冲突”与“执行反馈的增量作用”。
- **让验证产生新行为证据**：问题驱动、来源受限的 Research 提出可复用条件化检查策略，再针对匿名产物生成公共探针。同题所有条件执行同一组探针；模型提出的预期结果仍是假设，不能当作隐藏真值。
- **独立校准控制反馈**：只有通过独立 Coding 校准的完整检查策略，才能向 updater 提供限定的新探针反馈。未通过则回到固定公开反馈，不把不同名字的相同候选算成独立方法。
- **更可信地测量**：真实模型产物、冻结的数据分区、重复执行、任务族层面的描述性区间，同时报告原始和增强测试、unknown、误拒与成本。

这仍是 Coding 单轮内容更新实验，不是已证明的跨域泛化。现有 Skill Gate 工程路径保留，但本实验不发放部署或跨域授权，也不把强制使用候选的成绩当作条件部署成绩。

| 项目 | 设置 |

| 开发／校准／确认／最终 | 64／24／24／40 个任务，共 152 个；近重复按词面任务族隔离 |

| 父 Skill | 冻结的历史真实 Coding Skill，包含文件分段交付、输入保持等局部规则 |

| Research 对照 | 两个自适应分支共享开发证据、接口和预算上限；实际 token 成本另报 |
| 执行 | 远程 Linux、固定 Docker 镜像、隔离运行；不在宿主执行模型代码 |

固定对照仅使用原公开检查。Research 的主要比较对象是相同接口的无 Research 自适应分支，不能把相对固定对照的收益全部归因于研究资料。

## 自然模型结果

已完成开发区 **48 题 × 2 条件 × 第一次执行 = 96 个位置**。预设的第二次执行尚未开始；不是 96 个独立任务。以下仅是原始执行器输出，**不是经过契约复核的真实正确率**，也不是新方法最终成绩。

| 条件 | 增强 H 原始 pass | 增强 H 原始 fail | unknown | 总位置 |
| --- | ---: | ---: | ---: | ---: |
| No-Skill | 31 | 4 | 13 | 48 |
| 原父 Skill（Current） | 37 | 2 | 9 | 48 |

完整配对为 Current **1 胜、0 负、32 平、15 未知**。独立最小例执行确认了那一个胜利对应的边界错误，但这仍只是一道题、一次生成的观察。不能由上表宣称 Current 提升了 12.5 个百分点，更不能归因于本轮尚未运行的新 updater。

unknown 的来源：16 个 API 失败、4 个回答解析失败、2 个位置因同一任务参考 H 超时。API 失败在 No-Skill／Current 间为 10／6，缺失并不平衡。

本次尚未进入真实 Research 策略生成、验证器校准、Skill 更新、确认和 final。**三个验证器对照及新 Skill 的实际收益仍未测得**；工程 fixture 跑通不能替代这些结果。

### 为什么暂停

- 先出现连续 HTTP 503；一次独立短请求返回 200 后恢复原回执继续运行，但随后再次出现上游流错误和超时。
- 60 个新增有终态的实验请求中，44 成功、16 失败：9 个最终 HTTP 503、6 个 upstream stream error、1 个 timeout。另复用 a 的 36 个成功请求。单并发代表性代码生成检查随后仍能成功，说明**接口可调用但当前不够稳定**，不能断言密钥失效，也不能据一次成功就断言并发实验恢复稳定。
- 1 个正在读取流的请求被本地暂停中断，原 intent 保留，无服务端终态回执。身份为 `HumanEval/98 / current / repeat 0`；不得直接重采样或伪造 API 回执。恢复前需要显式登记本地中断 unknown，保持原记录。
- 主实验已有报告用量至少 **75,051 tokens**；失败／重试和中断请求的完整用量未知，不能视为精确总成本。

### 轨迹揭示的评分风险

`HumanEval/141` 的题面限制起始字符为 `a-z/A-Z`；模型按该范围检查，但参考实现用 `isalpha()`，可接受更广的 Unicode 字母。另做 9 次独立 Docker 诊断后，已确认参考审计会在该约束上误判，不能将这类不一致称为模型错误。Python 的 `isalpha()` 使用 Unicode 字母分类，而非仅 ASCII 范围，见 [Python 3.11 官方文档](https://docs.python.org/3.11/library/stdtypes.html#str.isalpha)。

| 公开契约可推导的最小例 | 题意预期 | 参考实现 | No-Skill | Current | 解释 |
| --- | --- | --- | --- | --- | --- |
| `/141`：`é.txt` | No | Yes | No | No | 参考实现与明确字符范围冲突；两份模型代码在此例正确 |
| `/141`：`a.txt` | Yes | Yes | Yes | Yes | 合法 ASCII 对照 |
| `/76`：`is_simple_power(0, 0)` | True（`0**1 == 0`） | True | False | True | 确认一个真实的局部配对改善，但不能由此证明因果或稳定泛化 |

这些检查没有调用模型，未修改原 b 标签或回执；是事后人工开发诊断，不进入当前 updater、校准或 final。回执见 `outputs/skill_validation/natural_development_diagnostic_20260920/summary.json`。

`HumanEval/145` 则发现双方对负数数字和处理不符合公开示例的共同错误。两类问题必须分开：**真实模型错误可以用于研究验证缺口；有争议的审计标签不能直接成为校准真值。** 这些是本次人工开发诊断，不是自动 Research 的已验证收益。

## 后续判读原则

1. 先复核上述 H／公开契约冲突，冻结独立的争议标记和修订依据，不为提高分数事后改答案。参考代码与自身一致不等于满足题面。
2. 在稳定接口下恢复同一面板，明确处理 1 个中断请求；保留失败和 unknown，不只重跑不利样本。再看校准是否新增检错、是否误伤正确实现；证据不足应拒绝或 Pending。
3. 将契约对照与执行反馈对照比较，判断改进来自消除父 Skill 的局部硬约束，还是新增行为证据。
4. 比较各候选对 No-Skill、Current 的配对收益和退化，不只看一个总准确率；共同父 Skill 的两次更新不能当作多条独立学习历史。
5. 本轮若仍接近天花板，只能说明该分布不适合证明微小正收益。后续独立协议再引入真实依赖修改任务与跨域约束保持，不回头挑选本轮测试集。
